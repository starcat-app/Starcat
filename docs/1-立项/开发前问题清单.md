### 1.2 数据库循环外键依赖

**问题**：`repos.id → starred_repos.repo_id` 形成循环外键，SQLite 无法创建。

**解决方案**：移除 `repos.id → starred_repos.repo_id` 这个不合理的外键。

```sql
-- repos 表：移除循环外键
CREATE TABLE repos (
    id TEXT PRIMARY KEY,                    -- GitHub repo ID (唯一标识)
    ...
    cached_at TEXT                          -- 移除：FOREIGN KEY (id) REFERENCES starred_repos
);

-- starred_repos 表保持
CREATE TABLE starred_repos (
    repo_id TEXT PRIMARY KEY,             -- 关联 repos.id
    ...
    FOREIGN KEY (repo_id) REFERENCES repos(id) ON DELETE CASCADE
);
```

### 3.1 Release 订阅通知

**问题**：功能清单中 Release 订阅追踪是 P2，但用户要求必须做。

**解决方案**：Release 订阅移到 **P1**，使用轮询方案监测。

```swift
/// Release 发布通知监测管理器
/// 使用 NSBackgroundActivityScheduler 在 macOS 后台定期执行（建议每 4-6 小时一次）
@MainActor
@Observable
class ReleaseMonitor {
    var newReleases: [ReleaseNotification] = []

    /// 检测所有订阅的仓库是否有新 Release
    func checkForNewReleases() async -> [ReleaseNotification] {
        let subscriptions = database.getActiveSubscriptions()
        var notifications: [ReleaseNotification] = []

        for subscription in subscriptions {
            if let notification = await checkRepo(subscription) {
                notifications.append(notification)
            }
        }

        return notifications
    }
}
```

### 4.5 RAG 无证据引导与 GitHub 联网审计

**决定（2026-07-14）**：知识库问答不能把“没有本地分片”直接等同于整轮失败，也不能在没有可信证据时让 Generator 自由回答。

| 场景 | 决议 |
|---|---|
| 明确问候 / 致谢 / 告别 | 本地直接返回知识库使用引导与推荐问题，不调用 Planner、Retriever 或 Generator |
| Planner 判断为非知识库闲聊 | 返回 `guided_discovery`，不执行检索与生成 |
| 本地无命中，但附件或 GitHub 临时上下文有真实内容 | 允许 attachment-only / remote-only 生成 |
| 所有证据都为空 | 明确说明未找到相关内容，展示最多 3 个可点击推荐问题，不调用 Generator |
| 推荐问题 | 持久化到历史消息；点击后恢复原问题的显式 repo 范围，再作为新问题发送 |
| GitHub 联网 | Planner 声明意图，执行层兜底高置信实时资源；默认按 `repo × resource` 逐项确认，Composer 主动联网时视为本轮已授权 |

GitHub Issues / PR 使用 `/search/issues`，执行层固定注入目标 `repo:` 与 `is:issue` / `is:pr`，并过滤 Planner query 中可扩大范围的 qualifier。审计仅保存资源、目标仓库、查询摘要、网络或缓存、HTTP 状态、结果数、耗时、脱敏 URL 与错误，不保存 token 或远程正文。

### 4.6 RAG 长流式内容的 UI 性能边界

**决定（2026-07-14）**：Provider 的原始 token/delta 不得逐条写入 SwiftUI 可观察状态。完整内容必须在独立 buffer 中累积，正文严格不超过 8Hz、Think 严格不超过 5Hz 发布快照，并在完成、失败、取消和流提前结束时 flush，性能保护不得截断回答或推理内容。

| 问题 | 决议 |
|---|---|
| 长 Think 高频刷新 | UI 严格不超过 5Hz；运行中只渲染最近 8,000 字，完整内容仍保留并在结束时收口 |
| 长回答实时尾部 | 继续使用稳定 Markdown 前缀与普通 `Text` 尾部，不对持续变化的尾部启用 `.textSelection(.enabled)` |
| Think 执行步骤 | 始终复用同一详情行身份，不以完整正文作为 `ForEach` identity |
| 滚动跟随 | 只有 `isFollowing` 作为外部可观察状态；phase、底部可见性与手势标志使用 `@ObservationIgnored` |
| 复制能力 | 流式中不创建 AppKit `SelectionOverlay`；完成态保留整条回答复制/导出入口 |

运行态采样已确认原故障为 SwiftUI/AttributeGraph 持续布局：主线程热点集中在 `SelectionOverlay`，内存持续增长并伴随 “Modifying state during view update”。因此该约束属于正确性边界，不只是体验优化。

**已更新**：`docs/3-设计/详细设计/30-本地RAG设计.md`、`docs/4-工程进度/知识库RAG专项/知识库RAG专项进度.md`、`docs/功能实现总览.md`

**Issue 阅读摘要补充（2026-10-27）**：摘要使用按语义分段、重点加粗的 Markdown，不套固定栏目。小型面板冻结完整段落，变化中的尾部最多每 125ms 渲染一次 Markdown，流式期间关闭文本选择层，完成、停止和错误时补齐尾段；不改变 RAG 的正文策略。入口以正文与输入区之间的分割线定位，整个按钮位于线上方，下缘留 8pt 间距，不占输入宽度。面板默认高 480pt，顶边支持纵向拉伸，最小 300pt 且以详情可用高度为上限；宽度不由拖动改变，底边固定。高度仅在展示容器维护，同帖收起后保留，完成态缩放不启用底部跟随；面板收起或切帖只隐藏展示，生成会话继续运行。

### 4.7 主窗口 AI 对话的 Think 展示边界

**决定（2026-07-14）**：主窗口 AI 对话只展示 Provider 明确返回的 reasoning，不把等待提示伪装成思考内容。Reasoning 首个 delta 到达后展开；收到 `reasoningCompleted` 时自动折叠，未发送该事件的兼容服务以首个正文 delta 兜底。

| 问题 | 决议 |
|---|---|
| 长 Think 性能 | 完整内容在独立 buffer 累积，UI 最多约每 150ms 或累计 256 字发布一次快照 |
| 文本选择 | 流式 Think 不创建 `SelectionOverlay`；完成态与历史回看恢复文本选择 |
| 终态收口 | 成功、取消、失败都 flush；只有 reasoning、尚无正文时取消也保留 assistant 消息 |
| 模型兼容 | Provider 未返回 reasoning 时只显示通用等待态，不生成虚假 Think |
| 历史持久化 | JSON 继续使用 `ChatMessage.reasoning`；独立 SQLite 追加 `v2-chat-message-reasoning`，保留既有数据 |

### 4.8 RAG 主动联网与统一审计

**决定（2026-07-14）**：RAG 联网分为 GitHub 结构化实时查询与用户显式开启的 External Search，两者都必须在请求发出前创建可展开的“联网搜索”执行步骤，完成后自动折叠。

| 场景 | 决议 |
|---|---|
| 最新 Issues / PR / Release 等高置信 GitHub 实时问题 | 执行层在 Planner 漏报时补齐结构化请求，不能用 README 中的旧链接代替现场数据 |
| Composer 未开启联网 | 不执行普通 Web Search；GitHub 结构化请求继续沿用 `repo × resource` 确认 |
| Composer 开启联网 | 视为本轮明确联网授权；允许 External Search，并自动批准本轮 GitHub 结构化请求 |
| 实时问题未取得成功非空的网络证据 | 拒绝用本地旧内容生成确定性答案，明确反馈联网失败或无结果 |
| 私有仓库 | 只有开启“允许私有仓库参与外部搜索”后，仓库身份才可进入 External Search query |

External Search 复用 Settings 已配置的 AnySearch、Tavily、Exa 或 Brave Search；审计保存 Provider、查询摘要、结果数、耗时与最多 5 条标题/URL，不保存网页正文。GitHub 临时正文仍只在本轮 Prompt 中使用；普通 Web 正文不写 `rag_message_remote_contexts`，因此不新增数据库迁移。

### 4.10 RAG 后台生成期间的会话切换性能边界

**决定（2026-07-15）**：会话选择属于高优先级交互，必须在第一次异步读取前提交选择意图；后台回答继续运行，但不得继续把流式状态投影到已离开的中栏。SQLite 是唯一真源，窗口内允许使用有界 LRU 展示缓存和低优先级预热，以空间换取最近会话同帧切换。

| 问题 | 决议 |
|---|---|
| 会话选择 | `selectedConversationID` 在首次 `await` 前更新；缓存未命中立即显示轻量加载态，不保留上一会话正文 |
| 缓存一致性 | 最近 24 个持久化会话快照使用 LRU；消息、摘要、标题、分组或置顶写入后失效对应项 |
| 流式正文 | 高频 UI 只发布 `StreamingMarkdownSnapshot`；完整字符串只在完成、失败或取消收口时物化 |
| 自动滚动 | 中栏使用非惰性 `VStack` + 永久 bottom sentinel；跟随时由 `.defaultScrollAnchor(.bottom, for: .sizeChanges)` 校正流式增长与折叠，用户上滚后关闭尺寸锚定；当前 `ScrollViewReader` 只处理历史恢复、滚底按钮与大纲，proxy 只允许被单次 MainActor 调度短暂捕获，禁止持久保存或直接修改 `NSClipView` offset |
| 历史布局 | 打开历史会话只渲染最新 2 轮，每次手动加载更早 10 轮并恢复原视口；窗口不改变 Prompt、引用、复制、导出或持久化使用的完整消息数组 |
| 布局 | 流式滚动禁止调用 `layoutSubtreeIfNeeded()` 强制整棵消息树同步布局 |
| 派生展示 | 大纲、引用和 Markdown 固定正则不得随每个流式 revision 重算或重编译 |
| Debug | 关闭时不读文件；开启时异步加载且不阻塞正文，解码结果使用有界会话缓存，历史文件不删除 |
| 标题 | 保留首轮并行生成与最终持久化，禁止逐字符修改全局会话数组 |

### 4.13 RAG Embedding 异步写回一致性

**决定（2026-07-16）**：Embedding 请求跨越网络 `await`，chunk id 可能在 source diff 或人工覆盖后继续复用，因此不得仅凭 id 写回。`rag_chunks` 通过追加 `v11-rag-embedding-claim` 获得 `embedding_claim_id`；请求前在 SQLite writer 事务内 claim，返回后仅在 id、`content_hash`、pending 状态和 claim id 全部匹配时写 ready/failed。

| 项 | 决议 |
|---|---|
| Schema | 只追加 v11 migration，不修改已发布的 `v7-knowledge-rag` 建表 SQL |
| 正文变化 | source 重建、人工覆盖和恢复原文都必须清空旧 claim 与旧向量 |
| Provider 异常 | 返回数量不一致或含空向量时整批失败并释放 claim，禁止错位或部分写回 |
| 并发语义 | 后领取者可接管同一 pending chunk；旧请求因 claim 不匹配静默丢弃结果 |

### 4.14 RAG 自托管检索后端回退语义

**决定（2026-07-16）**：`fallbackToSQLite` 同时约束 Meilisearch/Qdrant 的查询与索引同步。开启时，普通外部错误或查询空命中允许回退本地；关闭时，配置、查询与同步错误必须原样向上传播。`CancellationError` 表示用户或上层任务已取消，无论开关值都禁止触发本地回退。

| 项 | 决议 |
|---|---|
| 查询 | 两种外部 Provider 通过同一显式开关决定是否包装 SQLite fallback |
| 同步 | 索引同步复用统一错误策略；允许回退时记录错误但不阻断本地索引完成 |
| 无效配置 | 回退关闭时在 Service 装配边界抛错，禁止静默改成本地 Provider |
| 取消 | Meilisearch、Qdrant 查询与同步都必须继续抛出 `CancellationError` |

### 4.19 External Agent Runtime 多后端边界

**决定（2026-08-16，2026-08-21 扩展为多后端 POC，2026-08-22 补齐 Codex 工具桥）**：不推翻 DeepSeek Harness，也不让任一外部框架替换全部 Agent。Starcat 保留 `LoopAgentRuntime`，新增统一 `ExternalAgentRuntimeHost + Provider Adapter`；Codex App Server 与 DeepSeek Harness 都是可切换后端。Weekly、Repo Insight、Alternatives 可在 Loop 与 Codex 间切换；Untagged 等带审批写入的 Agent 继续锁定 Loop；General / Research POC 可在 Codex 与 DeepSeek 间切换。

| 项 | 决议 |
|---|---|
| UI | 继续使用 Starcat 原生 Workspace、Composer、Run Surface 与 Inspector |
| 路由 | `AgentDefinition.runtimePolicy` 声明允许后端；`AgentRuntimeRouter` 解析用户偏好，禁止 View 按 Agent ID 分支；用户显式选择外部后端后禁止静默回退 Loop |
| 模型路由 | 工作台统一按 `Runtime → Provider → Model → Reasoning` 选择；Codex Provider 来自本机 `config.toml`（依赖 `env_key` 的路由因凭据隔离不可选），DeepSeek Harness Provider/Model 来自 Starcat「设置 → AI」中已验证的 OpenAI-compatible 配置 |
| 运行形态 | Codex 使用用户已安装并登录的 `codex app-server`；DeepSeek 使用外部安装的固定 `0.1.1rc1` wheel，macOS arm64 需要主文件、`-rg` 与 `-spawn-helper`，不进入 App / DMG |
| 控制协议 | 共用 newline-delimited JSON-RPC Host；Codex 与 DeepSeek 各自维护握手、事件、停止和 capability adapter |
| 领域数据 | 外部 Runtime 禁止直接访问 SQLite；Codex 通过 App Server `dynamicTools` 仅调用 definition allowlist 内的 Starcat 自动只读工具，schema 与权限由宿主二次校验；DeepSeek 的临时 Loopback MCP Bridge 仍需单独完成 token / repo scope 验证 |
| 默认工具 | Codex 首批开放 Weekly、Repo Insight、Alternatives 已有只读工具；写入、审批、高成本工具不进入外部 Runtime。产品化时仍须硬禁用 Shell、FS、Terminal、Job、Browser 与 Subagent；prompt 约束不视为安全隔离 |
| Loop 预算 | 通用默认仍为 32 次；Weekly、Repo Insight、Alternatives 按 definition 提升到 96 次。外部 Runtime 不复用本地 Loop 的 32 次工具预算 |
| 插件 | 禁止运行时安装任意 npm / pnpm 或社区插件；只允许编译期锁定、审计并登记 manifest / License 的白名单依赖 |
| 渠道 | 只允许 Direct arm64 实验构建；签名、Notarization、进程组清理与凭据隔离通过前不得发布；Intel 未有验证 carrier 前隐藏入口 |
| 数据库 | 不持久化外部 Session、鉴权或原始协议 payload；产品化 Trace 只保存脱敏后的 Starcat 运行投影，并通过新的 `registerVN` 追加表结构 |
| 退出门禁 | 无法可靠 cancel / approval、必须嵌入 Web UI、必须直读 SQLite 或无法清理 Sidecar 时判定 NO-GO |
| 更新 | 安装脚本固定 wheel 版本与 Starcat Cordis Profile；禁止运行时 `latest`、`npx`，Runtime 与 Starcat Direct 独立升级 |

### 5.14 “我的项目”与 Private / 组织仓库授权边界

**决定（2026-07-29）**：星标模块新增固定一等分类“我的项目”，范围为当前用户个人拥有仓库和通过组织成员身份可访问的组织仓库。项目归属与 Star、知识库关系正交，使用独立 `user_projects` 关系表和追加迁移 `v17-my-projects`，复用现有 Repo 列表、详情、洞察与 Star History。

| 授权流程 | 安装 + GitHub App Web Flow 合并为一次浏览器操作；主 OAuth 登录 Device Flow 不变 |
| 禁止方案 | 不把现有 OAuth 扩为 `repo` scope，不把 GitHub App private key 放入客户端；Client Secret 不视为安全凭据 |

| 隐私 | Private 项目不进入 Discovery、External Search、公开分享、CloudKit 或默认 JSON 导出；GitHub Stargazers 响应只在内存聚合，数据库不保存用户身份 |

### 5.20 本地数据湖、History 增量与 Recommend 发布边界

**决定（2026-08-26）**：BigQuery 及后续大规模外部数据只在本地数据湖保存一份 Raw，不复制到云端或各业务服务目录。History 与 Trainer 通过 Artifact URI 只读复用同一份 WatchEvent；本地完成分析和训练后，云端只接收 History 日级 Delta/快照与 Recommend ServingBundle。History 不处理 Unstar，也不增加用户贡献链路。

| 项 | 决议 |
|---|---|
| Raw 存储 | 按 source/schema/date 分区的 Parquet，仅本地长期保存；当前 T0 下载目录先登记、不移动 |
| 分析 | DuckDB 直接读取 Raw/Silver；PostgreSQL 只保存 Dataset、Watermark、Job、Artifact、Deployment 等控制元数据 |
| 复用 | History 和 Trainer 共享同一 Artifact URI，不复制几百 GB Raw，也不互相调用业务接口 |
| History 口径 | 按 `repo_id + event_date` 统计 WatchEvent；不处理 Unstar，统一标记 `gh_archive + estimated` |
| History 同步 | 每日发布幂等 Delta SQLite，每月发布完整 Snapshot；失败不推进云端 active watermark |
| Recommend 同步 | 首期保持完整不可变 ServingBundle；达到真实 SLO 门槛后按 `source_repo_id` 分片，只增量上传变化文件，仍按完整 model version 原子激活 |
| 云端边界 | 只保存公开 repo 聚合结果、推荐边和公开 metadata；不保存 Raw、`actor_id`、匿名训练主体或家庭网络路径 |
| 网络 | 本地 Publisher 只主动 HTTPS Push，不为家庭网络开放入站端口；History 与 Recommend 使用独立 Publish Key |
| 运维 | 单机 LocalExecutor 起步；多机通过 PostgreSQL Lease 协调；Web 控制台由 5.21 与 67 号设计定义，不回写本条的数据平台存储契约 |

### 5.22 Star History 全量 Serving 存储与曲线校准口径

**决定（2026-08-30 修订）**：2016-01-01 至 2026-08-26 的 `510,106,622` 条 WatchEvent 已形成 `260,068,094` 个 repo-day，覆盖 `43,869,033` 个仓库。History Silver 继续保留 `repo_id + event_date + event_count` 的可审计日级 Parquet，但云端 Serving Snapshot 不再为每个 repo-day 建 SQLite 行和二级索引，改为每个 repo 一行的确定性压缩时间序列。Starcat 使用专用 `/star-history/events` 接口读取原始日事件，并用本机已有的公开 `stars_count` 校准；第三方兼容接口仍可由服务端使用公开 GitHub metadata 校准。两条路径使用同一公式，不还原 Unstar，均统一标记 `gh_archive + estimated`。

| 项 | 决议 |
|---|---|
| Silver | 继续按 `repo_id + event_date` 保存稀疏日级聚合，按稳定 bucket 分区，可由 Raw 重建 |
| Serving | `repo_id` 主键对应一个 varint 编码 BLOB，保存日期差值与当日事件数；查询只读取一行 |
| Delta | 每日 Delta 仍传输当日 `repo_id + event_count`，云端事务内解码、追加并重新编码受影响 repo |
| 校准 | `estimated(day) = round(current_stars * cumulative_events(day) / total_events)`，单调钳制且末点固定为 `current_stars`；Starcat 在本机执行，第三方兼容接口在服务端执行 |
| 精度 | 不处理具体 Unstar，不把比例校准描述为精确历史；API 固定返回 `source=gh_archive`、`precision=estimated` |
| 客户端范围 | `/events` 始终缓存完整日级序列；`3m` 保留日点，`1y` 只压缩远端周点且保留全部本机快照，`all` 保留全部真实点 |
| 曲线交接 | 第一条本机精确快照作为锚点重新校准此前估算形状；锚点开始只展示精确快照，避免估算与快照交叉形成虚假下降或尖峰 |
| 图表时间域 | `all` 横轴从仓库创建时间开始，但创建日至第一条数据之间保持空白；有事件或快照的日期才绘点，折线只做线性连接 |
| 完整性 | Snapshot/Delta 均记录 point count、event total、watermark、encoding version 和 checksum；失败不推进 active watermark |
| 大文件校验 | Builder 对完整 Snapshot 执行一次 `quick_check` 并写入 manifest v2 attestation；云端流式解压时同步计算 checksum，再校验大小、schema、统计和水位线，避免重复全盘扫描；Delta 仍由服务端执行完整 `quick_check` |
| 隐私与身份 | `/events` 只返回曾经进入公开 GH Archive 的 repo/day 聚合，不返回 actor 或当前私有 metadata；Starcat 在发请求前阻断 Private/Internal，路径中的 owner/repo 仅用于响应一致性，不作为服务端权限依据 |

### CLI 配对地址与 DNS 兜底

**问题（2026-10-04）**：可信网络模式把 `ProcessInfo.hostName` 直接写进配对 URI；系统可能返回无法正向解析的运营商公网名称，导致本机 CLI 也无法配对。证书变化后 CLI 只显示指纹差异，缺少重新配对指引。

### 主窗口许可证多选筛选

**决定（2026-10-20）**：在现有全局筛选内增加许可证多选，集合内取 OR、与其它条件取 AND；沿用已有 license / license_spdx 元数据，不新增后端请求或数据库字段。空值与 NOASSERTION 显示为“未提供或未识别”，只映射明确别名，不合并协议家族或版本。SQL 与内存统一匹配，先筛选再分页，同步计数、查询身份与派生缓存；完整来源生成选项并保留已选项。智能集合保存与搜索中心不在本轮范围。

**展示补充（2026-10-21）**：许可证候选项与筛选计数分别判断有效性，同一来源内切换筛选不清空标签；来源、搜索或数据版本变化仍丢弃旧候选项，计数失效规则不变。重置按钮预留布局空间，避免浮层跳动。胶囊以明确许可证白名单区分宽松型（绿）、弱 Copyleft（琥珀）、强 Copyleft（橙）、网络 Copyleft（红）；未知、自定义和复杂组合协议为灰色，“全部许可证”沿用强调色。颜色仅作分类提示，不作法律或商用许可判断，不改变协议匹配与筛选语义。

### AI 整理结果 Tab 宽度稳定性

**决定（2026-10-21）**：仓库分组与标签整理共用计数分段组件，保留紧凑靠左、小圆角灰底与蓝色选中态。数字槽位按完整批次总数的本地化格式预留宽度，当前数字只覆盖显示并右对齐；分隔线始终占位，处理过程中不随计数或选中项伸缩。批次总数、语言或字号变化时自然重新测量，不改计数来源、筛选绑定、队列处理和窗口承载方式。

### AI 整理后台任务入口

**决定（2026-10-21）**：未分组与未分类横幅读取现有会话，应用优先于分析展示；运行中用“查看进度”，暂停用“查看任务”，待确认或失败用“查看结果”，只重开当前工作区。分组应用按本次请求的仓库数冻结分母，完成、失败与跳过均推进处理数；标签复用现有应用进度，不改请求与写入语义。所有文字单行截断并保留完整提示，按钮空间不足时改图标；空列表仍保留入口，不重做窗口承载。

### Stars 同步收尾与组织授权重试

**决定（2026-10-21）**：Stars 拉取、入库与本地星标注册表更新完成后结束主刷新状态，分组快照、RAG 与共享快照作为有账号作用域的后台工作，不阻塞列表。分组快照读取不隐式重试授权失败项；只有用户主动刷新才在 Stars 成功后触发一轮待授权回写，304 同样触发。并行点击合并当前批次，按组织串行验证并限制跨组织并发；组织再次明确拒绝后本轮跳过其余仓库，成功后才清除对应本地覆盖。普通网络错误、限流和 Token 失效不归为组织受限。账号切换取消并等待旧工作退出，不改变排序、分页与本地分组，不新增数据库结构或界面文案。

### 洞察中栏与详情栏顶栏留白

**决定（2026-10-22）**：dong4j 确认压缩洞察两栏顶部留白。共用顶栏由固定 84pt 改为最低 64pt、上下内边距 8pt；按两栏当前内容的自然高度同步增高，窄窗口、长译文和大字号不能裁切，恢复宽窗口后也能收紧。正文顶部间距同步缩小；保留原字号、按钮尺寸、内容结构与业务逻辑，不改变其他分类或仓库洞察页。

### 仓库分组可选颜色图标

**决定（2026-11-04）**：dong4j 确认分组颜色提供「无图标」，新建及首次同步的分组默认无图标，已有分组保留颜色与名称中的 Emoji。沿用非空约束的 `color_hex` 字段，以空字符串明确保存无图标，Repository 的 `nil` 参数仍表示保留已有颜色；远端刷新不补色。侧边栏、分组菜单及 AI 分组中的装饰圆点遵循该选择，选择状态控件保留，不修改数据库 schema

### 状态面板后台任务总览

**决定（2026-10-21）**：后台任务卡片仅展开面板内的任务列表，完全空闲时不可点击且不显示箭头。工具栏徽章与卡片共用同一份会话投影，按任务批次而非待处理仓库数计数，覆盖分析、应用、暂停、待确认与失败；首次预热持有的 README 子工作不重复计数。人工分组、标签整理与知识库索引按各自入口打开，浮层消失后重新确认任务仍存在；自动分组和系统预取只显示状态，不因查看而转为人工任务。取消仅调用所选任务现有的停止能力，不停止周期调度或回滚结果。列表不添加进度条，文案单行并补齐十八种语言，不新增调度、持久化或任务历史系统。
