# 性能优化设计

> 本文档定义 Starcat 的性能优化策略，针对 1000+ stars 用户场景。

---

## 一、性能挑战分析

### 1.1 用户规模

```
├── 普通用户：200-500 stars
├── 重度用户：500-2000 stars
└── 超级用户：2000-10000+ stars
```

### 1.2 性能瓶颈

| 场景 | 挑战 |
|------|------|
| 列表渲染 | 2000+ 条数据滚动不卡顿 |
| 搜索响应 | 毫秒级返回 |
| 内存占用 | 不能加载所有图片到内存 |
| README 渲染 | 大型 README 可能上百 KB |
| 增量同步 | 只同步变化的部分 |

### 1.3 性能目标

| 指标 | 目标 |
|------|------|
| 冷启动 | < 2s |
| 列表滚动 | 60 FPS |
| 搜索响应 | < 500ms |
| AI 摘要 | < 10s |
| 增量同步 (100 repos) | < 30s |

### 2.3 列表项轻量化

```swift
// 预计算 + 缓存显示数据
struct CachedRepo: Identifiable {
    let id: String
    let displayName: String
    let displayStars: String  // 预格式化的字符串 "12.3k"
    let displayDescription: String?  // 预截断

// 格式化逻辑提前执行
func formatRepo(_ repo: Repo) -> CachedRepo {
    CachedRepo(
        id: repo.id,
        displayName: repo.name,
        displayStars: formatStars(repo.starsCount),
        displayDescription: truncate(repo.description, maxLength: 100)
    )
}
```

### 2.4 分页加载

```swift
// 列表分页：每页加载 50 条
struct RepoListView: View {
    @State private var repos: [Repo] = []
    @State private var hasMore = true
    @State private var isLoading = false
    @State private var currentPage = 1

    var body: some View {
        List {
            ForEach(repos) { repo in
                RepoRowView(repo: repo)
                    .onAppear {
                        // 滚动到最后一行时加载更多
                        if repo.id == repos.last?.id && hasMore {
                            Task { await loadMore() }
                        }
                    }
            }

            if isLoading {
                ProgressView()
                    .frame(maxWidth: .infinity)
            }
        }
    }

    func loadMore() async {
        guard !isLoading else { return }
        isLoading = true
        defer { isLoading = false }

        let newRepos = try await fetchRepos(page: currentPage, perPage: 50)
        repos.append(contentsOf: newRepos)
        hasMore = !newRepos.isEmpty
        currentPage += 1
    }
}
```

## 三、README 缓存与渲染

### 3.1 README 缓存层级

```
┌─────────────────────────────────────────────────────────────┐
│                  README 缓存层级                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  L1: 内存缓存                                              │
│  └── 已渲染的 HTML，切换 repo 时快速切换                    │
│                                                              │
│  L2: SQLite 缓存                                          │
│  └── 原始 Markdown + ETag/Last-Modified                   │
│      └── 节省 GitHub API 调用                              │
│                                                              │
│  L3: 按需加载                                            │
│  └── 用户点击才从 GitHub 拉取                             │
│      └── 不预先批量拉取，减轻网络和存储负担                  │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 README 加载流程

```
用户点击 Repo
    │
    ▼
检查 SQLite 缓存
    │
    ├── 缓存存在 + 未过期 ──▶ 直接渲染
    │
    ├── 缓存存在 + 已过期 ──▶ 用 ETag/Last-Modified 验证
    │                              ├── 304 Not Modified ──▶ 直接用缓存
    │                              └── 200 OK ──▶ 更新缓存 + 渲染
    │
    └── 缓存不存在 ──▶ 从 GitHub 拉取 + 存入缓存 + 渲染
```

### 3.3 Markdown 渲染库选型

| 库 | 优点 | 缺点 | 推荐度 |
|----|------|------|--------|
| **_markdown** | 纯 Swift、性能好、现代 API | 较新 | ⭐⭐⭐⭐ |
| **Down** | 成熟稳定、功能完整 | 社区较小 | ⭐⭐⭐⭐ |
| **SwiftMark** | 性能优秀、内存占用低 | 功能有限 | ⭐⭐⭐ |
| **markdown-cmark** | 最完整 GFM 支持 | C 绑定、API 复杂 | ⭐⭐⭐ |

**推荐方案**：`_markdown` 或 `Down`

```swift
// 使用 _markdown（推荐）
import Markdown

struct ReadmeView: View {
    let markdown: String

    var body: some View {
        // 渲染 Markdown 到 AttributedString
        Text(markdown.parseMarkdown())
    }
}

// 或使用 Down
import Down

struct ReadmeView: View {
    let markdown: String

    var body: some View {
        Text(try! Down(markdownString: markdown).toAttributedString())
    }
}
```

### 3.4 大型 README 优化

```swift
// README 截断策略：避免渲染超大文档
let MAX_README_SIZE = 100 * 1024  // 100KB
let MAX_README_LINES = 2000        // 或 2000 行

func prepareReadmeForRendering(_ content: String) -> String {
    // 1. 大小限制
    if content.utf8.count > MAX_README_SIZE {
        content = String(content.prefix(MAX_README_SIZE)) + "\n\n---太长已截断---"
    }

    // 2. 行数限制
    let lines = content.components(separatedBy: .newlines)
    if lines.count > MAX_README_LINES {
        content = lines.prefix(MAX_README_LINES).joined(separator: "\n")
        content += "\n\n---行数过多已截断---"
    }

    return content
}

// 分块渲染：对于超长 README，先渲染可见部分
struct LazyReadmeView: View {
    let content: String
    @State private var renderedContent: AttributedString?

    var body: some View {
        VStack {
            if let rendered = renderedContent {
                Text(rendered)
            } else {
                ProgressView()
            }
        }
        .task {
            await renderInBackground(content)
        }
    }
}
```

## 四、数据库性能优化

### 4.1 查询优化

```swift
// ❌ 避免 N+1 查询
for tag in tags {
    let repos = try db.query("""
        SELECT * FROM repos
        WHERE id IN (SELECT repo_id FROM repo_tags WHERE tag_id = ?)
        """, tag.id)
}

// ✅ 预加载 + 内存连接
let tags = try await Tag.prefetchAll()
let tagRepoIds = try await RepoTag.fetchAll()
    .groupBy(\.tagId)
    .mapValues(\.repoId)

for tag in tags {
    let repoIds = tagRepoIds[tag.id] ?? []
    let repos = repos.filter { repoIds.contains($0.id) }
}
```

### 4.2 批量写入优化

```swift
// 使用 GRDB 的批量写入
try await dbPool.write { db in
    try Repo.insertAll(repos, onConflict: .replace, using: db)
}
```

### 4.3 增量同步优化

```swift
// 只同步变化的部分
struct IncrementalSyncResult {
    let added: [Repo]      // 新增的
    let removed: [String]  // 删除的 repo_id
    let updated: [Repo]    // 更新的
}

func applyChanges(_ result: IncrementalSyncResult) async {
    // 批量删除
    try await deleteRepos(ids: result.removed)

    // 批量新增
    try await insertRepos(result.added)

    // 批量更新
    try await updateRepos(result.updated)
}
```

### 5.2 Embedding 内存

```swift
// Embedding 向量存储在 SQLite BLOB 中，按需加载
// text-embedding-3-small: 1536 维度 = 6KB/向量
// 10000 repos = 60MB

// 分批处理 Embedding
func generateEmbeddings(for repos: [Repo]) async {
    let batchSize = 50
    for batch in repos.chunked(into: batchSize) {
        let embeddings = await generateBatch(batch)
        await saveToDatabase(embeddings)
        await cleanup()  // 释放内存
    }
}
```
