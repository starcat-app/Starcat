# 项目结构设计

> 本文档说明当前仓库的主要目录与查找入口，2026-11-12 对照受控文件核对。
> 只列主要边界，不列完整文件树；这些目录不是独立 Swift Package，也不表示已由编译器强制隔离依赖。

---

## 一、目录结构

```
Starcat/                              # 仓库根
├── AGENTS.md                         # 协作规则
├── DESIGN.md                         # UI 设计入口
├── BRANCH.md                         # 分支意图登记
├── Starcat/                          # App 源码
│   ├── App/                         # 生命周期与依赖装配
│   ├── Core/                        # 数据、网络、设置及后台能力
│   ├── Features/                    # 功能视图与功能实现
│   ├── Shared/                      # 组件、服务、诊断与工具
│   └── Resources/                   # 本地化、图标、Web 资源与权限文件
├── StarcatTests/                     # 测试与 fixture
├── Configs/                          # 构建配置、受控 SwiftPM 锁
├── docs/                             # 现有产品、设计、进度与规范目录
├── skills/                           # 项目 Skill 的维护源
├── scripts/                          # 构建、校验、发布及开发脚本
├── supports/                         # 多个独立 Git 仓库与工作区脚本
├── resources/                        # 仓库素材，与 App Resources 区分
├── project.yml                       # XcodeGen 工程声明
└── Makefile                          # 标准开发命令入口
```

旧草案中的 `Features/Repo`、`Core/Network/AIService`、`Shared/Theme` 等不是当前目录。仓库详情从 `Features/Home` / `Features/Detail` 查找，AI 客户端从 `Features/AI` 查找；不要根据旧树创建重复模块。

## 二、模块职责

### 2.1 App 模块

| 文件 | 职责 |
|------|------|
| `StarcatApp.swift` | @main 入口，配置 App |
| `AppDelegate.swift` | 当前已有的 App 生命周期桥接 |
| `ContentView.swift` | 根视图，根据登录状态切换 |
| `AppDependencies.swift` | 依赖装配入口 |
| `StarcatCommandRouter.swift` | App 命令路由 |
| `StatusBarController.swift` | 菜单栏控制 |

### 2.2 Features 模块

**Auth**：认证相关
- GitHub OAuth 登录流程
- Token 管理

**Home**：主界面
- 三栏布局（Sidebar/RepoList/Detail）
- 导航和视图切换

**Home / Detail / Notes / Tags**：仓库列表、详情、README、笔记和标签。职责分布在这些现有目录中，不存在旧草案里的统一 `Features/Repo`。

**Search**：搜索
- 全局搜索
- 筛选面板
- FTS5 全文搜索

**AI**：AI 功能
- AI 摘要
- 标签推荐
- 语义搜索

**Explore / Trending / Activity / Recommendations**：探索导航、趋势、周刊、动态与推荐。Weekly 的部分文件仍在 `Activity` 目录，产品入口归属不能仅由文件夹名称推断。

**Agents / RAG / CodeGraph / MCP**：Agent 工作台、知识库检索、代码分析与外部工具入口。`Core/RAG` 还承载底层检索能力，不能把 UI 目录当成完整实现。

**FollowGraph / DailyRadar / Insights**：关注关系图谱、每日热点与洞察。它们各有状态、缓存和展示边界，不归并成旧版的单一 Explore ViewModel。

**Settings / Auth / Profile / About / Onboarding**：配置、登录、用户资料、关于与引导。其他功能以实际 `Features` 子目录为准。

### 2.3 Core 模块

**Database**：数据层
- GRDB 封装
- 数据库迁移
- 数据模型

**Network**：网络层
- GitHub API 客户端
- Starcat 服务请求、响应契约与健康检查
- 错误处理

AI 协议适配器位于 `Features/AI`，不要再按早期草案寻找 `Core/Network/AIService`。

**Sync**：同步
- 同步管理器
- 同步队列
- Rate Limit 处理

**Keychain**：安全存储
- Token 存储

**Settings / Distribution / Subscription / Updates**：持久化设置、渠道、权益与更新边界。

**Cache / RAG / DataContribution / Insights / Scheduling / Warmup**：缓存、检索、数据贡献、洞察与后台任务。已发布数据库迁移的规则以 `AGENTS.md` 为准。

### 2.4 Shared 模块

**Components**：共享组件
- Liquid Glass 风格组件
- 通用 UI 组件

**Extensions**：扩展
- Swift 扩展

**Services**：跨功能共享服务。

**Diagnostics / Telemetry**：诊断事件、日志与遥测支撑。

**Utilities**：工具
- 日志
- 常量

视觉规范从根目录 `DESIGN.md` 和 `docs/5-规范/` 进入；当前没有 `Shared/Theme` 目录。

## 三、依赖方向与查找方法

- 从 `AppDependencies` 查服务装配，再从对应 Feature 追踪调用到 Repository / API / 存储。
- 从 `project.yml` 确认 target、资源与依赖；`Starcat.xcodeproj` 是生成结果。
- 用知识图谱查实际符号和调用关系。目录层次只辅助导航，不能据此断言代码没有循环依赖。
- `supports/` 中的 API、CLI、文档站等维护自己的 Git 状态与工程规则；主仓库里的路径不能代替独立仓库的当前契约。

## 四、命名规范

### 4.1 文件命名

以下只解释命名习惯；示例名不保证对应当前已有文件，先查找可复用实现。

```
// View 文件：{Feature}{View}.swift
HomeView.swift
RepoCardView.swift
SearchView.swift

// ViewModel 文件：{Feature}ViewModel.swift
HomeViewModel.swift
SearchViewModel.swift

// Service 文件：{Feature}Service.swift
GithubOAuthService.swift
FTS5Service.swift

// Manager 文件：{Feature}Manager.swift
DatabaseManager.swift
SyncManager.swift
```

### 4.2 类型命名

```swift
// View
struct HomeView: View { }

// ViewModel (@Observable)
@MainActor
@Observable
class HomeViewModel { }

// Model (Codable, FetchableRecord)
struct Repo: Codable, FetchableRecord, PersistableRecord { }

// Service
protocol AIServiceProtocol { }
class AIProxyClient: AIServiceProtocol { }
```

## 五、资源管理

### 5.1 App 资源

图标与颜色在 `Starcat/Resources/Assets.xcassets`，文案在 `Localizable.xcstrings`；README、CodeFlow、Codebase 与 FollowGraph 分别维护自己的嵌入资源目录。第三方资源的来源与许可证说明保留在对应资源目录，并同步开源致谢。

### 5.2 工程配置与权限

Info.plist 字段、URL Scheme、资源打包和 target 配置以 `project.yml` 及其后处理脚本为准。App Store / Direct 的 entitlements 分开维护；不要新建一份草稿 `Resources/Info.plist` 来覆盖生成结果。

### 5.3 本地配置与生成产物

`Configs/Secrets.xcconfig` 是本机配置，不提交内容。SwiftPM 完整版本来自受控的 `Configs/SwiftPackages.resolved`。构建与测试使用 [本地编译教程](../../7-工具与脚本/本地编译教程.md) 中的 Makefile 入口。
