# 39 - 全局语言与列表控制详细设计

> 日期: 2026-07-03
> 状态: 设计稿
> 对应需求: `docs/2-产品/需求讨论/全局语言与列表控制需求讨论.md`
> 对应方案: `docs/2-产品/需求讨论/正式方案/全局语言与列表控制正式方案.md`

## 1. 目标

本设计用于指导“全局语言与列表控制专项”的落地:

1. Weekly 从 Activity 迁移到 Explore。
2. 语言筛选统一放到 Sidebar,随当前模块切换语言列表。
3. 中栏顶部统一排序体验,但排序状态按模块独立保存。
4. 模块筛选与排序拆开,避免“筛选”承载排序语义。
5. 列表偏好按账号本地持久化,并提供统一重置入口。

## 2. 当前结构

### 2.1 Explore

关键类型:

- `ExploreMode`
- `ExploreView`
- `ExploreDiscoveryListView`
- `ExploreDiscoveryViewModel`
- `TrendingView`
- `TrendingViewModel`

当前 Explore 包含:

- `.discover`
- `.trending`
- `.popular`
- `.newReleases`

目标 Explore 顺序:

1. `.discover`
2. `.trending`
3. `.popular`
4. `.newReleases`
5. `.weekly`

### 2.2 Weekly

关键类型:

- `ActivityCategory.weekly`
- `WeeklyContentView`
- `WeeklyContentViewModel`
- `WeeklySelectionService`
- `WeeklyLanguageStore`
- `WeeklyDetailView`
- `WeeklyDetailScaffoldShell`

Weekly 当前由 Activity 承载,但数据源、列表、筛选、排序和详情都已经是独立实现。

### 2.3 顶部控制区

当前已有基础组件:

- `UnifiedSortMenu`
- `ManageSortDriver`
- `WeeklySortDriver`

后续应复用这个方向,但控件放在中栏顶部,不是 window toolbar。

## 3. 数据与状态设计

### 3.1 ExploreMode 扩展

新增:

```swift
case weekly
```

要求:

- `localizedTitle` 增加周刊文案。
- `systemImage` / icon color 走 Explore 视觉体系。
- `ExploreView` 增加 `.weekly` 分支。
- `RepoListView` 与 `HomeView` 中与 Explore mode 相关的 identity / breadcrumb / toolbar routing 同步识别 `.weekly`。

### 3.2 Weekly 选择状态

保留 `WeeklySelectionService` 作为 Weekly 右栏详情与 toolbar actions 的单一选择源。

迁移后判断条件从:

```swift
selectedSidebarPage == .activity && selectedActivityCategory == .weekly
```

改为:

```swift
selectedSidebarPage == .trending && selectedExploreMode == .weekly
```

说明: 当前代码中 Explore 复用 `SidebarPage.trending` 作为顶层页面命名,详细实现时按现有命名迁移,不强制本轮改一级 page 名称。

Weekly 迁移后不保留 Activity 双入口:

- `ActivityCategory.weekly` 不再出现在 Activity Sidebar。
- Activity “全部”不包含 Weekly。
- Activity 路由、计数、toolbar spec 不再为 Weekly 兜底。

### 3.3 Weekly 语言状态

新增 Home 层状态:

```swift
@State private var selectedWeeklyLanguage: String?
```

或使用现有 `WeeklyContentViewModel.selectedLanguage` 的上提 Binding。推荐上提 Binding,原因:

- Sidebar 需要读写当前 Weekly 语言。
- `WeeklyContentView` 仍负责实际列表 reload / local filter。
- 避免 Sidebar 与 WeeklyContentView 维护两份语言状态。

迁移后:

- `WeeklyContentView` 接收 `@Binding var selectedLanguage: String?` 或等价参数。
- `WeeklyContentViewModel.changeLanguage(to:)` 仍负责应用筛选。
- `LanguagePickerMenu` 从 `WeeklyContentView.filterBar` 移除。

### 3.4 Sidebar 语言提供器

抽象一个轻量的“当前语言列表”派生逻辑,不一定第一版就做复杂 protocol。

推荐先在 `SidebarView` / `HomeView` 层按当前页面分支:

| 页面 | 语言列表来源 |
|---|---|
| 星标 | `HomeViewModel.languageStats` / `knowledgeLanguageStats` |
| Explore trending | `TrendingLanguageStore.displayList` |
| Explore discover/popular/newReleases | `ExploreCatalogStore.language...` 或现有 Discovery 语言聚合 |
| Explore weekly | `WeeklyLanguageStore.displayList` |

第一版保留单选语言。多选语言需要另起设计,不要混入本次迁移。

语言列表加载约束:

- `All Languages` 是 UI 固定哨兵项,不从接口或 DB 读取。
- 当前分类有缓存时先显示缓存,再刷新接口。
- 接口失败时保留已有语言列表;没有缓存时使用 fallback。
- 切换 Explore 子分类时不沿用上一个子分类的语言列表作为假数据。
- 已保存语言在当前分类不存在时,自动重置为 `All Languages` 并触发当前列表刷新。
- 语言列表失败不阻断主列表加载,只影响可选语言项。

当前代码参考:

- Explore catalog 已通过 `DiscoveryRepository.cachedSummary()` 支持 summary 缓存。
- Trending language store 当前没有 DB 缓存,但有内存 `aggregates` 和 `fallbackList`。
- Weekly language store 当前没有 DB 语言缓存,但有 `fallbackList`;迁移时可考虑复用 Weekly bulk snapshot 中的语言聚合,减少两套来源。

### 3.5 列表偏好存储

新增或收敛一个“列表偏好”存储层,用于保存当前账号下的列表控制状态。

建议 key 结构:

```text
listPreferences.<githubLogin>.<domain>.<field>
```

`domain` 示例:

- `starred`
- `explore.discover`
- `explore.trending`
- `explore.popular`
- `explore.newReleases`
- `explore.weekly`
- `activity`

保存内容:

- 语言选择。
- 排序选择。
- 模块筛选选择。
- Explore 上一次打开的子分类。

不保存:

- 当前搜索词。
- 搜索历史。
- Smart Collection 保存规则或编辑草稿。
- repo 数据缓存。
- 用户标签、笔记、知识库状态。

账号规则:

- 登录后读取当前 GitHub 账号对应偏好。
- 切换账号时立即切换偏好命名空间,并刷新当前页面。
- 重置只清当前登录账号的偏好。
- 第一版不做 CloudKit 同步。

## 4. UI 设计

### 4.1 Sidebar

Explore 下的语言区域根据当前子分类切换:

- 趋势: 展示 Trending 语言。
- 热门 / 新发布 / 发现: 展示 Discovery 语言。
- 周刊: 展示 Weekly 语言。

切换 Explore 子分类时:

- 语言列表切换为该子分类的数据源。
- 当前语言若新分类不支持,回落到 `All Languages`。
- 不展示无效语言,避免切换后必然空列表。
- 加载新语言列表时可以展示 `All Languages` + loading 状态,不要短暂显示上一子分类的语言列表。

### 4.2 中栏顶部

各模块的中栏顶部保持现有位置:

- 左侧: 排序 / 周期 / 模块筛选。
- 右侧: 新鲜度 / 同步状态 / 刷新。

Weekly 迁移后中栏顶部:

```text
筛选   排序                         刷新
```

其中 Weekly 筛选不再包含语言和排序:

- 来源
- 覆盖
- 隐藏 Archived
- 隐藏 Fork
- Stars
- 活跃度

排序单独显示:

- 默认
- Stars 降序 / 升序
- 最近更新 / 最早更新
- 最新创建 / 最早创建
- 名称升序 / 降序

Weekly 的 `latest_event_at desc` 只作为“默认”的内部排序,不单独暴露为“最新事件”。

### 4.3 排序组件

保留并扩展 `UnifiedSortMenu`:

- 视觉统一。
- 入参仍是当前模块的 options / selection / displayName / systemImage。
- 增加可选 `dividerBefore` 能力,用于把模块专属排序放到公共排序下方并用分割线隔开。
- 中栏顶部可以使用同组件或抽一个 `ListSortMenu` 包装,但不要新建与现有组件重复的体系。

各模块适配:

| 模块 | 排序类型 | 最终选项 |
|---|---|---|
| Manage | `RepoSortOption` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序、最高 Health、最高 OpenSSF |
| Explore discovery | `ExploreSortOption` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序 |
| Explore trending | `TrendingSortOption` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序、上升趋势 |
| Explore popular | `ExploreSortOption` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序 |
| Explore new releases | `ExploreSortOption` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序、最新发布 |
| Explore weekly | `WeeklyFeedSort` | 默认、Stars 降序、Stars 升序、最近更新、最早更新、最新创建、最早创建、名称升序、名称降序 |
| Activity 普通分类 | `ActivityTimeSort` | 最新优先、最早优先 |

Weekly API 需要支持 `latest_event_at`、`stars`、`updated_at`、`created_at`、`name` 作为排序字段,并继续使用 `order=asc|desc` 表达方向。客户端 `WeeklyFeedSort` 使用 UI case 映射到 API 字段与方向,避免在 UI 里再暴露第二个方向控件。

排序状态按模块保存。切换模块时不复用不兼容排序值。

### 4.4 重置列表偏好

入口:

- 设置页按钮。
- 菜单栏图标右键菜单。
- Dock 菜单。

实现要求:

- 三处入口文案统一为 `重置列表偏好`。
- 未登录时入口可见但 disabled,说明登录后可用。
- 点击后使用 alert 二次确认。
- 确认后清除当前登录 GitHub 账号下的语言、排序、筛选和 Explore 默认子分类偏好。
- 不清 repo 缓存、Discovery summary / bulk 缓存、Weekly bulk 缓存。
- 不清搜索词、搜索历史、标签、笔记、知识库状态、Smart Collection 规则或草稿。
- 当前页面立即重新读取默认偏好并刷新;未挂载页面下次打开时自然读取默认值。
- 成功后显示 toast: `已重置列表偏好`。

Telemetry:

- 不写本地诊断日志。
- 如果匿名 telemetry 可用,发送 `list_preferences_reset`。
- payload 只允许包含入口来源,不包含具体语言、筛选值、排序值、搜索词、tag 或 repo。

## 5. 路由迁移

### 5.1 中栏内容

`RepoListView` 当前根据 `selectedSidebarPage` 选择内容:

- Manage
- Explore
- Activity

迁移要求:

- `.weekly` 由 `ExploreView` 渲染 `WeeklyContentView`。
- `ActivityView` 不再处理 `.weekly` 分支。
- `ActivityCategory.weekly` 删除或至少从 UI 分类列表移除。由于项目未上线,无需保留旧兼容路径。
- Activity “全部”不再聚合 Weekly。

### 5.2 右栏详情

右栏详情迁移:

- 从 Activity weekly 条件迁到 Explore weekly 条件。
- 继续渲染 `WeeklyDetailView(item: dependencies.weeklySelectionService.selectedItem)`。
- 切换离开 Explore weekly 时清空 `WeeklySelectionService`。

### 5.3 Toolbar actions

`RepoListView.makeActivityToolbarSpec()` 当前含 Weekly 特殊分支。迁移后:

- Weekly 分支移到 Explore toolbar spec。
- `weeklyMultiSelectionStore` 仍用于 Weekly 多选。
- 选中项仍从 `WeeklySelectionService.selectedItem` 读取。

## 6. 计数与副标题

Weekly total 目前通过 Activity 的计数服务合并展示。迁移后:

- Activity 计数服务不再负责 Weekly total。
- Explore Sidebar 中 Weekly 行展示 `WeeklySelectionService.total` 或新增 Explore 计数服务承载。
- 中栏副标题在 Explore weekly 下使用 Weekly total。

如果第一版计数迁移成本过高,允许 Weekly 行暂不显示计数,但中栏列表 total 必须保持准确。

## 7. 多选与列表选择

Weekly 多选保持:

- `weeklyMultiSelectionStore`
- Cmd+A 当前可见列表全选
- 切换离开 Weekly 时退出 multi-select

需要调整的条件:

- 当前判断 `selectedActivityCategory == .weekly` 的位置改为 `selectedExploreMode == .weekly`。
- 切换 Explore 子分类时要退出非当前 remote store,避免 Trending / Weekly 多选状态互相残留。

## 8. 验证重点

实施后至少验证:

1. Activity 不再显示 Weekly 分类。
2. Explore 显示 Weekly 子分类。
3. Explore Weekly 列表可加载、刷新、分页。
4. Sidebar Weekly 语言列表来自 Weekly 数据源。
5. 切换 Weekly 语言后列表重筛选,详情选择按既有策略清空或更新。
6. Weekly 中栏不再显示独立语言控件。
7. Weekly 详情页仍能打开。
8. Weekly 多选仍可用,切换模块后自动退出。
9. 入库心形、列表角标、外链、README 详情不回归。
10. Activity 普通分类排序 / 刷新不受迁移影响。
11. 重置列表偏好只影响当前账号,并立即刷新当前页面。
12. 语言接口失败时主列表仍可加载,Sidebar 至少保留 `All Languages` 和 fallback。

## 9. 建议实施顺序

1. 新增 Explore weekly mode,先让 WeeklyContentView 在 Explore 下可显示。
2. 迁移右栏详情和 toolbar actions。
3. 从 Activity UI 移除 weekly 分类和计数绑定。
4. 将 Weekly 语言状态上提,Sidebar 接管语言列表和选择。
5. 拆分 Weekly 中栏筛选与排序。
6. 扩展统一中栏排序组件,逐步替换各模块当前排序菜单。
7. 接入列表偏好持久化与“重置列表偏好”入口。
8. 收敛文案、i18n、测试和进度 checklist。
