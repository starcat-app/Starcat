# 00-提示词设计

> 最后更新：2026-06-14

本文档是 Starcat 所有 AI 提示词的单一信任源，与代码一对一匹配。

---

## 架构总览

Starcat 共有 **5 套 AI 提示词**，全部统一走 `AIPromptConfiguration` 模板 + 占位符渲染机制：

| 任务 | 调用入口 | systemPrompt | userPromptTemplate | 用户可编辑 |
|-----|---------|---|---|---|
| Summary | `RepoAIInsightService.generateSummary` | 1 占位符 | 5 占位符 | ✅ |
| Tags | `RepoAIInsightService.generateTags` | 1 占位符 | 5 占位符 | ✅ |
| Chat | `RepoAIInsightService.assembleChatSystemPrompt` | 6 占位符 | 留空（用户消息走 messages 数组） | ✅ |
| Embedding | `IndexedTextBuilder.render` | 留空（API 不接受） | 8 占位符 | ✅ |
| Translation | `ReadmeTranslationService.translate` | 1 占位符 | 2 占位符 | ✅ |

所有任务的 `AIPromptConfiguration` 持久化在 `AppSettings`（UserDefaults JSON），用户在 **设置 → AI → Prompt** 编辑；改坏点 **Restore Default** 还原。默认值定义在 `AIDefaultPrompts` 里（`Starcat/Features/AI/AIConfiguration.swift`）。

## 渲染机制

唯一的渲染 helper（`AIConfiguration.swift`）：

```swift
struct AIPromptConfiguration: Codable, Equatable, Sendable {
    var systemPrompt: String
    var userPromptTemplate: String

    func renderedSystemPrompt(placeholders: [String: String]) -> String { ... }
    func renderedUserPrompt(placeholders: [String: String]) -> String { ... }

    static func render(template: String, placeholders: [String: String]) -> String {
        var result = template
        for (key, value) in placeholders {
            result = result.replacingOccurrences(of: "{key}", with: value)
        }
        return result
    }
}
```

**渲染语义**（5 个任务一致）：

- `{key}` 替换为 dict 中对应 value。
- **dict 中没有的 key 保留 `{key}` 原文**（不替换为空）—— fail-loud，让 LLM 看到字面量便于排错。
- **value 为空字符串 → 占位符替换为空**，外层模板的 section header / label 仍然渲染（LLM 自然忽略空段）。
- **不做空行 squeeze**：用户的 template 是用户的，service 不偷偷改格式。

## 数据源构造层

Summary / Tags / Chat 共享同一个 `Source` 数据结构（`RepoAIInsightService.makeSource(for:)`）。Embedding 用独立的 `IndexedSnapshot`。Translation 用 README 原始 HTML。

### `Source`（Summary / Tags / Chat 共用）

| 字段 | 渲染目标 | 数据组成 |
|------|---------|---------|
| `metadata` | `{metadata}` | 8 行多行块：`Repository: owner/name`、`Description: ...`、`Language: ...`、`Topics: ...`、`License: ...`、`Stars: N`、`Forks: M`、`Homepage: ...` |
| `readme` | `{readme}` | `ReadmeRepository.find(repoId:)` → `ReadmePreprocessor.process()` 清洗 + 截断（默认 8000 字符）后的纯文本 |
| `codeContext` | `{codeContext}` | `RepoContextPacker.pack()` 产物（`<repository>` XML，含文件结构 / 关键函数签名）；`aiRepoContextEnabled = false` 或 pack 失败 → 空字符串 |
| `externalContext` | `{externalContext}`（仅 Summary 任务实时填） | `AnySearchContextProvider.collect()` 返回的 markdown，内含 `<external_context source="AnySearch">` 包裹的最多 6 条 `[标题](URL) + snippet 前 500 字`；用户关 anySearch / 关 aiExternalContext / 私仓不允许 → 空字符串 |

> **HOM-199 缓存稳定化**：`metadata` 的 `Stars` / `Forks` / `Homepage` 字段进 `llmText`（让 LLM 感知热度），但**不进 hashText**——避免 GitHub sync 刷新流量数据导致整个 `ai_summaries` 缓存失效。`codeContext` 同时进 hashText（commit SHA 改 = 代码语义改 = 应重生成）。

> **Chat 任务的 externalContext 数据走另一条路径**：Chat 流程不调 `externalContextProvider.collect`，而是直接读 `ai_summaries` 表里上次 Summary 流程缓存下来的 `externalContextMarkdown` 字段（私仓门控仍在 `buildChatSystemPrompt` 里二次校验），所以 Chat 看到的外部参考 = 该仓库最近一次 Summary 生成时的 AnySearch 快照。

### `IndexedSnapshot`（Embedding 专用）

| 字段 | 来源 |
|------|------|
| `metadata.fullName` | `Repo.fullName` |
| `metadata.description` / `language` / `license` / `homepage` | 对应 Repo 字段（nil → 空字符串） |
| `metadata.topics` | `IndexedTextBuilder.normalizeTopics()` 把 JSON 数组转成 `"a, b, c"` 形式 |
| `body` | 三级降级：`RepoAIInsight.summaryMarkdown`（AI 摘要） → `ReadmeRepository.find` 清洗后的 README → `description + topics` 兜底 |
| `notes` | `RepoNoteRepository.find` |

## 1. Summary（仓库摘要）

**用途**：为 GitHub 仓库生成 Markdown 摘要，帮助开发者快速判断项目价值。生成结果写入 `ai_summaries` SQLite 缓存，UI 端从缓存读取。

**调用入口**：`RepoAIInsightService.generateSummary(source:onDelta:)`（`RepoAIInsightService.swift:535`）。在用户点击 **生成 AI 摘要** / **重新生成** 时触发；流式输出，UI 增量渲染。

**触发条件**：用户主动点击。**不会**自动触发批量生成。

### 占位符

| 占位符 | 出现位置 | 数据来源 | 空值时 |
|-------|---------|---------|-------|
| `{outputLanguage}` | system + user | `Locale.current` 派发为 `Simplified Chinese` / `Traditional Chinese` / `English` / `Japanese` / `Korean` / `French` / `German` / `Spanish` / `Russian` / `Portuguese`，其余 default `English` | 永不为空 |
| `{metadata}` | user | `Source.metadata` | 不会为空（至少有 `Repository: owner/name`） |
| `{readme}` | user | `Source.readme` | README 拉取失败时为空字符串，仍然渲染 `## README` 段标题 |
| `{codeContext}` | user | `Source.codeContext` | `aiRepoContextEnabled = false` / pack 失败时为空字符串 |
| `{externalContext}` | user | `Source.externalContext` | 用户关 anySearch / 私仓门控未通过 / 拉取失败时为空字符串（详见下文「外部上下文门控」） |

### System Prompt 模板

```
You are Starcat's repository summary assistant, helping developers quickly understand a project and assess its value.

# Output Format (STRICT)
- Write the final answer in message.content only, using Markdown format (no plain text, no JSON).
- Do NOT wrap the entire summary in an outer ``` fence; however, code examples, shell commands, configuration snippets, API calls, and similar within the summary MUST be wrapped in ``` fences with a language tag (e.g. ```bash, ```js, ```yaml, ```python, ```swift). Do not use indented code blocks or plain text to represent code.
- Do NOT output reasoning, analysis traces, or thought processes.
- Do NOT include <think>, <thinking>, <reasoning>, or other reasoning-trace XML tags; if your model has a thinking stage, return only the final answer.
- Output language: {outputLanguage} (use this language for the body; technical English proper nouns are excluded — see the next constraint).

# Factual Constraints
- Do NOT fabricate facts beyond what is provided in the metadata, README, or code context.
- Skip content that cannot be confirmed from the input materials. Do NOT write "unconfirmed" placeholders, and do NOT fabricate content just to fill out sections.
- Preserve technical English proper nouns as-is (library names, command names, framework names, API names, version strings, commit hashes, etc.) — do not force-translate them.

### 调用链路

```
用户在详情页点 [生成 AI 摘要] / [重新生成]
  → RepoAIInsightService.generateInsight(for:...)
  → makeSource(for:)                        // 构造 Source（metadata + readme + codeContext）
  → externalContextProvider.collect(for:)  // AnySearch（按门控决定是否调）
  → 派生 summarySource（externalContext 字段写入 source）
  → generateSummary(source:onDelta:)
    → outputLanguage = outputLanguageDescriptor()
    → renderedSystemPrompt(["outputLanguage": ...])
    → renderedUserPrompt(["outputLanguage", "metadata", "readme", "codeContext", "externalContext"])
    → OpenAIClient.chatStream(request:)    // 流式输出
  → 末尾追加 "## {本地化标题}\n- [host](url)" footer（i18n key: ai.assistant.summary.externalReferences.title）
  → 写入 ai_summaries 表
  → 触发 SemanticSearchService.refreshIndexIfChanged（让 embedding 重建用上新摘要）
```

### 输出后处理

- **footer 追加**：service 在 LLM 输出末尾追加 `## External References / 外部参考来源` 链接列表（仅 URL，不含 snippet），作为 UI 展示用附录。i18n key：`ai.assistant.summary.externalReferences.title`。
- **summaryMarkdown 字段**：完整摘要正文（含 footer）写入 `ai_summaries.summary_json.summaryMarkdown`，UI 优先读这个字段。

### 外部上下文门控（Summary / Chat 共用）

`AnySearchContextProvider.allowsExternalContext(repoIsPrivate:enabled:allowPrivate:)` 是一个 nonisolated 纯函数：

```
enabled && (!repoIsPrivate || allowPrivate)
```

- `enabled = settings.anySearchEnabled && settings.aiExternalContextEnabled`
- `repoIsPrivate = repo.isPrivate`
- `allowPrivate = settings.aiExternalContextAllowPrivateRepos`

**任意一项不满足 → `{externalContext}` 渲染为空字符串**，section header 仍保留（LLM 自然忽略空段）。

> Summary 与 Chat 走的是**同一个 helper**——保证两个任务对私仓的处理策略不漂移。

## 2. Tags（标签推荐）

**用途**：基于仓库上下文推荐 3–8 个标签，返回严格 JSON。生成结果**只进 UI 确认流**，用户点确认才写入 `repo_tags` 表（保守策略）。

**调用入口**：`RepoAIInsightService.generateTags(source:hints:)`（`RepoAIInsightService.swift:594`）。在 **生成 AI 摘要** 流程中与 Summary 并发跑（`includeTags = true`），或批量 AI 整理路径单独调用。

### 占位符

| 占位符 | 出现位置 | 数据来源 | 空值时 |
|-------|---------|---------|-------|
| `{outputLanguage}` | system | 同 Summary | 永不为空 |
| `{metadata}` / `{readme}` / `{codeContext}` | user | `Source` 同 Summary | 同 Summary |
| `{repoTags}` | user | 该仓库已绑定标签，逗号分隔，无 label | 单仓首次生成时为空字符串 |
| `{libraryTags}` | user | 用户标签库高频前 30 个，逗号分隔 | 标签库为空时为空字符串 |

**双层标签 hints 由 `RepoAIInsightService.makeTagHints(...)` 工厂方法构造**（trim + 去重 + 排序 + 截断），保证两条入口（单仓 / 批量）信号源不漂移。

### System Prompt 模板

```
You are Starcat's repository tagging assistant.

# Output Format (STRICT)
Return strict JSON only in message.content. NO prose, NO markdown fences, NO reasoning traces, NO explanations outside the JSON.

Schema (failure to match this schema will cause the output to be rejected):
{
  "suggestedTags": [
    {"name": "string", "confidence": 0.0, "reason": "string"}
  ]
}

Constraints:
- "confidence" MUST be a number in the closed interval [0, 1].
- "name" MUST be short (1-3 tokens), reusable, suitable for a local tag system.
- "reason" should be one short sentence explaining why this tag fits this repository.
- Generate 3 to 8 tags total. NO duplicates.

# Tag Style Rules
Apply ONLY the branch matching {outputLanguage}:

- If {outputLanguage} is "Simplified Chinese" or "Traditional Chinese":
  - Tag names ≤ 4 characters; nouns or short technical terms only (e.g. 「向量检索」「编辑器」「机器学习」).
  - NEVER full sentences.
  - Well-known technical English terms (e.g. RAG, LLM, GitHub, API) MAY remain in English.

- If {outputLanguage} is "English":
  - Tag names: a single domain word, abbreviation, or common technical term (e.g. RAG, LLM, DevOps, WebRTC, Editor).
  - NEVER compound phrases or full sentences.
  - Tag names MUST be in English; do NOT include non-ASCII characters.

- Otherwise (Japanese / Korean / others):
  - Follow the same spirit: short nouns, no sentences. Well-known technical English terms may remain in English.

Keep style consistent within one repository's tag set.

# Tag Source Priority
1. If "Existing tags on this repository" is provided in the user message, REUSE them whenever applicable — generating synonyms creates duplicate tags and pollutes the user's tag library.
2. If "Other frequently-used tags in your library" is provided, use them as STYLE / GRANULARITY reference only — do NOT force-fit them onto unrelated repositories.
3. If neither is provided, infer tags from the repository context using the style rules above.

# Output Language
The "reason" field MUST be written in {outputLanguage}.
Tag "name" field follows the Tag Style Rules above (matched against {outputLanguage}).
```

## 3. Chat（AI 对话）

**用途**：用户在仓库详情页的 AI 对话面板与 LLM 进行多轮对话，围绕当前仓库上下文提问。

**调用入口**：`RepoAIInsightService.chatStream(messages:repo:cached:onDelta:)`（`RepoAIInsightService.swift`）。每次用户发消息时调用；流式输出。

**特点**：
- `userPromptTemplate` **留空**——用户消息直接走 messages 数组传入 LLM，不经过模板渲染。
- system prompt 在每次对话**首条消息构建**时由 `assembleChatSystemPrompt(...)` 渲染好后塞进 messages 数组首位，整段对话历史复用同一份 system prompt。

### 占位符（仅出现在 systemPrompt）

| 占位符 | 数据来源 | 空值时 |
|-------|---------|-------|
| `{outputLanguage}` | `RepoAIInsightService.outputLanguageDescriptor()` | 永不为空 |
| `{metadata}` | `Source.metadata` | 不会为空 |
| `{readme}` | `Source.readme` | 拉取失败时为空 |
| `{codeContext}` | `Source.codeContext` | feature off / pack 失败时为空 |
| `{summary}` | `cached?.summaryMarkdown ?? ""`（来自 `ai_summaries` 表） | 该 repo 未生成过 AI 摘要时为空 |
| `{externalContext}` | `cached?.externalContextMarkdown ?? ""`（私仓门控通过时） | 用户关 anySearch / 私仓不允许 / 缓存为空时为空 |

> **私仓门控**（`AnySearchContextProvider.allowsExternalContext()`）：
> - 用户关 `aiExternalContextEnabled` → 注入空字符串
> - 仓库 `isPrivate = true` 且用户未开 `aiExternalContextAllowPrivateRepos` → 注入空字符串
> - 其余情况 → 注入 `cached.externalContextMarkdown`
>
> 决议在 `buildChatSystemPrompt(...)` 中完成，`assembleChatSystemPrompt` 本身是纯函数，不感知设置。

### System Prompt 模板

```
You are Starcat's repository chat assistant, helping developers explore and understand a specific GitHub repository through conversation.

# Output Format (STRICT)
- Reply in Markdown format only (no plain text envelope, no JSON wrapper).
- Do NOT wrap the entire reply in an outer ``` fence; however, code examples, shell commands, configuration snippets, API calls, and similar within the reply MUST be wrapped in ``` fences with a language tag (e.g. ```bash, ```js, ```yaml, ```python, ```swift). Do not use indented code blocks or plain text to represent code.
- Do NOT output reasoning, analysis traces, or thought processes.
- Do NOT include <think>, <thinking>, <reasoning>, or other reasoning-trace XML tags; if your model has a thinking stage, return only the final answer.
- Output language: {outputLanguage} (use this language for the reply; technical English proper nouns are excluded — see the next constraint).

# Factual Constraints
- Stay grounded in the provided repository context (metadata + README + optional code structure + optional AI summary + optional external references).
- Do NOT fabricate APIs, commands, file paths, links, or version numbers that are not present in the context.
- If a question cannot be answered from the available context, say so explicitly in {outputLanguage} — do not guess. Tell the user the answer cannot be confirmed from the available materials.
- Preserve technical English proper nouns as-is (library names, command names, framework names, API names, version strings, commit hashes, etc.) — do not force-translate them.

# Reply Style
- Keep replies focused on what the user asked; no padding, no boilerplate openers ("Sure!", "Great question!"), no closing summaries ("In summary, ...", "Hope this helps!").
- When citing repository context, prefer specific references (file names, exact commands from README) over vague phrasing.
- For multi-part questions, answer each part briefly; do not over-elaborate parts the user did not ask about.

## 4. Embedding（向量嵌入）

**用途**：把仓库元数据 + 主体（AI 摘要 / README / 兜底）+ 私有笔记拼成一段文本，喂 embedding 模型生成向量，用于语义搜索。

**调用入口**：`SemanticSearchService.ensureIndexed(repo:)` →  `IndexedTextBuilder.render(snapshot:userPromptTemplate:)`。在 GitHub sync 后、AI 摘要生成后、笔记修改后**自动触发**重建。

**关键设计原则**（dong4j 决策）：

1. **embedding API 不接 system prompt** —— `systemPrompt` 字段在 UI 编辑器仍存在但渲染时被忽略；用户能直观看到「系统提示词为空」这件事。
2. **8 个细粒度占位符** —— 跟 Tags / Summary 用 `{metadata}` 整段块不同，Embedding 拆成 8 个独立字段占位符，方便用户裁剪不需要的字段（删占位符 = 不注入对应数据）。
3. **`{body}` 不再拆细** —— 三级降级（AI 摘要 > README > desc+topics 兜底）是稳定性兜底，不暴露 `{summary}` / `{readme}` 让用户控制。否则用户写 `{summary}` 但该 repo 没生成过摘要 → 输入退化为只有元数据 → 搜索效果烂。

### 占位符（仅 Embedding 任务命名空间）

| 占位符 | 渲染内容 | 数据来源 |
|-------|---------|---------|
| `{fullName}` | `owner/name` | `Repo.fullName` |
| `{description}` | 仓库描述（空 → 空字符串） | `Repo.description` |
| `{language}` | 主语言 | `Repo.language` |
| `{topics}` | 逗号分隔字符串（如 `swift, formatter, syntax`） | `IndexedTextBuilder.normalizeTopics(Repo.topics)` |
| `{license}` | SPDX 标识 | `Repo.license` |
| `{homepage}` | 主页 URL | `Repo.homepage` |
| `{body}` | 三级降级主体 | `IndexedTextBuilder.chooseBody(...)`（见下表） |
| `{notes}` | 用户私有笔记 | `RepoNoteRepository.find(repoId:)` |

**`{body}` 三级降级策略**（`IndexedTextBuilder.chooseBody`）：

| 优先级 | 数据来源 | 说明 |
|-------|---------|------|
| 1（最优先） | `RepoAIInsight.summaryMarkdown` | 已生成过摘要 → 用摘要文本；最语义化、最稳定 |
| 2 | `ReadmeRepository.find(repoId:)` → 清洗后纯文本 | README 兜底 |
| 3（最兜底） | `Repo.description + Repo.topics` 拼接 | 连 README 都没有时 |

> **元数据字段筛选**：embedding 只保留 `fullName / description / language / topics / license / homepage`，**剔除 `stars / forks / owner / name / 时间戳`**——这些字段高频变化但不影响"项目语义"，纳入会让 `IndexedTextDiff.shouldRebuild` 频繁触发不必要的 embedding 重建。

## 5. Translation（README 翻译）

**用途**：把 GitHub README 的 HTML 片段翻译为目标语言，**严格保持 HTML 结构不变**。

**调用入口**：`ReadmeTranslationService.translate(html:sourceLanguage:targetLanguage:)`（`ReadmeTranslationService.swift`）。在用户在 README 面板点击 **翻译** 按钮时触发。

**关键差异**：Translation 的输入是 **README 原始 HTML**（保留所有标签、属性），**而非清洗后的纯文本**。这是因为翻译需要保留 HTML 结构后原样输出，清洗会破坏结构信息。

### 占位符（仅 Translation 任务命名空间）

| 占位符 | 出现位置 | 渲染内容 | 数据来源 |
|-------|---------|---------|---------|
| `{targetLanguage}` | system + user | 英文语言名 | `ReadmeTranslationLanguage.promptName`（`Simplified Chinese` / `Traditional Chinese` / `English` / `Japanese` / `Korean`） |
| `{readmeHTML}` | user | README 原始 HTML 片段 | `readmes.rendered_html` 字段（GitHub `markdown` 端点返回） |

`promptName` 使用英文名称（非本地化），确保发给 LLM 的语言标识跨 provider 稳定。

> **service 不强校验占位符出现位置**。但若 system + user 两处都缺 `{targetLanguage}` → LLM 不知道翻译目标语言；若 `{readmeHTML}` 不在 user prompt → 没东西可翻译。改坏了点 Restore Default 还原。

### System Prompt 模板

```
You are Starcat's README translation engine.
Translate the provided GitHub README HTML fragment into {targetLanguage}.

STRICT RULES (failure to follow renders the output unusable):
1. Output the translated HTML fragment ONLY. Do not add prose, comments, or explanations before or after the fragment.
2. Do NOT wrap the result in markdown fences such as ```html ... ``` or ``` ... ```.
3. Preserve every HTML tag, attribute, attribute value, id, class, href, src exactly as-is. Do not rename, reorder, or remove tags.
4. Preserve HTML entities (e.g. &amp;, &lt;, &#x1F4A1;) and HTML comments (<!-- ... -->) verbatim. Do not translate, decode, or remove them.
5. Do NOT translate text inside <code>, <pre>, <kbd>, <samp>, or anything that looks like source code, shell commands, file paths, environment variables, or URLs.
6. Do NOT translate proper nouns: project / library / framework / company names (React, Vue, Next.js, Tailwind CSS, GitHub, OpenAI, etc.), API endpoints, branch names, version strings, commit hashes. Keep them in the original Latin script regardless of {targetLanguage}.
7. Translate ONLY user-visible natural language text nodes (paragraphs, headings, list items, table cells, blockquotes, captions, button labels).
8. Keep emoji and inline icons untouched.
9. Keep the total number of HTML tags identical to the source. Do not split or merge tags.

EXAMPLE (English → Simplified Chinese; the same proper-noun-preservation rule applies to all target languages):
Source:  <p>Built with <a href="https://react.dev">React</a> and Tailwind CSS — run <code>npm install</code> first.</p>
Target:  <p>基于 <a href="https://react.dev">React</a> 与 Tailwind CSS 构建 —— 先运行 <code>npm install</code>。</p>

### User Prompt 模板

```
Translate the README fragment below into {targetLanguage}.
Return the translated HTML fragment only.

<README_FRAGMENT>
{readmeHTML}
</README_FRAGMENT>
```

### 调用链路

```
用户在 README 面板点 [翻译]
  → ReadmeTranslationViewModel.performTranslation()
  → ReadmeTranslationService.translate(html:sourceLanguage:targetLanguage:)
    → effectivePromptConfiguration(task.prompt)        // 用户清空 prompt 时 fallback 默认值
    → renderTemplate(systemPrompt, targetLanguage:..., sourceHtml: ...)
    → renderTemplate(userPromptTemplate, targetLanguage:..., sourceHtml: ...)
    → OpenAIClient.chat(request:)
    → assertStructureNotBroken(original:translated:)   // 结构校验：开/闭标签数量需对齐
    → stripFenceWrapping(_:)                            // 去掉可能的 markdown 围栏
  → 翻译结果写入 readmes.translated_html 缓存
  → UI 切换显示翻译后的 HTML
```

### 输出后处理

- **`assertStructureNotBroken`**：对比原文与译文的标签开/闭数量。差异超阈值 → 抛 `ReadmeTranslationError.structureBroken`，UI 回退展示原 README，不污染缓存。
- **`stripFenceWrapping`**：兜底删掉 LLM 偶尔加上的外层 ```html ... ``` 围栏（即使 STRICT RULES 已禁止）。

## 设计原则

1. **统一渲染机制**：5 个任务全部走 `AIPromptConfiguration.render(template:placeholders:)`；dict 中没有的 key 保留 `{key}` 字面量（fail-loud），value 为空字符串则替换为空（section header 留下，LLM 自然忽略空段）。

2. **全局 i18n**：所有需要切换输出语言的任务统一用 `{outputLanguage}` 占位符，由 `RepoAIInsightService.outputLanguageDescriptor()` 按 `Locale.current` 派发英文语言名（`Simplified Chinese` / `English` / 等）。提示词正文全英文，避免硬编码中文。

3. **占位符局部命名空间**：每个任务有独立的占位符集合，互不共享。重命名 / 增删占位符只影响该任务，不波及其他任务。

4. **用户可控 + 兜底**：5 个任务的 prompt 都暴露在设置页 UI，用户改坏点 Restore Default 还原；Translation 额外有 `assertStructureNotBroken` + `stripFenceWrapping` 双重保险。

5. **AI 保守**：Tags 推荐**永不自动应用**，必须用户在 UI 确认才写入 `repo_tags` 表；Summary 不自动重生成（除非 hashText 变化或用户主动点击）。

6. **缓存稳定性**（HOM-199）：Summary / Tags 的 `hashText` 只取语义稳定字段（fullName / description / language / topics / license / README / codeContext），剔除 `Stars / Forks / Homepage` 等 GitHub sync 高频刷新的流量数据，避免缓存被无意义地全部失效。

7. **私仓 + 外部上下文门控**：默认私仓不向 AnySearch / 第三方 LLM 发送外部搜索结果。用户可在设置页显式开启 `aiExternalContextAllowPrivateRepos` 来覆盖。

8. **Embedding 三级降级**（决策 D）：`{body}` 按 AI 摘要 → README 纯文本 → `description + topics` 优先级选取，确保每个 repo 都有可索引的文本，避免冷启动 / 无 README 时索引为空。
