## 1. 目标与非目标

### 1.1 目标

1. 在主窗口现有「关注者」统计入口上打开一个覆盖整个应用窗口的图谱遮盖层。
2. 以当前登录用户为根节点，分批读取 GitHub following 关系，默认自动探索两层。
3. 在本地维护按账户隔离、可离线恢复的关系快照与每个用户的分页状态。
4. 用离线打包的 WebView 渲染头像节点、有向关系、路径高亮和 2D 交互。
5. 用可测试的原生图模型完成去重、合并、层级计算和最短路径计算，避免把这些规则散落在页面脚本里。
6. 两渠道均免费开放，不接入 Pro 权益门控；设置页仅展示当前账户图谱缓存统计。

### 1.2 非目标

- 不创建独立窗口，不进入系统全屏，不修改主窗口尺寸。
- 不把关系数据写入用户数据库，不新增数据库 migration。
- 不在后台常驻同步，不在页面关闭后继续抓取。
- 不把 GitHub Token、完整图谱或推荐反馈发给 Starcat 服务端。
- 首版不做影响力评分、AI 分析、云端同步和图谱导出。

## 3. 总体架构

```text
Sidebar Followers StatCell
        │ open overlay callback
        ▼
HomeView full-window overlay state
        │
        ▼
FollowGraphWindowOverlay          ── AppKit：覆盖整个 NSWindow theme frame
FollowGraphOverlayView            ── SwiftUI：画布 + 悬浮工具栏 / 信息栏
        │
        ├─ FollowGraphViewModel   ── 展示状态、任务生命周期、查找、选择
        ├─ FollowGraphEngine      ── 纯函数图模型：merge / BFS / path / capacity
        ├─ FollowGraphStore       ── actor：请求调度、预算、快照装配
        ├─ FollowGraphDiskCache   ── 账户隔离 JSON 原子缓存
        └─ FollowGraphWebView     ── NSViewRepresentable + WKWebView
                 │ controlled script messages
                 ▼
          FollowGraphResources/FollowGraph.html + offline JS
```

关键分层约束：

- `FollowGraphEngine` 不访问网络、磁盘和主线程 UI，全部方法可单测。
- `FollowGraphStore` 是 actor，负责并发上限、任务代际、预算和缓存一致性。
- `FollowGraphViewModel` 只在 MainActor，持有展示状态，不直接拼 GraphQL。
- WebView 页面只负责渲染和交互，不做业务判断；图语义全部在原生层完成。

## 4. 入口与全窗口遮盖层

### 4.1 入口

`SidebarHeaderView.statsRow` 的 Followers `StatCell` 从「直接打开 GitHub URL」改为回调：

```text
StatCell(action:) → SidebarHeaderView.onOpenFollowGraph → HomeView state
```

要求：

- 视觉、字号、hover、帮助文案保持不变；tooltip 可按需求改为打开图谱。
- Starred 与 Following 统计仍保留现有浏览器行为。
- 未登录或用户资料缺失时按钮不可用或触发登录引导，不打开空图谱。

### 4.2 遮盖层

新增 `FollowGraphWindowOverlay`，不复用 `DailyRadarWindowOverlay`：

- 每日热点覆盖的是中右联合内容区；本需求必须覆盖整个窗口，包括侧栏与 toolbar。
- 探针挂主窗口根视图，宿主挂到 `window.contentView?.superview` 并铺满 `container.bounds`。
- `NSHostingView.sizingOptions = []`，`safeAreaRegions = []`，避免 fitting size 反向影响窗口。
- `interceptsEvents` 只在 `isPresented == true` 时为 true；关闭动画结束后不拦截输入。
- 关闭后恢复底层页面状态与键盘焦点，不销毁已加载的 ViewModel / 数据快照。

窗口生命周期：

- 打开时恢复快照，然后按需刷新；不因打开动作清空旧图。
- 关闭或窗口失焦隐藏时暂停 WebView 渲染与布局，并停止新增请求调度。
- 窗口 resize 时只更新宿主 frame，不重建 WKWebView。
- 账号切换或登出立即关闭遮盖层，取消任务，清空当前展示状态。

## 5. 数据契约

### 5.1 图谱节点

```swift
struct FollowGraphNode: Codable, Hashable, Sendable {
    let id: String            // GitHub GraphQL node ID；缓存身份
    let numericID: Int64       // REST 数值 ID；图内稳定排序与兜底
    let login: String
    var name: String?
    var avatarURL: URL?
}
```

约束：

- 图合并以 `id` 为主；`numericID` 用于防御 GraphQL ID 变化与日志展示。
- `login` 允许更新；改名不生成新节点。
- `name` 与 `avatarURL` 缺失不阻断关系展示。

### 5.2 关系边

```swift
struct FollowGraphEdge: Codable, Hashable, Sendable {
    let sourceID: String
    let targetID: String
    var fetchedAt: Date
}
```

- `sourceID → targetID` 表示 source 关注 target。
- 反向边、自环、重复边由 `FollowGraphEngine` 合并；自环不展示但仍可记录为异常防御。

### 5.3 用户加载状态

```swift
enum FollowGraphLoadPhase: String, Codable, Sendable {
    case idle
    case loading
    case partial
    case complete
    case failed
    case blocked
}

struct FollowGraphUserProgress: Codable, Hashable, Sendable {
    let userID: String
    var phase: FollowGraphLoadPhase
    var endCursor: String?
    var loadedCount: Int
    var totalCount: Int?
    var lastError: String?
    var fetchedAt: Date?
}
```

约束：

- `complete` 只能在 GitHub 明确 `hasNextPage == false` 且本批读取成功后设置。
- `partial` 表示还有未读分页或本次因预算 / 失败中止。
- `failed` / `blocked` 保留旧边，不把失败解释为空列表。
- `totalCount` 只用于展示「已加载 / 总数」，不作为停止条件；停止条件看 `hasNextPage`。

### 5.4 快照

```swift
struct FollowGraphSnapshot: Codable, Sendable, Equatable {
    static let currentFormatVersion = 1

    let formatVersion: Int
    let accountID: String
    var rootID: String
    var nodes: [String: FollowGraphNode]
    var edges: Set<FollowGraphEdge>
    var progress: [String: FollowGraphUserProgress]
    var session: FollowGraphSessionState
    var savedAt: Date
}
```

`session` 保存选中节点、二维视口状态、已加载预算统计；不强制保存精确 2D 布局。

## 6. GitHub 读取方案

### 6.1 API 选择

首版采用 **GraphQL**，原因：

- 一次查询同时返回用户基础资料、头像、following 总数、分页游标。
- GraphQL cursor 分页比 REST page number 更适合增量续读。
- 可避免 REST 方案中「先拉 following，再逐个补 profile」的二次请求。

查询形态：

```graphql
query($login: String!, $first: Int!, $after: String) {
  user(login: $login) {
    id
    databaseId
    login
    name
    avatarUrl
    following(first: $first, after: $after) {
      totalCount
      pageInfo { hasNextPage endCursor }
      nodes {
        id
        databaseId
        login
        name
        avatarUrl
      }
    }
  }
}
```

只使用公开字段；是否可见由 GitHub 权限与用户隐私设置决定。

### 6.2 分页策略

- `first` 初始建议 50；手动「加载更多」可升到 100。
- 每个用户维护独立 `endCursor`。
- 点击未加载节点只发首批，不循环到末页。
- 「加载更多」逐页追加；到达 `hasNextPage == false` 才标记 complete。
- 首版不做嵌套 following 批量查询，避免一次 GraphQL 过重并引入部分失败歧义。

### 6.3 默认两层探索

建议初始策略：

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 根节点首批 | 100 | 尽量覆盖一级关注 |
| 一级用户二级首批 | 20 / 用户 | 避免一个超大账号占满预算 |
| 请求并发 | 4 | 兼顾速度与 rate limit |
| 首次自动请求预算 | 300 requests | 500 个一级关注下可中断并保留结果 |
| 首次自动节点软上限 | 5,000 nodes | 达到后停止自动探索，允许手动小批量继续 |
| 硬上限 | 10,000 nodes / 30,000 edges | 超过硬上限禁止继续加载 |
| 最低剩余配额 | 200 core quota | 低于阈值暂停自动扩展 |

这些值是样板验证初始值，不是最终产品承诺；必须用真实 500 一级关注账号验证后调整。

### 6.4 调度器

`FollowGraphStore` 维护：

- `generation`：遮盖层打开代际，关闭 / 换账号后递增。
- `pendingUsers`：公平队列，按用户轮询发放二级页，不按请求发起顺序堆叠。
- `inFlight`：最多 4 个并发请求。
- `budget`：请求数、节点数、边数、最低剩余配额。
- `cooldownUntil`：rate limit 恢复时间。

规则：

- 任一请求返回 `NetworkError.rateLimited`，停止自动扩展并记录恢复时间。
- `RateLimitInfo.remaining` 低于阈值时停止继续出队，已返回的结果仍正常合并。
- 任务取消只阻止新请求，不回滚已成功结果。
- 迟到结果必须携带相同 `generation`，否则丢弃。
- 手动加载同样受硬上限与配额保护。

## 7. 图模型与算法

### 7.1 合并

`FollowGraphEngine.merge(snapshot:page:)`：

1. upsert page source 用户与 following nodes
2. 按 `(sourceID, targetID)` upsert edges
3. 更新 source progress / cursor / phase
4. 重算受影响节点的 BFS 层级
5. 输出新的 immutable snapshot

不使用 `Class` 引用图，避免 MainActor 和 actor 之间共享可变对象。

### 7.2 层级与路径

- 从 root 做 BFS，得到每个可达节点的最短层级与 predecessor。
- 多条等长路径按 `(depth, numericID, login)` 排序，保证稳定选择。
- 图更新后只重算 BFS 结果与当前选中路径，不重排全图布局。
- BFS 时间复杂度 `O(V + E)`，10,000 nodes / 30,000 edges 可在后台安全执行。

### 7.3 刷新删除

只有满足以下全部条件，才允许删除某用户旧出边：

1. 刷新从第一页开始，受当前展示预算约束；不能把二层首批样本自动刷新为全量关注列表；
2. 读取过程没有被取消、限流或失败；
3. GitHub 返回 `hasNextPage == false`。

否则保留旧边并标记 partial。刷新后从展示图中移除 root 不可达且非 progress 依赖的孤立节点。

## 8. 缓存设计

### 8.1 路径

```text
~/Library/Application Support/com.starcat.app/
  follow-graph-cache/
    <github-user-id>/
      snapshot.json
```

- 使用 GitHub 数值 ID 作为账户目录，login 改名不影响缓存。
- 目录名做安全校验，禁止 `/`、`\`、`.`、`..`、空字符串与 NUL。
- 快照 JSON 原子写入，格式版本不匹配时删除并重建，不迁移首版缓存。

### 8.2 缓存策略

- 打开图谱先读快照，再由用户刷新；不做后台静默校验。
- 快照永久可用于离线展示；页面显示 `savedAt` 与各用户 `fetchedAt`。
- 缓存大小上限建议 20 MB；超限时优先淘汰非当前账户目录，当前账户快照保留。
- 设置页展示当前账户的快照占用空间、节点数、关系数与保存时间；无缓存时显示无缓存，不提供图谱缓存清理入口。统计从本地缓存元数据读取，不触发 GitHub 请求；保存时间不代表全部关系同时更新。
- 既有工厂重置流程应覆盖图谱缓存，不另增图谱专用清理操作。

## 9. 渲染方案

### 9.1 已确认的 2D MVP

2026-11-05 经实际体验确认，替换三维渲染为 `force-graph 1.52.0` 的 2D Canvas。
直接依赖 `d3-force-3d 3.0.6` 仅供二维力计算与碰撞检测，移除 Three.js、透视相机与旋转控制。

- 圆形头像与首字母占位；普通节点半径 11，根节点 20，选中节点 17 个图坐标单位。
- 根节点固定在原点，确定性平面初始布局；碰撞半径为普通节点 21、根节点 25，缓解头像重叠。
- 空白区域拖动平移、滚轮或触控板缩放、节点拖动；选中路径使用加粗蓝线和方向箭头。
- 原生模型只在会话内保存 `[centerX, centerY, zoom]`，缩放范围 0.05–8，拒绝非有限值、越界值与旧三维消息。
- 在组件异步布局更新后恢复视口，防止内部首帧自动缩放覆盖原生恢复值。
- 增量批次复用节点对象；真实手势或主动定位后停止自动适配，避免数据到达时抢占视野。
- 缩远后普通头像降为圆点；图稳定后停止持续重绘，头像到达或选择变化时请求重绘。
- Reduce Motion 使用静态平面初始布局，取消视口过渡动画；非活跃和隐藏时暂停渲染。

### 9.2 后续性能验证

实测 5,000 / 10,000 节点的平移、缩放、点选、路径与头像内存，再决定是否需要 Worker 或进一步合批优化。当前不引入新的三维场景备选。

### 9.3 WebView 安全

- 资源全部放入 `Starcat/Resources/FollowGraph`，禁止 CDN。
- 使用 `loadHTMLString(_:baseURL:)` 或本地资源 URL，由样板验证 App Store / Direct 沙盒行为。
- 主 frame 只允许初始导航；后续主 frame 导航一律 cancel。
- 图片加载仅允许 GitHub avatars 域；失败回退 identicon / 首字母。
- JS 不接收 Token，不发起 GitHub API 请求，不打开任意 URL。
- Script message 白名单：`ready`、`select`、`viewport`、`error`。
- 原生调用页面方法白名单：`window.followGraph.update(payload)`、`window.followGraph.destroy()`。
- 所有 payload 带 `sessionID` 与消息序号，过期消息丢弃。
- 消息参数校验长度、类型、节点 ID 是否存在于当前快照。
