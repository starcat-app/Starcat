# 46 - 快捷键与应用命令设计

> 日期：2026-07-21
>
> 状态：方案已记录，尚未开发
>
> 范围：主窗口应用命令、知识库 RAG 工作台入口、当前仓库 AI 窗口入口
>
> 不包含：`docs/功能实现总览.md` 状态同步、Agent 工作台公开、全量快捷键自定义

## 1. 背景

Starcat 已经具备全局搜索、列表搜索、批量选择等键盘操作，但工作台和独立窗口入口仍主要依赖 toolbar 或详情按钮。对于频繁使用 RAG、仓库 AI 和 Stars 同步的用户，鼠标路径偏长；同时，现有“操作”菜单中的部分命令没有显示快捷键，发现性不完整。

本方案只补高频、低歧义且可安全复用现有执行链的命令。快捷键不是第二套业务入口：菜单、toolbar、详情按钮和键盘必须调用同一个动作，继续服从登录、Pro、分发渠道、当前选择和 Debug 门禁。

## 2. 当前实现基线

### 2.1 已有快捷键

| 操作 | 当前键位 | 作用域 | 配置方式 |
|---|---:|---|---|
| 全局搜索中心 | `⌘K` | 主窗口任意页面 | 可配置 |
| Manage 列表搜索 | `⌘F` | Manage 页面 | 可配置 |
| 进入/退出批量选择 | `⇧⌘M` | 支持批量操作的列表 | 固定 |
| 批量全选 | `⌘A` | 批量选择激活后 | 固定、上下文生效 |
| 设置 | `⌘,` | App 全局 | macOS 原生 |
| 关于 Starcat | `⌘I` | App 全局 | 固定，计划移除 |

现有代码入口：

- `Starcat/Core/Settings/KeyboardShortcutConfiguration.swift`：可配置快捷键值对象、默认值与保留键位。
- `Starcat/Features/Home/HomeView.swift`：通过隐藏按钮注册全局搜索快捷键。
- `Starcat/Features/Home/RepoListView.swift`：注册 Manage 搜索与批量全选快捷键。
- `Starcat/Shared/Components/Toolbar/MultiSelectButton.swift`：注册 `⇧⌘M`。
- `Starcat/App/StarcatApp.swift`：定义“操作”菜单、关于菜单和原生 Settings scene。

### 2.2 已有命令但没有默认快捷键

`StarcatAppCommands` 当前包含：

- 同步 Stars；
- 打开全局搜索；
- 打开 AI 用量窗口；
- Direct 渠道检查更新；
- 导出诊断信息。

知识库 RAG 工作台由主窗口 toolbar 和知识库详情入口打开；当前仓库 AI 窗口由仓库详情按钮打开。两者尚未进入统一应用命令体系。

## 3. 设计目标与非目标

### 3.1 目标

1. 为 Stars 同步、知识库 RAG 工作台和当前仓库 AI 窗口提供稳定快捷键。
2. 菜单、toolbar、详情按钮和快捷键复用同一动作，不复制业务逻辑。
3. 上下文不足时禁用命令，不自动猜测或改变用户选择。
4. 固定键位与用户自定义搜索键位统一做冲突校验。
5. 在菜单和 tooltip 中可发现快捷键，不要求用户先打开设置页。

### 3.2 非目标

- 不把所有按钮都快捷键化。
- 不在首轮开放同步、RAG、仓库 AI 的自定义键位。
- 不新建独立“快捷键”设置 Tab。
- 不通过快捷键公开仍受 Debug flag 控制的 Agent 工作台。
- 不为取消 Star、批量 AI、诊断导出、检查更新等低频或有明显副作用的动作分配默认键位。
- 不改变数据库、网络协议、RAG 检索逻辑或 AI 生成逻辑。

## 4. 首轮快捷键方案

| 优先级 | 操作 | 键位 | 生效条件 | 执行语义 |
|---|---|---:|---|---|
| P0 | 同步 Stars | `⌘R` | 应用依赖已就绪 | 复用 `StarcatAppCommands.syncStars()`；未登录时沿用现有登录引导 |
| P0 | 打开知识库 RAG 工作台 | `⇧⌘K` | 主窗口提供有效命令上下文 | 复用 `KnowledgeRAGWorkspaceWindowController.show(...)`，继续经过 `AIWorkspaceEntryGate` |
| P0 | 打开当前仓库 AI 窗口 | `⇧⌘A` | 主窗口存在当前选中仓库 | 复用 `RepoAIWindowController.show(...)`；无选中仓库时菜单禁用 |
| 清理 | 关于 Starcat | 移除 `⌘I` | 不适用 | 菜单入口保留，仅取消非必要快捷键 |

### 4.1 键位选择理由

- `⌘R`：符合 macOS 应用中“刷新/重新加载”的习惯，并与 Starcat 的 Stars 手动完整同步语义一致。
- `⇧⌘K`：`K` 表示 Knowledge，与 `⌘K` 全局搜索形成同族入口；避免让 `⌘R` 同时承担同步与 RAG 两种语义。
- `⇧⌘A`：`A` 表示 AI，且不会与仅在批量模式生效的 `⌘A` 混淆。
- `⌘I`：通常更接近 Info/Inspector 语义，“关于”属于低频菜单动作，不应长期占用该键位。

### 4.2 当前仓库 AI 的边界

`⇧⌘A` 的对象严格定义为主窗口当前选中的本地仓库：

- 不自动选择第一条仓库；
- 不使用 hover 行或未打开的搜索候选；
- 不自动生成或重新生成摘要；
- 只打开现有仓库 AI 窗口并加载既有状态；
- 用户在窗口内主动点击生成或发送消息时，才进入现有 Pro、模型配置与远程调用流程。

### 4.3 RAG 工作台的边界

`⇧⌘K` 只新增打开入口，不改变 RAG 工作台行为：

- 不自动创建新会话；
- 不自动发送问题；
- 不绕过 `AIWorkspaceEntryGate.authorizeOpening(...)`；
- 已打开时把同一个 RAG 工作台窗口带到前台，不重复创建。

## 5. 暂缓项

### 5.1 RAG 新会话 `⌘N`

`KnowledgeRAGWorkspaceViewModel.newConversation()` 当前会立即持久化一条空会话。直接加入 `⌘N` 容易因重复按键产生空白历史，因此不进入首轮。

后续满足以下条件后再实现：

1. 当前会话为空且没有消息时，`⌘N` 复用当前空会话；
2. 只有 RAG 工作台是 key window 时生效；
3. 输入法候选、文本编辑和 sheet 展示期间不拦截；
4. 菜单或可见按钮能够展示该快捷键。

### 5.2 Agent 工作台

Agent toolbar 入口当前受 `DebugFlags.agentToolbarEntry` 控制。首轮不得增加菜单或快捷键，否则会形成绕过现有公开门禁的第二入口。等 Agent 工作台正式公开后，再单独决定键位和设置归属。

### 5.3 AI 用量及其他低频动作

AI 用量已有 toolbar 状态入口和“操作”菜单入口；诊断导出、检查更新、打开 GitHub、取消 Star 和批量 AI 均不分配默认快捷键。高频证据出现前不占用键位。

## 6. 设置页归属

首轮继续放在：

```text
设置 → 通用 → 快捷键
```

理由：

- 真正允许用户修改的仍只有全局搜索 `⌘K`、列表搜索 `⌘F` 和 AI 输入发送行为；
- `⌘R`、`⇧⌘K`、`⇧⌘A` 是固定应用命令，通过菜单和 tooltip 发现，不增加设置项；
- 单独创建一级“快捷键”Tab 会产生过多导航和大面积空白。

只有同时满足下列条件时，才把快捷键从“通用”独立出来：

1. 可配置动作达到约 5～6 个；
2. 同步、工作台、仓库操作等固定动作也允许用户改键；
3. 需要按功能域分类；
4. 需要逐项恢复、恢复全部、禁用某项或完整冲突矩阵。

## 7. 命令路由设计

### 7.1 全局动作

真正全局、无需当前仓库上下文的动作继续放在 `StarcatAppCommands`：

- 同步 Stars；
- 打开全局搜索；
- AI 用量；
- 检查更新；
- 导出诊断。

`⌘R` 直接绑定已有同步方法，不新增通知或第二个同步实现。

### 7.2 主窗口上下文动作

RAG 和当前仓库 AI 需要 `HomeViewModel`、`OpenSettingsAction` 以及当前仓库选择，建议使用 SwiftUI `FocusedValues` 暴露一个轻量命令上下文：

```swift
struct StarcatFocusedCommandContext {
    let openGlobalSearch: () -> Void
    let openKnowledgeRAGWorkspace: () -> Void
    let openSelectedRepoAI: (() -> Void)?
}
```

约束：

- `HomeView` 只发布动作闭包，不复制窗口状态；
- 没有选中仓库时 `openSelectedRepoAI == nil`，菜单自然禁用；
- RAG、AI 独立窗口成为 key window 后，主窗口上下文动作可以禁用，避免快捷键误作用到后台选择；
- 动作闭包必须调用现有 `KnowledgeRAGWorkspaceWindowController.show(...)` 与 `RepoAIWindowController.show(...)`；
- Pro、登录、渠道和 Debug 门禁继续在执行层检查，不能只依赖菜单是否隐藏或禁用。

### 7.3 全局搜索注册收口

`⌘K` 当前由 `HomeView` 隐藏按钮注册，而“操作 → 全局搜索”菜单不显示键位。实施时应：

1. 把可配置的 `⌘K` 注册迁到 `StarcatAppCommands` 对应菜单按钮；
2. 通过 `StarcatFocusedCommandContext.openGlobalSearch` 直接调用主窗口现有 Search Center 展示动作；
3. 删除不再需要的 `.starcatCommandOpenGlobalSearch` 通知桥和 `HomeView` 中重复的隐藏按钮；
4. 主窗口不提供 focused context 时禁用该菜单命令，避免从 AI/RAG 独立窗口把搜索浮层打开在后台主窗口；
5. `⌘F` 仍留在 `RepoListView`，因为它只在 Manage 页面生效。

同一个快捷键只能注册一次，避免菜单命令与隐藏按钮同时竞争。

## 8. 快捷键目录与冲突规则

新增一个轻量固定键位目录，作为菜单、冲突校验、tooltip 和测试的单一信任源：

```swift
enum StarcatShortcutCatalog {
    static let syncStars = KeyboardShortcutConfiguration(/* ⌘R */)
    static let openKnowledgeRAG = KeyboardShortcutConfiguration(/* ⇧⌘K */)
    static let openSelectedRepoAI = KeyboardShortcutConfiguration(/* ⇧⌘A */)

    static let fixedReserved: Set<KeyboardShortcutConfiguration> = [
        syncStars,
        openKnowledgeRAG,
        openSelectedRepoAI,
        // Settings、批量选择等现有固定语义
    ]
}
```

不把固定键位存入 `UserDefaults`，避免制造“看似可配置、实际不可配置”的状态。

### 8.1 校验规则

用户录制搜索快捷键时必须拒绝：

- 没有 Command/Option/Control 的普通输入；
- 非单个英文字母或数字；
- `StarcatShortcutCatalog.fixedReserved` 中的固定键位；
- 与另一个可配置搜索动作相同的键位。

新增 `duplicateConfiguredAction` 错误文案，明确说明“该快捷键已分配给另一项搜索操作”。

### 8.2 旧配置升级

当前版本允许用户把全局搜索和列表搜索录成相同键位。升级后加载到冲突组合时：

1. 不崩溃、不静默抢占；
2. 将两个搜索快捷键一起恢复为默认 `⌘K` / `⌘F`；
3. 新固定键位与旧自定义值冲突时，冲突的自定义值回退到对应搜索默认值；
4. 不新增数据库 migration，仍使用现有 `UserDefaults` JSON 持久化。

## 9. 菜单与可发现性

“操作”菜单建议按以下顺序整理：

```text
全局搜索                         ⌘K
打开知识库 RAG 工作台           ⇧⌘K
打开当前仓库 AI                 ⇧⌘A
────────────────────────────
同步 Stars                      ⌘R
AI 用量…
────────────────────────────
检查更新…                       Direct only
导出诊断信息…
```

规则：

- 菜单标题、toolbar tooltip 和 accessibility label 必须走 String Catalog；
- toolbar tooltip 应显示实际键位，`⌘K` / `⌘F` 使用用户当前配置值；
- 键位符号使用字面文本，不作为本地化 key；
- 菜单禁用状态必须与当前命令上下文一致；
- “关于 Starcat”仍保留在 App 菜单，仅移除 `⌘I`。

## 12. 验收标准

### 12.1 自动化验证

- `⌘R`、`⇧⌘K`、`⇧⌘A` 均被固定键位目录识别为保留组合。
- 用户不能把 `⌘K` 或 `⌘F` 改成固定键位。
- 用户不能把全局搜索与列表搜索设置为相同组合。
- 旧版本相同组合可安全回退到 `⌘K` / `⌘F`。
- 无选中仓库时，当前仓库 AI 命令上下文为空。
- 不新增数据库 migration，不修改已发布 schema。

### 12.2 人工/UI 验证

- “操作”菜单显示正确快捷键和禁用状态。
- `⌘K` 在主窗口任意页面打开全局搜索，且只触发一次。
- `⌘F` 只在 Manage 页面聚焦列表搜索。
- `⌘R` 复用现有同步状态、登录引导和重复同步保护。
- `⇧⌘K` 打开或前置同一个 RAG 工作台，免费/未配置场景仍走现有门禁。
- `⇧⌘A` 只打开当前选中仓库的 AI 窗口，不自动生成摘要。
- 无选中仓库时 `⇧⌘A` 不自动选仓库、不打开错误对象。
- AI/RAG 独立窗口或文本输入成为焦点时，不误触主窗口后台上下文。
- Settings 中的快捷键分组仍位于“通用”，没有新增空的一级 Tab。

## 13. 风险与回退

| 风险 | 防护 |
|---|---|
| 同一键位注册两次 | 全局搜索迁到菜单后删除 `HomeView` 隐藏注册；固定键位由目录统一定义 |
| 快捷键作用到后台仓库 | 用 `FocusedValues` 提供当前 key window 上下文；无上下文时禁用 |
| 绕过 Pro/渠道/Debug 门禁 | 菜单只负责路由，执行层继续调用现有 gate |
| 旧用户自定义键位撞上新固定键位 | AppSettings 加载时校验并回退默认值 |
| 设置页膨胀 | 首轮固定键位不开放配置，快捷键分组继续留在“通用” |
| `⌘N` 产生空会话 | 首轮不实现，等空会话复用规则落地后再评估 |

如实施后出现系统级或输入焦点冲突，可单独撤销对应 `.keyboardShortcut(...)`，不会影响 toolbar、菜单动作或底层业务链。
