# 46 - 快捷键与应用命令设计

> 日期：2026-07-21（2026-07-22 修订上下文刷新、自定义、禁用与 AI 面板关系）
>
> 状态：代码已实现，待人工多窗口与焦点场景验收
>
> 范围：主窗口应用命令、知识库 RAG 工作台入口、当前仓库详情页底部 AI 面板入口
>
> 不包含：`docs/功能实现总览.md` 状态同步、Agent 工作台公开、移除系统保留键位

## 1. 背景

Starcat 已经具备全局搜索、列表搜索、批量选择等键盘操作，但工作台和详情面板入口仍主要依赖 toolbar 或详情按钮。对于频繁使用 RAG、仓库 AI 和内容刷新的用户，鼠标路径偏长；同时，现有“操作”菜单中的部分命令没有显示快捷键，发现性不完整。

本方案只补高频、低歧义且可安全复用现有执行链的命令。快捷键不是第二套业务入口：菜单、toolbar、详情按钮和键盘必须调用同一个动作，继续服从登录、Pro、分发渠道、当前选择和 Debug 门禁。

## 2. 当前实现基线

### 2.1 已有快捷键

| 操作 | 当前键位 | 作用域 | 配置方式 |
|---|---:|---|---|
| 全局搜索中心 | `⌘K` | 主窗口任意页面 | 可配置 |
| Manage 列表搜索 | `⌘F` | Manage 页面 | 可配置 |
| 进入/退出批量选择 | `⇧⌘M` | 支持批量操作的列表 | 固定 |

现有代码入口：

- `Starcat/Core/Settings/KeyboardShortcutConfiguration.swift`：可配置快捷键值对象、默认值与保留键位。
- `Starcat/Features/Home/HomeView.swift`：通过隐藏按钮注册全局搜索快捷键。
- `Starcat/Features/Home/RepoListView.swift`：注册 Manage 搜索与批量全选快捷键。

- `Starcat/App/StarcatApp.swift`：定义“操作”菜单、关于菜单和原生 Settings scene。

### 2.2 已有命令但没有默认快捷键

`StarcatAppCommands` 当前包含：

- 刷新仓库列表/详情（原“同步 Stars”命令已被上下文刷新替代）；
- 打开全局搜索；
- 打开 AI 用量窗口；
- Direct 渠道检查更新；
- 导出诊断信息。

知识库 RAG 工作台由主窗口 toolbar 和知识库详情入口打开；当前仓库 AI 摘要 / 对话由详情页底部 `RepoAIFloatingOverlay` 承载。底部面板内部可以继续派生 `RepoAIWindowController` 独立窗口，但该窗口不是外部主入口。两者尚未进入统一应用命令体系。

## 3. 设计目标与非目标

### 3.1 目标

1. 为当前内容刷新、知识库 RAG 工作台和当前仓库详情页底部 AI 面板提供稳定快捷键。
2. 菜单、toolbar、详情按钮和快捷键复用同一动作，不复制业务逻辑。
3. 上下文不足时禁用命令，不自动猜测或改变用户选择。
4. 五个应用命令支持改键、恢复默认、总开关和逐项开关，并统一做冲突校验。
5. 在菜单和 tooltip 中可发现快捷键，不要求用户先打开设置页。

### 3.2 非目标

- 不把所有按钮都快捷键化。
- 不新建独立“快捷键”设置 Tab。
- 不通过快捷键公开仍受 Debug flag 控制的 Agent 工作台。
- 不为取消 Star、批量 AI、诊断导出、检查更新等低频或有明显副作用的动作分配默认键位。
- 不改变数据库、网络协议、RAG 检索逻辑或 AI 生成逻辑。

## 4. 首轮快捷键方案

| 优先级 | 操作 | 键位 | 生效条件 | 执行语义 |
|---|---|---:|---|---|
| P0 | 刷新仓库列表/详情 | `⌘R` | 当前列表或详情发布可执行刷新动作 | 优先刷新 first responder 所在列；否则刷新最后操作列；详情不可刷新时回退当前列表 |
| P0 | 打开知识库 RAG 工作台 | `⇧⌘K` | 主窗口提供有效命令上下文 | 复用 `KnowledgeRAGWorkspaceWindowController.show(...)`，继续经过 `AIWorkspaceEntryGate` |
| P0 | 打开当前仓库 AI 面板 | `⇧⌘A` | 当前右栏详情发布有效、已 Star 的本地仓库 | 展开当前详情页底部 `RepoAIFloatingOverlay`；设置窗口前台时先前置主窗口并使用最后有效详情 |
| 清理 | 关于 Starcat | 移除 `⌘I` | 不适用 | 菜单入口保留，仅取消非必要快捷键 |

### 4.1 键位选择理由

- `⌘R`：符合 macOS 应用中“刷新/重新加载”的习惯；具体刷新中栏还是右栏由当前操作上下文决定。
- `⇧⌘K`：`K` 表示 Knowledge，与 `⌘K` 全局搜索形成同族入口；避免让 `⌘R` 同时承担同步与 RAG 两种语义。
- `⇧⌘A`：`A` 表示 AI，且不会与仅在批量模式生效的 `⌘A` 混淆。
- `⌘I`：通常更接近 Info/Inspector 语义，“关于”属于低频菜单动作，不应长期占用该键位。

### 4.2 当前仓库 AI 的边界

`⇧⌘A` 的对象严格定义为主窗口右栏当前实际渲染、且现有详情门禁允许使用 AI 的本地仓库：

- 不自动选择第一条仓库；
- 不使用 hover 行或未打开的搜索候选；
- 不自动生成或重新生成摘要；
- 只展开详情页底部 AI 面板并加载既有状态；
- 用户在面板内主动点击生成或发送消息时，才进入现有 Pro、模型配置与远程调用流程；
- `RepoAIWindowController` 只由底部面板内的“在独立窗口中打开”触发，作为附属展示形态保留，快捷键和搜索等外部入口不得直接调用。

### 4.3 列表 / 详情刷新判定

1. 主窗口 first responder 所在列发布了刷新动作时，优先执行该动作；
2. Settings 等独立 Scene 前台、拿不到主窗口 FocusedValue 时，使用主窗口记录的最后操作列；
3. 切换根页面或分类后，刷新目标重置为中栏列表；
4. 详情没有可执行刷新动作时回退当前列表；
5. 一次按键只执行一个刷新动作，不并发刷新列表和详情；
6. 加载中的动作禁用，由现有 ViewModel 状态阻止重复请求。

列表动作必须复用各页面现有刷新链：Manage 执行本地投影重载 + 完整 Stars 对比，Trending / Explore / Weekly / Activity / Undo Star 只调用当前分类对应的 reload/refresh。仓库详情统一复用 README `onRetry`；Activity Release 详情刷新当前仓库 Release 时间线。

### 4.4 RAG 工作台的边界

`⇧⌘K` 只新增打开入口，不改变 RAG 工作台行为：

- 不自动创建新会话；
- 不自动发送问题；
- 不绕过 `AIWorkspaceEntryGate.authorizeOpening(...)`；
- 已打开时把同一个 RAG 工作台窗口带到前台，不重复创建。

### 4.5 自定义与禁用语义

全局搜索、常规搜索、刷新当前内容、知识库 RAG 和当前仓库 AI 五项都允许用户改键并逐项恢复默认。设置页同时提供：

- “启用应用快捷键”总开关；
- 每个快捷键录制框后的独立开关；
- 每项独立恢复默认按钮。

总开关和逐项开关只决定 SwiftUI 是否注册 `.keyboardShortcut(...)`：关闭后菜单、toolbar、详情按钮和底层业务动作仍可点击。AI 输入区的 Return / `⌘Return` 发送方式是独立输入偏好，不受快捷键总开关或逐项开关控制。

关闭某项不会清空其键位；所有已保存键位无论启停都参与冲突检查，保证重新开启时不会出现两个命令抢占同一组合。toolbar / 详情 tooltip 在快捷键关闭时明确显示“键盘快捷键已停用”，不继续展示一个实际无效的组合。

## 5. 暂缓项

### 5.1 RAG 新会话 `⌘N`

`KnowledgeRAGWorkspaceViewModel.newConversation()` 当前会立即持久化一条空会话。直接加入 `⌘N` 容易因重复按键产生空白历史，因此不进入首轮。

后续满足以下条件后再实现：

1. 当前会话为空且没有消息时，`⌘N` 复用当前空会话；
2. 只有 RAG 工作台是 key window 时生效；
3. 输入法候选、文本编辑和 sheet 展示期间不拦截；
4. 菜单或可见按钮能够展示该快捷键。

### 5.2 Agent 工作台

Agent toolbar 入口当前受 `DebugFlags.agentToolbarEntry` 控制。首轮不得增加菜单或快捷键，否则会形成绕过现有公开门禁的第二入口。等 Agent 工作台正式公开后，再单独决定键位和设置归属。

### 5.3 AI 用量及其他低频动作

AI 用量已有 toolbar 状态入口和“操作”菜单入口；诊断导出、检查更新、打开 GitHub、取消 Star 和批量 AI 均不分配默认快捷键。高频证据出现前不占用键位。

## 6. 设置页归属

首轮继续放在：

```text
设置 → 通用 → 快捷键
```

理由：

- 五个动作都使用同一种“名称 + 录制框 + 开关 + 恢复默认”紧凑行，不需要再按功能域分组；
- AI 输入发送行为仍与应用命令放在同一 Section，但明确不受总开关控制；
- 当前内容仍可在 General 的 grouped Form 内完整滚动，单独创建一级 Tab 会增加导航而没有新的信息层级。

后续满足下列条件之一时，再把快捷键从“通用”独立出来：

1. 新增更多动作后需要按搜索、工作台、仓库操作等功能域分类；
2. 增加恢复全部、导入导出快捷键方案或系统级快捷键等二级能力；
3. General 的快捷键 Section 在最小窗口尺寸下已经明显妨碍其它通用偏好的扫描。

## 7. 命令路由设计

### 7.1 应用级路由

`StarcatCommandRouter` 由 `StarcatApp` 持有，并同时注入主窗口和 Settings Scene。它只保存短生命周期 UI 闭包和 owner ID，不新增业务状态：

- 打开全局搜索；
- 打开 RAG 工作台；
- 当前详情仓库 AI；
- 当前列表刷新；
- 当前详情刷新；
- 最后操作列。

发布者消失时只能清理自己 owner ID 对应的动作，防止分类切换期间旧页面 `onDisappear` 误删新页面动作。

### 7.2 FocusedValue 与跨 Scene 兜底

主窗口内用 `FocusedValues.starcatRefreshAction` 优先识别真实 first responder；Settings 成为 key window 后 focused value 自然为空，此时菜单回退 `StarcatCommandRouter.currentRefreshAction`。这既保留 macOS 原生焦点语义，又解决 Settings 前台时快捷键全部失效的问题。

约束：

- `HomeView` 只发布全局搜索和 RAG 动作；
- `RepoDetailScaffold` 按真实渲染 repo 发布 AI 动作，不再只读取 Manage `selectedRepo`；
- `ReadmeStateView` 直接发布已有 `onRetry` 作为详情刷新动作；
- RAG 动作闭包调用现有 `KnowledgeRAGWorkspaceWindowController.show(...)`；仓库 AI 动作通过 `repoAIInlineOpenRequested` 展开已挂载的底部面板，不得越级调用附属独立窗口；
- Pro、登录、渠道和 Debug 门禁继续在执行层检查，不能只依赖菜单是否隐藏或禁用。

### 7.3 全局搜索注册收口

`⌘K` 当前由 `HomeView` 隐藏按钮注册，而“操作 → 全局搜索”菜单不显示键位。实施时应：

1. 把可配置的 `⌘K` 注册迁到 `StarcatAppCommands` 对应菜单按钮；
2. 通过 `StarcatCommandRouter.openGlobalSearch` 直接调用主窗口现有 Search Center 展示动作；
3. 删除不再需要的 `.starcatCommandOpenGlobalSearch` 通知桥和 `HomeView` 中重复的隐藏按钮；
4. 主窗口关闭或尚未登记动作时禁用菜单命令；
5. `⌘F` 仍留在 `RepoListView`，因为它只在 Manage 页面生效。

同一个快捷键只能注册一次，避免菜单命令与隐藏按钮同时竞争。

## 8. 快捷键目录与冲突规则

`StarcatShortcutCatalog` 只保存三个新增动作的默认值；五项用户实际配置和开关状态统一由 `AppSettings` 持久化：

```swift
enum StarcatShortcutCatalog {
    static let refreshCurrentContentDefault = KeyboardShortcutConfiguration(/* ⌘R */)
    static let openKnowledgeRAGDefault = KeyboardShortcutConfiguration(/* ⇧⌘K */)
    static let openSelectedRepoAIDefault = KeyboardShortcutConfiguration(/* ⇧⌘A */)

    static let fixedReserved: Set<KeyboardShortcutConfiguration> = [
        // Settings、批量选择等现有固定语义
    ]
}
```

总开关、五项逐项开关和五个键位都写入 `UserDefaults`；缺失值分别回退“启用”和默认组合，不新增数据库 migration。

### 8.1 校验规则

用户录制任意一项应用快捷键时必须拒绝：

- 没有 Command/Option/Control 的普通输入；
- 非单个英文字母或数字；
- `StarcatShortcutCatalog.fixedReserved` 中的固定键位；
- 与另外四个可配置动作相同的键位。

`duplicateConfiguredAction` 明确说明“该快捷键已分配给另一项操作”。关闭的动作仍参与冲突检查，避免重新开启时才暴露竞争。

### 8.2 旧配置升级

升级后首次读取新增配置时：

1. 不崩溃、不静默抢占；
2. 新增三项键位缺失时使用 `⌘R` / `⇧⌘K` / `⇧⌘A`；
3. 新增总开关和五项开关缺失时默认开启；
4. 任一值非法或五项之间重复时，五项一起恢复默认组合；
5. 不新增数据库 migration，仍使用现有 `UserDefaults` JSON / Bool 持久化。

## 9. 菜单与可发现性

“操作”菜单建议按以下顺序整理：

```text
全局搜索                         ⌘K
打开知识库 RAG 工作台           ⇧⌘K
打开当前仓库 AI                 ⇧⌘A
────────────────────────────
刷新仓库列表/详情              ⌘R
AI 用量…
────────────────────────────
检查更新…                       Direct only
导出诊断信息…
```

规则：

- 菜单标题、toolbar tooltip 和 accessibility label 必须走 String Catalog；
- toolbar tooltip 应显示实际键位；总开关或逐项开关关闭时改为提示“键盘快捷键已停用”；
- 设置页五项统一使用录制框、独立开关和 `ResetIconButton`，总开关不连带禁用 AI 发送偏好；
- 键位符号使用字面文本，不作为本地化 key；
- 菜单禁用状态必须与当前命令上下文一致；
- “关于 Starcat”仍保留在 App 菜单，仅移除 `⌘I`。

## 12. 验收标准

### 12.1 自动化验证

- 五项默认键位合法，`⌘A` / `⇧⌘M` 等真正固定组合仍不可覆盖。
- 五项可配置动作不能使用相同组合，关闭状态仍参与冲突检查。
- 五项键位、总开关和逐项开关都可持久化，缺失值回退默认开启。
- 任一持久化重复配置可安全让五项一起回退默认组合。
- AI 发送方式不随应用快捷键总开关或逐项开关改变。
- 无有效详情仓库时，当前仓库 AI 命令上下文为空。
- 详情动作不可用时，`⌘R` 回退当前列表且只执行一次。
- 旧页面注销不能清掉新页面已经登记的动作。
- 不新增数据库 migration，不修改已发布 schema。

### 12.2 人工/UI 验证

- “操作”菜单显示正确快捷键和禁用状态。
- 关闭总开关后五项都不响应键盘，但菜单、toolbar、详情按钮和 AI 发送仍可使用。
- 关闭单项开关后只停用该动作键盘入口，重新开启恢复原键位。
- 修改任一键位后菜单和 tooltip 立即显示新组合；停用时 tooltip 不再展示无效组合。
- `⌘K` 在主窗口任意页面打开全局搜索，且只触发一次。
- `⌘F` 只在 Manage 页面聚焦列表搜索。
- `⌘R` 在中栏只刷新当前分类；Manage 继续执行完整 Stars 对比并重载当前投影。
- 点击或操作右栏后，`⌘R` 只刷新当前详情；详情不可刷新时回退中栏。
- `⇧⌘K` 打开或前置同一个 RAG 工作台，免费/未配置场景仍走现有门禁。
- `⇧⌘A` 只展开当前选中仓库详情页底部 AI 面板，不自动生成摘要。
- 无选中仓库时 `⇧⌘A` 不自动选仓库、不打开错误对象。
- Settings 窗口前台时，`⇧⌘A` 先前置主窗口，再展开最后一个有效详情仓库的底部 AI 面板。
- Settings 中的快捷键分组仍位于“通用”，没有新增空的一级 Tab。

## 13. 风险与回退

| 风险 | 防护 |
|---|---|
| 同一键位注册两次 | 五项完整冲突矩阵；关闭项仍保留占用，重新启用前已保证唯一 |
| 刷新目标不明确 | 主窗口优先 `FocusedValues`，跨 Scene 回退最后操作列；详情不可刷新再回退列表 |
| 页面切换残留旧动作 | 每个发布者带 owner ID，注销时只清理自己的登记 |
| 绕过 Pro/渠道/Debug 门禁 | 菜单只负责路由，执行层继续调用现有 gate |
| 损坏或手工篡改配置产生重复 | AppSettings 加载时把五项一起回退默认值 |
| 总开关误伤 AI 发送 | AI 发送偏好位于总开关上方且执行路径不读取应用快捷键开关 |
| 设置页膨胀 | 五项使用统一紧凑行并继续留在“通用”；出现功能域分类需求后再拆独立 Tab |
| `⌘N` 产生空会话 | 首轮不实现，等空会话复用规则落地后再评估 |

如实施后出现系统级或输入焦点冲突，可单独撤销对应 `.keyboardShortcut(...)`，不会影响 toolbar、菜单动作或底层业务链。
