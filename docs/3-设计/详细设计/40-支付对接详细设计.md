## 1. 设计目标

支付对接设计解决三个问题：

1. App Store 版本继续使用 StoreKit。
2. Direct 版本通过 Starcat License API 接入外部支付 / license provider。
3. 业务功能只依赖统一 `EntitlementGate`，不绑定具体支付平台。

## 3. 客户端协议

### 3.1 EntitlementProvider

```swift
protocol ProEntitlementProviding {
    func refreshEntitlements() async -> ProEntitlement
    func currentEntitlement() -> ProEntitlement
}
```

StoreKit 路径由既有 `SubscriptionManager` 实现，Direct 路径由 `DirectLicenseManager` 实现。`CompositeProEntitlementProvider` 聚合多个来源后供 `EntitlementGate` 消费。

### 3.2 DirectLicenseAPI

```swift
protocol DirectLicenseAPI {
    func activate(licenseKey: String, device: DirectDeviceDescriptor) async throws -> DirectEntitlementSnapshot
    func validate(licenseKey: String, instanceID: String) async throws -> DirectEntitlementSnapshot
    func deactivate(licenseKey: String, instanceID: String) async throws
    func customerPortal() async throws -> URL
}
```

客户端 API 不出现 Creem API key，不直连 provider 私密接口。

### 3.3 DirectLicenseStore

职责：

1. Keychain 保存 license key 和 instance id。
2. 不持久化 Pro 放行状态，避免离线状态长期绕过服务端授权。
3. 测试环境避免启动期 Keychain 调用。

## 4. 后端接口

### 4.1 activate

```http
POST /v1/direct/licenses/activate
```

请求：

```json
{
  "license_key": "XXXX-XXXX",
  "device_id": "hashed-device-id",
  "device_name": "Dong's Mac Studio",
  "app_version": "0.1.1",
  "build": "123",
  "distribution": "direct"
}
```

响应：

```json
{
  "is_pro": true,
  "status": "active",
  "plan": "pro_yearly",
  "expires_at": "2027-07-04T00:00:00Z",
  "license_instance_id": "provider-instance-id",
  "provider": "creem",
  "features": ["pro"]
}
```

### 4.2 validate

```http
POST /v1/direct/licenses/validate
```

用于启动、前台恢复、打开 License 设置页和访问 Pro 功能前的周期校验。

### 4.3 deactivate

```http
POST /v1/direct/licenses/deactivate
```

释放当前设备激活名额，并清理本地 license store。

### 4.4 webhook

```http
POST /v1/webhooks/direct/{provider}
```

处理 provider 事件：

| 事件 | Starcat 行为 |
|------|--------------|
| subscription active / paid | 更新为 Pro |
| subscription canceled / expired | 取消或到期后取消 Pro |
| refund created | 取消 Pro |
| dispute created | 冻结 Pro |
| license disabled | 取消 Pro |

Webhook 先验签，再写授权快照。

## 5. Provider Adapter

### 5.1 DirectPaymentProvider

```text
Checkout
CustomerPortal
```

首期对应 Go 代码中的 `PaymentProvider`。`StaticPaymentProvider` 从环境变量返回 Creem hosted checkout / customer portal URL，后续需要动态 checkout session 时新增 provider adapter，而不是改客户端契约。

### 5.2 DirectLicenseProvider

```text
activate
validate
deactivate
```

### 5.3 CreemProvider

Creem adapter 只存在后端：

```text
StaticPaymentProvider（首期支付 URL）
CreemProvider（license activate / validate / deactivate）
```

客户端只知道：

```text
provider = "creem"
displayName = "官网订阅"
```

## 6. 离线策略

首期不启用离线宽限放行：

| 状态 | 行为 |
|------|------|
| activate / validate 成功 | 当前运行期保持 Pro |
| 启动后无法 validate | 不新增 Pro 放行状态 |
| provider 明确返回 expired / refunded / disabled | 立即取消 Pro |
| 网络失败 | 保留错误状态，提示需要联网验证 |

后续如果增加离线宽限，需要单独设计持久化 snapshot、`lastValidatedAt`、撤销事件同步和上限策略。
