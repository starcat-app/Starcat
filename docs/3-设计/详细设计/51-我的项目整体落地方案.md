# 我的项目整体落地方案

> 状态：实施中
>
> 日期：2026-07-29
>
> 基线：`ec51a496`
>
> 范围：Starcat macOS 客户端；不新增 Starcat 后端服务

## 1. 目标

在“星标”模块下新增固定一级分类“我的项目”，展示当前 GitHub 用户：

1. 个人账号拥有的仓库；
2. 通过组织成员身份可访问的组织仓库；
3. 上述范围内经用户额外授权的 Private / Internal 仓库。

“我的项目”表示 GitHub 项目归属关系，不等价于 Star、知识库或 Smart Collection。同一个 Repo 可以同时属于“已 Star”“我的项目”和“知识库”。

## 2. 产品范围

### 2.1 首版包含

- Sidebar 固定入口、真实计数和独立 Repo scope。
- 个人 / 组织、Public / Private / Internal、具体组织筛选。
- 复用 Repo 列表、搜索、排序、多选、置顶、Tags、状态和知识库操作。
- 复用 Repo 详情、README、仓库洞察和 Star History。
- Public 项目使用现有 GitHub OAuth fallback。
- Private / Internal 使用可选 GitHub App 只读授权。
- 授权完整、部分仓库授权、组织待审批、过期、撤销和失败状态。
- 项目元数据成功同步后写入当天本机 Star snapshot。

### 2.2 首版不做

- 外部个人协作者仓库。
- Traffic、Views、Clones、Referrers。
- 列表逐仓请求 Commit、Issue、PR、Contributor 或 Security API。
- 独立项目详情页或第二套 Repo DTO。
- 把现有 OAuth 扩大为 `repo` scope。
- 把 GitHub App private key 放入客户端。
- Private 项目公共分享、Discovery 历史、External Search、CloudKit 或默认 JSON 导出。

## 3. 信息架构

```text
星标
├─ 全部仓库
├─ 我的项目
├─ 未分类
├─ 知识库
├─ 智能集合
└─ Release 时间线
```

Sidebar 只保留一个“我的项目”入口，组织和可见性放到中栏筛选，避免组织树撑大 Sidebar。

中栏继续复用 `RepoListView`。Repo 行在现有信息上增加：

- `Public / Private / Internal`；
- `个人 / 组织`；
- 当前访问权限；
- 本机 30 天 Star 增长。

详情继续复用 `ManageDetailContent` 和 `RepoDetailScaffold`。未获 GitHub App 权限的数据区块明确显示不可用，不为“详情完整”提前扩大授权。

## 4. 授权架构

### 4.1 双凭据职责

| 凭据 | 职责 |
|---|---|
| 现有 GitHub OAuth token | 登录、Public Stars、Public Star / Unstar、Public 项目 fallback |
| GitHub App user access token | 用户明确安装或组织批准的 Private / Internal 仓库及只读 Contents |

两个 session 独立：

- GitHub App token 失效不能清空现有 OAuth 登录；
- OAuth 登出时清理项目访问 token 和项目关系；
- 使用独立 Keychain account，禁止写日志、数据库或 UserDefaults；
- 请求端按用途选择 token，不允许依赖“当前刚好有哪个 token”。

### 4.2 GitHub App 权限

首版只申请：

- Repository permissions：Metadata read；
- Repository permissions：Contents read；
- Account permissions：无额外权限。

GitHub App 启用 Device Flow。客户端只保存公开 Client ID 和 user access token，不保存 client secret 或 private key。

### 4.3 授权状态

`ProjectAccessSession` 至少表达：

- 未连接；
- 连接中；
- 已连接；
- 部分仓库授权；
- 组织待审批；
- token 过期；
- 授权撤销；
- 失败。

## 5. GitHub API

项目列表使用 `GET /user/repos`，分两条 affiliation 链同步：

```text
affiliation=owner
affiliation=organization_member
visibility=public  // OAuth fallback
visibility=all     // GitHub App token
sort=updated
direction=desc
per_page=100
```

要求：

- 解析 `Link` Header 分页；
- owner 和 organization_member 分别维护 ETag；
- 单页失败时不清理旧数据；
- 所有页面成功后才完成 generation 对账；
- 401、403、Rate Limit、组织待审批和 token 过期不得被误报为空项目；
- selected repositories 只落 GitHub App 实际返回的仓库。

## 6. 数据库设计

追加 `v17-my-projects`，禁止修改任何已发布 migration。

### 6.1 `user_projects`

```sql
CREATE TABLE user_projects (
    user_id             INTEGER NOT NULL,
    repo_id             INTEGER NOT NULL,
    affiliation         TEXT NOT NULL,
    owner_login         TEXT NOT NULL,
    owner_type          TEXT NOT NULL,
    visibility          TEXT NOT NULL,
    permission          TEXT NOT NULL,
    authorization_source TEXT NOT NULL,
    installation_id     INTEGER,
    generation          TEXT NOT NULL,
    last_seen_at        DATETIME NOT NULL,
    created_at          DATETIME NOT NULL,
    updated_at          DATETIME NOT NULL,
    PRIMARY KEY (user_id, repo_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (repo_id) REFERENCES repos(id) ON DELETE CASCADE
);
```

索引覆盖 `user_id + affiliation`、`user_id + owner_login`、`user_id + visibility`、`user_id + permission` 和 `user_id + generation`。

### 6.2 `project_sync_state`

按 `user_id + credential_kind + affiliation` 保存 ETag、最后成功时间、generation、错误分类和 stale 状态。同步状态不保存 token、响应 body 或 Private repo full name。

### 6.3 Repo Upsert

Project upsert 只更新 GitHub 远端元数据，必须保留：

- `is_starred` / `starred_at`；
- Tags、Notes、Status；
- LibraryState；
- Repo pin；
- README、AI 和洞察缓存；
- Star snapshots。

项目关系删除只删除 `user_projects`，不删除 Repo 或用户内容。

## 7. 查询与状态层

新增 `RepoListScope.myProjects(userID:)`，通过 `JOIN user_projects` 查询，禁止附加 `repos.is_starred = 1`。

项目筛选使用独立 `ProjectFilter`：

- affiliation；
- organization login；
- visibility；
- permission；
- authorization source。

项目筛选只能在 `.myProjects` scope 生效；离开 scope 后不能污染 Stars、知识库或 Smart Collection。

Sidebar 计数、分页、搜索、排序、Cmd+A 和 selected repo 恢复均从数据库 scope 获取，不在内存中先加载全部项目再过滤。

## 8. Star History

| 项目类型 | 数据来源 |
|---|---|
| Public | 现有远端历史（可用时）+ Discovery snapshot + 本机 snapshot |
| Private / Internal | 仅本机精确 snapshot |

Private / Internal 必须在构造 Discovery 请求前拦截。项目元数据同步成功后写入当天 snapshot，同 Repo 同日写入幂等。

列表只读取本地历史计算 30 天增长，禁止逐行网络请求。

## 9. Private 数据边界

Private / Internal 默认禁止：

- Discovery 和 Starcat 公共 API；
- External Search；
- 公开分享与 Universal Link；
- CloudKit；
- 默认 JSON 导出；
- 普通日志中的 owner/name、README、错误 body。

README 可使用 GitHub App token 拉取并保存到当前用户本地缓存。AI/RAG 首版只允许用户主动触发，且继续受现有 Provider、Pro 和隐私提示约束。

授权撤销后：

1. 停止远端刷新；
2. 从当前项目关系中移除不可访问仓库；
3. 保留 Star、Tags、Notes、LibraryState；
4. 提供本地 Private 远端缓存清理入口。

## 11. 完成定义

- “我的项目”不依赖 Star 状态。
- 个人 Public / Private 和已获授权组织项目可展示。
- 未安装、待审批、部分授权和失败不会被伪装成空结果。
- 同 Repo 在 Star / Project / Library 间关系正确。
- 列表、搜索、分页、排序、筛选、多选和详情复用现有 Manage 体系。
- Public / Private Star History 来源明确。
- Private 项目不会访问 Starcat 公共服务。
- 失败、断网、撤销和 token 过期安全降级。
- v17 不修改历史 migration，不要求删库。
- 自动化测试、人工验收、专项 checklist、审查报告和结果报告保持一致。
