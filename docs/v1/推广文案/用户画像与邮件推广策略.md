# Starcat 用户画像与邮件推广策略

> 用途: 梳理 Starcat 的核心用户画像、不同用户关注的能力、分人群介绍文案,以及邮件推广的合规边界和可复用邮件模板。
> 官网地址: https://starcat.ink

## 1. 核心判断

Starcat 的用户不只是"会用 GitHub 的开发者"。更准确地说,它面向的是 **长期和开源项目打交道的人**: 他们会收藏 repo、筛项目、做技术选型、写内容、跟踪工具变化,并且希望把这些信息沉淀成自己的知识库。

所以 Starcat 的定位可以分成三层:

1. **GitHub Stars 管理器**: 解决 stars 太多、找不回、没分类的问题。
2. **开源项目研究工作台**: 帮用户阅读 README、写笔记、看 Release、比较相似项目。
3. **AI 辅助的 repo knowledge base**: 让 AI 围绕用户自己的 stars 库做摘要、标签、推荐、搜索和后续 Agent 工作流。

一句话口径:

> Starcat 是一个 macOS 原生的 GitHub Stars 管理和开源项目研究工具,把散落的收藏、README、标签、笔记、Release 和 AI 摘要放回同一个本地优先工作流里。

## 3. 分用户画像的功能关注点

### 3.1 重度 GitHub Stars 开发者

他们最容易被一句话打中:

> 你的 GitHub Stars 不是少了功能,而是太久没被整理。

关注功能:

- Stars 本地同步和缓存。
- 标签、笔记、阅读状态。
- 按语言 / 标签 / Smart Collections 浏览。
- 全文搜索、语义搜索。
- AI 摘要和标签建议。
- 后续的批量未分类整理、相似标签合并、回忆搜索。

介绍文案:

> Starcat 适合 GitHub Stars 已经多到不好管理的开发者。它把你的 stars 同步到本地,让 README、标签、笔记、搜索、AI 摘要和 Release 跟踪都在一个 macOS 原生界面里完成。你不需要再靠模糊记忆翻 GitHub 列表,也不用把"以后再看"继续堆成信息负债。

### 3.2 技术负责人 / 架构师

他们关心的不是收藏,而是判断:

- 这个库是否还维护?
- 是否有更好的替代品?
- License 和生态风险如何?
- 引入成本有多高?

关注功能:

- README 阅读和 AI 摘要。
- 相似仓库推荐。
- Release 订阅与更新状态。
- 健康度 / 维护活跃度 / License 风险。
- 后续技术选型 Agent、短名单对比、替代品发现。

介绍文案:

> Starcat 可以作为开源技术选型前的调研工作台。它把 repo 元数据、README、Release、AI 摘要和相似项目放在同一个上下文里,帮助你更快判断一个库是否值得采用。后续的技术选型 Agent 会进一步面向"选哪个库"这类问题输出带引用的对比报告。

### 3.3 独立开发者 / 产品型开发者

他们关注灵感、竞品、工具链和效率。

关注功能:

- Trending / Weekly / Activity。
- 相似仓库推荐。
- AI 摘要、README 翻译。
- 标签和笔记。
- 后续原创推荐栏目、Show HN Discovery、HelloGitHub 数据源。

介绍文案:

> 对独立开发者来说,Starcat 是一个开源项目雷达。它不只是展示 GitHub Trending,而是把你 star 过的项目、周刊来源、Activity、相似推荐和 AI 摘要放进一个持续可用的研究工作流里。你可以用它找灵感、看竞品、筛工具,也可以把有价值的项目沉淀成自己的素材库。

### 3.4 开源项目爱好者 / Contributor

他们关心活跃度、项目动态和参与机会。

关注功能:

- Release 订阅。
- Activity / GitHub Events。
- README 阅读。
- Tags / Notes / Status。
- 后续 Activity 解读、Release 升级建议、贡献机会分析。

介绍文案:

> Starcat 适合长期关注开源生态的人。你可以用它跟踪自己 star 过的项目,订阅 Release,记录阅读状态和笔记,并用 AI 快速理解一个项目的定位、技术栈和近期变化。它让"关注开源项目"不再只是点 star,而是变成可以持续跟进的工作流。

### 3.5 技术博主 / 自媒体 / UP 主

他们关注内容生产效率:

- 今天介绍什么项目?
- 如何快速判断一个 repo 是否值得写?
- 如何从 README 变成文章提纲?

关注功能:

- Trending / Weekly / Activity。
- AI 摘要。
- README 翻译。
- Notes。
- 相似仓库推荐。
- 后续 Stars 周报、技术选型报告、分享素材。

介绍文案:

> Starcat 可以作为技术内容创作者的选题和资料库。你可以从 Trending、Weekly、Activity 和自己的 GitHub Stars 里筛项目,用 AI 快速理解 README 和适用场景,再把判断沉淀成笔记或内容提纲。对于经常介绍开源项目的博主和 UP 主,它能减少大量"打开网页、读 README、做初筛"的重复工作。

### 3.6 AI 工具链重度用户

这类用户会被 MCP、RepoContextPacker、CodeFlow、AnySearch 打动。

关注功能:

- MCP Service。
- RepoContextPacker。
- CodeFlow。

介绍文案:

### 3.7 学习型开发者

他们关注"看得懂"和"学得下去"。

关注功能:

- README 阅读。

## 5. 关于通过 GitHub 邮箱推广

### 5.1 结论

不建议抓取 GitHub 用户公开邮箱后批量发送 Starcat 推广邮件。

即使 GitHub 用户的邮箱在 profile、commit、README 或公开仓库里出现,这也不等于他们同意接收商业推广邮件。更重要的是,GitHub 的 Acceptable Use Policies 明确禁止把 GitHub 服务中的信息用于 spam,包括通过 scraping、API 或其他方式获得的信息去发送 unsolicited emails。

参考:

- GitHub Acceptable Use Policies: https://docs.github.com/en/site-policy/acceptable-use-policies
- FTC CAN-SPAM Act Compliance Guide: https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business

### 5.2 风险

| 风险 | 说明 |
|---|---|
| GitHub 平台风险 | 抓取邮箱群发容易被视为 spam,可能影响 GitHub 账号和项目声誉。 |
| 品牌风险 | Starcat 面向开发者,开发者对被抓邮箱推广非常敏感,一次负面传播可能伤害产品信任。 |
| 法规风险 | 商业邮件需要遵守 CAN-SPAM、GDPR、当地反垃圾邮件法等规则。 |
| 转化风险 | 冷邮件批量发送看似低成本,但对开发者工具未必高转化,且容易被标记为垃圾邮件。 |

### 5.3 可以做的低风险方式

推荐三种方式:

1. **官网 waitlist / newsletter**
   - 在官网 `https://starcat.ink` 放订阅入口。
   - 用户主动留下邮箱后再发送更新。
   - 这是最干净、长期可复用的增长资产。

2. **手动、少量、强相关 outreach**
   - 只联系与你产品高度相关的人,例如开源周刊作者、技术博主、macOS 工具评测者。
   - 不批量抓取、不自动群发。
   - 邮件必须说明为什么联系对方,并提供明确拒绝后不再联系的方式。

3. **通过公开渠道互动后再邮件**
   - 先在 X、即刻、V2EX、GitHub Discussion、博客评论等公开渠道互动。
   - 对方表现出兴趣后,再通过邮箱发更详细信息。
   - 这种属于 warm outreach,比冷邮件更自然。

### 5.4 邮件必须包含的元素

商业推广邮件至少要做到:

- 发件人真实,不要伪装成 GitHub、开源项目维护者或系统通知。
- 标题不要误导。
- 正文说明为什么联系对方。
- 放官网地址: https://starcat.ink
- 提供退订 / 不再联系方式。
- 如果正式做邮件营销,按 CAN-SPAM 要求补有效实体邮寄地址和退订机制。
- 对欧盟用户要谨慎处理 GDPR 合法基础和反对权。

## 7. 不推荐使用的邮件方式

不要这样做:

- 批量抓取 GitHub profile / commit email。
- 给 star 过某些项目的人群发。
- 给开源项目 maintainer 批量发同一封模板。
- 用 GitHub issue / PR / discussion 当广告位。
- 标题伪装成合作、漏洞、项目反馈,正文再推广 Starcat。
- 没有退订方式或"不再联系"处理机制。

更好的做法是: 先做内容、社区和 opt-in,再用少量高相关的人工 outreach 补充冷启动。
