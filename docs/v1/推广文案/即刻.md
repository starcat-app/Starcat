# 即刻

## 发帖角度

即刻适合连续更新,不要一次写完全部功能。第一条先讲真实动机和截图,后续拆成开发日志。

## 首发动态

最近在做一个 macOS 小工具 Starcat。

它解决的是我自己的老问题: GitHub Stars 快两千个以后,它已经不是收藏夹了,而是一堆"以后再看"。想找一个以前 star 过的 AI agent、Swift SDK、CLI 工具,经常只能靠记忆和 GitHub 搜索。

Starcat 做的事很朴素: 把 stars 同步到本地,用原生 macOS 三栏界面管理;README 直接读;标签、笔记、阅读状态放在 repo 旁边;AI 摘要和对话也只围绕当前 repo 工作。

![管理视图](assets/01-manage-ungrouped.png)

我现在越来越觉得,Starcat 不应该叫"GitHub Stars 管理器",更像"开源项目知识库"。

后续想做三条线:

整理: 帮你把未分类 stars、相似标签、重复收藏理清楚。  
发现: 找相似项目、替代品,甚至做技术选型报告。  
消化: 生成 Stars 周报、Release 升级建议、回忆搜索,让 star 过的东西真的被用起来。

这个方向会慢慢 build in public。也想听听大家: 你们 star 过的项目,后来真的会回去看吗?

## 后续动态 1: AI 不是聊天框

Starcat 里的 AI 我不想做成通用聊天框。

更合理的入口是在 repo 详情页: 你正在看一个项目,AI 帮你总结 README、解释适用场景、建议标签、翻译文档,或者回答"这个项目适合用在什么场景"。

![AI Assistant](assets/04-ai-assistant-window.png)

它的边界也很明确: AI 可以建议,不能自动写入。标签、笔记、Agent 报告都要用户确认。

## 后续动态 2: 推荐服务

最近给 Starcat 加了相似仓库推荐入口。

第一版没有把推荐算法直接塞进客户端,而是做了一个 `recommend-api` 中转。这样客户端只认一个稳定接口,后续可以从 SimRepo 换成自研内容向量/行为混合推荐。

我更关心的是: 推荐应该和用户自己的 stars 库有关。不是"全网最热",而是"你正在看这个 repo,还有哪些更活跃、更新、更适合的同类项目"。
