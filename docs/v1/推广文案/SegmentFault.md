## 标题

做一个 GitHub Stars 本地知识库时,我遇到的几个架构问题

## 正文开头

我最近在做一个 macOS 原生应用 Starcat,用来管理和研究 GitHub Stars。

做这个工具时,我发现 Stars 管理并不是简单的列表问题,而是一个本地数据建模、缓存、搜索、AI 上下文和推荐服务边界的问题。

当用户有几百上千个 stars 时,真正需要解决的是:

- repo 元数据、README、标签、笔记和 AI 结果如何统一建模;
- README 如何缓存和刷新;
- 搜索如何同时覆盖标题、描述、README 和用户笔记;
- AI 摘要如何贴着 repo 上下文,而不是泛泛聊天;
- 相似仓库推荐如何留出后端替换边界。
