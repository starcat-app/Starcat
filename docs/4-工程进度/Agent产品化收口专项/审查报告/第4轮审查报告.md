## 2. 发现的问题

| 编号 | 问题 | 严重程度 | 修复计划 | 修复状态 |
|---|---|---|---|---|
| R4-01 | App 异常退出后，历史 Run 可永久停留在 `planning` / `running`；重新打开后 UI 误以为仍有任务，无法继续、取消或安全重试。 | 高 | Workspace 生命周期首次加载历史时，在单一事务中把遗留执行态收口为 `failed`；保留同一 Run ID 与全部事实，再复用既有安全重试。 | 已修复，`c870dd4` |
| R4-02 | 若把中断恢复混入普通 `reloadHistory`，本进程 Run 结束后的刷新可能误伤当前执行。 | 高 | 新增独立、单次的 `initializeHistory`；普通刷新保持只读。 | 已修复，`c870dd4` |
| R4-03 | `waitingForConfirmation` 属于可恢复协议，不能和遗留执行态一起失败化。 | 高 | SQL 只匹配 `planning` / `running`，并用测试锁定 waiting / completed 不变。 | 已修复，`c870dd4` |
| R4-04 | Mac 仍处于锁屏状态，最终代码的完整 Run Surface 视觉复核无法执行。 | 高（人工门禁） | 解锁后从最新 Direct Debug 构建执行真实 Run、历史回看与 Artifact 导出验收。 | 等待人工环境 |
