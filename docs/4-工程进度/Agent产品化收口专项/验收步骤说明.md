# Agent 产品化收口专项验收步骤说明

> 验收对象：Agent 工作台 P0～P4 产品化收口
> 验收分支：`dev`
> 创建：2026-08-14

## 1. 验收原则

1. 自动化测试只证明其覆盖的代码契约，不代替真实 SwiftUI、系统权限、Provider、GitHub 或分发渠道验收。
2. 失败 Run 重试必须延续同一 Run 的持久化消息与审计链，不能创建无法关联的新历史记录。
3. 写入型 Agent 的重试不得重复执行已经完成的写操作；无法证明安全时必须拒绝重试。
4. App Store 与 Direct 分别验收入口和权限边界，不使用一个渠道的结果代替另一个渠道。
5. 所有验收记录均写入本专项目录，不记录 API Key、Bearer、私有仓库正文或模型隐藏推理。

## 2. 自动化验收

### 2.1 最小相关测试

运行 Agent Session、Repository、Runtime、Workspace、Capability 与 MCP 契约 Suite，确认：

- 失败快照只能按安全条件恢复。
- 原 Run ID、message sequence、usage、预算与 Artifact 计数连续。
- 重试时旧 `error_message` / `finished_at` 被清除。
- 双击重试不会并发执行两次。
- 已完成写工具不重复执行。
- 等待确认恢复仍只执行匹配的 approval/tool call。

### 2.2 全量验证

```bash
rtk xcodegen generate
rtk xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO test
rtk xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO build
```

提交前还必须执行：

```bash
rtk git diff --check
rtk rg "String\\(localized:" --type swift Starcat/
rtk rg "NSLocalizedString" --type swift Starcat/
rtk jq empty Starcat/Resources/Localizable.xcstrings
```

## 3. 失败 Run 重试验收

1. 使用已配置 AI Provider 启动任一只读 Artifact Agent。
2. 在 Provider 请求阶段制造可恢复失败，确认 Run 进入 failed 并保存错误。
3. 从历史列表重新打开该 Run。
4. 点击错误行的“重试”。

预期：

- Header、Timeline、Composer 同时进入 running。
- 历史列表仍是同一 Run，旧消息保留，新消息 sequence 继续增长。
- 重试成功后旧错误消失、finishedAt 更新为本次终态时间。
- 连续点击不会发起多个 Provider 请求。
- 不可恢复附件或未决写操作会给出本地化说明，不会继续执行。

## 4. 写入安全验收

1. 选择多个未打标签仓库运行 Untagged Tidy。
2. 审核 dry-run diff 后明确批准。
3. 在写入完成、后续 Provider 失败的场景打开失败 Run 并重试。

预期：

- 已执行 Tag 写入只保留一份 approval/tool-result 审计。
- 重试从已持久化 tool-result 后继续，不再次执行相同写入。
- 完成后 read-back 与实际仓库标签一致。
- 存在 pending / approved / executing 写审批时拒绝失败重试。

## 5. 统一能力层验收

- Agent 与 MCP 的仓库读取返回同一领域模型与错误语义。
- Tag / Note / Status 写入均经过共享 Capability、权限判断和 Repository。
- Agent Knowledge Tool 只能访问 frozen business context 的 eligible repo。
- 关闭 MCP listener 或移除 MCP API Key 不影响内置 Agent。
- MCP 既有 Tool 名称、参数和响应保持兼容。

## 6. UI、国际化与渠道验收

- Light / Dark 下错误行、重试按钮、历史选中态和 Inspector 可读。
- 中文、英文、长错误消息、长仓库名和 RTL 下布局不溢出。
- 18 个 locale 均包含新增 Agent key，不出现裸 key 或中英文硬编码。
- Pro 用户且 AI Chat 配置有效时可打开 Agent；无权限或无模型时沿用既有门禁提示。
- App Store / Direct 均可看到正式 Agent 入口，但私有仓库、External Search 与写操作继续执行既有授权策略。

## 7. 审查与结果归档

至少完成三轮：

1. 文档、需求、checklist 与实现映射审查。
2. 代码架构、失败路径、重复实现与测试覆盖审查。
3. 工程进度、全量测试、UI/i18n 与 Release Gate 终审。

每轮先保存 `审查报告/第N轮审查报告.md`，再修复报告中的问题并更新修复状态。全部通过后生成 `Agent产品化收口需求完成结果报告.md`。
