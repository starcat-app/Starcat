# Keychain 临时绕过方案（DEBUG 文件 fallback）

> 创建日期：2026-05-30
> 状态：**临时方案，发布前必须移除**
> 影响范围：`Starcat/Core/Keychain/KeychainManager.swift`、`Starcat/Starcat.entitlements`

---

## 1. 背景

### 1.1 问题现象

每次 Xcode `Cmd+R` 启动 Starcat 都要重新走一次 GitHub Device Flow 登录，无法跨启动保持登录态。

### 1.2 根因

macOS App Sandbox + ad-hoc 签名（Xcode dev 期默认）组合下：

- 每次构建二进制的 codesign hash 不同
- 沙盒 keychain item 的 access control 与 codesign 关联
- 上次写入的 token 这次构建后被系统判定为"不同 App 的 item"，读取返回 nil

正确的修复需要：

- **A 项**：Apple ID Team 自动签名（产生稳定的 codesign identity）
- **B 项**：entitlements 声明 `keychain-access-groups`，让 Keychain item 落到稳定 group

但 A 项需要用户配 Apple Developer Team，配置完才能编译通过 B 项。

### 1.3 当前临时方案

DEBUG 编译期启用「Keychain + 沙盒文件双写」fallback：

| 操作 | DEBUG 行为 | RELEASE 行为 |
|---|---|---|
| storeGithubToken | 同时写 Keychain + `dev-github-token.txt` | 仅写 Keychain |
| loadGithubToken | 先读 Keychain，miss 时读文件 | 仅读 Keychain |
| deleteGithubToken | 两边都清 | 仅删 Keychain |

文件位置：`~/Library/Containers/com.starcat.app/Data/Library/Application Support/com.starcat.app/dev-github-token.txt`

---

## 2. 安全风险（必读）

DEBUG 文件存储**仅适用于开发期本人电脑**：

- ⚠️ Token 以**明文**存储在沙盒目录
- ⚠️ 任何能读这台电脑此用户目录的进程都能拿到 token
- ⚠️ 备份到 Time Machine / iCloud Drive 会带出去
- ⚠️ 截屏分享、屏幕录制泄露概率比 Keychain 高得多

仅靠 `#if DEBUG` 编译期切换隔离 RELEASE。**绝不可让此文件 fallback 流入 RELEASE 构建**。

---

## 3. 切换回纯 Keychain 的完整步骤

完成下列**全部 7 步**才算切换完毕。任何一步漏做都会回到"每次重新登录"或留下安全隐患。

### Step 1：Xcode 配置 Apple ID Team

1. Xcode → `Settings... → Accounts`，左下 `+` 添加 Apple ID（如已加跳过）
2. 打开 `Starcat.xcodeproj`，左侧 navigator 选 Starcat 项目
3. 右侧 `Signing & Capabilities` tab
4. `Team` 下拉选你的 Apple ID（Personal Team 也行，无需付费 Developer Program）
5. 勾选 `Automatically manage signing`
6. `Signing Certificate` 会自动变为 `Apple Development`，不再是 `Sign to Run Locally`

> 至此 codesign identity 跨构建稳定。

### Step 2：恢复 `keychain-access-groups` entitlement

编辑 `Starcat/Starcat.entitlements`，在 `</dict>` 之前重新加入：

```xml
<key>keychain-access-groups</key>
<array>
    <string>$(AppIdentifierPrefix)com.starcat.app</string>
</array>
```

### Step 3：移除 KeychainManager 的文件 fallback

打开 `Starcat/Core/Keychain/KeychainManager.swift`，删除所有 `#if DEBUG ... #endif` 块：

- 删除 `devTokenFileURL` 静态属性
- `storeGithubToken` 恢复为单纯 keychain.set + 失败抛错
- `loadGithubToken` 恢复为单纯 keychain.getString
- `deleteGithubToken` 恢复为单纯 keychain.remove + 失败抛错

参考 Week 1 原始实现，diff 在 Git 历史里看 `2026-05-30` 这条 commit 之前的版本即可。

### Step 4：清理沙盒残留 token 文件

```bash
rm -f ~/Library/Containers/com.starcat.app/Data/Library/Application\ Support/com.starcat.app/dev-github-token.txt
```

### Step 5：重启 Keychain 并验证

1. Quit Starcat
2. `xcodebuild -project Starcat.xcodeproj -scheme Starcat clean`
3. Cmd+R 重新启动
4. 走完 Device Flow 登录
5. **完全退出 App（Cmd+Q）**
6. **再 Cmd+R**，应该免登录直接进主界面
7. Console.app 过滤 `com.starcat.app` 应该看到：
   ```
   [keychain] loadGithubToken: keychain hit
   [auth] restore: keychain hit (token length=...) verifying via /user...
   [auth] restore: success login=...
   ```

### Step 6：删除本临时绕过方案的提醒

- 删除本文件（或移到 `docs/工程进度/archived/`）
- 删除 `CLAUDE.md` 顶部的"⚠️ Keychain 临时方案"段落
- 删除 `AGENTS.md` 顶部的"⚠️ Keychain 临时方案"段落
- 在 `docs/1-立项/开发前问题清单.md` 记录决议结束

### Step 7：commit

```bash
git add -A
git commit -m "chore: 切换到 Apple ID 签名 + keychain-access-groups，移除 dev 期文件 fallback"
```

## 4. 临时绕过方案的副作用与已知限制

### 4.1 副作用

- ⚠️ DEBUG 构建生成的 token 文件不会自动清理；切换签名方式时需要手动 `rm`
- ⚠️ 单测中 `KeychainManagerTests` 跑的是测试 host，沙盒目录可能与生产不同，文件 fallback 行为未在测试中覆盖
- ⚠️ 多人协作时，每个开发者的本地都会有自己的 token 文件，没有同步问题，但需要每人各自 Apple ID 配置

### 4.2 不解决的问题

- AI API key（未来 BYOK 功能）仍然走 Keychain。如果 AI key 也需要跨构建持久化，需要类似的双写
  - 当前 AI key 还未引入用户输入，所以暂不需要处理
- Cookie / 其他敏感 secret 也走 Keychain，如有跨构建场景同上
