# 洞察中心前端 Mock 验收步骤

> 状态：前端 Mock UI 已完成并通过首轮真实运行检查；真实 SQLite / GitHub / Discovery Provider 尚未接入
>
> 验收日期：2026-07-27
>
> 验收环境：macOS Debug、简体中文、Dark Mode、主窗口 1440 × 815

## 1. 本轮验收范围

本轮只验收洞察中心和仓库洞察的前端信息架构、布局、交互承载能力与 Mock 数据效果，不把演示数据视为真实 GitHub 或本地数据库结果。

- 洞察顶级入口复用 Starcat 现有三栏应用框架。
- “我的洞察”提供全部收藏 / 知识库范围、KPI、整理情况、技术分布、需要处理和覆盖率。
- Manage 详情提供 `README / 洞察`切换，切到洞察后卸载不可见 README `WKWebView`。
- 仓库洞察提供活动 KPI、Star 趋势、提交活动、贡献者、健康度、社区 / 安全信号和最近动态。
- Star 趋势支持 `3 月 / 1 年 / 全部`，区分“估算 · GH Archive”和“本机精确快照”，并明确标注演示数据。

## 2. 人工验收步骤

### 2.1 我的洞察

1. 启动 Debug App 并保持已登录状态。
2. 点击左侧主导航“洞察”。
3. 检查 Sidebar 的概览、整理情况、技术分布、项目健康。
4. 检查中栏概览、未打标签、未读和健康度待计算。
5. 切换“全部收藏 / 知识库”，确认 KPI 与明细同步替换。
6. 点击刷新按钮，确认只显示 Mock 刷新反馈，不触发全量 Stars 同步。

实际结果：通过。三栏结构、选择状态、KPI、统计区块和 Mock 标记均正常，无横向溢出。

![我的洞察 Mock 运行效果](验收截图/前端-Mock-我的洞察.png)

### 2.2 仓库洞察与 Star 趋势

1. 返回“星标”，选择任意已持久化仓库。
2. 在详情 Metadata 下方切换到“洞察”。
3. 检查活动 KPI 与 Star 趋势顺序：活动 KPI → Star 趋势 → Commit activity。
4. 切换 `3 月 / 1 年 / 全部`，确认只改变 Star 趋势观察范围。
5. 检查当前 Stars、30 天增长、1 年增长、来源、覆盖起点、更新时间和 Mock 说明。
6. 切回 README，确认仓库选择不丢失；再次切到洞察，确认页面可重新建立。

实际结果：通过。README Web 内容在洞察模式下从 Accessibility 树消失，证明不可见 `WKWebView` 未保活；Star 趋势首屏在实际 Detail 宽度下无横向溢出。

![仓库洞察 Star 趋势 Mock 运行效果](验收截图/前端-Mock-仓库洞察-Star趋势.png)

## 3. 自动化与静态验证

```bash
xcodegen generate
xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' -configuration Debug build
xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' \
  -only-testing:StarcatTests/InsightsMockDataTests test
jq empty Starcat/Resources/Localizable.xcstrings
git diff --check
```

结果：

- Debug build 通过。
- `InsightsMockDataTests` 3 项通过，覆盖分布总数、覆盖率边界和 Star 历史顺序 / 末点校准。
- String Catalog JSON 与 diff 检查通过。
- 定向测试编译阶段仍会打印既有 `KnowledgeRAGCoreTests` MainActor warning，本轮未新增该 warning。
