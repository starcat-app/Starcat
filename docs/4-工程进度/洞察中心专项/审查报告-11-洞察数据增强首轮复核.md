## 2. 发现

### R11-F01（P1）：专项设计与工程进度没有记录本轮数据增强

`49-洞察中心详细设计.md`、`checklist.md`、`需求追踪矩阵.md` 和既有 `结果报告.md` 均未记录上述 10 项新增指标，既有结果报告的 HEAD、功能清单和测试证据也已过期。代码、设计与工程进度不一致，不能直接宣告本轮完成。

修复要求：

- 在 49 号设计中补齐每个指标的数据口径、来源、缓存和不可误导边界。
- 在专项 Checklist 增加“洞察数据增强”章节，逐项关联提交与验证。
- 在需求追踪矩阵增加独立追踪项，并更新真实测试边界。
- 既有结果报告保留为上一阶段快照；本轮最终 clean 后新增结果报告，不覆盖历史报告。

### R11-F02（P1）：安全公告缺少真实 DTO、Provider 与缓存闭环测试

当前测试只覆盖 `highOrCriticalCount` 和 `latestPublishedAt` 的纯派生逻辑，没有验证：

- `GET /repos/{owner}/{repo}/security-advisories` 路径与 `per_page=100`。
- GitHub DTO 到领域模型的 severity、URL、时间解析和倒序规则。
- `.securityAdvisories` 独立缓存写读与 24 小时 TTL。
- GitHub 无权限 / 失败时不把结果伪造成“0 条”。

修复要求：在 `RepositoryInsightsRemoteProviderTests` 增加真实响应 fixture 和缓存闭环测试，并在 ViewModel 测试中覆盖缓存保留与失败状态。

### R11-F03（P2）：发布节奏缺少默认本地 Provider 集成断言

当前纯函数测试覆盖近一年数量与平均间隔，但 `DefaultRepositoryLocalInsightsProvider.releaseCadence(repoId:)` 从 GRDB Release 历史读取、过滤 draft / prerelease 既有口径并映射到发布节奏的链路没有直接断言。未来 Repository 查询参数或映射变化时，纯函数测试无法阻止 UI 悄然空白。

修复要求：扩充真实本地 Provider 测试数据和断言，至少覆盖多条 Release、近一年数量、平均间隔与最近发布日期。
