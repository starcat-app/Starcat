## 2. 已实现功能

### 2.1 我的洞察

- 使用 Starcat 现有 Sidebar / Content / Detail 三栏框架和指定的 `gauge.with.dots.needle.bottom.0percent` 图标。
- 最终分类为概览、整理情况、技术分布、项目健康；中栏承载主题分析和待处理集合。
- 支持“全部收藏 / 知识库”两个明确范围。
- 通过单次一致 SQLite Snapshot 计算 KPI、状态、已整理、语言 / topic / license、Health / OpenSSF 覆盖和需要处理项。
- 刷新只重读本地数据库，不触发 Stars 全量同步。
- 所有数字使用结构化 `.neutral` 筛选下钻到 Manage，并有数据库计数回归。

### 2.2 仓库洞察

- 在现有 `RepoDetailScaffold` 内提供 README / 洞察切换，主窗口与独立详情窗口复用 `ManageDetailContent`。
- 洞察模式不保活不可见 README `WKWebView`。
- 完整呈现活动 KPI、Star 趋势、Commit activity、贡献者、Health、OpenSSF、License、社区 / 安全信号和最近活动。
- 活动范围与 Star 范围独立；各区块拥有独立 loading / empty / unavailable / failed / stale 状态。
- 缓存优先、失败保留旧值；快速切 repo / range 时使用 cancellation 与 generation 丢弃旧响应。

### 2.3 仓库星标历史

- Starcat v16 增加仓库洞察缓存和 Star 历史点两张职责单一的表，未修改已发布 migration。
- 元数据成功落库后按日幂等记录本机精确快照。
- 客户端合并 GH Archive 估算、Discovery 精确快照和本机精确快照，支持 3 月 / 1 年 / 全部范围。
- UI 明确展示来源、精度、覆盖起点、更新时间、当前值和增长，不把估算描述为精确历史。
- 私有仓库在构造公共请求前被拦截，只使用本机快照。
- Discovery API 已实现独立缓存、BigQuery REST Provider、归一化、降采样、有界 worker、公开性复核、ETag、稳定错误和持久化 UTC 每日预算。

## 3. 数据、隐私与成本边界

- 我的洞察使用实时 SQLite 聚合，不建立新的 summary 表或后台定时任务。
- 洞察缓存是可重建数据，不进入 CloudKit 或用户 JSON 导入导出。
- 私有仓库的 owner、name 和 repo ID 不发送给 Discovery API。
- GitHub Metrics 使用登录用户现有认证链路；日志和缓存不记录 token。
- Discovery 的 `STAR_HISTORY_ENABLED` 默认保持 `false`。
- M0 未取得真实 BigQuery 凭据、预算与扫描结果，因此当前结论是“代码可验证，数据可行性尚不能 GO”；不能启用生产 GH Archive 估算。
- 每日查询预算保存在 SQLite，以 UTC 日期为主键，通过原子 UPSERT 覆盖并发、服务重建和跨日重置。
