## 1. 原因复核

原实现只读取 Release 订阅流程写入的本地 `releases` 表。未订阅仓库即使 GitHub 已有
Release，也会得到空结果；同时本地映射使用只接受毫秒格式的 formatter，数据库常见的
`2026-07-20T00:00:00Z` 会解析失败，使已有记录也无法参与节奏计算。

## 2. 修复后数据契约

- 本地 Release 历史存在时直接使用，不发送额外 GitHub 请求。
- 本地缺失或读取失败时请求 `GET /repos/{owner}/{repo}/releases?per_page=12`。
- 远端发布节奏使用独立 6 小时 SWR 缓存和 ETag，不写入 Release 订阅表或活动时间线。
- GitHub 确认无 Release 的 `nil` 结果也写入缓存，避免每次进入页面重复请求。
- 无毫秒和带毫秒的 GitHub 时间统一由 `ISO8601DateFormatter.githubDate` 解析。
- 全局刷新保留当前内容；新数据到达后原位替换，不显示中央加载图标。

## 3. UI 与失败语义

发布节奏卡片继续复用现有 `InsightsSectionContainer`、稳定占位和语义色，没有引入新动画
或新视觉体系。无内容状态被明确拆分为：

1. 仓库确认没有已发布的 Release；
2. 未登录 GitHub，无法执行远端回退；
3. Release 历史请求或缓存读取失败。
