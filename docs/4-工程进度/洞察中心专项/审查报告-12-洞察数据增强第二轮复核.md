## 2. 发现

### R12-F01（P1）：洞察初始化仍会显示全页不确定进度环

`ManageDetailContent.insightsBody` 在两个 ViewModel 尚未创建时仍渲染居中的 `ProgressView()`。虽然各仓库洞察面板已经改成透明稳定高度占位，但首次进入洞察仍可能短暂出现用户明确要求移除的加载样式。

修复要求：

- 初始化阶段保持洞察内容区域稳定且不显示进度环。
- 不启动 Starcat；通过测试目标编译和静态扫描验证。
- 不改回 skeleton 或另一套新加载动画。

### R12-F02（P1）：刷新保旧值测试仍只覆盖 5 个远端区块

生产 `load(repo:)` 与 `refreshAll(repo:)` 已包含 activity、commit、contributors、community、security advisories、recent activity 共 6 个远端任务。但“所有远端区块”和“全局刷新”测试仍使用 `expectedCount: 5`，没有让 Security Advisory 刷新进入 gate，也没有断言刷新期间与刷新后的安全公告 state。

修复要求：

- 全局刷新测试加入旧 / 新 Security Advisory 数据、缓存 handler、刷新 handler 和 state 断言，gate 更新为 6。
- 分区手动刷新测试保留 5 个有独立按钮的区块，并明确测试名称不包含只跟随全局刷新的安全公告。

### R12-F03（P2）：发布“平均间隔”没有说明使用最近 12 次 Release

`DefaultRepositoryLocalInsightsProvider` 为控制本地读取量只取最近 12 条 Release。`releasesLastYear` 明确按近一年计数，但 `averageIntervalDays` 对最近 12 条有效发布日期计算。当前 UI 只写“平均间隔”，容易被理解为全历史或近一年平均。

修复要求：

- 将指标文案改为“近 12 次平均间隔”及对应英文 / 繁体。
- 49 号设计明确两个指标的范围不同，避免代码和产品语义漂移。

## 3. 其余检查
