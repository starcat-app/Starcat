# 落地方案

## 输入与上游契约

固定 [NVIDIA SkillEvaluator v1.0.1](https://github.com/NVIDIA/SkillEvaluator/tree/v1.0.1)（`914c15cb`），Apache-2.0；使用本机外部 CLI，不嵌入 Python，不修改 Skill。先检查可执行文件与确切版本。自动查找失败时可手动选择；工具、扫描器和模型的就绪状态分别处理。

| 入口 | 命令范围 | 数据边界 |
|---|---|---|
| 快速检查 | `tier1 --checks schema,quality --no-llm` 和 `harness-check --json` | 当前 Skill 原始快照，无模型。单独读取上游 JSON 中的六种 Agent profile，仅呈现能由内容判断的规则。 |
| 静态安全 | `tier1 --checks security --no-llm` | 单独发起；提示首次可能下载扫描器。扫描器缺失、部分扫描或执行超时记录未完成。 |
| AI 质量评审 | `rubric-eval` | 显式选择 chat 模型；可能付费；仅所选 Skill 的评审输入。 |
| Skill 内去重 | `context-optimization-check` | 显式选择 embedding 与 chat 模型；核对重复段与证据。 |
| 所选 Skill 间重叠 | `similarity-check --type skill` | 至少两个明确选择的条目；仅本次比较集合，默认比较描述，不隐式扩大为全库。 |

全部命令用参数数组启动，指定 JSON 与独立输出目录。子进程在独立工作目录读取临时副本，持久报告只保留已识别的证据。非零退出码可以伴随有效的发现报告。缺失报告或缺少覆盖证据时，检查标为未完成。固定版本通过无害中英文 fixture 核实，界面说明静态质量规则以英文为主。

## 共享数据与界面

- 仓库目标绑定账号、仓库、提交和目录；下载完整可验证的 blob 快照。库目标从本机已发现的 UUID 解析；拒绝无法证明归属的链接和文件。保留清单原始内容、相对布局和 Skill 名称。文件数与体积采用现有预算，不做静默截断。
- 快照内容、模式、工具/规则版本、模型、选择集合参与报告身份。可重建报告放专用缓存，不改正式版数据库。读上次结果与重跑分开；只在用户要求时传给模型。账号切换隔离仓库结果；取消后不发布迟到结果。
- 两处复用原生评估面板：静态检查默认，AI 模式显示模型及范围；保留已读报告，首次加载使用骨架，适配 Reduce Motion 和键盘。管理窗口沿用多选模型，逐项报告、批量状态及筛选可回读。覆盖未运行、未完成、有发现、通过和已过期。
- [报告契约](https://github.com/NVIDIA/SkillEvaluator/blob/v1.0.1/docs/reports.mdx)中展示状态、分数、Agent、定位与建议；不将原始 Markdown、HTML 或终端文本当作可执行内容。

## CLI / MCP 暴露评估

| 动作 | 公共契约 | 约束 |
|---|---|---|
| 获取报告、查看任务状态、导出 JSON | `read` | 仅已知库 UUID 或账号范围内仓库与固定提交；调用方自行保存 JSON，不接受本机任意路径。 |
| 开始、批量、取消 | `write` | 使用 App 公共任务与相同执行服务；检查渠道、账号与数据范围。AI 必须带模型选择并显式同意数据范围。 |
| 选择本机二进制、文件保存面板 | GUI | 不开放外部指定可执行文件、环境、参数或本机输出路径。 |

使用通用 `starcat tools …` 与 MCP 目录，无需新 CLI 专用子命令。具体工具名、验证结果与差异记录在任务清单；人工验收前不关闭专题或写主总览。
