## 1. 背景与目标

dong4j 希望尽可能把 Starcat 已有业务能力开放给命令行用户、脚本、只会执行 Shell 的 AI 和 MCP 客户端，并要求后续新增功能时由 AI 主动评估暴露范围，避免逐项提醒。

本专项包含两条主线：

1. 存量补齐：盘点现有业务动作，补齐 CLI/MCP 入口与契约，再按功能域扩大覆盖。
2. 增量约束：把暴露评估纳入方案、实施、测试和交付流程，形成长期规则与可检查的覆盖清单。

2026-11-15 补充子任务：[浏览器免输 Key 配对与自动发现](浏览器免输Key配对与自动发现子方案.md)。浏览器主动请求、两端六位码核对、独立设备凭据、撤销、手工 Key 与有限发现已实施；Chrome 可选 CLI 宿主已接入，Safari 保留明确的 HTTP 通道例外。

目标是让所有批准开放的业务能力同时具备普通命令行和 MCP 调用路径。评估单位是可独立执行的业务动作，例如“查询索引状态”和“启动索引重建”，不能用一个“索引功能”条目掩盖动作差异。

最初授权为方案落档，随后 dong4j 明确要求使用 worktree 完整实施。当前工作区为 `../Starcat-cli-browser-access`，五仓均使用 `codex/cli-browser-access`。下文盘点表保留实施前历史基线；最终行为、自动化与限制以[能力覆盖清单](能力覆盖清单.md)和[验证与交付记录](验证与交付记录.md)为准。实现不代表人工验收或发布。

App 当前注册 **24 个 MCP 工具**，普通 CLI 命令映射覆盖其中 **18 个**。`starcat mcp` 对协议请求进行转发，不通过普通子命令执行，因此其工具调用路径不受这 18 个映射限制。

| 已有 MCP 工具 | 普通 CLI 当前覆盖情况 |
| --- | --- |
| `starcat.get_repo` | 无独立映射；`repo context` 可间接读取仓库信息 |

| `starcat.list_repos_by_tag` | 无独立命令映射 |
| `starcat.star_repo` | 无独立命令映射 |
| `starcat.unstar_repo` | 无独立命令映射 |
| `starcat.batch_organize_repos` | 无独立命令映射 |

“18 / 24”表示普通命令映射覆盖，不是整个 App 的业务覆盖率。App 已有 MCP resources 列表和读取接口，资源覆盖需要另行盘点，不能混入工具数量。

## 3. 目标架构与边界

```text
用户 / 脚本 / Shell AI ── 普通命令 ──┐
                                   ├── Starcat CLI
MCP 客户端 ──────────── stdio MCP ──┘
                                          │
                             能力发现 / 调用 / 连接管理
                                          │
                               现有 MCP HTTP 协议
                                          │
                                    Starcat App
                                          │
                          公共能力目录 → 权限校验 → 领域服务
```

| 层级 | 职责 |
| --- | --- |
| 外部调用方 | 发现能力、准备参数、发起调用、消费结果 |
| CLI | 普通命令与 MCP 入口、配对和连接、能力发现、参数处理、结果和错误输出 |
| App 公共能力层 | 能力定义、可见范围、权限、副作用、执行、任务状态和审计 |
| App 领域服务 | 数据读写、同步、搜索、AI、索引及实际业务逻辑 |

普通 CLI 与 MCP 共用能力目录、调用规则和 App 执行逻辑。MCP 请求进入 CLI 后直接使用内部模块，不再启动 CLI 子进程。现有 stdio 桥接可以继续承载协议；是否需要调整工具调用适配器，以契约一致性为依据，不为统一命名重写完整协议服务。

继续复用现有配对、设备凭据、TLS 与 MCP HTTP 链路，保留初始化、资源读取和错误响应等协议行为。CLI 是官方集成入口；最终鉴权仍由 App 执行，不能把进程名称当作可信凭据。

### 3.1 首批外部调用方

- 终端用户、脚本、Shell AI、MCP 客户端，以及已经调用 CLI 的启动器。
- Chrome / Safari 浏览器伴侣已纳入独立配对子任务：建议 B1 在现有 Companion 通道实现免输 Key 与本机有限发现，B2 验证原生桥接接入 CLI。配对体验改进不等于通道迁移完成；浏览器与渠道的适配范围单独确认。
- App 内置 Agent 继续调用进程内领域能力。受限 External Runtime 保留各自 allowlist、仓库范围和审批策略，公共目录增加能力不自动向它们开放。
- CLI 不直接读取 SQLite、CloudKit 或 App 的凭据文件，不复制业务实现。
- 本专项不建设脱离 App 的独立执行服务，也不恢复已取消功能或状态面板接入范围。

## 4. 公共能力目录

App 作为公共能力定义的维护端，每个批准开放的业务动作登记一次。优先扩展现有 Registry 和共享能力定义，保留已公开的 `starcat.*` 名称，按模块逐步整理。

| 定义内容 | 用途 |
| --- | --- |
| 稳定名称、功能域、说明 | 确定业务身份，支持发现与分组 |
| 输入 / 输出 Schema | 说明参数、结果、必填项及限制 |
| 权限与可用条件 | 表达渠道、Pro、登录、隐私、配置和数据范围要求 |
| 副作用 | 区分本地读取、联网、本地修改、远端修改和 AI 消耗 |
| 执行方式 | 即时返回或长任务；是否支持预览、取消及恢复 |
| 契约版本 | 表达所需协议能力及兼容条件 |

“App 支持该能力”和“当前调用方可以执行”分别表达。查询目录时应能说明权限关闭、渠道不支持、缺少配置等原因；执行时仍重新校验，不信任此前的可用状态。

输入 / 输出 Schema 与附加元数据如何通过现有协议发布，须在阶段 1 固定。不得把拟议字段冒充当前 `get_capabilities` 返回值，也不得仅凭工具的只读提示决定授权。

只登记已批准的公共能力，不能扫描所有内部 Service 后自动开放。Agent 的完成控制、内部阶段推进和维护者专用权限仍按原边界处理。

## 5. CLI 入口设计

### 5.1 通用入口

以下为拟新增形式，当前不能视作已交付命令：

```bash
starcat tools list --json
starcat tools describe starcat.get_repo_context --json
starcat tools call starcat.get_repo_context --input request.json
starcat tools call starcat.get_repo_context --input -
starcat resources list --json
starcat resources read <uri>
starcat stats --json
```

`--input -` 表示从 stdin 读取工具参数。已批准公开且符合当前契约的工具应能通过通用入口调用，不以是否存在专用子命令作为接入前提。

通用入口须根据已验证的能力元数据处理预览和执行。写工具参数中的 `dry_run=false` 不能绕过 CLI 的显式执行要求；不具备可靠副作用定义的调用不得按只读处理。

### 5.2 专用命令

高频业务继续提供 `repo`、`tags`、`stats` 等易用入口；后续按清单评估 `knowledge`、`insights`、发现与任务等命令组。

专用命令只处理参数、调用和展示，与通用入口使用相同业务契约。无需为每个工具强制增加别名，但常用入口的参数映射、help 和错误行为必须有对应验证。

符合现有契约的新工具可通过通用 CLI 和 MCP 使用；依赖新协议特性的能力仍需匹配的 CLI 版本，不能承诺任意旧 CLI 自动支持全部未来功能。

## 6. 数据、错误和版本契约

- 业务结果提供 JSON；保留现有命令的默认输出，为文本业务命令增加结构化选项。
- stdout 只输出约定结果；stderr 输出诊断。`starcat mcp` 的 stdout 继续保持纯协议流。
- 失败提供稳定错误码和非零退出码；明确部分成功、warning、分页及截断语义。
- 缓存读取、联网刷新与 AI 生成分别描述，不能把读取缓存隐式升级成付费生成。
- 大文本支持 stdin/file 输入。导入文件属于 CLI 所在设备；导出数据由 CLI 写到调用设备，不能混淆远端 Mac 与本地文件路径。
- 对敏感内容的返回遵循用户授权；日志与诊断不记录凭据、私有笔记和业务正文。
- 兼容增加工具或字段时增量演进；破坏性变化明确协议版本、客户端要求和升级行为，不保留无期限双轨。
- 保持已有 [global-search 契约](../../../supports/starcat-cli/contracts/global-search/README.md) 的稳定入口；变更时同步 Schema、fixtures、测试和启动器消费方。

App、CLI 和 Skill 分别版本化，组合验证以实际服务返回的版本与能力为依据。未来进入发布阶段时，先确认 App 已具备相关能力，再交付依赖它的命令与文档。

## 7. 写入、生成与权限语义

| 操作类型 | 目标行为 |
| --- | --- |
| 本地读取 | read 默认开放，包含笔记；遵循业务数据归属与账号范围 |
| 联网读取 | 明确来源、缓存状态和刷新行为 |
| 本地 / 远端修改 | 统一 write；有 dry_run 的操作默认预览，执行后返回原 App 结果 |
| AI 生成 | 需要明确发起，说明模型消耗和外部上下文使用 |
| 批量操作 | 预检目标，返回逐项结果；如实声明是否支持原子性及部分成功 |
| 替换、删除、安装、发布 | 统一 write；复用原 App 校验、事务和流程，不新增公共细分授权 |

写权限默认关闭，只在 App 设置页开启。CLI/MCP 保留显式 `dry_run` 参数；`--apply` 是 `dry_run=false` 的便利写法。没有预览参数的操作直接遵循 App 契约。App 执行最终授权；标签建议仍由显式应用操作保存。

当前 MCP 写工具默认 `dry_run=false`。本方案建议统一为省略时预览、显式执行时才修改；这属于已公开行为的变化，须在阶段 1 固定迁移与版本方案，并验证旧调用方行为。文档落档不改变现有默认值。

预览必须真实不执行变更。某项操作不支持预览时应明确声明并要求显式启动，不能先生成、联网发布或修改数据再把结果称作 dry-run。生成、批量和远端写入的具体参数在接入对应模块时评审。

沿用已有渠道、Pro、账号、私仓、隐私和审计边界；外部入口不自行为功能增加或取消付费限制。维护者专用的精选发布能力即使进入评估，也必须保留原身份校验。

## 8. 长任务

同步、索引、完整 Agent 运行等长任务采用“发起 → 返回任务 ID → 查询状态 → 获取结果 → 按能力取消”的接口形式。拟提供 `tasks list / status / result / cancel`，不直接等同于 MCP 协议中的某一版本任务扩展。

约束：

1. App 的真实业务执行器持有任务；CLI 负责等待或查询，不成为业务状态真源。
2. 只提供已实现的取消、暂停和恢复。没有真实进度时返回阶段，不伪造百分比。
3. 对每类任务明确 CLI 断开、App 退出、账号切换后的行为，以及结果保留与查询范围。
4. 请求超时不等于任务失败，不自动重放可能已接受的写入或启动请求。
5. 优先复用任务句柄与状态；若原任务由页面持有，先评估生命周期改造，不承诺离开页面后自然继续。
6. 不为本专项默认新增通用持久化调度器、无限任务历史或 App 重启恢复。

既有[状态面板后台任务接入方案](../../2-产品/需求讨论/状态面板后台任务接入方案.md)只作为真实状态和操作边界参考。2026-11-13 取消的 CodeFlow / CodebaseMemory、Agent 等状态面板接入仍保持取消；CLI 暴露评估不重新安排其 UI 接入。

## 9. 功能域与覆盖清单

以下是评估范围，不代表每项功能已实现或每个动作都决定开放。盘点以现有代码和已确认产品范围为准，规划中的功能登记依赖，不因本专项扩展为新的 App 功能。

| 功能域 | 待逐项评估的业务动作 | 关键边界 |
| --- | --- | --- |
| 仓库与整理 | 查询、筛选、分页、标签、笔记、状态、Star/Unstar、批量整理 | 保留用户数据、私仓及写权限 |
| 保存搜索 | 现有数据和执行能力 | 不恢复已取消的新增 UI 与同步计划 |
| 知识库与 RAG | 归属、证据检索、引用、来源、索引状态、问答 | 检索与生成分开，控制仓库范围和私有笔记 |
| 仓库分析 | 健康度、安全评分、Star 历史、洞察、上下文导出 | 区分缓存与刷新；尊重来源精度 |
| 发现与推荐 | Trending、Weekly、Awesome、AI 大事、相似推荐、历史和反馈 | 保留来源、分页和反馈语义 |
| 动态与协作 | Release、订阅、通知、Issue/PR 查询和操作 | 读取、已读及远端提交分别评估 |
| AI | 摘要、标签建议、笔记生成、翻译、用量和结果 | 生成消耗、隐私与用户确认 |
| 同步与数据管理 | 同步、导入导出、备份恢复、缓存和索引 | 长任务、文件归属和破坏性影响 |
| Agent 与代码分析 | 发起任务、查询结果、代码图谱与分析 | Runtime、渠道、工具范围及任务生命周期 |
| Skill 与本地工具 | Skill 查询、导入、更新、安装分配、模型及 Runtime 状态 | 受管目录、安装影响、凭据和渠道 |
| 设置与诊断 | 非敏感配置、服务状态、脱敏诊断、能力和权限状态 | 不输出密钥，不以诊断触发业务刷新 |
| 分享与产物 | 内容准备、导出、分享链接和公开发布 | 准备与发布分开，保留维护者限制 |
| 纯展示与系统交互 | 布局、动画、登录、配对和系统授权 | 无独立业务价值可不适用；保留必要用户操作 |

每个动作的评估结论只能是“本次开放 / 已有覆盖 / 暂缓开放 / 不适用”，并独立记录“未实施 / 已实现待验证 / 已验证 / 已验收”等交付状态。“待评估”是盘点期间的临时状态，不能作为阶段 1 完成结论。

完整能力覆盖清单在阶段 1 按以下字段建立：

`业务动作 → App 执行入口 → 公共工具 / 资源 → CLI 路径 → 权限与副作用 → 评估结论 → 验证状态 → 暂缓原因与条件`

衡量指标：

- 评估覆盖率：已完成评估的现有业务动作 / 本次盘点识别的现有业务动作。
- 双入口覆盖率：普通 CLI 与 MCP 均具备调用路径的已批准能力 / 已批准公共能力。
- 验证覆盖率：已具备约定测试与验收证据的能力 / 本批交付能力。

当前登记 127 个公共工具，目录、分派和文档集合由静态检查核对。原 32 个暂缓项已重新评估，多数已接入；Provider 全部管理、CodeFlow 浏览器实际分析、启动期恢复和全部设置的剩余范围单列。工具数不作为整个 App 的覆盖率，也不代表全部操作已真实执行验收。

## 10. 分阶段实施

| 阶段 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 盘点与规则 | 完整覆盖清单、契约、规则及跨仓库职责 | 各动作有结论；目录、写入和版本策略已确认 |
| 2. CLI 基础补齐 | 通用调用、资源入口、JSON、现有工具覆盖和 Skill 更新 | 24 个基线工具及公开资源均有双入口调用路径，权限约束有效 |
| 3. 高价值读取 | 知识检索、洞察、发现推荐、动态订阅等 | 按批次完成范围、隐私、分页及双入口结果验证 |
| 4. 长任务与写入 | 同步、索引、批量整理、AI、导入导出 | 预览、执行、任务状态、结果和取消符合真实业务 |
| 5. 剩余模块收口 | Agent、Skill、模型、分享等模块及暂缓项复核 | 所有动作已开放或保留有依据的暂缓 / 不适用结论 |

本轮按阶段 1–5 执行，复用 [KnowledgeSearchCapabilityExecutor](../../../Starcat/Features/RAG/Core/KnowledgeSearchCapability.swift) 接入范围限定、笔记来源过滤与证据读取，并记录无法无人值守或缺少执行契约的暂缓动作。

任务拆分和验收细目见[实施 Checklist](CLI与MCP能力开放Checklist.md)。人工浏览器、签名分发、外部任务关联及总览回写保留独立状态，不由源码完成推断。

### 10.1 浏览器配对子任务

浏览器配对作为本专项独立子任务，实施排期不强制等待主线阶段 5。建议先完成免输 Key、六位码确认、独立设备 token、单设备撤销和有限本机发现，再验证 Native Messaging / Safari 原生宿主与 CLI 接入。

该子任务复用认证机制，不自动向浏览器分发全局 Key，也不因复用 MCP 组件增加浏览器权益门槛。首批保持 loopback 范围；任意端口自动定位、原生宿主分发与局域网发现按[子方案](浏览器免输Key配对与自动发现子方案.md)记录边界及待验证项。

## 11. 后续功能自动评估规则草案

本节是拟议永久规则的唯一草案来源。待启用获批后，在 `docs/5-规范/CLI与MCP能力暴露规范.md` 维护正式正文，主仓库和 CLI / Skill 仓库的 `AGENTS.md` 只放职责及入口引用，避免并行维护多份规则。

> 新增或调整业务功能时，AI 必须在方案阶段主动评估 CLI 与 MCP 暴露范围，无需 dong4j 单独提醒。

1. 可脱离界面执行、输入输出明确且可校验权限的业务动作，默认建议开放；不自动把内部实现注册为公共接口。
2. 方案必须给出“本次开放 / 已有覆盖 / 暂缓 / 不适用”结论，并说明入口或原因；纯 UI 改动可以简述不涉及业务能力变化。
3. 暴露范围与整体方案一次确认；获批后同步实施，不在功能完成后再等待提醒。
4. 方案说明输入输出、范围、权限、联网与 AI 消耗、执行确认、长任务及验证方式。
5. 优先复用 App 领域服务。CLI 不直读数据库、不复制业务逻辑；各入口继续执行既有门禁。
6. 同批更新能力清单、契约、必要 CLI help、Skill 和测试。暂缓项必须写明原因及后续接入条件。
7. 交付说明必须报告暴露结论和验证证据，不能把未评估默认为不需要开放。

规则已接入[正式规范](../../5-规范/CLI与MCP能力暴露规范.md)、三仓 AGENTS 与任务录入规范；`scripts/check-public-capabilities.py` 检查已登记项一致性。尚未登记的新业务是否遗漏，仍由方案审查和代码评审判断，不能声称脚本已能自动识别全部新功能。

## 13. 验证与交付

| 层次 | 必须验证的内容 |
| --- | --- |
| App | 业务结果、隐私范围、渠道和权益、权限拒绝、预览无副作用、写入结果与任务生命周期 |
| CLI | 参数、stdin/file、JSON、错误与退出码、通用和专用入口一致性 |
| MCP | 工具 / 资源发现、Schema、协议输出、初始化与现有资源行为不回退 |
| 组合 | 同参数的两种入口语义一致；App/CLI 版本不匹配时有明确结果 |
| Skill | 指令、工具和命令真实存在，工作流符合授权与回读要求 |

实施时采用项目现有入口：

- App：相关 `make test TEST_ARGS="..."`，非 UI 逻辑改动后运行 `make build-appstore` 与 `make build-direct`；新增或删除 Swift 文件按既定工程生成流程处理。
- CLI：现有 Go 测试、race、vet 及适用的五个平台组合检查；不以本机构建替代跨平台验证。
- Skill：使用当前构建 CLI 执行契约校验，隔离用户配置和配对数据。
- 真实写入、AI 消耗、远端副作用及 GUI 验收按明确授权范围执行；测试使用隔离数据，不调用用户真实写入冒充单测。

当前文档落档只做链接、事实对应和 diff 检查，不运行 App / CLI 构建，不改测试状态。没有证据的实施与验收条目保持未勾选。

正式关闭专项前，应具备覆盖清单、公共契约、双入口实现、Skill 文档、验证结果和剩余限制。结果报告、总览回写、GitHub / Multica 状态、发布分别完成；写入 `docs/功能实现总览.md` 仍需单独授权，不能因本专项落档或代码完成自动更新。
