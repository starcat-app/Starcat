## 1. 审查结论与本轮结果

现在遵循“外部调用方 → CLI 连接与能力层 → App 业务操作”。普通 CLI 和 `starcat mcp` 共用连接、配对凭据、HTTP 传输和 App 工具目录；MCP 不再拥有另一套业务权限。CLI 不直接操作 App 的 SQLite、CloudKit、模型目录或用户业务数据。

原实现多数已调用 App，但部分公共接口只接到了底层方法，漏了按钮对应的准备、生命周期或状态更新；CLI 也曾额外覆盖预览参数、依赖细分能力开关。此次整改针对这些实际差异复用完整 App 流程，同时重新审查原来的 32 个暂缓项。已有下载、事务、取消和校验逻辑不再作为暂缓理由。

当前登记 **127 个工具**：Registry 基础条目 25 个，公共目录动态条目 102 个。相对最初 24 个工具增加 103 个；相对上一轮 69 个工具增加 58 个。它们均可通过动态 CLI 工具入口和 MCP 调用；高频命令只是快捷入口，不要求为每个操作再新增命令。

完整工具、资源与原 32 项的复审结论见[能力覆盖清单](能力覆盖清单.md)。127 是已登记工具总数，不是 App 所有按钮或偏好的覆盖分母；没有宣称 App 全功能已 100% 开放。

## 3. 权限行为

公共权限只有 `read` 和 `write`。

- 配对后默认可读，包括用户笔记；关闭写权限仍可查询目录、资源、状态和结果。
- 写权限默认关闭，只能在 App 的“设置 → MCP”页开启唯一的写入开关。
- 本地修改、远端修改、刷新、生成、安装、删除、任务启动和取消共用写权限。
- 移除私有笔记、GitHub Star、批量和破坏性等细分授权与旧设置键。
- 旧“允许本地写入”一次迁移到统一开关；仅开启过旧 Star 等细分权限不会自动升级为允许全部写入。
- App Registry 在校验写工具参数之前检查写权限，执行适配器再次使用同一授权；关闭时统一返回 `WRITE_DISABLED`。
- 公共设置工具不能自行开启写权限。账号、Pro、渠道、模型配置、GitHub scope 和系统授权继续使用原 App 的运行条件。

能力目录为 `contract_version: 3`，App MCP server 为 `0.7.0`。`write_default: "app_contract"` 与每工具 `preview_supported` 如实描述执行方式：
含 `dry_run` 的工具由 App 默认预览；显式 `dry_run:false` 或 CLI `--apply` 执行。显式 `dry_run:true` 与 `--apply` 冲突时提示参数错误；没有预览能力的工具遵循原 App 调用语义。

永久规则已接入主仓、CLI、Skill 的协作入口和任务流程：以后新增或修改业务动作，AI 必须主动评估 CLI/MCP 暴露，能复用 App 操作的默认接入公共目录。规则见[CLI 与 MCP 能力暴露规范](../../5-规范/CLI与MCP能力暴露规范.md)。
