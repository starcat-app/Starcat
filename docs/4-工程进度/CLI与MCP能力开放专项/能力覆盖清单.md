## 口径与入口

CAP 每行对应一个公共工具；REVIEW 记录旧暂缓项的现状，不与 CAP 重复累计。规划项、纯展示动作和资源单列。交付证据与接入结论分开。

下表工具统一支持 **MCP `tools/call`** 和 **`starcat tools call <完整工具名> --input FILE|-`**；参数及当前状态以 `tools list / describe` 和 `starcat://capabilities` 为准。契约 v3 只有 read/write：默认可读（包含笔记），写操作由设置页唯一开关开启。带 `dry_run` 的操作在 App 默认预览；CLI 保留显式参数，`--apply` 是设置 `dry_run=false` 的便利写法。没有预览参数的工具直接遵循 App 契约，不额外要求 `--apply`。账号、Pro、渠道和系统条件继续由 App 执行，不构成公共细分权限。

执行器缩写：

- **Facade**：`Starcat/Features/MCP/StarcatMCPFacade.swift`，复用 RepositoryRead、SemanticSearch、统计与缓存。
- **Write**：`Starcat/Features/MCP/StarcatMCPWriteFacade.swift`，复用 Metadata、Tag、StarMutation 领域能力及审计。
- **Public**：`Starcat/Features/MCP/StarcatMCPPublicFacade.swift`，装配已有 App 服务；目录在同目录 `StarcatMCPPublicCatalog.swift`。
- **Tasks**：`Starcat/Features/MCP/StarcatMCPTaskStore.swift`，进程内句柄、取消、切号等待和结果过期。
- **Ops**：`StarcatMCPAppOperations.swift`，转交原 App 刷新、标签、合集、通知及 Release 操作。
- **RAG**：`StarcatMCPRAGOperations.swift`，复用 RAG 工作台的问答、删除和持久化生命周期。
- **Local**：`StarcatMCPLocalOperations.swift`，适配原模型、Skill、Provider、设置、缓存及诊断服务。
- **Agent**：`StarcatMCPAgentOperations.swift`，复用 Agent 工作台及共享 RuntimeFactory。
- **Code**：`StarcatMCPCodeGraphOperations.swift`，调用原代码分析流程的可等待入口。

证据缩写：

- **R**：`StarcatMCPRuntimeTests` 的协议、Schema、基线工具、资源、错误及 allowlist 回归。
- **W**：`StarcatMCPWriteFacadeTests` 的预览、权限、范围、批量结果和写入回读。
- **C**：`StarcatMCPPublicCapabilityTests` 的目录、输入、翻译缓存身份、任务、隐私与切号生命周期。
- **G**：CLI `internal/cli/capabilities_test.go`、MCP 与 global-search 全量测试；动态新工具、stdin/file、预览覆盖、分页、JSON、未知工具和资源。
- **D**：复用领域 Suite，例如 `ReleaseRepositoryTests`、`AgentKnowledgeToolTests`、`RepoNoteAIGenerationViewModelTests`；不等于所有新适配器已经真实连接验收。
- **S**：`scripts/check-public-capabilities.py` 的登记与 dispatch 静态一致性。实际命令、通过数和限制见[验证与交付记录](验证与交付记录.md)。

以下“实现待验收”表示有真实执行路径及所列自动化证据，仍未做真实用户库、付费 AI 或 GUI 验收；不把静态检查算成执行器集成测试。

Skill 文件导出：先调用 `starcat.get_repo_skills` 读取当前加载的 `id` 与 `files[].path`，再调用 `starcat.export_repo_skill_file`（仓库 selector、`skill_id`、`path`）。省略 `dry_run` 只预览，明确 `dry_run=false` 后取得 `task_id`，通过 `starcat.get_task_status` / `starcat.get_task_result` 取得 `artifact_id`，最后用 `starcat.read_export_chunk` 分块保存到 CLI 设备。App 不接受客户端路径，不扫描缺失证据，不改变安装队列。切账号取消任务并清理产物。

整个 Skill 导出：同一流程调用 `starcat.export_repo_skill`（仓库 selector、`skill_id`），文件名为 `<skill-name>.zip`。例如仓库中的 `skills/engineering/ask-matt/` 导出后只有 `ask-matt/` 根目录，内部文件和执行位保持原样，不添加安装 receipt。

时间线组合筛选：`events` 接受 `issue / pullRequest / discussion / release / star / unstar / fork` 多选，`reasons` 接受 `mention / review` 多选；同组 OR、跨组 AND，省略或空数组表示不限。`read_state` 为 `all / unread`，`issue_state` 为 `all / open / closed / merged`，`library_state` 为 `all / inLibrary / outsideLibrary`。未读与原因只匹配通知，状态只匹配 Issue / PR；矛盾组合返回空。`limit` 默认 20、上限 200，返回筛选后的 `total`、`has_more`、`next_cursor`；续页须保持原筛选，并原样传回 `next_cursor` 到 `cursor`。所有条件均先于分页，入库条件同时覆盖通知和账本，通知无本地仓库缓存时视为未入库。

```bash
printf '%s' '{"events":["issue","pullRequest"],"read_state":"unread","reasons":["mention","review"],"library_state":"inLibrary","limit":20}' | starcat tools call starcat.list_activity_timeline --input -
```
