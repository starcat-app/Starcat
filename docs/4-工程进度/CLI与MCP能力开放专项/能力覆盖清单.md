## 口径与入口

每行是一个可以独立讨论的动作。结论只使用“已有覆盖 / 本次开放 / 暂缓开放 / 不适用”；交付证据与该结论分开。规划项和纯展示动作不计现有业务动作分母。基础设施行也不计 App 业务覆盖率。工具数量只用于目录回归。

下表工具统一支持 **MCP `tools/call`** 和 **`starcat tools call <完整工具名> --input FILE|-`**；参数及当前可用权限以 `tools list / describe` 和 `starcat://capabilities` 为准。写入和新生成默认预览，明确执行加 `--apply`；既有同步生成工具没有预览时必须加 `--apply`。表中“只读”不代表免除 MCP Pro、配对、服务开启、账号和私有数据权限。

执行器缩写：

- **Facade**：`Starcat/Features/MCP/StarcatMCPFacade.swift`，复用 RepositoryRead、SemanticSearch、统计与缓存。
- **Write**：`Starcat/Features/MCP/StarcatMCPWriteFacade.swift`，复用 Metadata、Tag、StarMutation 领域能力及审计。
- **Public**：`Starcat/Features/MCP/StarcatMCPPublicFacade.swift`，装配已有 App 服务；目录在同目录 `StarcatMCPPublicCatalog.swift`。
- **Tasks**：`Starcat/Features/MCP/StarcatMCPTaskStore.swift`，进程内句柄、取消、切号等待和结果过期。

证据缩写：

- **R**：`StarcatMCPRuntimeTests` 的协议、Schema、基线工具、资源、错误及 allowlist 回归。
- **W**：`StarcatMCPWriteFacadeTests` 的预览、权限、范围、批量结果和写入回读。
- **C**：`StarcatMCPPublicCapabilityTests` 的目录、输入、翻译缓存身份、任务、隐私与切号生命周期。
- **G**：CLI `internal/cli/capabilities_test.go`、MCP 与 global-search 全量测试；动态新工具、stdin/file、预览覆盖、分页、JSON、未知工具和资源。
- **D**：复用领域 Suite，例如 `ReleaseRepositoryTests`、`AgentKnowledgeToolTests`、`RepoNoteAIGenerationViewModelTests`；不等于所有新适配器已经真实连接验收。
- **S**：`scripts/check-public-capabilities.py` 的登记与 dispatch 静态一致性。实际命令、通过数和限制见[验证与交付记录](验证与交付记录.md)。

以下“实现待验收”表示有真实执行路径及所列自动化证据，仍未做真实用户库、付费 AI 或 GUI 验收；不把静态检查算成执行器集成测试。

| DEFER-06 | 执行完整 RAG 问答 | KnowledgeRAGService.ask | 暂缓开放 | 包含 planner、metadata、insights、代码与上下文旁路；仅过滤检索 notes 不能保证全链路 repo_ids 隔离，需全链路范围契约后开放 |
| DEFER-07 | 创建或续接 RAG 会话 | RAGConversationStore、RAG 工作台 | 暂缓开放 | 会话持久化、历史预算和私有上下文授权尚未形成公共会话契约；不能用临时 task ID 冒充会话 ID |
| DEFER-08 | 删除 RAG 会话 | RAGConversationStore | 暂缓开放 | 需独立破坏性范围、预览目标和回读；不是取消任务 |
| DEFER-09 | 置顶或改名 RAG 会话 | RAGConversationStore | 暂缓开放 | 随公共会话身份与账号隔离契约接入 |
| DEFER-10 | 刷新仓库健康与安全度 | RepoHealth、OpenSSF 服务 | 暂缓开放 | 缓存读取已开放；额外网络刷新和速率控制需要各自任务，不借读取偷偷执行 |
| DEFER-11 | 下载完整 Star 历史 | RepoStarHistory 服务 | 暂缓开放 | 缓存读取已分页开放；远端成本、速率与取消另订任务契约 |
| DEFER-12 | 刷新洞察数据集 | RepositoryInsights 服务 | 暂缓开放 | 读取指定缓存已开放；刷新需区分 GitHub、网络及模型消耗 |
| DEFER-13 | 刷新 Trending/探索/Weekly | 各列表 Repository 刷新路径 | 暂缓开放 | 各服务来源、缓存 namespace 与限流独立；本批只提供不会隐式联网的缓存查询 |
| DEFER-14 | 编辑 Awesome 来源订阅 | AwesomeRepository | 暂缓开放 | 需独立来源身份、抓取任务与后续缓存影响预览，不能复用 GitHub Star 操作 |
| DEFER-15 | 主动加载推荐更多内容 | RecommendationContextService | 暂缓开放 | 现分页仅覆盖已缓存 snapshot；下一页有服务 scope、模型版本与推荐请求身份约束 |
| DEFER-16 | 重命名标签 | TagRepository | 暂缓开放 | 涉及同名冲突、共享标签引用与权益；现公共能力尚无原子重命名用例，不能以创建+删除拼接 |
| DEFER-17 | 删除标签 | TagRepository | 暂缓开放 | 必须预览受影响仓库关联并保留用户标签数据；现写能力不提供共享标签删除事务 |
| DEFER-18 | 编辑智能合集 | SmartCollectionRepository | 暂缓开放 | 已开放定义查询；变更谓词必须使用受验证的结构，不能接收任意 SQL |
| DEFER-19 | 删除智能合集 | SmartCollectionRepository | 暂缓开放 | 随共享合集身份、权限与破坏性预览接入 |
| DEFER-20 | 扫描仓库 Skill | RepoSkillStore | 暂缓开放 | 已加载证据可读；远端目录扫描需独立网络/完整性/生命周期任务 |
| DEFER-21 | 安装 Skill | Skill 管理与受管目录服务 | 暂缓开放 | 本地文件写入、目标 Agent 和受管目录审批未形成远端 CLI 文件归属契约 |
| DEFER-22 | 更新或卸载 Skill | Skill 管理服务 | 暂缓开放 | 必须区分本地修改、共享目标与回滚；不能借通用写开关覆盖安装审批 |
| DEFER-23 | 下载、删除本地模型 | Local AI 模型管理 | 暂缓开放 | 体积、磁盘空间、进程使用与 Direct 渠道门控独立；查询只返回已配置模型投影 |
| DEFER-24 | 修改 Provider 或 Key | AppSettings、Keychain | 暂缓开放 | 凭据设置及外部端点信任不进入普通公共读写；不得经目录泄露 Key |
| DEFER-25 | 启动完整 Agent 运行 | AgentRuntime、Approval | 暂缓开放 | 未抽出跨进程审批与运行仓库/工具授权；本批只返回 Direct 状态投影，保留受限 Runtime allowlist |
| DEFER-26 | 执行 CodeFlow 分析 | CodeFlowViewModel、Direct runtime | 暂缓开放 | 本机源码、外部工具和路径授权；不是外部 CLI 可提供的远端路径 |
| DEFER-27 | 构建 CodebaseMemory 图谱 | CodebaseMemoryViewModel | 暂缓开放 | 本机目录权限、受控 Runtime 与图谱生命周期需独立契约；不恢复已取消状态面板接入 |
| DEFER-28 | 上传或发布分享页 | 分享 API 客户端与维护者检查 | 暂缓开放 | 公网提交、隐私和维护者身份独立；已有 Markdown/HTML 导出不产生公开链接 |
| DEFER-29 | 导出原始诊断包 | 诊断归档与导出 | 暂缓开放 | 原始日志、路径和业务正文需要脱敏白名单及 CLI 文件契约；只读聚合健康度已开放 |
| DEFER-30 | 清除缓存 | 设置页缓存清理 | 暂缓开放 | 不同缓存有重建、账号与离线影响；需逐类预览，不能开放“删除全部文件” |
| DEFER-31 | 恢复 App 数据备份 | AppStoreToDirectImport | 暂缓开放 | 现有跨渠道首次导入依赖本机容器权限、应用关闭与用户确认；不是通用远端恢复接口 |
| DEFER-32 | 更改同步、隐私与服务设置 | AppSettings、AuthSession | 暂缓开放 | 可能重启服务、切库或改变授权；本次仅非敏感读取，不能由当前连接自改授权 |

## 覆盖率计算限制

执行 `python3 scripts/check-public-capabilities.py` 输出本表登记数、公共目录数与静态双入口登记数。业务分母只含 CAP 中非基础设施行和 DEFER 行；FUTURE、UI 与重复资源行排除。本表把同一 App 服务的刷新动作单列评估，但没有把所有 UI 方法或内部缓存函数当成业务动作。

“所有登记动作已评估”不等于“所有动作已开放”。“目录能经两入口发现和调用”不等于“每个新增适配器已做真实端到端验收”。本轮自动化证据、不能执行的真实场景及暂缓能力必须保留在结果记录中。
