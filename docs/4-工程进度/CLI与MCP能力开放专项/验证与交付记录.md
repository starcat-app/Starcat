## 4. 浏览器与渠道矩阵

| 组合 | 配对 / 业务通道 | 宿主与安装 | 当前证据 | 待验收 |
| --- | --- | --- | --- | --- |
| Chrome × App Store | background HTTP；安装 host 后可固定 CLI Native 通道 | 用户级 Chrome manifest + 脚本，精确 extension ID；不写 App bundle | App 配对 / SSE 单测、Go host、Chrome VM 与语法 | 签名 App、真实 Chrome、权限、Profile、更新 / 卸载 |
| Chrome × Direct | 同上，App 维持现有 Companion 权益 | 同一用户级 host，不依赖 App 路径 | 同上；Direct 以独立构建验证 | 双实例选择、自定义端口、真实写入与事件 |

| Safari × Direct | background HTTP，独立设备 token | 未接入 CLI 原生宿主 | 同上；不宣称已统一经过 CLI | 原生工程与分发决策、实际双渠道连接 |

Chrome CLI 升级或移动后重新执行 host install；卸载删除用户目录 `NativeMessagingHosts/com.starcat.browser.json` 和 `.sh`。发现请求不带凭据，失败可只在发现阶段回退 HTTP；已选择 Native 的写入失败不换通道重放。App 路径移动不影响 loopback HTTP，但服务地址变化仍需重新确认，不能把未认证发现结果当信任迁移。

2026-11-15 直接读取官方文档，两页均 HTTP 200，核对 Chrome 的 `allowed_origins`、用户级 host 位置和 32 bit 长度前缀，以及 Safari containing-app 原生消息边界：

- [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- [Safari 原生消息](https://developer.apple.com/documentation/safariservices/messaging-between-the-app-and-javascript-in-a-safari-web-extension)

这是平台机制核对，不是本项目签名安装证明。Safari 原生通道、任意端口可信定位和商店终审是明确未完成项。

## 8. 浏览器连接反馈补齐

2026-11-15，dong4j 确认补齐上一轮核查发现的超时与提示缺口。Chrome、Safari 自动发现均限制为总计 5 秒；Chrome 原生发现最多 3.5 秒，HTTP 保存地址与默认地址并行且单地址最多 1.3 秒。页面对发现消息也设置总预算，后台队列等待不会导致页面一直查找；迟到原生发现不改变已选 HTTP 通道。原生和 HTTP 请求都限制为 5 秒，包含响应体读取，不自动重放业务写入。

配对页按 App 返回的截止时间每秒更新剩余时间，正常新请求为 120 秒；到期独立于轮询，清空六位码和倒计时并恢复“重新配对”，后台尽力取消请求及清理临界时刻领取的设备授权。终态更新请求身份，忽略过期响应。新增共享错误文案，覆盖发现超时、连接超时、请求失效、凭据保存失败、原生组件不可用、重复配对和手工 Key 认证失败；未知技术错误不直接显示。提示状态使用 120ms 淡化并遵循系统 Reduce Motion，倒计时不反复触发辅助功能朗读。
