# 标签关系图谱 · 实现方案

`HOM-242` · [GitHub #211](https://github.com/starcat-app/Starcat/issues/211) · [需求与固定样例](需求说明.md) · [任务清单](checklist.md)

## 1. 从当前账户读取归属图

在同一个 GRDB 读取事务中，从 `tags` 读取全部标签，从 `repos` 读取仍为 Star 且至少有一个已应用标签的仓库，从 `repo_tags` 读取这些仓库的实际归属。复合主键 `(repo_id, tag_id)` 保证每对标签与仓库只有一条边。节点 ID 用 `tag:<id>` 和 `repo:<id>` 区分类型，仓库节点只有一份。无权重计算、数据库写入或 schema 变更。[图谱查询](../../../Starcat/Core/Sync/TagGraphQuery.swift)

从侧栏「标签」旁的按钮打开全窗口覆盖层。`TagGraphViewModel` 通过 GRDB `ValueObservation` 绑定当前身份与数据库，数据改变时生成新快照，重复结果不发到渲染端。切号或关闭时销毁旧画布、取消订阅并拒绝过期回调。同账户刷新失败时保留最后一次快照并提供重试。[主窗口接入](../../../Starcat/Features/Home/HomeView.swift) · [数据库订阅](../../../Starcat/Features/TagGraph/TagGraphViewModel.swift)

## 2. 复用关注者的 2D 画布

复用关注者的 `FollowGraphWindowOverlay`、`FollowGraphWebView` 和同一份 `follow-graph.html` / `follow-graph.js`。标签节点传入现有颜色和 SF Symbol。每个图标栅格化后缓存，仓库头像走关注者现有的 GitHub 头像缓存和限速路径。头像缺失时显示文字占位，首帧不等网络。图本身不需要联网。[标签图宿主](../../../Starcat/Features/TagGraph/TagGraphWorkspace.swift) · [WebKit 桥](../../../Starcat/Features/FollowGraph/FollowGraphWebView.swift) · [共享渲染器](../../../resources/follow-graph/entry.js)

共享入场队列按真实归属数选择标签最多的仓库作中心，同数按仓库 ID 决定。只有标签时选择一个稳定的标签。中心固定在画布原点，首帧显示名称与头像占位，收到绘制回执后退出原生占位。随后沿标签与仓库的归属边按层展开，先逐个呈现，再随规模加快。只有已入场节点参与布局和点选，连线两端都出现后才绘制。只要中心还在，实时数据更新就沿用它。

有连接的节点从实际相邻节点附近出现，独立小组从中心周围入场。标签画布用短距离排斥和朝中心的吸引力约束布局，组内只绘制真实归属。减少动态效果时直接按相同的顺序布置全部节点，跳过入场、头像运动和布局动画。稳定后动画队列停止刷新。

单击在 Canvas 内用邻接索引更新高亮，点击空白清除。不会重新查库或重建布局。左上角原生浮层可搜索标签名和 `owner/repo`，结果有上限。键盘提交或点结果可定位尚未出现的节点。完整名称可从悬停或选择中读取，仓库在全览时以头像为主。平移、拖拽、缩放和重置沿用共享画布。

## 3. CLI / MCP 暴露评估

App 运行时工具目录同时服务通用 CLI 和 MCP。两个工具均使用 `read` 与当前账户连接权益，不触发网络请求或刷新。[公共目录](../../../Starcat/Features/MCP/StarcatMCPPublicCatalog.swift) · [执行器](../../../Starcat/Features/MCP/StarcatMCPPublicFacade.swift) · [能力覆盖清单 CAP-131／132](../CLI与MCP能力开放专项/能力覆盖清单.md)

| 动作 | App 执行入口 | 公共工具 | 输出与验证 |
| --- | --- | --- | --- |
| 读取归属图 | `TagGraphQuery.snapshot` | `starcat.get_tag_graph` | 按仓库 ID、标签 ID 分页返回 `edges[{source,target}]`。每页 `nodes` 包含全部标签及本页边引用的仓库，节点 `kind` 为 `tag` 或 `repo`。`total_nodes`、`total_edges` 是全量计数。固定样例校验合并各页得到 9 个节点、7 条边 |
| 按多个标签 ID 查仓库 | `RepoTagIntersection.page` | `starcat.list_repos_by_tags` | 独立的 AND 查询，非空 `tag_ids` 接受数据库原始标签 ID，重复 ID 去重。返回 `items` 和 `total`。固定样例以 `limit=1` 查询 Agent 和 RAG 时，两页分别为 r1、r2 |
| 中心选择、布局、入场、搜索定位与点选 | 图谱界面 | 不适用 | 这些动作只改变当前画布的显示 |

两个查询均接受 `limit`（默认 20，范围 1～100）和从 0 开始的 `offset`，并返回 `has_more`、`next_offset`、`network_used: false`。末页 `next_offset=null`。非法参数返回 `INVALID_ARGUMENTS` 与参数路径，合法但不存在的标签 ID 返回空交集。调用之间若数据变化，各页可对应不同的快照。既有 `starcat.list_repos_by_tag` 保持原契约。

## 4. 验证与复测

从干净样例核对空态、孤立标签、归属查询、增删改与切号。离线渲染测试覆盖共享的关注者行为、标签与仓库入场、点击高亮及搜索定位。公共读取使用独立 CLI 进程与 App 回环服务，分别走通用命令和 MCP stdio。两渠道产物核对同一套 HTML 和 JavaScript。[逐项任务与证据](checklist.md)

### 5,000 个 Star 的数据读取实测

`make test TEST_ARGS="-only-testing:StarcatTests/TagGraphScaleTests"` 输出 `TAG_GRAPH_SAMPLE`。典型样本含 17 个标签、每仓 0～3 个已应用标签，应读到 3,767 个节点和 7,500 条边。密集样本含 40 个标签，第一个仓库用全部标签，其余每仓 8 个，应读到 5,040 个节点和 40,032 条边。

每组用独立临时账户，在同一数据库连接池开启三个新会话。计时从开始订阅到主线程收到完整快照。实机另测点击入口到首节点可读的时间、全部节点入场时间、点击到高亮的时间，以及画布稳定且指针静置 10 秒时的重绘和 CPU。

2026-11-20 在 Mac Studio（Apple M2 Ultra，64 GB）以 Debug 配置跑过三轮。典型样本分别为 29.8、28.6、26.3 ms，密集样本为 96.9、93.8、95.8 ms。这些数值只计数据交付，画布显示和交互耗时待实机测量。
