## 用户要看到什么

在同一张全窗口图里看标签和收藏仓库。标签显示原来的颜色和图标，仓库显示 GitHub owner 头像。一个仓库打了 `Agent` 和 `RAG`，就由这个仓库节点分别连到两个标签节点。线只表示实际归属，每条线含义相同。

从侧栏「标签」旁的图谱按钮打开。Starcat 应用 Logo 固定在中央并率先出现，标签和仓库用「关注者／正在关注」的 2D 图谱逐个入场。标签从 Logo 周围出现，每个标签先展示最多 10 个仓库，按收藏时间由近到远排序。同一个仓库在画布里只出现一次。

点标签高亮它和已展示的直接邻居，右下角浮出同款资料卡。卡片包含图标、名称、创建时间、已加载数和项目总数。「更多」每次追加最多 50 个仓库，沿用关注者展开后的入场动画。计数随仓库加入画布变化，逐个入场期间防止重复点击，全部出现后收起按钮。

点仓库高亮已展示的归属，并用同一个右下角卡片呈现仓库头像、名称、简介和本地可用资料。点空白清除选择，卡片可关闭和定位节点。左上角仍可按标签名或仓库全名搜索，定位未出现的仓库时只补出该仓库及真实归属。画布支持拖动、平移、缩放与视角重置，保持全窗口。

## 数据范围与验收样例

仅展示当前账户的标签、仍为 Star 且已经打了标签的仓库，以及已实际应用的标签关联。未使用的标签也接入 Logo。Logo 与标签的连线只组织画布。无标签仓库、已取消 Star 的缓存仓库、GitHub Topics、标签父子关系和待确认的 AI 建议都不产生归属边。

| 仓库 | 状态 | 实际标签 | 画布结果 |
| --- | --- | --- | --- |
| r1 | Star | Agent、RAG、Python | 1 个仓库节点，3 条边。重复添加 Agent 后仍为 3 条 |
| r2 | Star | Agent、RAG | 1 个仓库节点，2 条边 |
| r3 | Star | Python | 1 个仓库节点，1 条边。待确认的 Agent 建议不入图 |
| r4 | Star | CLI | 1 个仓库节点，1 条边 |
| r5 | Star | 无 | 不入图 |
| r6 | 已取消 Star | Agent、RAG | 不入图 |

样例合计 **5 个标签、4 个仓库、7 条真实归属边**。打开先显示 Logo，再出现 5 个标签和各自的仓库。点 `Agent` 后卡片显示已加载 2、项目总数 2，r1、r2 和两条归属边高亮。点 r1 看到仓库资料和它实际关联的 `Agent`、`RAG`、`Python`。取消 r2 的 Star 后移除它及两条边。切到账户 B 后只看到 B 的标签与仓库，各标签从首批开始。

另用一个包含 63 个仓库的标签检查分页。打开后加载到 `10 / 63`，两次点「更多」分别到 `60 / 63` 和 `63 / 63`，最后隐藏按钮。少于 10 个仓库的标签一次出完。若某个仓库已从另一个标签出现，追加时只补本标签的连线。

## 首版实施口径

经 dong4j 授权，继续在基于远端 `dev` 的 `codex/tag-cooccurrence-graph` worktree 逐项提交。App Store 和 Direct 面向已登录账户。公共读取沿用现有连接权益和 `read` 授权。2.0.0 发布优先级和发布门槛待验收后确定。

无标签时显示空态，首次加载到画布首帧前有占位，同账户刷新失败可保留最后一次结果并重试。验收覆盖明暗主题、键盘与 VoiceOver 搜索、系统减少动态效果和 Starcat 动画设置。性能以画布首帧、节点入场、点击高亮和静止后的重绘为准，数据读取与画布指标分别记录。[复测方法](实现方案.md#5000-个-star-的数据读取实测)
