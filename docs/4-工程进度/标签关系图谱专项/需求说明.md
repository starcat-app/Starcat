# 标签关系图谱 · 需求说明

目标版本为 2.0.0。专题任务 `HOM-242`。2026-11-20 已授权实施，见[首版实施口径](#首版实施口径)。[GitHub #211](https://github.com/starcat-app/Starcat/issues/211) · [版本规划](../../2-产品/需求讨论/v2.0.0-版本规划.md#tag-cooccurrence) · [实现方案](实现方案.md) · [任务清单](checklist.md)

## 用户的问题

标签墙能告诉我收藏里有多少个 `Agent` 仓库。我还想知道 `Agent` 经常和哪些标签一起出现，以及具体是哪些仓库把它和 `RAG` 联系起来。前一个问题适合看全图，后一个问题必须能回到仓库核对。

参考「关注者／正在关注」图谱的全窗口画布、搜索和视角操作。标签之间的关系来自用户的收藏，没有中心用户，也没有关注方向。

## 统计口径

| 对象 | 如何计算 | 用户看到什么 |
| --- | --- | --- |
| 节点 | 当前账户每个现存标签对应一个节点，以标签 ID 标识 | 使用已有名称、颜色、图标。改名保留身份，尚未用于任何当前收藏的标签显示 0 |
| 节点计数 | 当前仍为 Star 且已实际应用该标签的不同仓库数 | 单标签仓库也计入。仓库只打了一个标签时，该仓库不贡献连线 |
| 连线和边权 | 两个不同标签共同出现在至少一个当前 Star 仓库上就连一条无向边。边权等于同时拥有两者的不同仓库数 | 同一仓库对每个无序标签对只贡献 1。交换端点、重复应用标签都不会多出一条边，也没有自环 |
| 数据范围 | 仅读取当前账户本地的已应用标签和当前 Star 状态 | 无标签仓库、Unstar 后保留的缓存、待确认的 AI 建议、GitHub Topics 均不贡献关系。父子标签各自计数，层级本身不产生边 |

## 可复核的样例

账户 A 有 `Agent`、`RAG`、`Python`、`CLI`、`资料` 五个标签。`资料` 是 `RAG` 的父标签。下表中的仓库名和标签仅作测试用。

| 仓库 | 状态 | 实际标签 | 附加条件 |
| --- | --- | --- | --- |
| r1 | Star | Agent、RAG、Python | 重复给 r1 应用一次 Agent |
| r2 | Star | Agent、RAG | — |
| r3 | Star | Python | AI 建议 Agent，用户尚未确认 |
| r4 | Star | CLI | — |
| r5 | Star | 无 | — |
| r6 | 已取消 Star | Agent、RAG | 本地保留关联 |

结果应恰有 **5 个节点、3 条边**。节点计数为 `Agent=2`、`RAG=2`、`Python=2`、`CLI=1`、`资料=0`。`CLI` 和 `资料` 都能搜索到。三条边可以逐一核对：

| 标签对 | 边权 | 共同仓库 |
| --- | ---: | --- |
| Agent ↔ RAG | 2 | r1、r2 |
| Agent ↔ Python | 1 | r1 |
| RAG ↔ Python | 1 | r1 |

将最少共同仓库数设为 2 时，只显示 `Agent ↔ RAG`，五个节点及其计数仍可查。将 r2 取消 Star 后，这条边的权重变为 1，交集只剩 r1。若账户 B 仅有一个同时打了 `Agent`、`RAG` 的仓库 b1，切换后只显示 B 的数据，交集为 b1。各场景从上表的初始状态独立执行。

## 首版交互建议

1. **进入全图。** 在侧栏「标签」标题附近放独立图谱按钮，保留展开、创建及标签筛选入口。首次打开全览，节点沿用标签颜色和图标，名称可读。节点大小表示仓库数，线宽表示共同仓库数。用上下限控制视觉大小，精确数字可在详情和关联列表中读取。布局距离仅辅助阅读。
2. **找一个主题。** 搜索名称并定位到节点，或直接选择节点。高亮直接邻居，详情显示仓库数和按共同仓库数降序排列的关联标签。键盘和辅助功能可以经搜索结果和关联列表完成相同操作，无须点中细线。
3. **查一条关系。** 点击一条边或在关联列表选择另一个标签，显示「Agent ∩ RAG · 2 个共同仓库」。通过「查看全部」打开具名的交集列表，能进入仓库详情。返回图谱时恢复焦点和视角。现有标签墙多选是并集，图谱下钻须使用交集。
4. **读密集的图。** 支持平移、缩放、拖动、恢复全览和最少共同仓库数筛选。建议默认阈值为 1，用户调整后显示可见边数与全部边数。刷新保留仍存在的选中项及视角。布局稳定后停止运动。

| 情形 | 期望反馈 |
| --- | --- |
| 没有标签 / 有标签但没有共现 | 前者说明可以先给收藏打标签。后者保留全部节点，提示需要有仓库同时使用两个标签才会形成连线 |
| 阈值隐藏了全部边 / 搜索无匹配 | 分别提供降低阈值、清除搜索的入口。只有前者改变可见边数 |
| 首次加载 / 同账户刷新失败 | 首次显示加载反馈。已有数据时保留上次图并标明刷新失败，可重试。退出或切换账户立即清空旧图及详情 |
| 显示与操作 | 验证明暗主题、长标签名、键盘与 VoiceOver 的名称和计数、减少动态效果。新增文案覆盖 App 当前支持的全部语言 |

## 首版实施口径

2026-11-20 dong4j 授权基于远端 `dev` 使用独立 worktree 实施，逐项提交。采用标签区独立入口、全窗口 2D 画布、原生关系详情与分页交集。仓库详情在仍保留图谱状态的视图上打开，返回恢复选择及视角。默认最少共同仓库数为 1。

首版实施默认在 App Store 与 Direct 均开放给已登录的当前账户，不加 Pro 门槛。公共查询仍受现有连接与 `read` 授权约束。纳入 2.0.0 规划。权益、发布优先级、具体排期和是否为发布门槛由正式验收确认。

开发测量使用当前 Mac Studio（Apple M2 Ultra，64 GB）。典型样例用 5,000 个 Star、17 个标签、每仓最多 3 个标签。密集样例用 5,000 个 Star、40 个标签、至少一个仓库同时应用全部 40 个标签。暂用冷开首个可读画面 1 秒以内、切换关系到首屏列表 250ms 以内作为实机参考。稳定时布局停止并在 10 秒空闲期间无持续重绘。正式性能通过线以实机采样后确认的结果为准。

自动聚类、AI 命名、相对关联评分和历史演变留作后续独立讨论。首版验收以共同仓库和精确计数为依据。六项版本交付的依赖和证据见[任务清单](checklist.md)。
