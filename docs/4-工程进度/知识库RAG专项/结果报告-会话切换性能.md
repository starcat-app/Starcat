# RAG 会话切换性能结果报告

> 状态: 代码与自动化验证完成，真实长会话手感待人工验收。

## 1. 交付结果

后台回答不再因为切换会话而停止，切换动作也不再等待 Debug 文件或旧会话的可见流式刷新。最近会话通过容量 24 的窗口级 LRU 缓存消息、大纲与引用投影；缓存未命中时立即提交选择并在后台加载，旧请求用 generation 门闩阻止迟到覆盖。

流式回答只高频发布 `StreamingMarkdownSnapshot`，后台会话 registry 明确排除 Observation；自动尾随最多约 5Hz 且不再强制整条时间线同步布局。Debug 关闭时不读文件，开启后异步加载并缓存解码结果；标题仍在首轮并行生成，但只提交最终标题，不再逐字刷新全局会话数组。

## 2. 现有功能边界

- 保留回答、标题、联网确认、执行轨迹和 Debug 按 `conversationID + generationID` 归属。
- 保留停止、删除、关窗和切库的原取消语义；普通切换不取消后台任务。
- 保留完整回答、引用、执行轨迹、复制、导出和历史恢复；SQLite 仍是唯一会话真源。
- 不修改 RAG schema、检索策略、Prompt、Provider 请求或 App Store / Direct 共用边界。

## 3. 同轮附带修复

- 修复 `fetchKeywordSearchableChunks` 将 SQL 占位符误写为字面量的问题，并补批量 repo 查询回归测试。
- JSON 聊天历史改用精确 Unix 秒数写入，同时兼容读取正式版既有 ISO8601 日期，避免 reasoning/response 亚秒丢失。
- 清理产品与测试代码中的未使用值、Binding Sendable、MainActor 和 Notification 并发捕获 warning。
- 修正 3 条与当前融合分、证据裁剪和 Token 上限不一致的过期测试 fixture/断言。

## 5. 人工验收建议

在一个会话持续生成长回答时，连续切换 5 个以上历史会话并来回返回，确认左栏选中立即响应、历史内容无串会话、后台回答持续增长；同时覆盖手动上滚、点击“滚到底部”、Debug 开关和回答完成后的最终贴底。自动化已验证状态与数据边界，但不替代真实窗口下的主观流畅度验收。
