# 知识库 RAG 脱敏评测集模板

> 状态: 待填充（本文件只定义采集口径，不包含任何真实问题、仓库名、内容或测试结果）
> 关联专项: `docs/4-工程进度/知识库RAG专项/知识库RAG专项进度.md`

## 1. 使用边界

评测集用于判断现有 FTS、embedding/vector、RRF 和 parent packing 是否满足真实检索需求，不能用合成
关键词替代真实结论。每条记录只保留脱敏后的问题和证据判断，不记录 token、私有仓库全名、绝对路径、
README/笔记原文或模型完整回答。

固定同一份知识库快照、embedding model、Provider 配置和 Top K 后才比较两次结果；调参前后必须使用
同一批 case。外部 GitHub 临时上下文、附件和历史对话不属于第一轮检索评测输入。

## 2. Case 模板

每条 case 以一个本地编号记录。`预期证据` 可以是「repo 别名 + source + section 描述」，不必暴露原文。
`相关度` 用于 nDCG：2=直接回答问题，1=有帮助但不完整，0=无关。拒答题不填写预期证据。

| 字段 | 模板 | 说明 |
| --- | --- | --- |
| ID | `zh-001` | 稳定编号；语言前缀用 `zh`、`en`、`mix` 或 `refuse`。 |
| 问题 | `<脱敏问题>` | 保留用户真实表达方式，不改写成关键词。 |
| 类型 | `fact / compare / filter / discover / refuse` | 用于按问题类型分组。 |
| 语言 | `zh / en / mixed` | `mixed` 至少保留一次中英文混输。 |
| 预期证据 | `repo-a · readme · Installation` | 可接受多个，按相关度排序。 |
| 相关度 | `2 / 1 / 0` | 对应预期证据的 nDCG 权重。 |
| 应拒答 | `是 / 否` | 没有本地证据或问题超出知识库时为「是」。 |
| 备注 | `<脱敏判定依据>` | 只说明为什么该证据足够，不能粘贴私有内容。 |

建议首批至少覆盖：中文、英文、中英文混合、跨 repo 比较、筛选问题、私有笔记命中、无证据拒答各一类。

## 3. 执行与记录

1. 在知识库管理器的「召回测试」中逐条输入问题；它会绕过 Planner 和回答生成，直接复用真实混合检索。
2. 记录 Top 5 与 Top 10 的命中是否包含预期证据，并记录每条命中的相关度。
3. 对需要回答的 case，再从知识库工作台执行完整问答，人工记录引用是否覆盖关键结论；拒答题记录是否明确说明证据不足。
4. 从 Debug trace 记录 keyword、semantic、evidence packing 和总耗时，分别汇总 P50/P95。
5. 将汇总结果写回本文件末尾，并注明知识库快照日期、embedding model、Provider 和 Top K；未填真实 case 前不得记录质量结论。
