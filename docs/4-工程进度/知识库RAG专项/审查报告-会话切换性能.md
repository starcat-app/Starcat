# RAG 会话切换性能审查报告

> 状态: 整改完成，专项与全量自动化验证通过。

## 1. 问题结论

会话数据量与 SQLite 批量读取不足以解释生成期间的明显切换卡顿。主线程负载主要来自流式回答每次可视快照触发的重复滚动定位、AppKit 强制布局、完整字符串复制和历史消息派生计算；会话选择又串行等待 Debug JSON 全量读盘，放大了点击后的等待感。

## 2. 已确认热点

1. 流式快照约每 100ms 同时驱动 `ScrollPosition` 与原生 bridge；bridge 对滚动容器和 document view 分别执行强制布局。
2. `selectConversation` 等待 SQLite 与 Debug 文件全部读取后才提交选中状态，加载期间旧会话仍持续刷新可见 UI。
3. 每个流式提交同时复制完整 `streamingAnswer`、会话级完整答案和 Markdown snapshot，长回答成本随内容增长放大。
4. 当前会话标题逐字更新全局 `conversations` 数组，约每 32ms 使左栏和中栏标题失效。
5. Answer Surface 在每次流式重绘时重新构建会话大纲；Markdown 展示反复编译固定正则。
6. Debug 历史读取无显示上限，且关闭 Debug 时仍参与普通会话切换。

## 3. 整改边界

- SQLite 继续作为会话真源；内存缓存只加速展示，写入、删除和摘要更新后必须同步失效或回写。
- 回答任务、标题任务、联网确认、执行轨迹和 Debug 归属继续按 `conversationID + generationID` 隔离。
- 切换会话不取消后台回答；停止、删除、关窗和切库的取消语义保持不变。
- Debug 历史不删除：仅在 Debug 开启时异步读取，完整历史展示能力保持不变。
- 不修改 RAG 检索、Prompt、模型请求、引用生成、数据库 schema 或发布渠道差异。

## 4. 整改项与验证

1. 会话展示快照使用有界 LRU 缓存，连同大纲和引用投影一起预计算；点击先提交选择意图，缓存命中同步安装，未命中在后台构建并使用 generation 防止迟到覆盖。
2. Debug 仅在开关开启时异步加载，不再阻塞会话正文；底层保留有界读取能力供后续分页使用。
3. 流式正文以 `StreamingMarkdownSnapshot` 作为唯一高频展示状态，完整字符串只在终态或取消持久化时使用。
4. 自动尾随请求合并限频，不再对每个 snapshot 同时执行 SwiftUI 和原生强制布局；历史加载与用户点击保留立即定位。
5. 会话大纲、引用集合和 Markdown 正则改为稳定缓存或一次编译；历史回答块隔离无关流式刷新。
6. 标题生成保留最终值与持久化语义，移除对全局会话数组的逐字高频写入。
7. 增加缓存淘汰、选择 generation、Debug 有界读取、滚动请求合并与流式内容完整性测试；最终执行 Debug build 和全量单元测试。

## 5. 验证结论

- 相关 8 个 Suite：166/166 通过。
- 全量测试：1459 项，1451 通过、7 跳过、1 项预期失败、0 失败。
- 全新 DerivedData 完整编译与最终全量重跑均未发现 warning/error。
- 额外修复构建暴露的 SQL 占位符错误、JSON 历史日期亚秒丢失及测试并发捕获警告；不改变 RAG 数据库 schema。
