## SwiftPM 冻结方式

- `Configs/SwiftPackages.resolved` 是唯一受版本控制的完整依赖锁，共 32 个远程 pin
- `project.yml` 保留直接依赖约束；XcodeGen 的 `postGenCommand` 自动把源锁恢复至生成工程
- 构建、单测和已有打包入口使用严格 resolved-file 参数，成功后只读核对 pin，禁止自动换版
- `make check-package-lock` 检查漂移，`make test-package-lock` 验证恢复、幂等、损坏源与漂移拒绝
- 本目录 [swiftpm-audit-2026-11-09.json](swiftpm-audit-2026-11-09.json) 记录升级前后完整快照、候选、选择与验证摘要，不被任何构建入口读取，也不是第二份构建锁

10 月 29 日方案快照之后，实施前已有四项传递依赖发生漂移：`swift-http-types 1.8.0`、`swift-jinja 2.5.2`、`swift-nio 2.105.0`、`swift-openapi-runtime 1.13.4`。本轮从实际 32 项 pin 建立基线，没有把这四项误写成本次升级

## 剩余验收与回退

1. 在全新机器或独立干净 checkout 执行标准构建入口，验证源锁恢复与完整构建；本轮隔离解析使用过本机 Git 对象缓存，不能勾选“干净环境构建”验收
2. 使用可回收的 1.9.x 旧库副本验证标签、笔记、关系、事务与同步元数据，不访问真实用户库试错；本轮没有 schema 或迁移修改
3. 按已验证 Runtime 版本执行真实只读工具、流式输出、取消、超时与进程回收，覆盖模型缓存、Embedding / Rerank 契约；不把 fixture 或 initialize 当作完整验收
