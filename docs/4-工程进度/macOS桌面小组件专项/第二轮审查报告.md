## 4. 新发现项

### P1-01 旧账号异步发布任务可能越过 preparing 写回

**现状**

`WidgetRefreshCoordinator.publishReady()` 在构建快照和下载头像时存在多个 `await`。
账号切换会立即调用 `publishEmpty(.preparing)`，但它只能取消去抖任务，无法撤销已经开始
执行的 `publishReady()`。旧任务恢复后仍可能把旧账号的 ready 快照写回共享容器，直到
新账号下一次发布才被覆盖。

**影响**

在窄竞态窗口中违反“切换用户后不得继续展示上一账号数据”的核心安全不变量。

**修复要求**

为每次发布分配单调 revision，并记录开始时的 user ID。任何新的 ready 发布或 empty
发布都使旧 ticket 失效；在真正保存前同时校验 revision 和当前 user ID。补充纯 gate
测试，覆盖用户切换、同用户后发覆盖和 user ID 不匹配。

### P2-01 仓库行 VoiceOver label 覆盖了来源与操作语义

**现状**

Focus、Rediscovery 和 Release 行先使用 `.accessibilityElement(children: .combine)`，
随后又用仅包含仓库名 / tag 的 `.accessibilityLabel` 覆盖组合结果。Focus 的置顶 /
using 来源不会被读出，仓库行也没有统一“在 Starcat 中打开”的 hint。

**影响**

视觉信息已补齐，但 VoiceOver 用户仍拿不到与视觉用户等价的来源和操作含义。

**修复要求**

Focus label 包含仓库名和来源；三个 Widget 的可点击仓库 / Release 增加本地化操作 hint。

### P2-02 Extension 降级路径缺少诊断日志

**现状**

缺失文件、未来 schema 和损坏 JSON 已正确映射为 preparing / upgrade / unavailable，
但 `StarcatWidgetSnapshotLoader` 没有记录任何 Extension 诊断。

**影响**

真实桌面出现 unavailable 时无法从统一日志判断是配置、版本还是损坏文件问题，与详细
方案“记录 Extension 诊断”的约定不一致。

**修复要求**

使用 `Logger` 只记录稳定错误分类，不输出 App Group 路径、JSON 内容或用户数据。

### P2-03 checklist 与最新回归证据已过期

**现状**

checklist 仍记录 19 个专项测试和 2051 个全量测试，提交表也未包含第一轮报告及其后
六个修复提交。

**影响**

工程进度和实际 Git / 测试状态不一致，不满足最终交付的可追溯要求。

**修复要求**

完成本轮代码修复后统一回填测试数量、提交记录和第一轮问题关闭证据；继续保留签名及
人工验收项为未完成。
