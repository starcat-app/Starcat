## 3. 发现项

### P1-01 Focus 没有保留并展示真实来源状态

**现状**

- SQL 已查询 `widget_pinned_at`，但 `WidgetRepository` 没有保存“置顶”来源。
- Medium / Large 行只在 `status == using` 时显示“正在使用”；置顶仓库没有来源文字。
- Small 对所有候选都固定显示 `pin.fill`，正在使用但未置顶的仓库会被误表达为置顶。

**影响**

与详细方案和 checklist 的“每行展示来源状态”不一致，用户无法判断仓库为何进入 Focus。

**修复要求**

在共享投影中增加稳定的 Focus 来源字段，构建器按“置顶优先、using 次之”赋值，三个尺寸
都按真实来源展示本地化文案，并补充模型和投影测试。

### P1-02 Widget 空态使用未定义的 `starcat://`

**现状**

`StarcatWidgetEmptyView` 默认打开 `starcat://`。主应用没有该路由，URL 会落入
`AuthSession.handleWebFlowCallback` 的兜底分支。Release 空态也只能打开泛化根 URL，
没有按方案进入 Release 时间线。

**影响**

空态点击虽可能唤醒进程，但会走错误的认证回调链路；Release 空态操作与文档不一致。

**修复要求**

新增严格、版本化的 App 根路由和 Release 时间线路由；主应用在 OAuth 之前消费。普通
空态打开主窗口，Release 空态打开 Release 时间线。补充正常、错误 host/path/version
和重复参数测试。

### P2-01 非 ready Timeline 刷新策略与方案不一致

**现状**

- Focus / Release 对所有状态固定 30 分钟刷新。
- Rediscovery 对所有状态固定到次日 00:05。
- 详细方案要求 preparing / signedOut 等非 ready 状态 1 小时后重试。

**影响**

Rediscovery 在登出或首次准备状态下可能到第二天才由系统主动重试；代码、文档不一致。

**修复要求**

抽取可测试的纯刷新策略：ready 普通组件 30 分钟、ready 重逢次日 00:05、非 ready
统一 1 小时。补充边界测试。

### P2-02 Small 尺寸缺少过期提示

**现状**

Focus Small 和 Rediscovery Small 没有消费 `entry.base.isStale`，而 Medium / Large
已有过期图标。

**影响**

超过 24 小时的快照在 Small 中继续展示，但用户无法知道数据可能过期，与详细方案不一致。

**修复要求**

Small 顶部状态区增加与其它尺寸一致的 `clock.badge.exclamationmark`，使用
`.secondary` 和本地化 VoiceOver label。

### P2-03 两处 plain Link 缺少 Focus Ring 门控

**现状**

Focus 与 Release Watch 列表的 `Link` 使用 `.buttonStyle(.plain)`，但未追加
`.focusEffectDisabled()`。

**影响**

违反 `UI-Focus-Ring-规范.md` 的强制规则，键盘焦点可能出现与 Widget 设计不一致的蓝框。

**修复要求**

两处补充 `.focusEffectDisabled()`，不改变 Link 点击语义。

### P2-04 账户隔离与 Extension 策略测试仍有缺口

**现状**

- `WidgetSnapshotStoreTests` 的非 ready 解码测试由模型先清空数据再编码，未模拟磁盘上
  “signedOut 但夹带旧业务数据”的异常 JSON。
- Timeline 刷新规则仍在 Extension 专属文件中，没有纯函数测试。

**影响**

关键安全不变量和降级时间策略缺少直接回归证据。

**修复要求**

增加原始异常 JSON 解码测试；将刷新时间计算下沉到 App / Extension 共用的 Foundation
文件并覆盖 ready、非 ready、次日边界。

## 4. 文档与进度一致性

第一轮发现以下 checklist 条目在修复前不应视为最终关闭：

- “每行展示 owner avatar、仓库名与来源状态”；
- “空态可点击打开 Starcat”及“无未读 Release 时打开 Release 页面”；
- “所有交互元素有 VoiceOver label”中的操作含义；
- 非 ready Timeline 的 1 小时降级策略；
- Small 尺寸过期提示。

本轮报告按要求先落档。修复完成并验证后，再在后续进度提交中回填证据；不修改
`docs/功能实现总览.md`。

## 5. 外部阻断

Store / Direct 正式签名、Widget Gallery、桌面添加、深浅色和 VoiceOver 人工验收仍受
本机 Xcode 账号凭据与两个 Widget provisioning profile 阻断：

- `No Accounts: Add a new account in Accounts settings.`
- `No profiles for 'com.starcat.app.store.widgets' were found.`

该阻断不影响本轮代码修复和自动化测试，但在 Xcode 重新登录并生成 profile 前，不得把
签名与真实桌面验收项标记完成。
