## 3. 跨模块链路审查

### 3.1 账号隔离与快照发布

- 每次 ready 发布取得带 revision 和 user ID 的 ticket。
- 新 ready、preparing、signedOut 或 unavailable 发布都会使旧 ticket 失效。
- 数据库读取和头像处理跨越 `await` 后，保存前再次校验 ticket、当前 user ID 和任务取消状态。
- 非 ready 快照在构造及解码两条路径都强制清空仓库与 Release 数据。
- App Group 写入使用同目录临时文件和原子替换，不扫描或删除共享容器。

结论：账号切换后，旧账号在途任务不能越过 preparing 把 ready 数据重新写回。

### 3.2 Timeline 与 Extension 边界

- ready 的 Focus / Release Watch 以 30 分钟为请求刷新间隔。
- ready 的今日重逢在次日 00:05 后请求新 Timeline。
- 非 ready 状态统一在 1 小时后重试。
- Extension 只读取版本化 JSON 和 App Group 头像，不链接 GRDB、Keychain 或网络客户端。
- 缺失、未来 schema、损坏和容器配置错误均映射到稳定空态并记录脱敏分类日志。

### 3.3 Deep Link 与冷启动导航

- 普通仓库、Release 和应用空态使用三种严格、版本化路由。
- 主应用先消费 Widget App 路由，再消费 Release、仓库、License 与 OAuth 路由。
- 主窗口导航 dispatcher 先保存请求再激活窗口；`HomeView` 挂载后消费 pending request。
- Release ID 缺失时仍打开仓库 Release 区域，不把错误输入转交 OAuth。
