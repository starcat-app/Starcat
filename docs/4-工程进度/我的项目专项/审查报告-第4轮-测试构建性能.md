## 2. 全量测试失败

### R4-01：Release 时间解析不兼容无毫秒格式

- 级别：P1
- 失败：
  - `RepositoryInsightsViewModelTests.releaseCadenceDerivesFromLocalReleaseHistory`
  - `RepositoryInsightsViewModelTests.defaultProviderMapsExistingLocalData`
- 证据：两条测试分别在测试文件第 18、972 行解析无毫秒 Release 时间时得到 nil 并崩溃；单独运行新增隐私用例通过。
- 根因校正：`ISO8601DateFormatter.shared` 是仅启用 `.withFractionalSeconds` 的计算属性，并非共享可变实例；真实问题是生产 Release 洞察只接受带毫秒格式。
- 修复：生产解析统一改用 `ISO8601DateFormatter.githubDate(from:)`，兼容 GitHub 返回的带毫秒和无毫秒时间；测试 fixture 使用明确的无毫秒 formatter。
- 验证：完整 `RepositoryInsightsViewModelTests` 与全量单测通过。

### R4-02：My Insights 收藏范围知识库分布断言与当前 fixture 不一致

- 级别：P1
- 失败：`MyInsightsSnapshotProviderTests.starredScopeUsesManageStatusSemantics`
- 证据：测试期望 `knowledgeCoverageItems.library == 0`，实际为 1。
- 根因：`GRDBRepoNoteRepository.updateStatus(.using)` 的既定产品语义会自动把仓库加入知识库，生产 SQL 返回 1 正确，旧断言已过时。
- 修复：将知识库分布断言调整为 1，不改生产查询。
- 验证：完整 `MyInsightsSnapshotProviderTests` 与全量单测通过。
