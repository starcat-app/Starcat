## 2. 发现的问题

### R1-01：部分授权与组织审批状态只有展示能力，没有生产状态来源

- 级别：P1
- 证据：
  - `ProjectAccessSession.markPartialAuthorization()` 和 `markOrganizationApprovalPending()` 只被单元测试调用。
  - `UserProjectSyncCoordinator` 虽允许一条 affiliation 成功、另一条失败并保留成功数据，但最终只抛出首个错误。
  - `UserProjectSyncService` 因此只能进入通用失败状态，无法把“owner 成功、organization_member 失败”映射为部分授权，也无法把组织链 403 映射为待审批。
- 影响：方案和 UI 声明的“部分授权 / 待组织审批”在真实同步中不可达。
- 修复要求：
  1. 同步摘要保留每条 affiliation 的成功/失败结果。
  2. GitHub App 下，一条成功一条失败映射为部分授权。
  3. organization_member 的 403 在 owner 成功时映射为组织审批待处理。
  4. OAuth fallback 继续保持通用失败语义，不能伪造成 GitHub App 审批问题。
  5. 增加 Coordinator 与 Service 单元测试。

### R1-02：CloudKit、默认导出和 External Search 边界缺少可执行回归证据

- 级别：P1
- 证据：
  - 当前仓库没有已启用的 CloudKit adapter，`user_projects` 和 `project_sync_state` 也没有任何同步注册点。
  - 当前文件导出只提供 `.starred` 和 `.library`，没有“我的项目”导出 scope；GitHub App token 位于独立 Keychain，不在 renderer 输入中。
  - `ProjectPrivacyPolicy.allowsExternalSearchContext(for:)` 已定义并有纯策略测试，但当前不存在从 Repo 详情把项目上下文送入 External Search 的生产调用点。
- 影响：实现边界目前成立，但主要依赖“没有调用点”，后续扩展容易无意突破。
- 修复要求：
  1. 为项目数据增加明确的 CloudKit / 默认导出边界声明，并用单元测试冻结。
  2. 测试默认导出 scope 不包含 `.myProjects`，且项目凭据不属于任何导出模型。
  3. 保留 External Search 的 deny-by-default 策略；文档明确当前无 Repo 级生产入口，未来接入必须先过该策略。

### R1-03：专项 checklist 与当前代码进度明显不一致

- 级别：P1
- 证据：Sidebar、`.myProjects`、筛选、详情复用、授权状态、刷新触发、Private README、撤销清理、缓存清理等已完成项仍为 `[ ]`。
- 影响：工程进度不能作为交付单一核对入口。
- 修复要求：完成功能补缺和测试后，按真实证据回填；人工权限矩阵与 GitHub App Client ID 必须标记为外部 Gate，不能伪造完成。

### R1-04：GitHub App Client ID 仍是外部配置 Gate

- 级别：外部 Gate
- 证据：`STARCAT_GITHUB_APP_CLIENT_ID` 已接入构建配置和模板，但仓库默认值为空。
- 影响：无真实 GitHub App Client ID 时只能验证 OAuth Public fallback，不能完成真实 Private / Internal 授权。
- 处理：代码不内置生产 Client ID；最终结果报告必须列出配置与人工权限矩阵步骤。

### R1-05：Repository Insights 全 Suite 暴露两条既有并行测试崩溃

- 级别：P2
- 证据：运行 `RepositoryInsightsViewModelTests` 时，`releaseCadenceDerivesFromLocalReleaseHistory` 与 `defaultProviderMapsExistingLocalData` 在 `ISO8601DateFormatter.shared.date(...)!` 处崩溃；新增“私有项目零远端调用”用例单独运行通过。
- 判断：失败与本轮门禁逻辑无直接关系，但会阻断“全量测试通过”的最终验收。
- 处理：在第 4 轮测试审查前消除共享 formatter 的并行可变状态风险，并回跑完整 Suite。
- 根因校正：第 4 轮单独复现后确认并非共享实例竞争，而是原 formatter 只支持带毫秒时间；最终改用 `githubDate(from:)` 兼容 GitHub 的两种 ISO 8601 格式，完整 Suite 与全量测试均已通过。
