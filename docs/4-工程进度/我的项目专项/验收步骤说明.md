## 2. Public fallback

1. 只使用现有 GitHub OAuth 登录，不连接 GitHub App。
2. 打开“星标 → 我的项目”。
3. 确认展示当前账号个人 Public 项目和组织成员 Public 项目。
4. 确认页面明确提示 Private 项目需要额外连接，不声称数据完整。

## 3. GitHub App 权限矩阵

使用测试 GitHub App，启用 Device Flow，并只申请 Metadata read + Contents read：

1. 个人全部仓库：展示个人 Public / Private。
2. 个人 selected repositories：只展示获准仓库并显示“部分授权”。
3. 组织已批准：展示用户通过组织成员身份可访问且 App 获准的项目。
4. 组织待审批：不展示未授权 Private 项目，显示等待审批。
5. token 过期：保留本地旧值并显示失效，不清空现有 OAuth 登录。
6. 撤销 App：停止刷新并移除不可访问项目关系，保留 Star、Tags、Notes 和知识库状态。

## 4. 关系与列表

1. 用户拥有但未 Star 的项目只出现在“我的项目”。
2. 用户 Star 自己的项目时同时出现在“全部仓库”和“我的项目”。
3. 取消 Star 后从“全部仓库”消失，但仍保留在“我的项目”。
4. 项目加入知识库后同时属于“我的项目”和“知识库”。
5. 验证个人、组织、具体组织、可见性和权限筛选。
6. 验证搜索、排序、多选、Cmd+A、置顶、分页和 selection 恢复。

## 5. 详情与历史

1. Public 项目复用现有 README、洞察和 Star History。
2. Private 项目 README 从 GitHub App 读取并进入当前用户本地缓存。
3. Private 项目只显示本机 Star snapshot，明确覆盖起点和精度。
4. 未授权指标显示 unavailable，不触发额外权限申请。

## 6. 隐私

1. 使用网络 stub 确认 Private owner/name 不进入 Discovery、Sharing 或 External Search 请求。
2. 检查 CloudKit adapter 和默认 JSON 导出不包含项目关系、同步状态及 Private 缓存。
3. 检查日志与错误落库不出现 Private full name、README、token 或 HTTP body。
4. 使用缓存清理入口删除 Private 远端缓存，确认用户 Tags、Notes 和知识库状态保留。

## 7. UI 与辅助功能

1. 验证 Light / Dark、最小窗口和 2,000+ 项目分页滚动。
2. 切换简体中文 / English，确认入口、筛选、授权状态、空态和错误态同步切换。
3. 使用 VoiceOver 遍历 Sidebar、筛选、刷新、连接和缓存清理操作。
4. 使用键盘完成 Sidebar 选择、筛选和列表操作，确认没有异常 focus ring。
