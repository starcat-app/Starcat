# 精选发布台需求说明

## 1. 项目目标

在 Starcat 内提供一个维护者专用的可视化发布工具。维护者可以粘贴平时收集到的项目线索，经搜索与 GitHub 官方仓库核验、选择 weekly-api 允许人工导入的来源分类后，将项目推送给其他 Starcat 用户。

本功能是运营工具，不改变普通用户的 Weekly 浏览、同步与本地缓存流程。

## 2. 用户与权限

- 当前唯一允许用户：GitHub 数字用户 ID `20341123`。
- 非允许用户看不到入口；即使通过窗口 ID 或内部调用触发发布，也必须在执行层再次拒绝。
- 管理员密钥由维护者首次使用时录入，连接验证成功后保存到本机安全凭据存储。
- 管理员密钥不得写入源码、普通设置、UserDefaults、日志、审查报告或错误消息。
- 后续若开放给其他用户，只替换集中式访问策略，不修改发布工作流。

## 3. 功能流程

1. 维护者从 Weekly 工具栏打开单实例「精选发布台」独立窗口。
2. 输入 GitHub URL、`owner/repo`、普通文字或任意站点链接。
3. 点击「识别项目」：直接仓库地址走精确核验；普通线索使用现有外部 Web Search（可用时）与 GitHub Search 查找候选。
4. 候选超过一个时由维护者显式选择；系统填入可编辑的最终 GitHub 地址。
5. 再次核验最终地址，展示仓库名、描述、语言、Stars 与更新时间。
6. 维护者填写展示标题、原始来源链接，选择 weekly-api 返回的人工导入来源分类。
7. 维护者勾选「已确认这是官方仓库」。任何最终地址变化都会撤销确认。
8. 点击「确认并推送」，客户端提交幂等批次并持续轮询状态。
9. 窗口展示 pending / processing / success / partial_success / failed 状态和逐项错误；关闭后重新打开仍能恢复最近批次。

## 4. 交互与异常

- 未登录、非允许用户、未连接管理员 API、没有可用分类、未核验、未确认时，发布按钮不可用。
- 外部 Web Search 未配置或失败时，自动退化为 GitHub Search，不阻断直接仓库核验。
- 401/403 明确提示重新录入管理员密钥；服务端其他错误展示安全的用户可读信息，不回显密钥。
- 网络超时或窗口关闭不重复提交；幂等键由来源、仓库和原始线索稳定生成。
- 服务器返回 `partial_success` 时按终态展示，不误报为全部成功。

## 5. 不在本期范围

- 不允许在 Starcat 中创建新的 weekly-api 来源分类。
- 不支持一次批量发布多个仓库。
- 不建设公网运营后台，不把管理员密钥下发给普通用户。
- 不修改 weekly-api 数据模型、Worker、公开 Weekly API 或现有 Skill 契约。
- 不提供定时发布、草稿云同步、多人审批和撤回已发布项目。

## 6. 验收标准

- 只有允许的 GitHub 用户能看到入口并执行发布。
- 三类输入（GitHub URL、`owner/repo`、普通线索）均可得到可确认的官方仓库或清晰失败原因。
- 分类来自 weekly-api 动态目录，提交契约与现有 Skill 一致。
- 发布提交具有幂等性，状态可轮询、可恢复、终态可读。
- 管理员密钥只进入安全凭据存储，代码与日志中无明文。
- 核心解析、API、权限、会话状态与发布守卫有自动化测试。
