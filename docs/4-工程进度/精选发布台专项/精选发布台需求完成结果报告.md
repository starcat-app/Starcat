# 精选发布台需求完成结果报告

## 项目目标

在 Starcat 内为维护者提供一个真正可用的 AI 精选发布工作台：接受自然语言、网页链接、GitHub 地址和多项目混合清单，按 `starcat-weekly-import` 的流程完成项目拆分、联网证据收集、官方 GitHub 仓库核验和人工复核，再通过 weekly-api 动态分类与批量导入推送给 Starcat 用户。当前只向 GitHub 用户 ID `20341123` 开放。

## 完成内容

- 将识别能力从 GitHub-only 搜索升级为三阶段 AI 甄别：理解拆分、逐项联网检索、证据判断。
- 复用 Starcat 已配置 AI 模型、External Search、GitHub Search、canonical 元数据和 README；AI 不可直接构造未经核验的仓库。
- 支持 `confirmed`、`needs_review`、`not_found`，可审阅证据、选择候选或手工核验 GitHub 地址。
- 将 AI 甄别会话和 Weekly 发布会话彻底拆分；窗口启动与识别阶段不访问 weekly-api，识别成功后才激活发布端。
- 将界面升级为“输入项目线索 / 审阅甄别结果 / 分类与推送”三栏工作台，并收紧结果卡、连接区、预览与批次状态；中栏结果列表和证据区独立滚动。
- 支持发布台直接创建人工分类，并一次提交全部勾选且确认的仓库。
- weekly-api 人工事件键改为 `manual:<source_code>:<owner/repo>`，同来源同仓库稳定更新/去重，不依赖客户端识别时预查。
- 保留 Keychain 管理员凭据、入口与执行层双重权限、批次幂等、终态轮询和状态恢复。
- 删除已不再使用的 GitHub-only Resolver，避免形成第二条识别路径。
