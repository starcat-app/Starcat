## 本轮未发现的问题

- Awesome 模式顺序、动态左栏、独立管理按钮位置和三栏路由与方案一致。
- 精选来源没有业务清单硬编码，卡片元数据来自 Discovery API。
- `gh_repo_id` 去重保留多来源证据；Awesome 表与 Stars/知识库/Tags/Notes 隔离。
- API/Admin 鉴权分离、ETag/304、同步事务、旧快照保留和 active run 幂等已有测试证据。
- 全量测试无失败；既有 `DiagnosticsTests.swift` 的 4 条 runtime warning 不由本次变更引入。

## 修复后验证计划

1. 增加“预览不落库、确认后才保存”的服务测试。
2. 增加“保存预览仍未订阅、完成 Sheet 后才启用”的 Store/Repository 测试。
3. 运行 Awesome 定向测试和 Starcat 全量测试。
4. 更新本报告修复状态并提交中文 commit，不 push。

## 修复结果

- `AwesomeCustomSourceService` 已拆分 `preview(input:)` 与 `save(_:)`，预览阶段不触碰数据库。
- 确认对话框展示有效 GitHub Repo 数与不会进入列表的外部链接数；确认后才创建来源。
- 新来源以 disabled 保存，只写入 Sheet draft；底部“完成”统一持久化订阅。
- 删除自定义来源增加 destructive 二次确认，并明确不会影响 Stars、知识库、Tags、Notes。
- 新增服务与 Repository 状态测试；Awesome 定向测试通过，`exit_code: 0`。
- 本轮遗留问题：无。
