# 审查报告 06:第四轮审批搜索与产品闭环

> 审查时间: 2026-07-11
> 审查范围: Approval、External Search、GitHub Weekly Report、Repo Insight、正式 Agent definition 与端到端测试
> 审查结论:两条正式 Agent 链路已闭环,发现 1 项产物定义漂移和 1 处测试语义漂移

## 1. 已核对证据

- Approval 以 runID/approvalID/toolCallID 三元组匹配命令,支持提前决策缓冲、拒绝回灌、取消唤醒和 App 重启恢复。
- requiresConfirmation 与 highCost 工具在宿主执行前暂停;拒绝或取消不会执行原工具。
- `external_search` 参数来自模型 tool-call,不会拿用户整段 prompt 兜底;结果包含来源、状态、耗时、日志和受预算控制的 Markdown。
- External Search 复用现有 Provider、API Key、缓存、聚合开关和隐私设置;关闭、未知 repo、私有 repo 未授权和 Provider 失败均不会伪造来源。
- Weekly 和 Repo Insight 都通过同一个 `LoopAgentRuntime`、消息事实源、Repository 与 Workspace 运行。
- 两条产品链路在搜索 skipped/failed 时仍可基于本地冻结上下文生成真实 Markdown artifact。

## 2. 发现项

### P1-1 正式 Agent 仍声明不存在的 log artifact

`BuiltInAgents.githubWeeklyReport` 与 `repoInsight` 的 `artifactTypes` 仍为 `[.markdown, .log]`,但当前正式完成工具只持久化一个 Markdown artifact;日志和工具输出属于消息审计事实,不再是独立产物。该定义会让 UI、测试和文档错误认为每次 run 应产出两个 artifact 类型。

修复:两个正式 Agent 只声明 `.markdown`,同步定义测试。

### P2-1 AgentDefinition 测试仍描述固定工具序列

`AgentDefinitionTests` 的模块注释和测试名仍写“Runtime 按 toolIDs 顺序执行”“线性工具序列”。当前 `toolIDs` 是模型可见 allowlist,不代表执行顺序。

修复:把测试语义改为锁定正式工具 allowlist 和产物类型,不暗示固定编排。

## 3. 无问题项

- 正式 Weekly 与 Repo Insight 没有默认 demo 数据或 sample artifact。
- 模型缺配置、搜索关闭、搜索失败和产物缺失均有明确终态。
- artifact 完成工具在多工具响应中延迟到所有 tool-result 之后提交,结果严格位于执行顺序底部。
- 预览 Agent 保持禁用,没有被误计为已交付。

## 4. 修复顺序

1. 收敛两个正式 Agent 的 artifactTypes。
2. 更新 AgentDefinition 测试命名和注释。
3. 运行定义、产品 Runtime、Weekly 工具与 External Search 测试。

- 联合回归:AgentDefinition、AgentProductRuntime、GitHubWeeklyReportTools、AgentExternalSearchTool、AgentApprovalCoordinator 共 22 项通过,0 失败。
