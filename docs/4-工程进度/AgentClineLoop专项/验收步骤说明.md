## 2. 空态与工作台验收

1. 从主窗口 toolbar 打开 Agent 工作台。
2. 首次进入时不要输入内容。
3. 检查左侧仅展示 Agent 定义和真实历史,中栏为正式空态,右侧为 run summary。

预期结果:

- 不自动填充 prompt、消息、固定步骤、artifact 或演示仓库。
- 只有 `GitHub Weekly Report` 和 `Repo Insight` 可运行;预览 Agent 不可启动。
- 左右栏折叠、置顶、窗口缩放和输入框自适应可用。

## 3. GitHub Weekly Report 主流程

选择 `GitHub Weekly Report`,输入:

```text
基于当前 Starcat 冻结仓库快照生成一期 Swift 开源项目周刊。先按需要选择本地工具；如果 External Search 可用，再搜索近期 Swift 工具链动态。所有结论必须列明来源和限制。
```

预期结果:

- 状态依次进入运行中和已完成。
- 模型自主选择 allowlist 中的工具,不要求每次运行保持固定步骤数量或固定顺序。
- 每个 tool-call 和 tool-result 可展开查看真实参数、输出、状态、耗时、重试和来源。
- 最终 Markdown 包含执行范围、主题分析、真实仓库 URL/Stars/Topics、来源与限制。
- Artifact 节点位于本轮执行顺序底部,点击后右侧 Inspector 展示同一份内容。
- 不出现 `SQL(elements: ...)`、sample repo、固定 `24 repos` 或声称未取证的实时 GitHub 数据。

## 4. Repo Insight 主流程

选择 `Repo Insight`,输入一个本地确实存在的仓库 full name,例如:

```text
分析 groue/GRDB.swift 的定位、采用价值、风险和下一步验证建议。只使用本地快照及实际取得的外部证据。
```

预期结果:

- 模型通过 `context_select_repo` 或等价的实际工具调用选择目标仓库。
- 产物中的仓库名称、URL、Stars、语言和 Topics 与本地快照一致。
- README、License、维护活跃度等未取得的事实进入限制说明,不能被补写或猜测。
- 右侧 Inspector 仍为通用 artifact/approval/run summary,没有 Repo Insight 专用假面板。

## 5. External Search 关闭验收

1. 在设置页关闭 AI 外部上下文搜索。
2. 使用唯一搜索词运行 Weekly,并在 prompt 中明确要求先调用 `external_search`。

预期结果:

- `external_search` 返回 `skipped`,节点可展开看到 Settings 已关闭的原因。
- skipped result 会回灌模型,模型可以继续使用本地仓库事实生成产物。
- 产物的 External Search 来源明确写为未使用/已关闭,不得伪造 URL。

## 6. External Search 失败验收

1. 开启外部上下文搜索并选择已配置 Provider。
2. 临时断开网络,使用唯一查询词避免命中缓存,再运行要求调用 `external_search` 的 Weekly。
3. 验收后恢复网络。

预期结果:

- 搜索节点返回结构化 `failed` result,Provider 错误经过脱敏且不会显示 API Key/Bearer Token。
- 模型仍可基于本地数据收敛;若无法满足目标,则进入明确失败终态。
- 无论哪种终态都不能生成伪造的外部来源。

## 7. 取消与失败边界

1. 发送一个需要多步分析的 Weekly 请求,在模型或工具运行中点击停止。
2. 再临时切换到缺 API Key 的 Chat Provider 运行一次。

预期结果:

- 停止后 run 立即进入已取消,不会随后被完成事件覆盖,也不生成假 artifact。
- 缺配置时 run 明确失败并显示可读错误,不回退固定步骤或 sample 结果。
- 历史列表可区分 completed、failed 和 cancelled。

## 8. 历史恢复与审批边界

产品 UI 验收:

1. 完成一个 run,关闭 Agent 窗口后重新打开。
2. 从左侧历史列表打开该 run。
3. 检查消息、工具输入输出、usage、来源和 artifact 顺序与运行结束时一致。

Approval 说明:

- 当前两个正式内置 Agent 均为只读,没有为了演示而启用生产写工具,因此正常 UI 不会凭空出现审批卡片。
- Approval pause/approve/reject/cancel/restart-resume 必须通过第 10 节自动化命令验收;这验证的是底层框架和工作台恢复契约。
- 后续正式接入 tag/note/status/star 写工具时,必须使用现有 `approvedAction` 模式和同一审批链,不能绕过确认。

## 9. Inspector、复制与导出

1. 选择一个真实 artifact。
2. 点击复制,粘贴到文本编辑器核对完整内容。
3. 点击导出,保存 Markdown 后重新打开核对。
4. 在中栏展开 tool-call/tool-result,检查 input/output/error/elapsed/source/retry 信息。

预期结果:

- 复制和导出内容与选中 artifact 一致。
- 失败时显示用户可见错误,不会静默无响应。
- 中栏与 Inspector 都只消费同一组 message/approval/artifact 事实,顺序一致。
