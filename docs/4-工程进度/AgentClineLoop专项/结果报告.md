## 1. 交付结果

- Prompt Pipeline:统一注入 Agent、mode、locale、工具、规则、External Search 策略、冻结仓库上下文、附件和预算。
- Message Contract:`user / assistant / tool` 与 text/reasoning/tool-call/tool-result 成为可持久化、可回放、可审计的唯一消息事实源。
- Tool Contract:模型可见 JSON Schema、宿主参数校验、allowlist、permission、completesRun、timeout 和 retry policy 全部落地。
- LLM Adapter:复用现有 Provider、模型参数与 Keychain,支持流式/非流式 text、reasoning、tool-call、usage 和多 choice 隔离。
- Loop Runtime:唯一正式路径为 `model -> tool-call -> tool-result -> model`;旧线性 Runtime 已删除,没有 fallback 或兼容 facade。
- Run Session:稳定 runID、iteration/tool/token/duration 预算、取消竞争、工具超时、只读重试和终态一致性已闭环。
- Approval:requiresConfirmation/highCost 工具在执行前暂停,支持批准、拒绝、取消、命令关联、持久化与 App 重启恢复。
- Persistence:GRDB 保存 run、message、approval、artifact;历史工作台按统一 sequence 恢复同一条时间线。
- External Search:模型主动调用 `external_search`,完全复用现有设置、Provider、API Key、缓存、聚合和私有仓库边界。
- 正式 Agent:GitHub Weekly Report 与 Repo Insight 共用同一底座,读取真实本地快照并生成单个 Markdown artifact。
- Workspace:独立三栏窗口、可折叠侧栏、置顶、流式回复、可展开工具输入输出、通用 Inspector、附件、取消、复制和导出均接真实动作。

## 2. 正式产品边界

- 当前只启用 GitHub Weekly Report 和 Repo Insight;其余 Agent 保持预览禁用。
- 当前正式工具均为只读;Approval 是已验证的底层能力,没有为了演示而注册生产写工具。
- 不包含 shell、任意命令、文件编辑、浏览器自动化、subagent、后台定时 Agent 或自动发布。
- 不自动写 tag/note/status,不自动 star/unstar;后续写工具必须复用现有 `approvedAction` 与 Approval 链。
- 不新增第二套 AI 或 External Search 设置;缺 Provider/API Key 时明确失败,搜索关闭或失败时不伪造来源。
- 正式产物只有 Markdown;工具日志和证据属于消息审计事实,不是额外 artifact。
