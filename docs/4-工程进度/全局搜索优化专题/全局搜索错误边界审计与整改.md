# 全局搜索错误边界审计与整改

> 状态：2026-11-13 已授权逐项整改；C23 共享截止时间与 C24 取消隔离已完成并验证，C22、C25–C29 继续按项独立提交。

> 源码基线：`codex/global-search-optimization` / `61e9e9cf`

> 执行入口：[全局搜索优化 Checklist](全局搜索优化Checklist.md) C22–C29；原始设计见 [全局搜索优化方案](全局搜索优化方案.md)。

## 1. 审计结论

全局搜索增强涉及 Jev / Laya 决策、Chat Planner、专用或 Chat Ranker、外部搜索、GitHub 搜索与核验。当前已能在若干阶段失败时保留基础搜索结果，但配置错误识别、共享预算、取消、迟到响应、缓存失效和恢复流程尚未完整贯通。

历史 Checklist 的勾选只表示当时条目描述的实现与验证完成，不表示下述异常组合已经覆盖。原有测试中的“重排超时保留候选”通过 Ranker 替身直接抛出超时，不能证明真实 Provider 会按整轮截止时间停止等待。

## 2. 八项错误边界整改

### C22 配置与服务错误分类

- **现状**：`resolveChatSelection` 已检查 Provider 是否存在、配置是否验证、模型是否选择与模型类型；外部搜索和 Rerank 也有各自的错误类型。
- **缺口**：`UserFacingError.map` 未接入 `AIChatSelectionError`、`ExternalSearchError`、`RAGExternalBackendError`，这些错误进入智能发现诊断后可能被归为未知错误，丢失明确原因、HTTP 状态和恢复方向。
- **用户影响**：没有选择模型、搜索 Provider 未开启、重排鉴权失败，也可能被建议更新应用或联系支持。
- **整改目标**：按阶段保留错误类型与状态，区分未开启、待配置、鉴权失败、余额不足、限流、服务异常和响应无效；提供对应模型或搜索设置入口。未开启的可选能力正常跳过，不一律告警。
- **验收**：覆盖 Provider 缺失 / 未验证、模型未选择 / 禁用 / 类型不匹配、缺 Key、401 / 402 / 403 / 429 / 5xx；普通提示不暴露底层类名或原始服务正文。
- **源码**：[AIConfiguration.swift](../../../Starcat/Features/AI/AIConfiguration.swift)、[UserFacingError.swift](../../../Starcat/Shared/Diagnostics/UserFacingError.swift)、[SearchDiscoveryModels.swift](../../../Starcat/Features/Search/SearchDiscoveryModels.swift)。

### C23 整轮共享截止时间

> 整改：已完成。Router / Planner / 发现服务与专用 Rerank 共用提交时 deadline；真实等待用一次性竞速结果约束，Provider 不响应取消时上层仍按时返回；TEI / Cohere HTTP 超时使用剩余时间。验证见 Checklist C23。

- **现状**：Router 给 Planner 最多 15 秒；发现服务进入时又以当前时间加 15 秒创建 deadline。
- **缺口**：首轮没有从分流开始共享一个截止时间。专用 Rerank 接收 `maxSeconds` 但未使用，远程 Transport 仍设置固定 20 秒超时。
- **用户影响**：界面约定的首轮 15 秒不能作为真实整轮上限，剩余时间很少时仍可能等待较长的重排请求。
- **整改目标**：分流、规划、检索、核验与重排共享同一 deadline；请求超时使用剩余时间，截止后保留已有结果并结束本轮等待。底层资源按任务真实退出释放。
- **验收**：用可控时钟或受控延迟覆盖累计耗时、临近截止启动重排、未及时响应取消的 Provider；验证上层按时停止采纳结果，不能只让替身主动抛超时。
- **源码**：[SearchIntentRouter.swift](../../../Starcat/Features/Search/SearchIntentRouter.swift)、[RepositoryDiscoveryService.swift](../../../Starcat/Features/Search/RepositoryDiscoveryService.swift)、[RAGSearchProviders.swift](../../../Starcat/Features/RAG/Core/RAGSearchProviders.swift)。

### C24 取消与旧查询响应隔离

> 整改：已完成。搜索提交、Router、Discovery 与基础搜索共享请求身份；新提交 / 清空会取消旧链路并丢弃迟到响应，取消不产生失败诊断，也不再启动后续 Web、GitHub 或重排请求。验证见 Checklist C24。

- **现状**：发现服务返回时会校验 generation；Router / Planner 的等待前后没有相同的会话校验。
- **缺口**：A 查询的 Planner 晚于 B 返回时，A 仍可能启动发现并替换当前 generation。部分包装器还会把取消转成超时或网络失败，编排没有统一终止后续阶段。
- **用户影响**：快速提交、清空后，旧查询可能继续运行或重新写入当前会话，取消也可能误显示为失败。
- **整改目标**：请求身份从提交起固定，覆盖 Router 到合并结果；替换或清空查询时取消整条链路；用户取消与超时分别处理，已取消任务不再启动后续请求。
- **验收**：覆盖 A 慢 B 快、A 晚失败、等待 Planner 时清空、发现期间替换查询，以及取消后不再调用检索 / 重排、不出现失败告警。
- **源码**：[SearchCenterViewModel.swift](../../../Starcat/Features/Search/SearchCenterViewModel.swift)、[SearchIntentRouter.swift](../../../Starcat/Features/Search/SearchIntentRouter.swift)、[RepositoryDiscoveryService.swift](../../../Starcat/Features/Search/RepositoryDiscoveryService.swift)。

### C25 终态与缓存恢复

- **现状**：检索阶段全部失败后，发现服务仍可能返回 `.completed`；ViewModel 缓存所有该终态的结果。
- **缺口**：缓存键仅为 `SearchRequest`，未包含 Chat / Rerank 配置、凭据变更身份、AI 联网开关，也没有过期时间。
- **用户影响**：网络或配置恢复后再次搜索同一句话，可能复用旧失败快照；切换模型也不一定重新执行发现。
- **整改目标**：区分成功、无命中、部分失败、失败与取消；失败不能作为成功缓存。配置、凭据、权限与账号变化后失效，时效查询有明确有效期；缓存身份不包含密钥原文。
- **验收**：覆盖全部失败后的重试、局部失败后的恢复、替换模型 / Provider / Key / 联网开关、缓存过期，以及真正零命中与服务故障的区别。
- **源码**：[SearchCenterViewModel.swift](../../../Starcat/Features/Search/SearchCenterViewModel.swift)、[SearchModels.swift](../../../Starcat/Features/Search/SearchModels.swift)、[RepositoryDiscoveryService.swift](../../../Starcat/Features/Search/RepositoryDiscoveryService.swift)。

### C26 首轮与继续查找的联网权限

- **现状**：首轮 Planner 使用 `externalContextEnabled`；继续查找重新规划时使用 `includeWebInAll`。
- **缺口**：AI 联网检索权限与网页资料展示开关混用。
- **用户影响**：两个开关取值不同时，首轮和下一轮联网行为不一致。
- **整改目标**：所有 AI 发现入口统一读取 `externalContextEnabled`；`externalSearchIncludeInAll` 只控制独立网页资料展示。继续查找前重新核对当前权限与可用 Provider。
- **验收**：覆盖两个开关的四种组合、首轮与继续轮次，以及执行期间关闭 AI 联网后不再发起新的 AI 网页请求。
- **源码**：[SearchIntentRouter.swift](../../../Starcat/Features/Search/SearchIntentRouter.swift)、[RepositoryDiscoveryService.swift](../../../Starcat/Features/Search/RepositoryDiscoveryService.swift)、[HomeView.swift](../../../Starcat/Features/Home/HomeView.swift)。

### C27 决策失败与降级详情

- **现状**：Jev / Laya 失败或超时后，可以按已确认的搜索专属策略由一次 Planner 接管。
- **缺口**：失败信息留在 `decisionStatus`，最终步骤主要保留失败状态，缺少对应原因与降级说明。
- **用户影响**：详情出现“查询分流失败”，却看不到为何失败、后续是否已接管。
- **整改目标**：保留引擎身份、阶段原因、超时或不可用状态及 Planner 接管结果；可选能力关闭说明为跳过。成功降级不误报整轮失败，不跨 Jev / Laya 隐式重试。
- **验收**：覆盖未开启、未配置、模型未安装、鉴权失败、无效概率、阶段超时，以及 Planner 接管成功 / 失败；每个失败步骤均有可解释的对应详情。
- **源码**：[SearchIntentRouter.swift](../../../Starcat/Features/Search/SearchIntentRouter.swift)、[SearchDiscoveryModels.swift](../../../Starcat/Features/Search/SearchDiscoveryModels.swift)、[SearchCenterView.swift](../../../Starcat/Features/Search/SearchCenterView.swift)。

### C28 重排有效响应与候选标识

- **现状**：远程 Rerank 的越界索引会被过滤，搜索适配层将未返回的候选补回并赋予统一重排说明。
- **缺口**：过滤后没有有效评分时，也可能把原检索顺序当作重排成功；补回的未评分候选与有效评分候选缺少区别。
- **用户影响**：列表虽然保留，但“模型匹配”标识可能不代表模型给出了有效结果。
- **整改目标**：校验有效索引、重复索引和有限评分；无有效结果时报告响应无效并保留检索候选。未评分候选保留原有来源，不伪装为模型匹配。
- **验收**：覆盖空结果、全部越界、重复索引、非有限评分、部分评分与候选截断；验证重排步骤状态和卡片标识均与真实评分一致。
- **源码**：[RAGSearchProviders.swift](../../../Starcat/Features/RAG/Core/RAGSearchProviders.swift)、[LocalMLXRAGReranker.swift](../../../Starcat/Features/RAG/Core/LocalMLXRAGReranker.swift)、[RepositoryDiscoveryService.swift](../../../Starcat/Features/Search/RepositoryDiscoveryService.swift)。

### C29 外部搜索错误传递与重试

- **现状**：客户端已区分鉴权、余额、限流与服务错误，但网络异常统一包装为消息字符串。
- **缺口**：取消、超时类型会丢失；HTTP 状态、Provider 身份和 `Retry-After` 没有完整进入发现诊断与恢复行为。
- **用户影响**：无法准确区分超时、断网和用户取消，重试入口也没有完整利用服务要求的等待时间。
- **整改目标**：跨层保留结构化原因，技术详情按既有机制脱敏；取消静默结束，超时保留结果，限流展示等待时间并约束重试。鉴权与配置错误不自动重复调用，也不隐式更换 Provider。
- **验收**：覆盖取消、断网、DNS / TLS 错误、超时、401 / 402 / 403 / 429 / 5xx、无效响应，以及限流等待期间不重复发起请求。
- **源码**：[ExternalSearchProviderClients.swift](../../../Starcat/Features/ExternalSearch/ExternalSearchProviderClients.swift)、[ExternalSearchModels.swift](../../../Starcat/Features/ExternalSearch/ExternalSearchModels.swift)、[SearchDiscoveryModels.swift](../../../Starcat/Features/Search/SearchDiscoveryModels.swift)。

## 3. 实施与验证边界

1. 搜索前根据现有配置生成可用能力状态，不为每次搜索额外发送一轮联网探测；真实服务可用性由本次实际请求验证。
2. 优先统一截止时间、请求身份、取消与终态，再补错误映射、缓存失效、权限和详情，避免各阶段自行解释同一故障。
3. 每项整改补能复现问题的回归测试，完成后在 Checklist 勾选并单独提交；不能用构建通过代替故障恢复或真实服务验收。
4. 2026-11-13 dong4j 已明确授权启动 Direct 后处理全部 8 项，每个问题单独提交；实施与验证完成后再勾选对应条目。
