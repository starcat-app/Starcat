# 全局搜索内容过滤方案

> 状态：2026-11-13 dong4j 确认实施；文档先行，进度见 [内容过滤 Checklist](全局搜索内容过滤Checklist.md)。
> 范围：Search Center 的全部、本地、GitHub、网页与智能发现。
> 原方案：[全局搜索优化方案](全局搜索优化方案.md)；主关联 GitHub #207 / Multica HOM-239。

## 目标与边界

全局搜索使用 Starcat 自有、版本化、可解释的本地规则库，过滤已确认不展示的仓库、指定主题和明确的危险交易或招募内容。优先控制误杀与额外延迟，不依赖模型、网络审核或新增服务。

用户提供的 `cirosantilli/china-dictatorship` 加入精确仓库规则。指定政治宣传、组织主题属于产品展示策略，与危险交易等安全类别分开记录，不统一称为违法内容。不因一个项目屏蔽同一作者全部项目。

仅影响全局搜索面板的可见性和发现上下文；保留原有收藏、笔记等数据。其他入口、数据库 schema、后端协议、MCP 和 Spotlight 不在本轮范围。

## 来源与维护

首版根据已确认类别与正反样本编写自有规则，随 App 发布，不整库导入第三方词表。参考项目如下，引用其思路不表示已经将其数据或实现嵌入 App：

| 项目 | 许可证与用途 | 取舍 |
|---|---|---|
| [konsheng/Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon) | 仓库标注 MIT，中文分类词库 | 作为候选来源；第三方数据须逐项核对出处与授权 |
| [houbb/sensitive-word](https://github.com/houbb/sensitive-word) | Apache-2.0，Java 匹配实现 | 参考归一化、边界、例外与测试设计，不引入 Java 运行时 |
| [dsojevic/profanity-list](https://github.com/dsojevic/profanity-list) | MIT，多语言冒犯性词条 | 参考类别与例外结构，不将脏话词表当成完整安全策略 |

规则记录 ID、类别、作用字段、匹配方式、词条、局部例外、来源和维护说明。更新时补正反样本并更新版本；缓存身份包含规则版本，回读仍过滤。首版覆盖简繁中文和英文，不以 UI 语言数量代替过滤覆盖。

## 匹配设计

### 精确对象

完整仓库名、GitHub 数字 ID、明确域名或 URL 精确匹配。仓库名忽略大小写，URL 按实际主机与路径解析，不把任意网页中的相似字符串当作 GitHub 身份。域名匹配须有标签边界，避免误伤相似域名。

已知仓库的 README、Issues 等子路径同属该仓库；其他作者的同名项目不自动屏蔽。查询 URL 与 `owner/repo` 执行相同规则。

### 指定主题

用户指定的政治宣传、组织主题与明确别称独立维护。不把“中国”“政治”“宗教”等宽泛词作为屏蔽条件；英文使用词边界，中文短词不跨单词拼接。

### 上下文组合

枪弹、毒品、人口、器官、隐私等对象词本身不触发屏蔽。明确交易、招揽、制作或暴力招募表达须与对象在同一字段的同一短文本片段内匹配，不能将标题和描述中的无关词拼起来。

首版覆盖枪弹或爆炸物危险活动、毒品交易、人口或器官交易、性剥削、极端暴力招募、诈骗或隐私凭据交易、赌博引流。采用保守的明确短语和组合条件，未知表达不靠猜测补判。

例外只作用于对应规则，不能覆盖精确对象或其他明确交易规则。“研究”“公益”“检测”等词不能构成全局放行条件。正常药物研发、枪声检测、反人口贩卖、器官移植、防诈骗和网络安全项目纳入保留样本。

## 性能约束

- 使用固定 locale 归一化大小写与兼容字符；保留原始字段，繁简体和别称单独维护。
- 处理已知零宽字符与常见分隔变体，保留英文词边界，避免无条件删除空格造成误杀。
- 精确集合与文本规则只加载、校验、编译一次；每个字段每次评估只归一化一次。
- 正常英文走快速路径，不为每条结果执行完整繁简转换。
- 过滤发生在结果接入时，不在 SwiftUI `body` 或重复读取的派生属性里扫描词库。
- 仅处理已经取得的元数据，不额外抓取所有 README 或完整仓库；长文本有界处理且不拼接出原文不存在的命中。

待验证目标：热态每批 100 个常规候选 P95 不超过 10 ms。基准记录实际设备、构建类型、批量规模与耗时；目标不能写成实测。

## 搜索链路

1. 查询提交：精确对象或明确禁止意图命中后，终止该轮 Provider、Router、Planner 请求，展示普通说明。
2. Provider 返回：普通搜索与发现共用过滤，在证据收集、身份提取、Rerank/Chat 前处理仓库和网页。
3. 生成查询与核验：Planner 子查询、网页提取身份与核验补全元数据同样检查。屏蔽是正常处理，不伪装成网络失败。
4. 合并与缓存：重复来源、继续查找、缓存回读保持同一规则；模型只能排序已允许候选。

Provider 本身保持通用，只在 Search Center 装配、协调与发现边界执行，避免改变其他调用者。

## 分页与数量

- 保留原游标和 `hasNextPage`，过滤空页不代表源站没有后续结果。
- 空页最多自动补取一页，计入原有预算；仍为空且有后续页时提供继续加载入口，不无限请求。
- 来源数量表示当前已加载、筛选后的去重结果。上游未过滤总量保留为检索元信息，不显示为过滤后总数。
- 按候选身份去重统计，不因最终合并或缓存读取重复累计。

## 界面反馈

复用现有详情面板，增加“内容筛选”及检查、隐藏、保留数量。普通搜索没有发现过程时，也可查看过滤结果。正常隐藏不使用错误三角，不在卡片底部增加说明行。

查询被拦截或结果全部被隐藏时提供简短说明，保留调整查询与继续加载入口。17 种 UI 语言完整覆盖，AI 初稿保留真实审核状态。详情按内容自然伸缩，不新增内部滚动与控件遮挡。

技术记录只包含规则 ID、类别、版本与统计，不复制被拦截正文、用户笔记或凭据。

## 验收样本

| 方向 | 必须覆盖 |
|---|---|
| 已知对象 | 截图仓库、大小写 URL、子路径；同名其他仓库保留 |
| 主题与变体 | 简繁中文、明确英文别称、词边界、零宽字符 |
| 上下文 | 明确交易命中；枪声检测、药物研发、公益防治、器官移植保留 |
| 误杀 | `gunicorn`、`kill-process`、Omarchy、Star 管理工具、跨字段无关词 |
| 一致性 | 本地关键词、语义、GitHub、网页、核验、重排、缓存与继续查找 |
| 请求边界 | 拦截查询不调 Provider/Planner；拦截候选不进入模型 |
| 分页 | 空页有限补取、保留游标、继续加载、统计不重复 |
| 性能 | 热态批量、规则复用、长文本有界与重复合并 |
| 构建 | 定向单测、双渠道标准构建、17 语言 Catalog 与编译资源 |

已知对象和正反回归集要求全部通过；不能据此宣称全网零漏网或零误杀。真实联网、GUI、人工译文审核与发布状态分别报告。
