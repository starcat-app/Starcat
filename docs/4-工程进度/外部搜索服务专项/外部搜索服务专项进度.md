# 外部搜索服务专项进度

> 状态: 进行中
> 创建: 2026-07-03
> 正式方案: `docs/2-产品/需求讨论/正式方案/外部搜索服务集成方案.md`
> ADR: `docs/adr/0001-external-search-provider-view-and-context-aggregation.md`
> Glossary: `CONTEXT.md`

## 1. 目标

把当前 AnySearch 专属能力升级为 Starcat 的通用 External Search 能力:

1. AnySearch、Tavily、Exa、Brave LLM Context 都作为 External Search Provider 接入。
2. 全局搜索 Web tab 保持单 Provider View,不做跨 Provider 聚合。
3. `.all` scope 只使用设置页默认 External Search Provider。
4. External Context 默认使用单 Provider,可选 Automatic。
5. Aggregate External Context Search 仅 Pro 可用,默认关闭,只用于 AI 功能外部上下文。
6. Provider API Key 是本机凭据,Test 成功后才保存并启用。
7. 外部搜索结果第一版只作为 Reference 展示,不自动入库。

## 2. 不做范围

- [ ] 不把全局搜索 Web tab 做成多 Provider 聚合视图。
- [ ] 不让 `.all` 同时调用多个 External Search Provider。
- [ ] 不做 Provider 结果质量评分或 LLM rerank。
- [ ] 不接入 SearXNG / Jina / Kagi / Perplexity / Firecrawl 等额外 Provider。
- [ ] 不把 Provider API Key 同步到 CloudKit。
- [ ] 不把 Provider enabled/default selection 同步到 CloudKit。
- [ ] 不把 External Search Result 自动识别为 `RepositoryCandidate`。
- [ ] 不自动写入 repo 数据库或知识库。
- [ ] 不让 SearchCenter filters 影响 External Context。
- [ ] 不把 External Context sources 放入 JSON 导入/导出。

## 3. 优先实施顺序

- [ ] 优先完成设置页 External Search UI 验证。
  > 说明: 先让 dong4j 看到 `External Search` 总设置组、4 个 Provider 设置组、Pro-only 聚合开关、Provider Test 状态和错误展示的真实界面;第一版可以先使用本地设置状态和占位 Test action,不阻塞于 Tavily / Exa / Brave 网络 client 全部完成。
- [ ] UI 验证通过后再进入 Provider client、缓存、SearchCenter、External Context 的完整实现。
