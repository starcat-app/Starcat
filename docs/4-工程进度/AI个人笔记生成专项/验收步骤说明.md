# AI 个人笔记生成验收步骤

> 更新: 2026-07-22
> 性质: 人工 UI / 真实 Provider 验收契约
> 注意: 本文不代表已完成人工验收；实际执行后再逐项记录证据。

## 1. 前置条件

1. 使用 Pro 权益账号，在 AI 设置中为“摘要”任务配置可用 Provider、Model 和 API Key。
2. 准备两个仓库：A 已有本地 `readme_contents.content`，B 尚未下载 README Markdown。
3. 为 A 的个人笔记写入一条不应丢失的个人决策，例如：“仅用 stable API，不使用 beta API”。
4. 打开诊断日志或 AI 用量面板，用于核对请求归因；不记录 prompt / response 正文。

## 2. 核心流程

### 2.1 本地 README 命中

1. 打开仓库 A，在“个人笔记”折叠标题行右侧点击“AI 生成”。
2. 确认标题行持续显示当前步骤和 `n/7`，展开后可见七个固定步骤。
3. 确认“读取本地 README”为已完成，“下载 README”为已跳过。
4. 确认 AI 草稿按流式逐步出现，且原笔记中的个人决策仍存在。
5. 点击“使用此草稿”，确认第七步完成，正式笔记替换为草稿并可继续手工编辑。

### 2.2 README 下载

1. 打开仓库 B 并点击“AI 生成”。
2. 确认“下载 README”先显示进行中，然后显示已完成。
3. 结束后核对本地 `readme_contents.content` 已有 Markdown，且 AI 未收到渲染 HTML。

## 3. 安全与失败路径

### 3.1 取消与折叠

1. 在 AI 正在生成时点击取消，确认当前步骤显示“已取消”，个人笔记未被改写。
2. 重试后在生成期折叠“个人笔记”，确认同样取消，标题行仍显示取消状态。
3. 生成期切换到另一个仓库，确认旧仓库 delta 不会回写新页面。

### 3.2 笔记冲突

1. 启动生成后，在 AI 完成前手工修改正式笔记。
2. 生成完成后点击“使用此草稿”。
3. 确认 Starcat 拒绝覆盖，显示“生成期间个人笔记已变更”，手工修改与 AI 草稿都保留。

### 3.3 可诊断失败

1. 用无 README 的仓库验证“下载 README”失败与“该仓库没有 README”提示。
2. 暂时移除摘要任务的 API Key，确认流程在“检查 AI 配置”失败，未下载 README，并显示现有解锁原因。
3. 制造一次本地笔记保存失败，确认 AI 草稿仍可见，恢复后可重试保存。

## 4. 外观、可访问性与用量

1. 分别在浅色 / 深色主题下验证标题行、步骤卡片、错误提示和 Markdown 草稿边界清晰。
2. 打开“减少动态效果”，确认折叠 / 展开不使用非必要动画。
3. 用 VoiceOver 读取“AI 生成”、“取消生成”、当前步骤和各步状态，确认不仅靠颜色表达。
4. 打开 AI 用量面板，确认本次请求归类为“个人笔记”，且未保存 prompt / response 正文。
