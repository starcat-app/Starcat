# AI 个人笔记生成验收步骤

> 更新: 2026-07-22
> 性质: 人工 UI / 真实 Provider 验收契约
> 注意: 本文不代表已完成人工验收；实际执行后再逐项记录证据。

## 1. 前置条件

1. 使用 Pro 权益账号，在 AI 设置中为“摘要”任务配置可用 Provider、Model 和 API Key。
2. 准备两个仓库：A 已有本地 `readme_contents.content`，B 尚未下载 README Markdown。
3. 为 A 的个人笔记写入一条不应丢失的个人决策，例如：“仅用 stable API，不使用 beta API”。
4. 打开诊断日志或 AI 用量面板，用于核对请求归因；不记录 prompt / response 正文。

## 2. 核心流程

### 2.1 本地 README 命中

1. 打开仓库 A，在“个人笔记”折叠标题行右侧点击“AI 生成”。
2. 确认标题行不重复显示当前步骤或 `n/7`，输入框下方可见七个固定步骤和当前进度。
3. 确认“读取本地 README”为已完成，“下载 README”为已跳过。
4. 确认已完成步骤使用绿色圆形勾，并仍显示“已完成”文字。
5. 确认 AI 草稿按流式逐步出现、标题整行可折叠，且原笔记中的个人决策仍存在。
6. 点击“使用此草稿”，确认正式笔记替换为草稿、步骤面板与 AI 草稿预览全部隐藏，并可继续手工编辑。

### 2.2 原位扩展与 Markdown 预览

1. 点击笔记输入框右下角扩展按钮，确认没有出现新窗口，输入框在详情页内扩展到约 480pt。
2. 确认“编辑 / 预览”切换位于右侧，且首次扩展默认选中“预览”。
3. 切换“编辑”输入 Markdown，再切回“预览”，确认渲染结果与正文一致。
4. 在预览模式收起编辑器，确认恢复约 76pt；再次扩展时仍默认进入预览。
5. 确认扩展期间仍能在同一详情页查看仓库其他信息并继续输入。

### 2.3 草稿折叠与应用收口

1. AI 草稿生成完成后折叠“AI 草稿预览”，确认 Markdown 正文和下方三个操作按钮一起隐藏。
2. 重新展开草稿，确认正文和放弃 / 重新生成 / 使用此草稿按钮一起恢复。
3. 点击“使用此草稿”，确认步骤面板和整个 AI 草稿预览均消失。

### 2.4 README 下载

1. 打开仓库 B 并点击“AI 生成”。
2. 确认“下载 README”先显示进行中，然后显示已完成。
3. 结束后核对本地 `readme_contents.content` 已有 Markdown，且 AI 未收到渲染 HTML。

### 2.5 步骤耗时与草稿复制

1. 启动一次生成，确认当前运行步骤的耗时持续增长，已完成步骤的数值保持不变，未执行与已跳过显示 `—`。
2. 生成期折叠笔记、切换 repo 后再切回，确认同一会话的步骤耗时连续；放弃或重新生成后确认旧耗时已重置。
3. 草稿完成后点击复制，核对系统剪贴板是完整 Markdown，按钮显示绿色圆形勾并在约 1.5 秒后恢复。
4. 折叠“AI 草稿预览”后重复复制，确认仍可写入完整 Markdown，且点击复制不会切换折叠状态。

## 3. 安全与失败路径

### 3.1 显式取消与折叠继续生成

1. 在 AI 正在生成时点击取消，确认当前步骤显示“已取消”，个人笔记未被改写。
2. 重试后在生成期手工折叠“个人笔记”，等待一段时间再重新展开，确认没有进入“重试”状态，并继续显示同一个生成任务或已生成草稿。
3. 再次生成并切换到另一个仓库，确认原任务继续且 delta 不会回写新仓库页面。
4. 切回原仓库，确认“个人笔记”自动展开，并继续显示同一个生成任务或已生成草稿。

### 3.2 笔记冲突

1. 启动生成后，在 AI 完成前手工修改正式笔记。
2. 生成完成后点击“使用此草稿”。
3. 确认 Starcat 拒绝覆盖，显示“生成期间个人笔记已变更”，手工修改与 AI 草稿都保留。

### 3.3 可诊断失败

1. 用无 README 的仓库验证“下载 README”失败与“该仓库没有 README”提示。
2. 暂时移除摘要任务的 API Key，确认流程在“检查 AI 配置”失败，未下载 README，并显示现有解锁原因。
3. 制造一次本地笔记保存失败，确认 AI 草稿仍可见，恢复后可重试保存。

## 4. 外观、可访问性与用量

1. 分别在浅色 / 深色主题下验证标题行、步骤卡片、错误提示和 Markdown 草稿边界清晰。
2. 打开“减少动态效果”，确认折叠 / 展开不使用非必要动画。
3. 用 VoiceOver 读取“AI 生成”、“取消生成”、当前步骤和各步状态，确认不仅靠颜色表达。
4. 打开 AI 用量面板，确认本次请求归类为“个人笔记”，且未保存 prompt / response 正文。
