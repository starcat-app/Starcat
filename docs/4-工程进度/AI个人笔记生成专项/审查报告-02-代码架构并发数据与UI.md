# AI 个人笔记生成审查报告 02：代码架构、并发、数据安全与 UI

> 审查日期: 2026-07-22
> 审查基线: `dev@e0b9d69`
> 范围: README 准备、AI Service、七步状态机、Repository 写入、SwiftUI 生命周期与可访问性
> 结论: 发现 1 项数据暴露风险和 1 项 UI 语义漂移，本轮不通过，需先修复。

## 1. 审查方法

1. 沿 `RepoNotesSection -> RepoNoteAIGenerationViewModel -> RepoAIInsightService` 正向追踪输入、流式回调、取消与保存。
2. 反向核对 `generationID`、Task cancellation、视图销毁、仓库切换和折叠时的迟到回包保护。
3. 检查 AI 请求字段、日志和 UI 错误详情，确认 README / 私有笔记 / Prompt / 响应不会进入诊断输出。
4. 核对 `repo_notes.is_ai_generated` 在 AI 应用、人工修改、状态修改和知识库状态修改中的写入语义。
5. 对照 UI 规范检查折叠整行点击、同级 Button、focus ring、颜色、Reduce Motion 和辅助功能。

## 2. 发现

### P1-01：错误详情接受任意底层 `localizedDescription`

- 现状：`RepoNoteAIGenerationViewModel.fail` 把任意 `Error.localizedDescription` 写入 `errorDetail`，面板会直接展示。
- 风险：当前 `AIClientError` 的 `errorDescription` 已是受控短文案，但 README Repository、第三方 Provider 或未来错误类型可能把数据库路径、请求细节甚至响应片段放进 `localizedDescription`，与“不得展示完整 Provider 响应 / 本地敏感诊断”的设计边界冲突。
- 修复：只允许本专项错误、`RepoAIInsightError`、`AIClientError`、`EntitlementGateError` 等已审计 `LocalizedError` 的受控 `errorDescription` 进入详情；未知错误只显示稳定通用 i18n 文案，不透传底层描述。
- 验证：新增未知错误不进入 `errorDetail`、受控配置错误仍可读的单元测试。

### P2-01：空笔记与已有笔记的入口文案没有区分

- 需求：正式方案 §6.1 约定空笔记显示“AI 生成笔记”，已有笔记显示“AI 优化笔记”，让用户在发送现有私有内容前理解操作语义。
- 现状：标题行始终显示同一个 `repo.notes.ai.generate`。
- 修复：Header Control 接收 `hasExistingNote`，按当前编辑 buffer 切换 generate / optimize 文案与帮助文本；两种帮助文本都保留发送到配置 AI Provider 的隐私明示。

## 3. 已确认无问题项

- 请求构造仅包含 README Markdown、existing note、输出语言、模型和参数；未注入 HTML、metadata、代码、外部搜索、标签、摘要或 RAG。
- `generateText` 对流式和非流式都在返回前检查 Task cancellation；delta 只写独立草稿。
- `generationID` 在每个异步阶段和 delta 回调处阻止旧请求写回；切仓、折叠、视图销毁均会取消任务。
- 应用前比较当前 `editingContent` 与冻结快照；冲突与保存失败均保留草稿，不写正式 buffer。
- Repository 只原子更新 content、`is_ai_generated`、edited_at；不覆盖 status / library state。
- AI 应用写 `true`，人工 UI、Companion 与 MCP 通过两参数 API 自然写 `false`；状态与知识库写入不改 AI 标记。
- 标题行没有嵌套 Button；plain Button 均禁用 focus ring；状态不只依赖颜色。
- 本轮审查未发现 schema 变更需求。

## 4. 修复顺序

1. 收紧错误详情白名单并补单元测试。
2. 区分生成 / 优化入口文案和隐私帮助文本。
3. 执行专项测试与静态检查，再回填本报告及 Checklist。
