## 1. 交付结论

本专项已把 `starcat-weekly-api` 从三类硬编码来源升级为可扩展的 Weekly 多来源聚合服务，并完整接入 HelloGitHub、AI 情报批量录入、多项目置顶、Starcat 动态来源展示和本地运营台。新增来源不再要求复制来源专属数据库表、DTO 与 UI 分支；后续渠道必须先登记固定来源目录，再完成客户端与运营能力后启用。

## 2. 已完成能力

### weekly-api

- 追加 schema migration，建立固定来源目录、通用来源事件、持久化批次/任务与有序置顶；
- 旧 weekly/ZRead/Show HN 来源事实幂等迁移，Collector 停止双写；
- bulk v2 返回动态来源目录、通用来源条目与置顶字段；
- POST 先持久化，commit 后非阻塞唤醒 Worker；Worker 启动扫描并每 15 分钟兜底；
- 支持 30 分钟租约恢复、15/30 分钟退避、最多 3 次尝试和失败剔除；
- HelloGitHub featured 增量、月刊对账、全历史回填、持久化 cursor 与重启恢复；
- AI 情报批量录入、来源能力校验、稳定幂等、批次查询和安全来源链接；
- 仓库搜索与多项目置顶完整顺序原子替换。

### Starcat

- Weekly 来源改为 raw-value + 动态 descriptor，未知来源可无损解码和展示；
- 追加 `v11-weekly-multi-source`，缓存来源目录、通用条目和置顶字段；
- 来源/语言/状态过滤后统一执行置顶优先排序；
- 来源筛选显示动态 count，支持 HelloGitHub 与 AI 情报分类；
- 来源 presentation resolver 跟随应用语言，已知来源使用本地图标或 SF Symbol；
- 详情展示可折叠通用来源事件时间线与原文链接。

### Skill 与 local-admin

- 新增中文 `.claude/skills/starcat-weekly-import`，覆盖文本提取、网络搜索、真实性核验、用户确认、受控来源查询、整批提交和终态轮询；
- 提交脚本默认 dry-run，只从环境变量读取 admin key，相同 payload 生成稳定 SHA-256 幂等键；
- local-admin 增加 Weekly 通用 API Console、来源/队列状态、HelloGitHub 增量/对账/回填、异步批次反馈和多项目置顶编辑。
