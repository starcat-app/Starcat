## 发现问题

### P1-1 状态 popover 为一行摘要执行完整 Dashboard 聚合

状态 popover 只展示今日 `AIUsageSummary`，但调用 `statistics(recentLimit: 1)` 后仍执行按日、按功能、按模型、最近调用和两个全历史 DISTINCT 查询。用户每次打开全局状态入口都会产生不必要的多组 SQL，事件量增长后影响轻量入口响应。

修复要求：Repository 提供只执行汇总 SQL 的 `summary` 查询；完整 `statistics` 复用同一汇总实现，popover 改走轻量接口。

### P1-2 当前代加载被取消后 `isLoading` 不会复位

`reload()` 在捕获 `CancellationError` 时直接 `return`，跳过末尾的 `isLoading = false`。窗口仍存活而当前加载任务被取消时，刷新按钮和加载态会永久停留；旧 generation 被新请求替代时则不应清理新请求的 loading 状态。

修复要求：用 generation-aware 的统一收尾保证“仅当前代”结束时复位 loading，取消仍不展示错误。

### P2-1 缺少 ViewModel 并发和错误状态单元测试

Checklist 要求 ViewModel 单元测试，但现有专项测试只有采集和 Repository，无法防止取消卡 loading、旧请求覆盖新筛选结果、错误展示后成功请求不清理等状态回归。

修复要求：新增可控 Repository test double，覆盖成功加载、错误状态、当前代取消、旧请求晚返回不覆盖新快照。
