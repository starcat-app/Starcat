# 第一轮审查报告：代码架构、数据库迁移与隐私

> 审查时间: 2026-07-19
> 审查范围: `v14-ai-usage-events`、GRDB Repository、`AIUsageRecorder`、`OpenAIClient` 采集边界、全部业务归因调用点
> 结论: 发现 3 项需修复问题，隐私与迁移边界通过

## 已通过

1. `v1-initial` 未修改，新表通过追加 `v14-ai-usage-events` 创建，符合已发布数据库迁移铁律。
2. 事件表和领域模型不含 prompt、response、API Key、Base URL、HTTP body 或完整错误文本。
3. 用量表没有 CloudKit model / sync adapter，数据保持当前用户本地 SQLite 物理隔离。
4. Repository 每次读取 `database.writer`，账号切换后不会继续写入旧用户数据库。
5. 缓存输入和推理输出作为输入 / 输出子集保存，聚合总量不做二次相加。
6. 所有生产 `OpenAIClient` 调用点均获得稳定功能归因；RAG 请求级 context 能区分 planning / answer / compression / title。
7. 统计旁路写入失败不会改变 AI 请求成功或失败结果。

## 发现问题

### P1-1 流式兼容 fallback 少记一次 HTTP 调用

Provider 拒绝 `stream_options.include_usage` 后，当前实现会无 usage 重试并最终只记录一次成功事件。真实网络侧发生了“第一次拒绝 + 第二次成功”两次 HTTP 请求，与“一次推理 HTTP 请求计一次调用”的口径不一致。

修复要求：进入 fallback 前先记录第一次失败事件，并为第二次请求重新开始计时；最终成功 / 失败单独记录第二次事件。

### P1-2 Embedding 无效响应丢失已返回 usage

Embedding Provider 可能返回 `usage`，但向量数量或维度为空导致 Starcat 判定 `emptyResponse`。当前 catch 路径统一写 token 不可用，丢掉 Provider 已返回的精确 token。

修复要求：在结构校验前保存 `EmbeddingsResult.usage`，失败事件继续携带精确 input / total token。

### P2-1 取消事件写入 `error_category = unknown`

取消是请求终态，不是 Provider 错误。当前传入 `CancellationError` 后被工厂归为 `unknown`，会让后续错误分类统计把用户取消混入未知失败。

修复要求：`status = cancelled` 时固定 `error_category = NULL`。

## 隐私结论

通过。新增持久化字段均为数值、时间、稳定枚举或用户已配置的 Provider / 模型标识；没有扩大内容型敏感数据落盘面。
