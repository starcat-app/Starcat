# Agent Run 持久化专项审查报告 02

> 审查时间: 2026-07-07 17:52
> 审查范围: Runtime 写入、Repository 读写、数据库迁移、单测覆盖

## 结论

发现 1 个取消路径持久化不稳定问题,需要修复后再跑专项单测。

## 发现

1. `DefaultAgentRuntime` 的完成、失败路径会明确写入 run 终态,但 stream 消费端取消时只依赖循环中的 `Task.isCancelled` 检查写入 `.cancelled`。如果取消发生在工具执行中或 run 任务尚未推进到下一次检查,本地历史可能短暂或永久停留在 `.running`。

## 修复计划

- 在 Runtime 内维护 run 终态标记,让 `AsyncStream.onTermination` 在非终态取消时补写 `.cancelled`。
- 补充 Runtime 持久化取消状态的单测。
- 重新执行 Agent Runtime / Repository / ViewModel 相关单测。
