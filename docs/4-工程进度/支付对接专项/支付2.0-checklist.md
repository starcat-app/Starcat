# 支付 2.0 改造 Checklist

> 创建：2026-07-08
> 状态：核心链路已完成；Waffo 真实接入等待后续 API 文档与测试凭证
> 前置：`docs/4-工程进度/支付对接专项/checklist.md`
> 当前问题：落地页 Buy 按钮未接入支付；后端只有单 Creem provider 装配，没有 payment router、渠道切换与失败策略。

---

## 1. 目标

- [x] 落地页 `Buy Pro Monthly` / `Buy Pro Lifetime` 真实接入自家 checkout API。
- [x] 落地页不直连 Creem / Waffo / 任意第三方支付 URL。
- [x] `supports/starcat-license-api` 提供 payment router，统一管理支付 provider 选择。
- [x] Creem 作为当前首个可用支付渠道接入 router。
- [x] Waffo 作为后续支付渠道预留 provider adapter 边界，不在落地页或 App 内写死。
- [x] 支付成功页继续统一生成 `starcat://license/activate?...`，App 不感知支付渠道。
- [x] 支付渠道故障时有明确切换策略、错误语义和验证记录。

## 2. 已满足约束

- [x] 不把 Creem product id 暴露到落地页 JavaScript 或 macOS App。
- [x] 不让落地页直接持有支付渠道 API key。
- [x] 不在本轮实现 Waffo 真实 API，除非后续已拿到 Waffo API 文档、测试 key 和 webhook 规则。
- [x] 不实现跨支付渠道自动迁移订阅；月订阅升级 lifetime 的取消订阅仍走当前 Direct 设置页入口。
- [x] 不把 App Store StoreKit 流程并入 Direct 支付 router。

## 3. 落地页改造

- [x] 英文页 Monthly 按钮从 disabled span 改为可点击按钮 — `pages/index.html`。
- [x] 英文页 Lifetime 按钮从 disabled span 改为可点击按钮 — `pages/index.html`。
- [x] 中文页 Monthly 按钮从 disabled span 改为可点击按钮 — `pages/index-zh.html`。
- [x] 中文页 Lifetime 按钮从 disabled span 改为可点击按钮 — `pages/index-zh.html`。
- [x] 按钮点击调用 `POST /v1/direct/checkout`，请求只传 `plan=monthly|lifetime` 和可选 `requestID`。
- [x] checkout 成功后跳转后端返回的 hosted checkout URL。
- [x] checkout 请求失败时展示落地页内联错误，不暴露 provider 原始错误、API key、product id。
- [x] 按钮 loading / disabled 状态完整，避免重复创建 checkout。
- [x] 英文页和中文页行为保持一致。

## 4. 后端 Payment Router

- [x] 新增 provider id 模型，例如 `PaymentProviderID`：`creem`、`waffo`。
- [x] 新增 payment router，handler 只依赖 router，不直接持有某个 provider。
- [x] router 按配置选择 primary provider。
- [x] router 支持 configured fallback provider 列表。
- [x] router 返回的 `PaymentURLResponse.provider` 必须是真实命中的 provider。
- [x] provider 不可用时返回稳定错误码：`PAYMENT_PROVIDER_UNAVAILABLE`。
- [x] plan 到 product id 的映射留在后端 provider 配置中。
- [x] provider request / response 日志脱敏，不记录 API key、完整 license key、完整 customer 私密信息。

## 5. Creem Provider

- [x] `CreemPaymentProvider` 接入 payment router。
- [x] Creem checkout 创建保留当前 `plan` metadata。
- [x] Creem success redirect 继续校验签名。
- [x] Creem checkout retrieve 能反推出 `plan`，并写入 activation deep link。
- [x] Creem webhook endpoint 保持当前 `/v1/webhooks/creem`，不因 router 改造破坏。
- [x] Creem test/live 两套 product id 配置保持隔离。

## 6. Waffo Provider 预留

- [x] 新增 Waffo provider adapter 文件骨架或设计文档，明确未配置时不可用。
- [x] Waffo provider 不影响 Creem 当前生产路径。
- [x] Waffo product id / API key / webhook secret 配置项命名预留。
- [ ] Waffo success redirect 必须适配到统一 `CheckoutResult` 模型后才能启用。
- [ ] Waffo webhook 必须适配到统一授权事件模型后才能启用。

## 7. 失败切换策略

- [x] 配置项支持 `PAYMENT_PROVIDER_PRIMARY=creem`。
- [x] 配置项支持 `PAYMENT_PROVIDER_FALLBACKS=waffo`。
- [x] 配置项支持禁用自动 fallback：`PAYMENT_PROVIDER_FALLBACK_MODE=off`。
- [x] 默认策略建议先设为 `off`，避免真实订单被静默切到未完整验收的渠道。
- [x] 允许后端在 provider 明确不可用时返回可观测错误，由运营手动切换 primary。
- [x] 若后续启用自动 fallback，只允许在 checkout 创建前失败时切换；已经创建 checkout 后不得跨 provider 继续同一订单。
- [x] fallback 发生时记录 provider、plan、requestID、错误码，不记录敏感信息。

## 8. 成功页与 License Activation

- [x] 成功页只展示 Order 和 License；生产环境不展示 checkout/subscription 调试信息。
- [x] 测试环境保留调试信息但标明 Test Mode。
- [x] 成功页 activation URL 带 `license_key`、`product_id`、`plan`。
- [x] 月订阅成功页 activation URL 带 `subscription_id`。
- [x] lifetime 成功页不要求 `subscription_id`。
- [x] 成功页不出现 Creem-only 文案，除非在测试/技术详情中显示 provider。
- [x] App 侧 `activateFromPaymentSuccessURL` 不依赖 provider 名称。
