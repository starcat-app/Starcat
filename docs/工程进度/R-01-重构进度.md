## 7. v1.4 修订（dong4j 2026-06-10 14:30 bug 反馈）

### 背景

dong4j PR 合并到 main 后真机测试发现：trending / weekly / activity / manage 详情页在**未登录**且本地命中（曾登录留下的本地数据 → `repo.id != 0`）时，**Tags / Notes (含阅读状态) / Releases 订阅** 三段 + **分享 / AI** trailing actions 仍会渲染——但这些组件在语义上都是「用户登录后的私人功能」，未登录态展示是误导，且会泄漏上一个登录用户的私人数据。

根因：

1. `RepoLocalSections` 仅以 `repo.id != 0` 作为可见性条件，漏了「已登录」前提；
2. `AuthSession.signOut()` 出于「保护用户数据，重新登录后不丢笔记」的合理设计，**不**清空 `repo_tags` / `repo_notes` / `release_subscriptions` 表；
3. trending / weekly 详情页 `resolveRepo` 走 `findByOwnerName` 仍可能命中本地（`repo.id != 0`），单 id 守卫无法防住「已登出 + 本地有历史数据」corner case；
4. `trailingActions` 的 4 个调用方同样只看 `repo.id != 0`（trending）或无条件展示（manage / activity），漏了「已登录」前提。

### 修复（2 个 commit）

| commit | 范围 | 改动 |
|---|---|---|
| `e00bdf5` | 三段（Tags / Notes+阅读状态 / Releases 订阅） | `RepoLocalSections.swift` 内部注入 `@Environment(AuthSession.self)`，把可见性收紧为 `isAuthenticated && repo.id != 0`，4 个 ContentView 调用方零改动；`.animation(value:)` dependency 从 `repo.id` 切到计算属性 `isVisible` 覆盖三种触发源（登录态变 / repo.id 变 / 切不同详情页） |
| `1564481` | trailingActions（分享 / AI） | 4 个调用方一致加 `isAuthenticated` 守卫——`TrendingScaffoldShell.trailingActions(for:)` / `WeeklyDetailView.trailingActions(for:repo:)` / `RepoDetailView` 行内三元 / `ActivityDetailView` 行内三元；`.weeklyIssue`（公开 GitHub issue 外链）与登录态独立保持原样；不抽 helper（每处 1-2 行，间接层得不偿失）；`RepoDetailView` 顺手新增 `@Environment(AuthSession.self)` 注入 |

### 设计文档同步

- `docs/详细设计/18-三场景共用架构.md` §3.2.4 末尾追加 「v1.4 设计修订」段（与 v1.3 同风格的 amendment block），明文记录可见性条件从 `repo.id != 0` 收紧为 `isAuthenticated && repo.id != 0`，并配套说明 trailingActions 的同步守卫。
- 4 个调用方源码内注释提及 v1.4 修订日期 + dong4j 反馈来源，与设计文档双向引用。

### 决策要点

- **不抽 helper**：4 个调用方每处 1-2 行，抽出一个全局 `detailActionsForLocalRepo(repo:isAuthenticated:)` 反而增加间接层 + 文件依赖网，违反「Surgical Changes」原则。
- **manage / activity 加守卫纯防御**：业务上这两个场景必登录才能进（HomeViewModel / ActivityFeed 都依赖 token 拉数据），但加守卫不增成本，且与 trending / weekly 全场景一致 → 后续不必担心新接入场景漏检。
- **`.weeklyIssue` 不动**：公开 GitHub issue 外链与登录态语义独立，与「分享卡上传后端 / AI 摘要 BYOK key」的登录依赖性质不同。

### 测试基线

xcodebuild test 维持 **405 项全绿**。无新增 / 删除测试（守卫纯 view 层条件，View 层目前无 SwiftUI snapshot 测试覆盖；功能验证由 dong4j 真机回归）。
