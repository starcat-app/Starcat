# UI 规范：列表交互、详情切换与骨架加载

> 生效日期：2026-11-14
> 默认适用更新：2026-11-15
> 适用范围：所有新增或修改的列表、导航菜单、详情页及其加载状态。
> 执行方式：AI 必须主动读取并执行，无需 dong4j 再说“参考 Codenotch”。
> 本文是 Starcat 的默认 UI 约定；交互动效参考 Codenotch，参数取自本项目设置页与 Skills 的实现，不代表上游项目的原始参数。

## 一、需求含义与范围

新增或修改上述界面时，按当前页面具备的列表、选择、详情和异步加载场景，默认交付对应效果：

| 区域 | 必须呈现的效果 |
|---|---|
| 常规行列表 | 弱对比斑马纹，交替区分相邻数据行 |
| 列表悬停 | 整行轻微提亮并平滑恢复，图标或名称可局部微移，行布局保持稳定 |
| 单选导航 | 同一块选中背景与描边通过弹簧动画跨行滑动 |
| 原生详情 | 固定区域内，旧页模糊淡出、新页同步恢复清晰 |
| 异步 / WebView 详情 | 旧内容退场后更新内容，当前内容渲染就绪后再淡入 |
| 列表 / 详情主体加载 | 贴合真实布局的骨架屏 + 柔和扫光或明暗动画，就绪后平滑交接 |
| 已有内容刷新 | 保留当前结果，通过局部刷新状态反馈进度 |
| 减少动态效果 | 关闭跨行位移、悬停微移、模糊与骨架扫光，保留静态高亮、静态骨架和短时纯淡化 |

左侧选中反馈应在点击后立即响应，独立于右侧加载进度。只做悬停提亮、逐行切换底色，或只给新详情加淡入，均不满足完整要求。

只调整当前任务涉及的页面；不自动批量改造历史界面。仅有列表时应用列表规则，有详情时检查完整出入场，存在主体加载时落实骨架与内容交接。斑马纹面向常规行列表，卡片网格和独立分区沿用其既有表面层级。原生控件已有对应反馈时优先复用，保持原有操作语义。实施前仍按 `AGENTS.md` 给出方案并等待明确授权，已获授权的任务直接落实这些默认要求，无需为每项效果重复询问。

## 二、列表底色、选中与悬停

### 2.1 常规行列表默认使用斑马纹

- 使用低对比、中性的交替底色区分相邻数据行，适配明暗主题；复用页面现有配色，避免硬编码只能适用一种主题的颜色。
- 条纹按筛选、排序后的展示索引计算，分页追加时延续索引；滚动或视图复用不能让同一行的条纹无故跳变。
- 视觉优先级统一为选中 > 悬停 > 斑马纹底色，条纹不覆盖选中背景、描边或语义色。

### 2.2 单选导航的选中背景必须连续滑动

- 单选导航列表使用稳定的共享几何空间；选中背景和描边共享身份，随当前选择跨行移动。`@Namespace` 与 `matchedGeometryEffect` 是现有参考方式。
- 移动的是背景与描边，文字、图标、复选框和整行位置保持稳定。悬停引起的局部微移另行处理。
- 选中、悬停、普通行背景分别表达状态，优先级为选中 > 悬停 > 普通底色 / 斑马纹；悬停不能抹掉当前选中态。
- 原生 `Button`、键盘导航、焦点与辅助功能语义继续保留。使用 `.buttonStyle(.plain)` 时遵守 [Focus Ring 规范](UI-Focus-Ring-规范.md)。
- 多选列表保留每个已选项的状态，不用一块滑动背景替代多选；同时存在“当前详情”和“批量勾选”时，两种状态保持独立。
- 保留已有 `LazyVStack`、分页与滚动策略。不得仅为背景动画把长列表改为全量创建；滚动驱动分页继续遵守 [列表分页加载规范](UI-列表分页加载规范.md)。
- 源行或目标行因懒加载未实例化、筛选或删除而不可见时，不构造不存在的跨行轨迹；新选中态仍须准确落位。可见行之间必须实际验证连续滑动。

### 2.3 鼠标悬停时整行高亮

- “光标聚焦高亮”指鼠标悬停反馈，键盘焦点语义独立保留。移入时整行低透明度提亮，移出时平滑恢复；按页面结构选择图标或名称区做轻微水平位移。
- 不移动复选框，不改变行高、间距、点击区域或列宽，不缩放整行。
- 保留图标原有强调色、品牌色及语义色，不能因加动画或统一前景色而丢失颜色；普通文字与图标继续遵守 [颜色规范](UI-颜色规范.md)。
- 批量勾选与当前详情选择保持独立；点击复选框不能被新增的整行点击手势吞掉。

## 三、详情切换

### 3.1 原生页面：交叉模糊淡化

- 详情承载区域在切换前后保持尺寸稳定；切换时保留离场页，让旧页模糊淡出、新页同步从模糊透明恢复清晰。
- 通过透明度和模糊表达交接，不缩放、推移整个表单，也不让详情尺寸随动画跳动。
- 需要 `.id(selection)` 驱动页面出入场时，仅作用于对应详情子树。导航、搜索、历史、弹框及需要跨页保留的状态由稳定的外层持有。
- 局部表单状态继续遵守原页面的保存规则；不能把加了过渡等同于所有草稿都会自动保留。
- 检查 `ZStack` 层级与裁剪范围，避免离场页提前被遮住，或模糊内容越过分栏边界。

### 3.2 异步 / WebView：退场、换内容、就绪、入场

复用同一个阅读器时，按以下顺序切换：

1. 点击后立即更新列表选择；异步准备新内容可与旧内容退场并行。
2. 保留旧内容的展示快照，直到退场完成。标题、文件清单、目录等同属该快照的内容不能提前换成下一项。
3. 收到退场完成信号后，检查任务取消及当前选择；仍需等待时显示对应布局的骨架，再更新阅读器内容和展示快照。
4. 原生文件清单或目录准备好即可入场；Markdown / WebView 必须等当前文档的渲染就绪回调。
5. 只允许当前请求、当前选择及当前文档匹配的结果入场；过期任务或回调不得把旧内容重新显示出来。

使用动画完成回调安排换内容，例如现有 `withAnimation(..., completionCriteria: .removed)`；不能用固定 `sleep` 猜测退场或渲染完成时间。动画参数描述动效节奏，实际读取与渲染耗时另计。

缓存命中也要经过正确的退场与入场；若阅读器仍持有同一份已渲染文档，应复用其有效就绪状态，不能等待不会再次发生的导航回调。

`WKWebView` 保持稳定身份，通过文档身份区分内容。不得为重播动画给整个阅读器加条目 `.id`，造成重复创建、解析或加载。只有旧内容实际退场后才能替换其 DOM。

退场及等待期间，隐藏内容不能继续接收点击或被辅助功能当作当前详情。读取失败沿用页面原有错误与重试反馈，过渡状态不能让内容永久透明或一直等待。

## 四、内容加载：骨架屏与动画

### 4.1 主体加载默认使用对应布局的骨架

- 列表、详情、文档等主体区域的首次异步加载必须使用骨架屏和轻量动画，不能只在空白区域放一个 `ProgressView` 菊花。
- 列表骨架保留真实行高、图标或复选框、文字条及斑马纹；详情骨架按标题、正文、元数据、文件大小列或目录缩进等实际结构占位。骨架到内容的尺寸和起始位置应稳定。
- 复用已有骨架组件、主题配色和动画时钟，使用柔和扫光或明暗变化；少量首屏占位即可，不为每行单独创建高频计时器。
- 刷新按钮、提交按钮等紧凑操作可以使用局部旋转指示器；滚动追加沿用[列表分页加载规范](UI-列表分页加载规范.md)，已有结果保持可见，不用全屏骨架覆盖。

### 4.2 骨架和内容跟随真实状态交接

- 首帧已知要加载且尚无结果时就显示骨架，覆盖异步任务尚未启动的短暂窗口；真实空结果、失败和重试分别进入页面原有状态，不能永久显示骨架。
- 列表数据与筛选结果可发布后再淡出骨架、淡入列表。Markdown / WebView 必须等待当前文档的渲染就绪信号，不能把 HTML 准备完成当成渲染完成。
- 详情切换先让旧内容完成退场，确有等待时再显示骨架；当前内容就绪后，骨架淡出、内容恢复清晰，衔接三节规定的详情过渡。
- 缓存内容已经就绪时直接完成正常出入场，不强行插入骨架；不使用固定 `sleep` 或最短展示时间制造等待。
- 已有内容刷新时保留当前结果；仅在没有可展示内容的加载阶段显示主体骨架。筛选最终无结果时回到真实空状态。
- 骨架不响应点击，也不作为真实内容被辅助功能朗读；隐藏或退场中的旧内容同样不应接收交互。减少动态效果时使用静态骨架和简短淡化。

## 五、默认参数与减少动态效果

以下是本项目的默认起点；确需调整时，在实施方案中说明原因和验收口径，不能通过拉长动画掩盖加载卡顿。

| 动效 | 默认参数 | 减少动态效果 |
|---|---|---|
| 选中背景跨行 | `.spring(response: 0.34, dampingFraction: 0.82)` | 关闭位移动画，直接更新选中态 |
| 悬停 | `.easeOut(duration: 0.14)`；局部水平位移 `1.5pt` | 保留静态提亮，关闭微移与悬停动画 |
| 原生详情交叉过渡 | `.easeOut(duration: 0.24)`；模糊半径 `10pt` | `120ms` 纯淡化 |
| 异步详情退场 / 入场 | 各 `120ms`；模糊半径 `10pt`；等待时间另计 | 各 `60ms` 纯淡化；等待时间另计 |
| 骨架加载 | 复用现有骨架的柔和扫光时钟与主题配色 | 静态骨架，关闭扫光 |
| 列表骨架到内容 | `.easeOut(duration: 0.18)`；详情交接沿用对应详情过渡 | `120ms` 纯淡化 |

统一读取 `starcatReduceMotion`，不另设页面私有开关。明暗主题分别检查背景、描边与文字对比度；圆角和颜色延续所在页面的视觉规范。

## 六、状态与性能边界

- 快速 A → B → C 时，允许动画被打断，最终选择和详情必须都是 C，B 的延迟结果不得回填。
- 重复点击当前项不应无故重播过渡或重新读取；明确的刷新动作沿用原行为。
- 搜索、筛选、分页、键盘导航、批量勾选、页面保存与滚动位置策略不因新增动画改变。
- 将动画限制在选中背景、悬停绘制及详情承载区域；避免对整窗或业务数据更新施加宽泛动画。
- 优先参考现有实现；共享组件抽离需要单独评估与确认，不把遵守本规范等同于必须引入通用组件。

## 七、实施与验收

实施方案至少说明：目标页面、列表容器与选择语义、斑马纹与悬停状态、详情是原生还是异步、加载骨架布局、状态由谁持有、渲染就绪信号及验证方式。先核对源码和已确认决策，再做最小改动。AI 应主动核对下表所有适用项，不能把用户未单独提及某种效果当作遗漏理由。

| 检查场景 | 验收要点 |
|---|---|
| 常规行列表、筛选与分页 | 斑马纹清晰克制，索引连续，滚动时条纹稳定 |
| 相邻行与跨多行切换 | 背景和描边连续滑动，文字与复选框不跟着滑 |
| 悬停进入、离开及悬停选中行 | 整行平滑提亮、恢复，选中 > 悬停 > 斑马纹，图标颜色正确 |
| 快速连续点击、重复点击当前项 | 最终详情准确，无过期回填、闪回或无故重播 |
| 滚动后切换、搜索与筛选变化 | 选中落位正确，懒加载与分页行为不退化 |
| 原生详情切换 | 旧页确实退场、新页入场，表单尺寸和保存行为稳定 |
| 首次加载、筛选等待与慢加载 | 对应布局的骨架和加载动画可见，真实就绪后平滑交接，布局不跳动 |
| 缓存命中与已有内容刷新 | 缓存直接过渡、刷新保留内容，无骨架闪现或人为等待 |
| 空结果、失败与恢复 | 正确结束骨架，空态、错误和重试可用，不永久透明或停留在旧详情 |
| 文件清单与目录 | 退场快照一致，没有提前替换成下一项的附件 |
| 明暗主题、减少动态效果 | 条纹与高亮可辨，减少动态时无位移、模糊和扫光 |
| 键盘导航与批量勾选 | 原有焦点、选择和操作语义保留 |

交付时分别记录代码完成、自动化测试、构建 / 启动及 GUI 实际验收。代码中出现 `matchedGeometryEffect`、测试通过或 App 成功启动，都不能代替“实际看到背景跨行滑动和详情完整出入场”的验收结论。

测试、构建及启动按根 `AGENTS.md` 选择标准入口和 UI 豁免规则；界面操作继续遵守 Computer Use 授权边界。无法做实机验收时明确标为待验收，不补写为通过。
