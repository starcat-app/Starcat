> 本文档是 Starcat 国际化（i18n）开发的【硬性规约 + 踩坑清单】，所有 AI Agent / 协作者新增或修改国际化代码前必读。
> 单一信任源；与 `CLAUDE.md` / `AGENTS.md` 中相关章节冲突时，以本文为准。
> 最后更新：2026-08-18

## 0. 硬性铁律（看不懂下面再看，先把这 6 条印进脑子）

1. **新代码禁止** `String(localized:)`，**禁止** `NSLocalizedString`。返回 `String` 的本地化场景只能用 **`String.l10n("key")`**。
2. SwiftUI 接 `LocalizedStringKey` 的 view（`Text` / `Label` / `Button` 等）**直接写 `Text("key")`，不要套 `String.l10n`**。
3. **每个** `.sheet { }` / `.popover { }` 闭包内根视图、**每个**自建 `NSWindow` / `NSPanel` 的 hostingView 根视图，**必须**挂 `.appLocaleEnvironment()`。
4. **任何 Foundation 日期/数字 formatter（`RelativeDateTimeFormatter` / `Date.RelativeFormatStyle` / `DateFormatter` / `NumberFormatter` 等）默认走系统 locale，必须显式注入 SwiftUI `\.locale` 才会跟随设置切换。**
5. **编辑 `Localizable.xcstrings` 必须保持 Xcode String Catalog 格式：每个 JSON 键后的冒号左右各一个空格，即 `"key" : value`。禁止使用会将整个文件重排为 `"key": value` 的 formatter 或序列化脚本。**
6. **禁止用脚本读写 / 拼接 / 插入 `Starcat/Resources/Localizable.xcstrings`。** 目录已经非常大（约 48 万行）。只允许用相邻已有 key 做**唯一关键词匹配**的局部插入或修改。改完立刻看 `git diff --stat`：只应增加几十行，出现上万行删除必须停手，**禁止再写抢救脚本**。

### `Localizable.xcstrings` 编辑格式

字符串目录体积大。工具把文件读进内存再写回、或 `json.dump` / `jq` 重写，会截断、重排、毁掉未提交的其它 key，dong4j **无法从这种损坏里干净还原**。

**只允许**：在相邻已有 key 的唯一上下文里做局部替换（编辑器 search-replace / StrReplace）。例如新增 `search.semantic.querying` 时，匹配 `placeholder` 块结束到 `refreshIndex` 块开始那一小段，只插入新 key：

```json
    "search.semantic.placeholder" : {
      ...
    },
    "search.semantic.querying" : {
      "localizations" : {
        "en" : { "stringUnit" : { "state" : "translated", "value" : "..." } },
        "zh-Hans" : { "stringUnit" : { "state" : "translated", "value" : "..." } }
      }
    },
    "search.semantic.refreshIndex" : {
```

**禁止**（功能开发改运行时 Catalog 时，下列全部违规）：

- `python3` / `<<'PY'` 读入全文再 `write_text` / `json.dump`
- `jq` 输出重定向覆盖该文件（`jq empty` 只校验、不写回，可以）
- `scripts/xcstrings_patch.py set` / `set-batch --apply`（内部 `json.dump` 整文件）
- `sed` / `awk` / 一次性「按字母序找后继再 splice」的辅助脚本
- 截断后用 `git show HEAD` 拼后半段「抢救」——未提交的其它 key 会丢，且再次截断

写完立刻：

```bash
git diff --stat -- Starcat/Resources/Localizable.xcstrings
jq empty Starcat/Resources/Localizable.xcstrings
```

`diff --stat` 出现上万行删除 / 文件行数明显变少 → **立刻停手**，向 dong4j 报告，不要自己跑还原脚本。

编辑时只能对目标 key 做局部修改，并保持以下排版：

❌ 错误：冒号左侧没有空格。

```json
"zh-Hans": {
  "stringUnit": {
    "state": "translated",
    "value": "版权声明"
  }
}
```

✅ 正确：冒号左右各一个空格。

```json
"zh-Hans" : {
  "stringUnit" : {
    "state" : "translated",
    "value" : "版权声明"
  }
}
```

- 禁止用 `jq` 输出、`JSONEncoder` / `JSONSerialization` 或通用 JSON formatter 覆写整个文件。`jq empty` 只用于语法校验。
- 少量 key 变更却出现大面积 diff 时，必须停止并重做局部编辑，不得将格式化噪声混入功能改动。

## 1. 决策矩阵：3 秒选对路径

| 场景 | 写法 | 为什么 |
|------|------|--------|
| SwiftUI `Text` / `Label` / `Button` / `TextField` placeholder / `.help(...)` | `Text("key")` | SwiftUI 自动按 `\.locale` 环境查表 |
| 任何返回 `String` 的 Foundation API：`NSWindow.title` / `NSSavePanel` / `String(format:_:)` / `errorDescription` / `contextMenu` 标题 / URL 显示名 | **`String.l10n("key")`** | `String(localized:)` 在 macOS 上**不响应** `\.locale`，也**不响应** `locale:` 参数 |
| 自建 `NSWindow` / `NSPanel`（如 `RepoAIWindowController` / `AboutWindowController`）| hostingView 根挂 `.appLocaleEnvironment()` | 自建 NSWindow 不继承父 scene 的 `\.locale` |
| SwiftUI `.sheet { }` / `.popover { }` 闭包内根视图 | 闭包内根视图末尾挂 `.appLocaleEnvironment()` | macOS 上 sheet / popover **不**继承父 scene 的 `\.locale`（与 iOS 行为不同）|
| `RelativeDateTimeFormatter` / `Date.RelativeFormatStyle` 等 Foundation formatter | 视图内 `@Environment(\.locale) private var locale` + `formatter.locale = locale` 或链式 `.locale(locale)` | Foundation formatter 不自动桥接 SwiftUI `\.locale`，默认走 `Locale.current`（系统进程级 locale，App 启动后固定）|

## 2. 6 大 Root Cause（已踩过的坑，给你看是为了别再踩）

### #1 AppKit 自建 NSWindow 不继承 `\.locale`

**症状**：AI 助手浮窗 / About 窗口标题不跟随设置切换。

**修复**：hostingView 根挂 `.appLocaleEnvironment()` + 用 `.id(LocaleStore.shared.selection.rawValue)` 强制子树重建。参考 `RepoAIWindowController` / `AboutWindowController`。

### #2 `LocalizedBundle` ISA swap 拦不到 `String(localized:)`

**症状**：诊断 log 加在 ISA swap 拦截器里，`String(localized:)` 调用一条都打不出。

**根因**：Swift Foundation 内部不走 `Bundle.main.localizedString(forKey:value:table:)` 的 ObjC 方法分派。

**当前定位**：`LocalizedBundle` ISA swap 仅作 `NSLocalizedString` / 第三方库直调 `Bundle.main` 的兜底，**对 `String(localized:)` 无效** —— 这是 `String.l10n` wrapper 必须存在的根本原因。

### #3 `String(localized: key, locale:)` 的 `locale:` 参数不影响 `.lproj` 选择

**症状**：硬编码 `String(localized: "k", locale: Locale(identifier: "en"))`，英文环境下仍出中文。

**根因**：`locale:` 参数仅用于 plural / number / date 格式化。`.lproj` 选择固定按 `Bundle.main.preferredLocalizations`（**系统启动期决定，运行期不可改**）。

**结论**：所有 `String(localized:)` 已全工程迁到 `String.l10n`，wrapper 直接读 `UserDefaults["AppLocaleOverride"]` 显式选 lproj 子 bundle。

### #4 SwiftUI sheet / popover 在 macOS 上不继承父 scene 的 `\.locale`

**症状**：父视图已挂 `.appLocaleEnvironment()`，但 `.sheet { ChildView() }` 内 `Text("key")` 仍卡在系统 locale。

**修复**：每个 `.sheet { }` / `.popover { }` 闭包内根视图末尾必须独立挂 `.appLocaleEnvironment()`。

### #5 Foundation formatter 默认走系统 locale，不跟 `\.locale` 环境

**症状**（dong4j 2026-06-16 反馈）：详情页左下角 `Cached 3小时前` —— 模板 `Cached %@` 已英文化，但 `cachedAt.formatted(.relative(presentation: .named))` 默认按系统 locale 拼出 "3 小时前"。

**根因**：`RelativeDateTimeFormatter` / `Date.RelativeFormatStyle` / `DateFormatter` / `NumberFormatter` 全部用 `Locale.current` 当默认 locale，**不**自动桥接 SwiftUI `\.locale` 环境。

**修复模板**：

```swift
struct MyView: View {
    @Environment(\.locale) private var locale  // ← 必须

    private func relativeText(_ date: Date) -> String {
        let f = RelativeDateTimeFormatter()
        f.unitsStyle = .short
        f.locale = locale  // ← 必须
        return f.localizedString(for: date, relativeTo: Date())
    }

    var body: some View {
        // 链式注入也行：
        Text(date, format: .relative(presentation: .named).locale(locale))
    }
}
```

**注意**：`static func` 拿不到 `@Environment`，遇到原 `static func relativeDate(_:)` 必须改成 instance method（参考 `ActivityView`）。

**例外**（不需要修）：
- `ISO8601DateFormatter`：固定 RFC 3339 格式，与 locale 无关；
- 显式硬编码 `formatter.locale = Locale(identifier: "en_US_POSIX")` 的内部用途（如 `ActivityView.absoluteDate`），是 ISO 标准固定格式，不面向用户。

### #6 用脚本读写 `Localizable.xcstrings` 会截断，无法干净还原

**症状**（dong4j 2026-08-18）：Agent 用 Python 对运行时 Catalog 做插入/拼接，`git diff --stat` 出现十余万行删除，JSON 在文件中段断开。未提交的其它 key 与 HEAD 缠在一起，脚本「抢救」会再次写坏。

**根因**：Catalog 约 48 万行。读入全文再写回、`json.dump`、或截断后拼 HEAD 后半段，都会丢掉中间内容或重排整文件。编辑器/工具对超大 JSON 的 search-replace 一旦失败，工作区里没有第二份干净副本。

**修复 / 禁令**：功能开发只对相邻 key 做唯一上下文局部编辑。`jq empty` 只校验。dong4j 未明确要求走本地化同步流程时，禁止 `xcstrings_patch.py --apply`。损坏后停手汇报，禁止再写还原脚本。

## 3. 新代码自检清单（每次提交前过一遍）

1. 写 SwiftUI `Text` / `Label` / `Button` ? → `Text("key")`，**不要**套 `String.l10n`
2. 写 String 类型本地化（`window.title` / `errorDescription` / `String(format:)`）? → `String.l10n("key")`，**严禁** `String(localized:)` / `NSLocalizedString`
3. 新增 `.sheet { }` / `.popover { }`? → 闭包内根视图末尾挂 `.appLocaleEnvironment()`
4. 新建独立 `NSWindow` / `NSPanel`? → hostingView 根挂 `.appLocaleEnvironment()`
5. 用 `RelativeDateTimeFormatter` / `Date.RelativeFormatStyle` / `DateFormatter` / `NumberFormatter`? → 视图加 `@Environment(\.locale)` 并 `formatter.locale = locale` / 链式 `.locale(locale)`
6. 新增字符串到 `Localizable.xcstrings`? → en + zh-Hans 双语都填
7. 编辑 `Localizable.xcstrings`? → **关键词局部匹配**插入/修改目标 key，保持 `"key" : value`；**禁止脚本读写**；`git diff --stat` 不得出现大面积删除
8. 提交前自检：

```bash
rg "String\(localized:"  --type swift Starcat/   # 必须只出现在注释里
rg "NSLocalizedString"   --type swift Starcat/   # 必须只出现在注释里
rg "RelativeDateTimeFormatter\(\)" --type swift Starcat/ -A 5 | rg -B 1 "localizedString" | rg -v "\.locale ="   # 任何 RelativeDateTimeFormatter 命中都要确认下方有 .locale = locale
rg -n '^[[:space:]]*"[^"]+":' Starcat/Resources/Localizable.xcstrings      # 冒号左侧缺空格；必须无输出
rg -n '^[[:space:]]*"[^"]+" :[^ ]' Starcat/Resources/Localizable.xcstrings # 冒号右侧缺空格；必须无输出
jq empty Starcat/Resources/Localizable.xcstrings                             # 只校验 JSON 语法，不覆写文件
git diff --stat -- Starcat/Resources/Localizable.xcstrings                   # 少量改动不应出现大面积 diff
```

## 4. 反例（看到立刻拒绝）

```swift
// ❌ String(localized:) 已废弃
window.title = String(localized: "key")
// ✅
window.title = String.l10n("key")

// ❌ NSLocalizedString 已废弃
let s = NSLocalizedString("key", comment: "...")
// ✅
let s = String.l10n("key")

// ❌ locale: 参数不影响 lproj 选择
String(localized: "key", locale: Locale(identifier: "en"))
// ✅
String.l10n("key")  // 自动跟随用户设置

// ❌ 套 String.LocalizationValue 多此一举
String.l10n(String.LocalizationValue(actionKey))
// ✅
String.l10n(actionKey)  // wrapper 直接接受 String

// ❌ SwiftUI Text 不要套 wrapper（旁路了 \.locale 环境响应）
Text(String.l10n("settings.general.title"))
// ✅
Text("settings.general.title")

// ❌ sheet 内根视图漏挂 appLocaleEnvironment
.sheet(isPresented: $showFoo) {
    FooView()                // sheet 内 Text("k") 永远卡在系统 locale
}
// ✅
.sheet(isPresented: $showFoo) {
    FooView()
        .appLocaleEnvironment()
}

// ❌ formatter 不注入 locale
let f = RelativeDateTimeFormatter()
f.unitsStyle = .short
return f.localizedString(for: date, relativeTo: Date())  // 默认走系统 locale
// ✅
@Environment(\.locale) private var locale
...
let f = RelativeDateTimeFormatter()
f.unitsStyle = .short
f.locale = locale
return f.localizedString(for: date, relativeTo: Date())

// ❌ 硬编码用户可见文本

// ✅
```

## 6. 已知技术债（暂不要求修复）

- `alert(...) { actions } message: { ... }` 闭包内 `LocalizedStringKey` 字面量在 macOS 跨进程 dialog 上可能仍受 root cause #4 影响（这俩 modifier 没有 closure 包装可挂 `appLocaleEnvironment()`）。出现错位时记作单独技术债，不归入军规违规。
- 绝对日期格式化（`date.formatted(date: .abbreviated, time: .shortened)` / `DateFormatter` 拼自定义日期格式）目前尚有约 13 处未一并迁移，等用户实际验收反馈再决定。
