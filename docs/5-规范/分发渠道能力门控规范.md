# 分发渠道能力门控规范

> **强制,2026-07-10 起生效**
> 来源:App Store / Direct 双渠道共用代码后的能力边界沉淀。详细设计只引用本文,不重复正文。

---

## 适用范围

本文适用于 Starcat 同一代码库产出 App Store 与 Direct 两种包时的运行时能力判断,包括:

- 仅 Direct / 非 App Store 版可用的功能。
- 同时受 Direct 渠道和 Pro 权益限制的功能。
- App Store 不应链接、打包、展示或执行的 SDK / framework / 本机能力。

支付权益、免费额度和 Pro 功能仍归 `EntitlementGate` 管,本文只管分发渠道能力。

---

## 核心边界

三类对象职责必须分清:

| 对象 | 只负责 | 禁止负责 |
|------|--------|----------|
| `DistributionChannel` | 读取当前构建渠道 | 判断某功能是否付费、猜测运行环境 |
| `DistributionGate` | 判断当前渠道是否允许某能力 | 判断 Pro 权益、免费额度、StoreKit 状态 |
| `EntitlementGate` | 判断 Pro 权益和免费额度 | 判断 App Store / Direct 构建渠道 |

渠道来源只能来自 `DistributionChannel.current` 或测试注入的 `DistributionChannel`。

禁止用以下方式猜渠道:

- bundle id 字符串判断。
- App Store receipt 是否存在。
- App 安装路径。
- Sparkle / StoreKit / Direct License 相关 class 是否存在。
- 当前 entitlements 是否包含 sandbox key。

这些信息可以用于打包产物自检,不能作为业务运行时渠道判断入口。

## 标准写法

### UI 入口

UI 可以用 `DistributionGate.isAvailable(...)` 隐藏 Direct-only 入口:

```swift
if dependencies.distributionGate.isAvailable(.localAutomation) {
    LocalAutomationButton()
}
```

UI 隐藏只是体验优化,不等于安全边界。

### 执行层

真实执行系统能力前必须再次调用 `requireAvailable(...)` 或 `requireDirect(...)`:

```swift
try distributionGate.requireDirect(.localAutomation)
try await localAutomationService.run(...)
```

原因:入口可能来自菜单、URL callback、MCP、快捷键、测试或后续新 UI,不能只依赖某个 View 是否隐藏按钮。

### 同时需要 Pro

同时受 Direct 渠道和 Pro 权益限制时,顺序固定为先渠道、后权益:

```swift
try distributionGate.requireDirect(.externalToolBridge)
try entitlementGate.requirePro(.mcpService)
```

这样错误原因更准确:App Store build 先报渠道不可用,Direct 免费用户再进入 Pro 付费墙。

### Direct-only SDK

App Store 不应包含的 SDK / framework 必须:

1. 只挂到 `StarcatDirect` target。
2. 用 `#if canImport(...)` 包在小 facade 内。
3. 对 App Store build 提供 no-op 或 unavailable 行为。
4. 打包脚本验证 App Store 产物不包含该 SDK。

参考实现:`DirectUpdateController` + Sparkle。

---

## 禁止写法

- 禁止把 Direct-only 功能写进 `ProFeature` 伪装成付费能力。
- 禁止在业务模块直接判断 StoreKit、Direct License provider 或第三方支付 provider。
- 禁止只隐藏 UI,不在 service / action 执行层拦截。
- 禁止 App Store target 链接 Direct-only framework 后靠运行时隐藏入口。
- 禁止在多个 View / ViewModel 里散落 `DistributionChannel.current.isDirect` 判断执行能力。
- 禁止为了“兼容 App Store”保留旧路径或运行时猜测逻辑;本项目未上线,渠道边界要直接改清楚。

## 新增 Direct-only 功能 Checklist

新增任何 Direct-only 功能前后必须检查:

- [ ] 在 `ChannelFeature` 增加对应 case,命名表达能力本身,不要表达具体 UI。
- [ ] 在 `DistributionGate.isAvailable(...)` 中定义渠道规则。
- [ ] UI 入口使用 `distributionGate.isAvailable(...)`。
- [ ] 执行层调用 `distributionGate.requireDirect(...)` 或 `requireAvailable(...)`。
- [ ] 如同时需要 Pro,再调用 `entitlementGate.requirePro(...)`。
- [ ] 如引入 SDK / framework,只挂到 `StarcatDirect` target,并用 `#if canImport(...)` facade。
- [ ] 补 App Store 拒绝测试和 Direct 放行测试。
- [ ] 如涉及产物隔离,补打包脚本或发布检查。
- [ ] 更新 `docs/功能实现总览.md` 和对应专项 checklist。

## 当前渠道能力

当前已登记的 Direct-only 渠道能力:

| `ChannelFeature` | 用途 |
|------------------|------|
| `automaticUpdates` | Direct 版 Sparkle 自动更新 |
| `directLicense` | Direct 版官网支付与授权码激活 |
| `localAutomation` | 后续本机自动化能力,例如外部命令或非沙盒文件操作 |
| `externalToolBridge` | 后续外部工具链桥接,例如访问沙盒外用户环境 |

新增能力时先扩展此表对应的代码枚举,再接业务入口。
