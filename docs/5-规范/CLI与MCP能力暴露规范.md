# CLI 与 MCP 能力暴露规范

> 生效：2026-11-15；2026-11-16 按 read/write 与共享业务流程修订；适用于主 App、`starcat-cli`、`starcat-skill` 及新增外部适配器
> 实施跟踪：[CLI 与 MCP 能力开放专项](../4-工程进度/CLI与MCP能力开放专项/CLI与MCP能力开放Checklist.md)

## 1. 每次功能变更都要评估

新增或修改业务功能时，AI 必须主动完成下列评估并在方案、任务与交付说明中留下结论，无需维护者再次提醒。不能只因当前没有专用 CLI 命令就判定不可开放。

1. 按可独立执行的动作列出读取、查询、预览、执行、状态、结果、取消和文件输入输出。
2. 判断能否复用已有 App 服务，记录账号、渠道、Pro、数据范围、隐私及系统授权约束。
3. 给出“已有覆盖 / 本次开放 / 暂缓开放 / 不适用”结论。暂缓须写具体缺口及接入条件。
4. 可以开放的动作进入 App 公共目录及 Schema；普通 CLI 通用调用和 MCP 共用该目录。
5. 新增高频专用 CLI 命令属于可选便利入口，不能成为开放新能力的必要条件。
6. 同步覆盖清单、使用文档与适用测试；交付说明报告评估结论和实际验证范围。
7. **已有按钮能执行的业务，默认接入公共接口。** 下载、限流、事务、校验、取消、通知等是 App 既有职责，不能将它们当作不开放的理由。若编排藏在 ViewModel，抽出或复用同一用例；不能只调用底层生成器/Repository 就声称与按钮等价。

纯间距、颜色、字号等展示改动可记录“不适用：未新增或改变可独立执行的业务动作”。GUI 展示、OAuth、系统权限弹窗、付费购买和发布审批不得伪造成无人值守操作。

## 2. 调用方向与职责

目标链路为“外部调用方 → CLI 的连接与能力层 → App 领域执行器”。`starcat mcp` 与普通命令在同一 Go 进程复用 HTTP、初始化、profile 与凭据模块，两种入口都由 App 执行业务。

App 是账号、Pro、渠道、写入开关和数据范围的最终边界。公共授权只有 `read` / `write`：读默认开放，包括笔记；写默认关闭，在设置中用唯一开关开启，涵盖刷新、生成、安装、删除和远端提交。禁止新增笔记、Star、批量或破坏性细分授权。CLI 不直接打开 App SQLite、CloudKit、Keychain 或模型目录，也不实现另一套搜索、排序、整理规则。App 内部 Agent Runtime 的工具作用域仍属于该运行任务的约束，不是外部 MCP 的设置权限。

浏览器 B1 继续使用现有 loopback Companion 通道，属于明确登记的阶段例外。原生桥接的浏览器、宿主与分发矩阵验证通过前，不宣称所有浏览器已经过 CLI；不能因迁移改变浏览器原有权益。

## 3. 单一目录与输入输出

- `tools/list` 是运行时工具 Schema 来源；`starcat://capabilities` / `starcat.get_capability_catalog` 描述版本、权限、联网与任务语义。
- 新增目录条目和真实执行器在同一变更交付。不得注册空壳、只返回“已评估”或后台偷偷调用 GUI。
- `starcat tools list / describe / call` 与 `resources list / read` 动态发现，不在 CLI 复制工具名映射。
- 输入为单个 JSON 对象；通用 CLI 接受 stdin 或文件，最大 8 MiB。CLI 的结构预检用于早反馈；App 再验证类型、必填、枚举、范围与业务范围。
- JSON Schema 未实现的关键字不得宣称已完整校验。领域约束和权限必须由执行器校验。
- 结构校验错误保留 `INVALID_ARGUMENTS`，消息包含参数路径（例如 `arguments.limit: above maximum`）；调用方按错误码处理，不依赖可读文案。global-search 的业务结果 Schema 和错误码继续保持原契约。
- stdout 仅业务结果 JSON 或 MCP 协议；诊断写 stderr。现有终端展示命令提供 `--json` 或通用工具路径。
- 分页结果明确 `limit`、`offset`、`has_more`、`next_offset`；空列表与 `cache_hit=false` 分开。不要把局部页长度当全量总数。
- 仅读取缓存不得隐式刷新、生成、修复或建索引；检索若使用已配置 embedding / reranker，要声明联网与可能消耗。
- 不输出凭据、向量或内部请求头；诊断导出复用 App 标准脱敏归档与有期限的分块下载。笔记筛选属于调用参数，不能要求再开启独立读取权限。

## 4. 写入与版本升级

App 公共能力契约 v3 从 server `0.7.0` 开始：能力权限只返回 `read` / `write`，移除旧细分字段。旧本地写开关一次迁移到唯一写开关；其它旧细分开关移除。未开启本地写入的旧用户保持写入关闭。

含 `dry_run` 的工具继续由 App 默认预览（默认值 `true`）。专用 CLI 写命令保留默认预览、`--apply` 执行。通用 CLI 保留明确输入的 `dry_run`，省略时遵循 App Schema；`--apply` 只是传入 `false` 的便利写法，与明确 `true` 冲突时报参数错误。CLI 不再覆盖用户 JSON 或额外增加执行授权。

没有预览能力的工具遵循 App 的显式调用语义；不能在 CLI 添加额外门禁或伪造预览。摘要、标签建议、问答和翻译属于写操作；建议不自动应用。执行后读取真实状态，批量返回逐项结果与实际原子性，不宣称跨 GitHub 和本地数据库事务回滚。

`contract_version` 是业务契约版本；MCP 初始化协议版本继续按现有协商，不随业务版本改名。未知工具返回升级 / 不支持错误，不静默降级到另一个含义不同的动作。`global-search` 的独立 schema v1、错误码和 launcher 输出保持原契约。

## 5. 长任务与文件归属

App 持有任务句柄；返回 `task_id` 后客户端可查询状态和结果。断开 CLI 不取消任务；超时可能已经接受任务，不自动重放启动或写入。

任务只宣告真实执行器支持的取消和进度。`cancelling` 表示已请求，只有执行器退出才是 `cancelled`。没有总量时返回未知，不估造百分比。首版任务只在 App 进程内，完成结果保留一小时；App 重启、账号切换及结果过期后句柄无效。切号前必须取消并等待执行器退出，再切数据库，不能只清空任务字典。

CLI 输入输出文件属于 CLI 设备；模型、Skill、缓存和诊断操作处理 App 设备上的受管数据。App 不解释客户端任意路径；导出通过内容或 artifact 分块传输。输出明确格式、截断与数据范围；不把 Markdown 导出包装成数据库备份。恢复、替换、删除、安装和分享共用写权限，仍由 App 执行既有业务校验。

## 7. 交付检查

执行 `python3 scripts/check-public-capabilities.py`，并完成对应 Swift Suite、CLI Go 检查及 Skill 契约检查。静态检查只保证已登记条目的目录、执行分支与覆盖文档一致；发现没有登记的新业务仍依赖代码评审，不能把工具数量当 App 全部功能分母。

报告必须区分实现、自动化验证、真实连接 / GUI 验收、本地提交、合并、推送与发布。总览回写、Changelog、GUI、外部任务收尾和发布遵循各自已有授权边界，不因本规范自动获得许可。
