# UI 规范：主窗口仓库分类接入

适用于「星标」「探索」「活动」中新建或修改的仓库分类，包括左栏菜单、中栏 Repo 卡片和右栏仓库详情。设计参数、实现约束及交互细节沿用各专项规范。

- 页大小、视口预取和补页边界见[列表分页加载规范](UI-列表分页加载规范.md)。
- 导航反馈、骨架及详情出入场见[动效规范](UI-动效规范.md)和[列表与详情切换动效规范](UI-列表与详情切换动效规范.md)。
- README 阅读器、排版与字号见[Markdown 字号与渲染规范](UI-Markdown字号与渲染规范.md)。

## 左栏菜单与选择

- 接入所属板块的现有菜单、图标样式、键盘导航及本地化。用稳定分类 ID 标识选择，点击当下更新选中态并启动列表加载。板块和子分类切换沿用原有局部动效。
- 菜单数量来自该分类的目录摘要或聚合查询。目录总数、当前筛选命中数和已加载卡片数各用自己的数据口径。总数待确认时按未知处理，确认目录为空后才显示 0。
- 切分类时遵循「切换分类时打开首个详情」设置。当前选中项仍属于新结果时可沿用，自动打开时选择过滤和排序后的首项。无选中项时显示右栏占位，滚动追加和后台刷新保留仍有效的选择。

## 中栏卡片与分页

- **首批和每次追加均最多 20 条**，共用 `ListPaginationPolicy.repoCardPageSize`。使用懒加载容器、`UnifiedRepoRow` 和业务稳定 ID。以仓库为单位的列表按 repo ID 去重，以收录记录为单位的列表使用稳定记录 ID。
- 容器和行共用 `automaticListPagination`。实际进入视口的行距筛选后的已加载列表尾部剩 **10 项以内**时预取，同一分页快照最多触发一次。正常可滚动的首屏停在顶部时保持首批，视口能容纳首批全部卡片或筛选后结果稀疏时走共享规则。自动补页沿用来源预算，规模未知的远端由服务端筛选或设定有限补页边界。
- 搜索、筛选和排序以分类完整结果为口径，优先在分页前交给数据源处理。排序同值时用稳定 ID 决定次序。`hasMore` 取自可靠的总量、分页边界或游标，追加成功后才推进位置，失败时保留现有列表和重试入口。
- 列表请求身份包含分类、来源、账号或服务环境、搜索、筛选和排序。身份变化时重置分页快照。异步返回时同时检查当前身份和请求代次，覆盖 A → B → A 回切。已有内容可继续用于同一查询的刷新，成功追加时只更新需要新增的行。
- 首次读取且没有可展示结果时，显示与卡片布局一致的骨架。首批就绪后，用 `listRowReveal` 衔接入场，动画身份跟随用户查询。缓存可直接展示，刷新和追加采用局部状态，徽章补全、分页和后台刷新保持已出现卡片的入场状态。真实空结果、首次加载失败和重试各有明确界面。

## 数据来源与本地缓存

- 菜单摘要、中栏卡片页、跨分类来源关系、原帖或详情正文各使用对应的查询。后台同步规模由来源契约决定。以外部目录快照为例，在导入或更新时解析和入库，日常切换只查询摘要和当前卡片页。缓存读取、解析、迁移和批量查证在主线程之外执行，主线程负责提交界面状态。
- 本地查询型目录优先用 SQLite 支撑按范围筛选、排序、计数和分页。以主仓库数据派生的分类复用现有仓库表和卡片投影。外部目录缓存按来源、服务与有授权意义的账号范围区分。仓库的 Star、标签和笔记仍使用现有用户数据路径。
- 支持本地缓存的来源先显示可用数据，再按该来源的有效期后台校验。同一资源的并发刷新可合并。服务提供 ETag 或版本时复用条件请求及版本校验，`304` 沿用现有快照。成功更新时把数据与版本、校验时间一起提交。离线或刷新失败时保留可用缓存，按现有样式提供局部反馈。
- 改变已交付的缓存格式时提供自动、可离线执行的迁移。校验旧来源身份和数据后原子写入新缓存，事务成功后才清理对应旧文件。升级首次读取允许等待必要的迁移。涉及已发布数据库 schema 时追加版本迁移。
- **分类已经证明来源时，卡片直接显示来源徽章。** 例如「探索 → Linux.do」的卡片直接显示 Linux.do。周刊、星标等其他列表先显示卡片，再把本批尚未查证的 repo ID 交给共享入口异步批量查本地来源关系。命中后更新徽章，追加页复用已查结果，来源版本变化时按新版本查证。健康度等补充信息同样随各自异步结果更新。

## 右栏详情与渲染

- 复用主窗口详情宿主和 README 阅读器。选中项用稳定仓库或记录 ID 表达。来源说明、原帖和活动上下文接入现有详情扩展。按实际使用时机读取扩展数据，例如在点击 Linux.do 来源链接时加载对应原帖。
- 选择立即响应，新详情读取可与旧内容退场并行。退场完成后替换标题、来源和正文所属的展示快照。尚待渲染时使用右栏骨架。原生区按自己的内容就绪信号入场，README 以**当前导航的正文 DOM 和布局就绪**为准，正文入场后图片和视频可以继续加载。
- `WKWebView` 保持稳定身份，正文、失败和就绪回调都校验当前选择与文档身份。缓存中的同一已就绪文档可复用。快速切换时只接纳最后一次选择的结果，骨架、空态和错误态都能正常收口。
- 遵循 `starcatReduceMotion`。用静态选中反馈、静态骨架和简短淡化完成同样的状态交接。

## 验收场景

| 场景 | 通过条件 |
|---|---|
| 冷加载、热缓存、离线 | 首次无数据时正常展示骨架，命中缓存时直接交接。刷新失败后已有卡片可用。若有格式迁移，断网升级后能读取首批，重启后可继续翻页。 |
| 大目录与首屏 | 用接近实际规模的目录检查。正常可滚动视口中，未滚动时最多呈现 20 张卡片，菜单仍显示目录总数。记录从选择分类到首批可用的耗时与实际读取量。 |
| 滚动和分页失败 | 到预取窗口触发一页，快速滑底可继续加载。筛选后补页有界。失败保留已展示卡片，可重试且位置正确。 |
| 切分类、排序或账号 | 使用新的查询和页边界。旧分页响应晚到时，当前列表、计数和选择保持正确。 |
| 徽章慢于卡片 | 本来源徽章随首批出现。跨分类查证延迟、失败或来源版本变化时，卡片仍先呈现，滚动追加只查本次待确认的 ID。 |
| 详情快速切换、媒体加载慢 | 快速 A → B → C 最终只显示 C。旧内容完整退场，正文就绪即可显示，正文显示时慢图片仍可继续加载。 |
| 动效和交互 | 选中反馈即时，布局稳定。滚动、刷新和徽章更新保留已出现卡片的状态。检查明暗主题、键盘导航与 Reduce Motion。 |

验收记录包含分页、迁移及过期回写的自动化证据，以及动效和响应的实机结果。实机结果尚缺时记为待验收。
