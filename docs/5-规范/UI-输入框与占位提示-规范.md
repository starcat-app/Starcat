# UI 规范：输入框与占位提示

> 生效：2026-11-20；适用于所有新增或修改的单行、多行输入框及自绘 placeholder。

## 控件与排版

- 普通表单优先使用自带占位提示的 `TextField`，多行使用 `axis: .vertical`。只在确有编辑能力需求时使用 `TextEditor` 或已有 AppKit 编辑组件，不为简单表单单独叠加一个 `Text` 模拟 placeholder。
- 字号相同不代表位置对齐。光标、占位提示与实际输入的首字符必须使用相同的首行起点、字体和基线；输入框内边距只在统一容器上设置。禁止凭观感给 overlay 写独立 padding/offset 修补位置。
- 必须自绘时，沿用同一编辑器的字体、段落样式、换行宽度及文字布局；从实际 `textContainerOrigin`、`lineFragmentPadding` 和首行布局取得绘制位置，不能假设 macOS 原生编辑器的内边距为某个常数。字号、字体或宽度变化时同步更新。
- 保留光标、选择、输入法组合文本、换行、粘贴和撤销；不能为调整占位提示替换草稿或重建编辑器。输入法存在组合文本时不得叠加空输入提示。
- 表单使用界面 typography；Markdown 内容输入仍遵守 [Markdown 字号与渲染规范](UI-Markdown字号与渲染规范.md)，不能为解决对齐问题改变正文用途或字号来源。

## 高度与滚动

- 短任务窗口按实际内容确定高度，不用固定高度制造底部空白，也不为容纳短说明增加整页滚动。
- 要求无滚动条的窗口，应移除外层滚动容器，采用内容自适应高度；时间选项、状态、长译文与字号变化必须计入高度，不能只隐藏滚动条或裁剪内容。
- 长文本输入可限定可见行数并在输入框内滚动；要求无滚动条时隐藏输入框滚动指示，不影响继续输入与查看完整内容。不要让 2000 字草稿无限撑高任务窗口。

## 验收

- 检查空框未聚焦、空框聚焦、输入首字符、全选清空、中文输入法组合、多行换行与长文本粘贴。
- 占位提示的首行起点必须与光标和输入首字符一致，输入后不能跳行或横向位移。
- 覆盖界面字号档位、适用的阅读微调、明暗外观及长译文；检查动态内容完整可见，按钮不被挤压或裁剪。
- 自动化测试和实际界面验收分开记录。GUI 操作仍需遵守 `AGENTS.md` 的授权要求；未观察真实界面时不得宣称对齐观感已验收。
