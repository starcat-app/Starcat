# 本地编译 Starcat 与配套项目

> 给想从源码跑起来的人：先编 macOS 客户端，再按需拉配套仓库、起本地 API、编 CLI。  
> 不覆盖打包、公证、App Store 上传。那些走 [`SOP-发版流程.md`](../6-发版与上架/SOP-发版流程.md) 和 [`SOP-新Mac开发发布环境搭建.md`](../6-发版与上架/SOP-新Mac开发发布环境搭建.md)，且必须由维护者明确要求后才能执行。

创建：2026-08-19

## 1. 你能编出什么

| 目标 | 位置 | 本地要不要编 |
|------|------|-------------|
| macOS App | 本仓库 `Starcat/` | 要。这是主产物 |
| 六个业务 API | `supports/starcat-*-api/` | 可选。官方托管默认可用；自建或改 API 时再编 |
| CLI / MCP | `supports/starcat-cli/` | 可选 |
| 用户文档 / 官网 / 插件 / Skill / Homebrew | `supports/` 下独立仓 | 一般不用编 App；改对应项目时看该仓 README |
| Direct 授权 API | `supports/starcat-license-api/` | 私有仓。没有组织权限就跳过 |

日常开发在 `dev` 分支。`main` 是发布基线，不要在上面直接开功能。

## 2. 本机环境

- macOS 15 Sequoia 或更高
- Xcode 26 或更高（含 Command Line Tools）
- Apple Developer 账号，用来给本机 Debug 签名。没有 $99 账号编不出可运行的 App
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)：`brew install xcodegen`
- Git。拉配套项目建议装 [GitHub CLI](https://cli.github.com/)：`brew install gh`
- 编 Go API / CLI 时再装 **Go 1.25.0**（与各 API 的 `go.mod` 一致）
- 可选外部检索后端需要 Docker Desktop

确认工具：

```bash
xcodebuild -version
xcodegen --version
git --version
```

## 3. 克隆主仓库

```bash
git clone https://github.com/starcat-app/Starcat.git
cd Starcat
git checkout dev
```

`Starcat.xcodeproj` 由 xcodegen 生成，不进 git。不要去搜一份现成的工程文件。

## 4. 编译 macOS App

### 4.1 本地密钥文件

```bash
cp Configs/Secrets.xcconfig.template Configs/Secrets.xcconfig
```

`Secrets.xcconfig` 已在 `.gitignore`，不要提交。

只想先把 App 跑起来：各 `STARCAT_PRODUCTION_API_KEY_*` 可以留空。留空时 Trending / 周刊 / 发现等走「设置 → 服务」里用户自己填的 Key；不填就 401。GitHub 登录用源码里的公开 OAuth Client ID 即可，Device Flow 不需要 Client Secret。

需要接自己的后端或 Web Flow 登录时，再填：

| 字段 | 何时填 |
|------|--------|
| `STARCAT_PRODUCTION_API_KEY_*` | 本机或自建 API 的 Bearer Token，与对应服务 `.env` 里 `API_KEYS` 一致 |
| `STARCAT_OAUTH_CLIENT_SECRET` | 只用 Web Application Flow 时需要 |
| `STARCAT_GITHUB_APP_CLIENT_SECRET` | 「我的项目」要访问私有仓时需要 |
| `DEVELOPMENT_TEAM` | 建议填自己的 Team ID，Xcode Run 和 `make run-*` 用同一套签名 |

生成 API Key：

```bash
bash supports/scripts/gen-api-key.sh --env
```

把输出写进各 API 的 `.env`，需要 bake 进 App 时再 `make setup-production-api-keys`。

### 4.2 GitHub 登录

源码里的 Client ID 是官方构建的公开标识，Device Flow 可以直接用来登录。Scope 是 `read:user` 和 `public_repo`。

要自己建 OAuth App：

1. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App
2. Authorization callback URL 填 `starcat://callback`
3. 打开 Device Flow
4. 不要把 Client Secret 写进仓库。Web Flow 才放到本机 `Secrets.xcconfig`

PAT 登录是 App 内可选路径，不需要 OAuth App。

### 4.3 生成工程并运行

```bash
xcodegen generate
```

然后任选一条：

- Xcode 打开 `Starcat.xcodeproj`，选 Development Team，Run `Starcat` scheme
- 沙盒 Debug（接近 App Store）：`make run-appstore`
- 非沙盒 Debug（接近 Direct）：`make run-direct`

新增或删除 Swift 文件后必须再跑 `xcodegen generate`，否则 `xcodebuild` 会报找不到类型。

两个 scheme 的数据目录不同，不要混着用同一份库去对行为：

| Scheme | Bundle | 数据大致位置 |
|--------|--------|-------------|
| `Starcat`（App Store Debug） | `com.starcat.app.store` | `~/Library/Containers/com.starcat.app.store/...` |
| Direct Debug | `com.starcat.app.direct` | `~/Library/Application Support/com.starcat.app` |

### 4.4 测试

命令行和 Xcode IDE 不要同时跑测，会抢同一个 `testmanagerd`。先 Cmd+Q 退出 Xcode，或只在 IDE 里 Cmd+U。

```bash
xcodegen generate
xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' test
```

只跑一个 Suite：

```bash
xcodebuild -scheme Starcat -destination 'platform=macOS,arch=arm64' \
  -only-testing:StarcatTests/TagRepositoryTests test
```

启动期任何 Keychain / 系统授权调用必须用 `TestEnvironment.isRunning` 门控，否则测试 host 会弹授权框然后超时。

## 5. 拉配套项目

`supports/` 里多数目录是独立 git 仓库，主仓库只放工作区脚本。第一次：

```bash
cd supports
./clone-all.sh
```

以后更新：

```bash
./clone-all.sh --pull
```

`starcat-license-api` 和 `starcat-api` 是私有仓，需要 `starcat-app` 组织权限（`gh auth login` 或已配置的 SSH key）。没有权限时脚本会跳过或失败，不影响编客户端。

完整清单见 [`supports/README.md`](../../supports/README.md)。

## 6. 编译并启动本地 API

只做客户端、用官方托管服务时，可以跳过这一节。

前置：Go 1.25.0。每个 API 根目录复制 `.env.example` 为 `.env`，填 `API_KEYS`；Trending / Weekly / Discovery / Sharing 还需要 `GITHUB_TOKENS`。

一键编 + 起六个业务 API：

```bash
cd supports
./start-all.sh
```

默认端口：

| 服务 | 端口 |
|------|------|
| sharing | 5001 |
| trending | 5002 |
| weekly | 5003 |
| wiki | 5004 |
| recommend | 5005 |
| discovery | 5006 |

健康检查：`GET http://127.0.0.1:<port>/healthz`（不鉴权）。业务接口要 `Authorization: Bearer <api-key>`。

```bash
./start-all.sh --status
./start-all.sh --stop
```

单独编某一个：

```bash
cd supports/starcat-trending-api
cp .env.example .env   # 再编辑
go build -o bin/starcat-trending-api ./cmd/server/
go run ./cmd/server
```

App 里把「设置 → 服务」指到 `http://127.0.0.1:500x`，Key 与 `.env` 的 `API_KEYS` 一致。不要把 `.env` 提交进 git。

本地 API 详细约定见 [`supports/AGENTS.md`](../../supports/AGENTS.md)。不要在这里跟生产 Fly 部署混写。

## 7. 可选：本机 Meilisearch / Qdrant

知识库默认用 SQLite FTS5 + 本地向量。要验证外部检索后端：

```bash
cd docker/meilisearch
cp .env.example .env
# 把 MEILI_MASTER_KEY 换成至少 16 字节随机串
docker compose up -d

cd ../qdrant
cp .env.example .env
# 把 QDRANT_API_KEY 换成随机串
docker compose up -d
```

端口只绑 `127.0.0.1`。说明见 [`docker/meilisearch/README.md`](../../docker/meilisearch/README.md) 和 [`docker/qdrant/README.md`](../../docker/qdrant/README.md)。

## 8. 编译 CLI

CLI 不读 App 的 SQLite，所有读写走 Starcat 内的 MCP。先在 App 里打开「设置 → MCP Service」，再配对。

```bash
cd supports/starcat-cli
go build -o starcat ./cmd/starcat
./starcat doctor
```

安装发行版用 Homebrew tap [`homebrew-starcat-cli`](https://github.com/starcat-app/homebrew-starcat-cli)，不必从源码编。配对步骤见该仓 README。

## 9. 其它配套项目

这些一般不用「编译 Starcat」：

| 项目 | 本地做什么 |
|------|------------|
| [starcat-skill](https://github.com/starcat-app/starcat-skill) | 拷到 Agent 的 skill 目录即可 |
| [starcat-docs](https://github.com/starcat-app/starcat-docs) | Mintlify 文档站，按该仓 README |
| [starcat-site](https://github.com/starcat-app/starcat-site) | 静态官网。部署脚本会改远程服务器，不要擅自跑 |
| Chrome / Safari 插件 | 按各自仓库的扩展加载说明 |
| Alfred / uTools / Raycast | 按各自仓库安装 |
| [starcat-localization](https://github.com/starcat-app/starcat-localization) | 改翻译资源，不编 App |

## 10. 不要在本地教程里做的事

除非维护者在当前任务里明确要求，否则不要执行：

- `scripts/package-*`、`scripts/release-*`
- `make package-direct` / `make release-direct` / `make package-appstore`
- `supports/starcat-site/direct/deploy.sh`
- notary 上传、App Store 上传、服务器 rsync

本地编通、单测通过，就够了。
