# 同步脚本使用说明（sync-untracked.sh）

> **本文档**：说明如何在 MBP / Studio 之间同步"git 不管理但两台机器都要用"的那批文件。
>
> 创建：2026-06-30
> 维护原则：每加一项需在两台机器间同步的内容，必须同步追加到 `scripts/sync-manifest.list` 并 git commit；每删一项，从清单里划掉并 commit。

---

## 0. 这个脚本解决什么问题

仓库里有些文件**不**进 git、但需要在两台开发机上各持有一份：

- `Configs/Secrets.xcconfig`：含 GitHub OAuth / 飞书 Webhook 等生产密钥
- `notes.md`：临时凭据 / 备忘
- `supports/Makefile`、`supports/start-all.sh`：本机辅助脚本
- `supports/.weekly-repo/`、`supports/scripts/`、`supports/backups/`：本机维护目录

`git push` 不会推这些（被 `.gitignore` 排了），手动 cp 又容易丢。`scripts/sync-untracked.sh` 把这步**显式化、清单化、可审计**。

## 1. 一次性配置

### 1.1 创建 `sync-hosts.json`

```bash
# 在仓库根目录
cp scripts/sync-hosts.example.json scripts/sync-hosts.json
# 编辑 sync-hosts.json，把 ssh / remote_path 改成真实值
```

模板里 `studio.local` / `mbp.local` 是占位符，**两边机器上 `sync-hosts.json` 内容应该一样**（别名对称），文件本身不进 git（已被 `.gitignore` 排除）。

### 1.2 确认 SSH 别名能通

```bash
# ~/.ssh/config 里应有形如：
#   Host studio
#       HostName 192.168.x.x
#       User dong4j
#   Host mbp
#       HostName 192.168.x.x
#       User dong4j

# 验证
ssh studio true   # 第一次可能需要 ssh-add
```

### 1.3 验证 `sync-hosts.json` 不进 git

```bash
git check-ignore scripts/sync-hosts.json
# 应输出该路径；如果没输出 = .gitignore 没生效，检查同步脚本旁边的 rules
```

## 2. 日常使用

```bash
# 预演：看将同步什么（默认就是 dry-run，零风险）
./scripts/sync-untracked.sh --to studio

# 真传（会问 y/N 二次确认）
./scripts/sync-untracked.sh --to studio --apply

# 在 Studio 反向用
./scripts/sync-untracked.sh --to mbp --apply

# 跳二次确认（CI / 脚本里用）
./scripts/sync-untracked.sh --to studio --apply --yes

# 只看清单，不做 git/SSH 检查（最快）
./scripts/sync-untracked.sh --to studio --list-only
```

输出形如：

```
>>> SSH 连通性: studio ...
==========================================
  源   : /Users/dong4j/Developer/1.AI/ai-incubator/Starcat
  目标 : studio:~/Developer/1.AI/ai-incubator/Starcat/

  条目 : 8 个（清单 8 - 不存在 0）
  体积 : 约 12M
==========================================
将同步：
  • Configs/Secrets.xcconfig
  • notes.md
  • supports/Makefile
  • supports/start-all.sh
  ...

Info: 这是 dry-run。要真传请加 --apply
```

## 3. 添加 / 删减同步项

### 添加

1. 编辑 `scripts/sync-manifest.list`，加一行路径（相对仓库根）
2. `git commit + push`
3. 对端 `git pull`
4. 之后两台机器 `./scripts/sync-untracked.sh --to <alias> --apply` 都会带上这一行

### 删减

1. 编辑 `scripts/sync-manifest.list`，删一行
2. `git commit + push` + 对端 `git pull`
3. **对端不会自动删本地已同步过的文件**——本脚本只推不删，删是手动活

### 排除规则

`scripts/sync-exclude.list` 是兜底用的——`sync-manifest.list` 里**不应**包含 .DS_Store / .build/ / .codegraph/ / `**/*-api/` 等。改 exclude 列表要谨慎，会影响所有目录类条目。

## 4. 安全说明

| 风险 | 缓解 |
|---|---|
| `Configs/Secrets.xcconfig` / `notes.md` 含明文密钥 | 同步后脚本自动 `chmod 600` 对端文件 |
| SSH over LAN 传输 | 本身已加密，明文风险**仅**在两端本地磁盘 |
| `sync-hosts.json` 误 commit | 已在 `.gitignore` 排除；用 `git check-ignore` 兜底验证 |
| `backups/` 里可能含旧密钥副本 | 已知风险；建议定期清理 |

**绝不**做：
- ❌ 把 `scripts/sync-hosts.json` 加进 git
- ❌ 把 `Configs/Secrets.xcconfig` 改成"既然都明文同步了不如也 commit"——`.gitignore` 是不同维度的事，git 仓库是公开面

---

## 5. 已知约束

1. **单向推**：源 = 当前机器，目标 = `--to` 指定机器；不做双向合并。
2. **覆盖语义**：Studio 上手动改过的 `notes.md` 会被 MBP 推过来的覆盖。要保留改动的版本需先 cp 一份。
3. **`**/*-api/` 排除**：`supports/` 下 6 个 `starcat-*-api` 目录是独立 git 仓库（`starcat-discovery-api` / `starcat-recommend-api` / `starcat-sharing-api` / `starcat-trending-api` / `starcat-weekly-api` / `starcat-wiki-api`），**不通过本脚本同步**，各自走 `cd supports/starcat-xxx-api && git push`。
4. **不做 git status 检查**：脚本是"按显式清单同步"，不关心你本机 / 对端 git 状态怎么样——你自己清楚就行。如果怕覆盖对端脏文件，先 `ssh <alias> 'cd <path> && git status'` 自己看。
5. **首次同步会拷大体积**（`supports/` 减去 6 个 api 目录后约 100+ MB），建议先 `--list-only` 看清单再 `--apply`。

## 6. 故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `Error: sync-hosts.json 不存在` | 第一次跑没 cp 模板 | `cp scripts/sync-hosts.example.json scripts/sync-hosts.json` 后填值 |
| `Error: SSH 连不上 studio` | `~/.ssh/config` 没配 / ssh-agent 没 add 密钥 | `ssh-add ~/.ssh/id_ed25519` 后重试 |
| `Warning: 清单里有 N 个路径在本机不存在` | 你是从 Studio 跑、清单里有 MBP 独有的路径 | 正常，跳过即可 |
| 同步后对端 `chmod 600` 报"无此文件" | 清单里没那俩文件 | 正常（`2>/dev/null \|\| true` 兜底） |
| 对端脏文件被覆盖 | 脚本单向推不查 git status | 同步前自己 `ssh <alias> 'cd <path> && git status'` 看一眼 |

## 7. 相关文件

| 路径 | 进 git | 用途 |
|---|---|---|
| `scripts/sync-untracked.sh` | ✅ | 主脚本（可执行） |
| `scripts/sync-hosts.example.json` | ✅ | SSH 别名 + 远端路径模板 |
| `scripts/sync-hosts.json` | ❌ | 真实配置（你 cp + 填） |
| `scripts/sync-manifest.list` | ✅ | 显式同步清单 |
| `scripts/sync-exclude.list` | ✅ | 排除规则（兜底） |
| `.gitignore` | ✅ | 含 `scripts/sync-hosts.json` 排除规则 |
