## 3. 权限（macOS Sandbox / Entitlements）

> 来源：`Starcat/Starcat.entitlements`（v1 当前快照）。

### 3.1 实际配置的 Entitlements

| Key | 状态 | 触发场景 |
|-----|------|---------|
| `com.apple.security.app-sandbox` | ✅ true | Mac App Store 上架硬性要求 |
| `com.apple.security.network.client` | ✅ true | 出站网络：GitHub API / 自建后端 / AI Provider |
| `com.apple.security.network.server` | ✅ true | MCP Service 监听 127.0.0.1:5555（Pro 用户开启） |
| `com.apple.security.files.user-selected.read-write` | ✅ true | AI 产物输出目录（NSOpenPanel 选）+ 未来 JSON 导入导出 |
| `keychain-access-groups` | ⚠️ 暂未开启 | ad-hoc 签名拒绝编译；Apple ID Team 接入后再开 |

### 3.2 每条 Entitlement 的 App Store 审核口径

#### 3.2.1 `app-sandbox`

**为什么需要**：Mac App Store 上架硬性要求，**无 App Sandbox 会被直接拒**。

**触发场景**：所有 App 运行期行为均在沙盒内，包括：
- 写 `~/Library/Application Support/com.starcat.app/`（数据库 / 缓存 / 诊断 / MCP 审计）
- 写 `~/Library/Group Containers/`（暂无，未来 CloudKit 准备）
- 写 `~/Library/Caches/com.starcat.app/`（README 渲染缓存）
- 读写 `~/Library/Preferences/com.starcat.app.plist`（UserDefaults 镜像）

#### 3.2.2 `network.client`

**为什么需要**：Starcat 是**联机 + 本地混合**应用，本地核心（搜索 / 整理）虽不依赖网络，但：
- 登录 GitHub OAuth 后**必须**拉 Stars（断网会提示）
- 自建后端（Trending / Weekly / Wiki / Sharing）提供数据源
- AI Provider（BYOK / 自建代理）需要出站到 OpenAI / DeepSeek / OpenRouter 等

**触发场景**：
- App 启动后（`AuthSession.restoreSessionIfAvailable`）拉 `/user`
- 主窗口打开时拉 Trending / Weekly
- 详情页拉 README / Release / Issue
- AI 调用（按需）
- 后台 Poller（详见 §6）
- MCP 写工具触发 GitHub API 远端 star/unstar（仅 Pro + 用户显式开启）

#### 3.2.3 `network.server`

**为什么需要**：Starcat 的 **MCP Service**（详见 `功能实现总览.md` §0.3）需要监听本地 HTTP server，让本机 Agent（Claude / 其它 LLM 工具）通过 `http://127.0.0.1:5555/mcp` 读取 Starcat 的 repo / README / tags / 搜索能力。

**触发场景**：
- **完全可选**：Pro 用户在「设置 → MCP」手动开启，默认关闭
- 监听 `127.0.0.1:5555`（loopback only，**绝不监听** `0.0.0.0`）
- 端口可在 5555~5599 之间自定义
- 启用需 Bearer token 鉴权

**为什么不上架被拒**：MCP 监听本机端口属于「提供 loopback 网络服务」典型用法，Apple 审核允许；只要明示**仅 loopback** + 需鉴权 + 默认关闭 + 不暴露公网，就不会触发「隐式网络服务」问题。

**appLocaleEnvironment() 不需要这个**，network.server 仅给 MCP 用。

#### 3.2.4 `files.user-selected.read-write`

**为什么需要**：
- **AI 上下文产物输出**：Pro 用户在 `AISettingsView` 用 `NSOpenPanel` 选择输出目录，AI 自动整理（`AutoTidyScheduler`）的 context.xml / summary.json 写入此目录
- **未来 JSON 导入 / 导出**（v1 未实现，但已声明 entitlement 留口）

**触发场景**：
- 用户**主动点选**目录后才获得读写权限（macOS Security-Scoped Bookmark）
- App **不会**主动读 / 写用户 `~/Documents`、`~/Desktop` 等未授权位置

#### 3.2.5 `keychain-access-groups`（**暂未开**）

**现状**：ad-hoc 签名下 Xcode 拒绝编译带此 key 的 entitlements；已注释掉（见 `Starcat.entitlements` 注释 22-29 行）。

**App Store 上架时**：Connect 自动使用 Apple ID Team 签名，此 key 必须打开，**不打开**会导致 Keychain 写入失败（401 / 鉴权异常）。

**触发场景**：
- 存 GitHub OAuth token（AES-GCM 加密后入库）
- 存 BYOK AI Provider API key
- 存 Pro Entitlement 备份

### 3.3 Starcat **不使用**的权限（反向声明）

> 明确告诉审核员「我**不**需要这些」，减少反复问询。

- ❌ **摄像头 / 麦克风** — 完全不调用 `AVCaptureSession` / `AVAudioEngine`
- ❌ **位置** — 完全不调用 `CLLocationManager` / CoreLocation
- ❌ **通讯录 / 日历 / 提醒事项** — 完全不调用 EventKit / Contacts
- ❌ **蓝牙** — 完全不调用 CoreBluetooth
- ❌ **辅助功能** — 不使用 `AXIsProcessTrusted`，无后台「自动化控制」
- ❌ **照片库** — 不使用 `PHPhotoLibrary`，头像 / favicon 仅作远端 URL 加载后缓存到沙盒
- ❌ **Apple Music / iTunes** — 不调用 MediaPlayer
- ❌ **iCloud Drive 文件** — 不使用 `NSFileCoordinator.iCloud`（CloudKit 也未启用，详见 §8.3(详见 `docs/6-发版与上架/v1-上架信息准备.md`)）
- ❌ **App Groups** — 不使用，App 单实例
- ❌ **Hardened Runtime 之外的 dylib 加载** — 不动态加载非 Apple 签名 dylib
- ❌ **Hardened Runtime 之外的 JIT / W^X** — 不调用 `mmap` 写可执行页

## 4. 网络请求 / Outgoing Connections

> 4 大类 + 1 辅助。所有出站走 `URLSession`，**不**走第三方网络 SDK（Alamofire / Moya 等）。

### 4.1 GitHub REST API（主同步源）

| 项目 | 值 |
|------|---|
| **域名** | `api.github.com`（主）、`github.com`（OAuth / redirect）、`raw.githubusercontent.com`（不进，沙盒下 `WebView` 可访问） |
| **TLS** | HTTPS only（App Transport Security 默认开启） |
| **鉴权** | OAuth token（`Authorization: Bearer <token>`，token 经 AES-GCM 加密后从 Keychain 取出） |
| **OAuth 范围** | `read:user` + `public_repo`（**最小权限**，详见 `GitHub OAuth 设计.md`） |
| **OAuth 回调** | `starcat://callback` |
| **实际调用端点** | 详见 `Starcat/Core/Network/GitHubAPI/AppEndpoints.swift`（同目录下每个子模块如 `StarsAPI.swift` / `ReadmeAPI.swift` / `ReleasesAPI.swift` / `IssuesAPI.swift` / `EventsAPI.swift` 等） |
| **Rate Limit 处理** | 解析 `X-RateLimit-*` 头，主动退避；详见 `功能实现总览.md` §3.1 |

**端点（不完整列表，按使用频次排序）**：

| 方法 | 端点 | 用途 |

| `DELETE` | `/user/starred/{owner}/{repo}` | 取消 Star |
| `GET` | `/repos/{owner}/{repo}` | 拉 repo 元数据 |

#### 4.5.1 BYOK 模式（用户自配 Provider）

**触发条件**：用户在「设置 → AI」配置 OpenAI / DeepSeek / OpenRouter / Ollama / LM Studio / 任意 OpenAI-compatible endpoint。**未配置不触发**。

**上传字段**（每次 AI 调用必传）：

| 字段 | 来源 | 何时上传 |

| `messages[].role = user` | repo 名称 / 描述 / topics / language + **截断的 README**（前 N KB，见下）+ 用户笔记（仅 AI Chat 场景） | 摘要 / 标签 / 翻译 / Chat 触发时 |
| `temperature` / `max_tokens` 等参数 | 用户在「设置 → AI」配置 | 全部 AI 调用 |

**截断策略**（保护用户隐私 + 控制 token 成本）：

- **AI 摘要**：README 截前 ~6 KB（约 2,000 tokens），保留标题 + 安装段 + API 段 + 关键代码段
- **AI 翻译**：整段 README 按段落分块
- **AI 标签**：仅 repo 元数据 + description（**不**上传 README）
- **AI Chat**：完整 README 按 token 限制动态截断

#### 4.5.2 自建代理模式

**触发条件**：用户在「设置 → 服务」使用 Starcat 内置的 AI 代理（路径 B 默认，2026-06-21 后允许所有用户；BYOK 解锁需要 Pro）。

**上传目的地**：4 个 `*.fly.dev` 自建后端的 `/api/v1/ai/*` 端点（如果存在；目前**主要 BYOK 模式**，自建代理的 AI 转发未启用）。

**上传字段**：与 BYOK 模式相同（截断 README + repo 元数据）。

**用户停止方式**：「设置 → 服务」关闭 Starcat Pro AI 开关 / 取消勾选该服务；或完全卸载 App。

## 6. 后台任务

> 全部使用 `NSBackgroundActivityScheduler`（macOS 原生 API，由系统在低负载 / 合适功耗窗口触发）。**不**使用 `BGTaskScheduler`（iOS API，macOS 不支持）。
> v1 共有 **3 个** poller + **1 个** AI 调度器（Timer）+ 同步任务的触发（前台 + 启动期，非后台）。

### 6.1 releasePoller

| 项目 | 值 |

| **Identifier** | `com.starcat.app.releasePoller` |

### 6.6 后台任务合规自检（App Store 审核口径）

>
> 给审核员的**一句话总结**：
> > Starcat 共有 3 个 `NSBackgroundActivityScheduler` 实例（releasePoller / openSSFScorePoller / repoHealthPoller），全部以 `interval ≥ 30 min` + `tolerance ≥ 10 min` 运行，要求 `requiresNetworkConnectivity=true`，不要求外接电源。这是 macOS 上「数据预热 + 通知订阅」典型用例，不会造成 CPU / 电量过度消耗。所有 3 个 poller 都有 `isRefreshing` 防重入，上一轮未完成时跳过下一轮。

## 8. AI 数据流

### 8.1 BYOK 模式（Pro 用户自配 Provider）

> **默认模式**。v1 拍板（2026-06-19 D-4 修订）：免费版零 AI，BYOK 配置需要 Pro。

**数据流向**：

```
Starcat App
  │
  │ ① 用户选中 repo + 点 "AI 摘要"
  │
  ▼
[RepoAIInsightService.cachedInsightFast(for:)] ──→ 本地 cache hit? ──yes──→ 立即返回
  │ no
  ▼
[RepoAIContextProvider.makeSource(repo:)] ──→ 截断 README（~6 KB） + 拉 GitHub metadata
  │
  ▼
[OpenAI-compatible Chat Completions]  ──→ 用户在「设置 → AI」配置的 baseURL
  │                                       （OpenAI / DeepSeek / OpenRouter / Ollama / LM Studio / Custom）
  ▼
[返回 LLM 响应]
  │
  ▼
[写入本地 ai_insights 表 + UI 展示]
```

**上传字段**（详见 §4.5.1）：
- repo 名称 / 描述 / topics / language
- 截断的 README（AI 摘要 ~6 KB / AI 翻译按段落 / AI 标签仅元数据 / AI Chat 动态）
- 用户笔记（仅 AI Chat 场景）

**Starcat 自建后端收到的内容**：❌ **完全没有**。BYOK 模式是端到端用户 → Provider，Starcat 不做 MITM 转发。

### 8.2 自建代理模式（如果未来启用）

> **当前未启用**。v1 不内置 AI 转发服务；如未来在 fly.io 后端加 `/api/v1/ai/proxy`，需在本文档 + 隐私政策同步更新。

### 8.3 本地仓库分析

> Starcat **不**主动读取用户本机 Git 仓库。
> v1 **不**实施「打开本地 Git 目录分析」功能；未来如加入（参考 `v2-功能清单.md`），需走「NSOpenPanel 用户主动选 + security-scoped bookmark」路径。

### 8.4 网络搜索（AnySearch Web provider）

> AnySearch 全局搜索 ⌘K 支持 3 个 provider：Local / GitHub / Web。
> Web provider 默认 DuckDuckGo lite（无 API key），详见 `AnySearchWebProvider.swift` §4.5。

**上传字段**：
- 用户的搜索 query 字符串
- App 版本号（User-Agent）

**不上传**：用户的 GitHub 身份信息、Stars 列表、本地标签 / 笔记。

| 项目 | 值 |

**App Store 审核关注点**：

> macOS App **不**强制要求 Sign in with Apple（iOS / iPadOS 才强制）。Starcat 是 GitHub 专属工具，登录目的就是拉 Stars，**必须**接 GitHub OAuth 才能用核心功能；不接入 Apple ID 是合理的产品决策。

### 10.2 用途说明

GitHub OAuth 在 Starcat 内的**唯一**用途：
1. 拉取用户公开 Stars 列表

3. 取消 Star（用户主动触发）
4. 拉关注列表的 Events（Activity → Following）
5. 拉取每个 repo 的 security advisories（Activity → Security Advisory）

**不**用于：
- ❌ 写仓库（创建 / 修改 / 删仓库）
- ❌ 读私有仓库
- ❌ 写 Issue / PR / Comment
- ❌ 读 Gist

- ❌ 读通知
