# Starcat 1.1 RAG 隐私与审核备注

> 适用版本：Starcat 1.1.x（Mac App Store）  
> 最后更新：2026-07-20  
> 用途：发布前核对 App Store Connect App Privacy、公开隐私政策和 App Review Notes。本文只记录当前代码事实与建议填写口径，App Store Connect 中的最终选项必须由发布人根据实际提交 build 和 Provider 合同人工确认。

## 1. 结论

Starcat 的知识库仍是本地优先，但 RAG 不是“所有数据永不离开设备”：用户调用远程 AI、Embedding、重排、GitHub 实时上下文或 External Search 时，完成该次请求所需的数据会发送给相应 Provider。

1.1 发布前必须保证以下三处一致：

1. 提交 build 的真实网络行为。
2. `https://dong4j.app/starcat/privacy` 的公开隐私政策。
3. App Store Connect 的 App Privacy 与 App Review Notes。

## 2. 真实数据流

| 数据 | 默认位置 | 离开设备的条件 | 接收方 | Starcat 长期保存 |
|---|---|---|---|---|
| Stars、标签、状态、私有笔记 | 本地 SQLite | 被检索为远程 RAG 证据时 | 用户选择的 AI Provider | Starcat 自建服务不保存；本机继续保存原数据 |
| RAG 问题与有限会话历史 | 本地 SQLite | 用户发送问题且使用远程模型时 | 用户选择的 AI Provider | 会话历史在本机保存 |
| README、AI 摘要、仓库元数据 | 本地 SQLite | AI 摘要、RAG、Embedding 或重排需要时 | 对应 AI / Embedding / 重排 Provider | Starcat 自建服务默认不保存正文 |
| 本轮附件 | 本机文件与本轮草稿 | 用户选择附件并发送问题时 | 用户选择的 AI Provider | 回答完成后从 Composer 草稿移除；原文件不由 Starcat 托管 |
| RepoContext 代码上下文 | 本机临时生成 | 用户启用相应 RAG 能力并发送问题时 | 用户选择的 AI Provider | 本机保存必要的执行与引用信息 |
| External Search query | 本轮生成 | 用户开启本轮联网搜索时 | AnySearch / Tavily / Exa / Brave Search 中的已选 Provider | 本机可保存 query 摘要与执行审计 |
| External Search 网页正文 | 本轮临时上下文 | 搜索成功并进入回答生成时 | 用户选择的 AI Provider | 不写入长期 RAG 历史 |
| GitHub Issues / PR / Releases 查询 | 本轮临时上下文 | 用户授权联网或开启本轮联网时 | GitHub | 本机保存必要审计元数据 |
| Embedding 输入文本 | 本地知识片段 | 选择远程 Embedding 模型并构建索引时 | 用户选择的 Embedding Provider | 向量与状态保存在本机 |
| 本地 Ollama 请求 | 本机 | 不离开设备 | 本机 Ollama | 由用户本机环境决定 |

隐私保护边界：

- External Search 关闭时，不执行普通 Web 搜索。
- 私有仓库名称默认不进入 External Search query；只有用户另行允许私有仓库 External Search 时才可使用。
- 网页结果正文只作为本轮临时证据，不写入长期 RAG 历史。
- RAG 联网审计保存 Provider、query 摘要、URL、结果数、耗时和错误等元数据，不应持久化网页正文或 API Key。
- BYOK API Key 保存在本机 Keychain；请求发往用户配置的 Provider endpoint。
- 如提交 build 提供 Starcat 托管的 AI 代理，需额外确认代理的日志、保留期和底层 Provider，并保持隐私政策一致。

## 3. App Store Connect App Privacy

Apple 将“Collected”定义为：数据离开设备，并允许开发者或第三方合作方在完成实时请求所需时间之外继续访问。仅在本机处理不属于 Collected；仅为实时完成请求且不保留的数据也可能不属于 Collected。官方说明：<https://developer.apple.com/app-store/app-privacy-details/>。

由于 Starcat 支持多个远程 AI / Search Provider，且各 Provider 的保留策略由其合同、账户设置和隐私政策决定，1.1 建议采用保守披露，不继续使用“用户内容与搜索历史仅本地”的旧口径。

### 3.1 RAG 新增项建议

| App Privacy 数据类型 | 建议答案 | Purpose | Linked to User | Tracking |
|---|---|---|---|---|
| User Content → Other User Content | Collected | App Functionality | Yes | No |
| Search History | Collected | App Functionality | Yes | No |

填写理由：

- RAG 的自由文本问题、私有笔记、附件和知识片段属于 `Other User Content`。
- External Search query 属于 `Search History`。
- 远程请求通常通过用户 Provider API Key 或账户执行，Provider 可能把请求关联到其账户，因此保守选择 `Linked to User`。
- Starcat 不将这些数据用于广告、广告归因、数据经纪或跨 App 跟踪，所以 `Tracking` 为 `No`。
- RAG 是 1.1 的核心能力，不满足 Apple“偶发且不是主要功能”的可选披露例外。

### 3.2 必须和既有标签合并核对

- `Identifiers → User ID`：GitHub user ID / login，用于认证和本地账号隔离。
- `Purchases`：按 StoreKit 2 实际返回和开发者可访问范围填写。
- `Usage Data`：Aptabase 仅在用户 opt-in 后发送匿名白名单事件；Purpose 为 Analytics，不用于 Tracking。
- `Diagnostics`：根据提交 build 中实际上传的 crash / performance 数据填写；仅本地保存的数据不算 Collected。
- 不要把 App Store Connect 的 `Collected` 与“App 在本地保存”混为一谈。

### 3.3 发布人必须人工确认

- [ ] 核对提交 build 实际启用的 AI、Embedding、重排与 External Search Provider。
- [ ] 核对各远程 Provider 是否保留请求正文、query、日志或账户关联信息。
- [ ] 核对 App Store Connect 中 `Other User Content` 与 `Search History` 的 Purpose、Linked、Tracking。
- [ ] 核对 Aptabase、StoreKit、GitHub 和诊断数据的既有答案没有被 RAG 修改意外覆盖。
- [ ] 确认公开隐私政策 URL 已部署为 2026-07-20 或之后版本。
- [ ] 在提交审核前从 App Store Connect 产品页预览最终 Privacy Label。

## 4. App Review Notes 模板

以下英文可直接作为 1.1 RAG 审核备注的基础文本；尖括号字段必须由发布人替换，不能把 API Key 写进普通备注。

```text
Starcat 1.1 introduces an optional, local-first knowledge-base RAG workspace for GitHub Stars.

Entry path:
1. Sign in with GitHub.
2. Open Smart Collections > Knowledge Base.
3. Add one or more starred repositories to the knowledge base.
4. Open the RAG workspace and submit a question.

The RAG workspace is a Pro feature and requires configured chat and embedding models. Review access is provided through <sandbox subscription / review account / temporary Pro entitlement details entered in App Store Connect secure fields>.

Data handling:
- The knowledge index, conversations, citations, and audit metadata are stored locally on the Mac.
- When a remote AI provider is selected, the app may send the user's question, a limited conversation-history window, retrieved repository evidence, private notes, selected attachments, and repository code context to that provider to generate the requested answer.
- When a remote embedding or reranking model is selected, the content needed to create vectors or rank evidence is sent to that configured provider.
- External Search is optional and controlled by the per-turn network toggle. When enabled, a generated search query is sent to the provider selected by the user. Private repository names are excluded unless the user separately enables private-repository External Search.
- External web content is used only as temporary evidence for the current answer and is not persisted in long-term RAG history. Local audit metadata may include provider, query summary, result count, URLs, timing, and errors.
- Users may select local Ollama models to keep AI processing on their Mac.
- Starcat does not use RAG content for advertising or cross-app tracking.

GitHub live context requests are sent directly from the Mac to GitHub. BYOK provider keys are stored locally in Keychain and are not sent to Starcat-operated services.

Privacy Policy:
https://dong4j.app/starcat/privacy
```

如果提交 build 确实启用了 Starcat 托管 AI 代理，在上述模板中追加：

```text
If the user explicitly selects the Starcat-hosted AI service, request content transits through that service to the underlying AI provider. Request content is not persistently stored; limited operational metadata such as request time, quota usage, and error codes may be retained for service operation and abuse prevention.
```

## 5. 审核演示准备

- [ ] 在 App Store Connect 的安全字段提供可用 GitHub 测试账号，或明确审核员可使用自己的 GitHub 账号。
- [ ] 准备至少 2 个已加入知识库的公开仓库，避免审核员等待首次索引。
- [ ] 提供可用的 Pro sandbox 权益或临时审核权益。
- [ ] 提供可用的 chat / embedding 配置；API Key 只放安全字段，不放公开描述或截图。
- [ ] 验证“智能集合 → 知识库 → RAG 工作台”在 Release / App Store build 可达。
- [ ] 验证关闭 External Search 后不会产生 Web 请求。
- [ ] 验证默认设置下私有仓库名称不会进入 External Search query。
- [ ] 验证本地 Ollama 路径在不访问远程 AI Provider 时可工作（如把它作为审核说明的一部分）。
- [ ] 截图或录屏不得包含真实 API Key、私有笔记、私有仓库名或用户 Token。

## 6. 发布门禁

- [ ] 三份公开隐私页内容一致：App Store English、Direct English、Direct 中文。
- [ ] App Store 隐私页与提交 build 的 AI 代理路径一致。
- [ ] App Store Connect App Privacy 已由发布人复核并保存。
- [ ] App Review Notes 已填入真实入口、权益和测试配置。
- [ ] 隐私页 HTTPS URL 在无登录状态下可访问。
- [ ] 本地 HTML 链接检查与线上部署后链接检查均通过。
- [ ] 本清单不替代 Provider 合同与隐私政策审查；Provider 变更时重新核对。
