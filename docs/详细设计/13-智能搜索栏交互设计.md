# 智能搜索栏交互设计

> 本文档定义 Starcat 右上角快速搜索栏的交互、视觉状态与后续 Pro / AI 搜索扩展方案。
> 创建：2026-06-02

---

## 一、背景

Starcat 当前右上角搜索栏由 `CollapsibleSearchBar` 实现，位于中栏 `RepoListView` 的 toolbar 最右侧。它不是 SwiftUI 原生 `.searchable`，也不是 AppKit `NSSearchField`，而是 `Button + TextField` 组合出的自定义 SwiftUI 控件。

当前数据流是合理的：

- `RepoListView` 通过 `CollapsibleSearchBar(text: $vm.searchQuery)` 绑定搜索词。
- `HomeView` 对 `viewModel.searchQuery` 做 250ms debounce。
- `HomeViewModel.reloadItems()` 在 `isSearching == true` 时走 `RepoRepository.searchFTS(query:)`。

因此本次改造只处理搜索入口的交互与视觉，不改 FTS5 查询、不改数据库 schema、不改搜索结果排序策略。

---

## 二、当前问题

### 2.1 视觉状态弱

展开态背景是透明的，只显示一条很淡的边框。用户点击后虽然出现了输入框，但视觉上不像进入了稳定的搜索模式。

### 2.2 失焦行为过急

当前实现中，输入框失焦后会立即收起并清空 `text`。这会带来两个问题：

- 用户只是切到列表或详情页查看结果时，搜索条件会消失。
- 列表已经处于搜索结果状态时，顶部没有稳定状态提示。

### 2.3 按钮语义不清

展开态右侧仍然是放大镜按钮，再点击会关闭并清空搜索。放大镜在用户认知里通常表示“搜索入口 / 执行搜索”，不适合作为“关闭搜索”的唯一控件。

### 2.4 后续 Pro / AI 搜索没有预留空间

Starcat 后续会加入语义搜索、AI 推荐、命中原因解释等 Pro 能力。当前组件只有一个普通文本框，没有明确的模式槽位、权益提示和 AI 状态视觉。

---

## 三、设计目标

1. **保留 macOS 原生 toolbar 骨架**：搜索入口仍放在 `ToolbarItem(placement: .primaryAction)`，不手写整条假 toolbar。
2. **形成明确的 icon → search field 变形**：默认只有图标，点击后向左展开成稳定胶囊搜索框。
3. **搜索状态可持续**：有 query 时即使失焦也保持展开，用户能看见当前列表被搜索过滤。
4. **普通搜索克制，AI 状态有识别度**：基础 FTS5 搜索用系统中性色；只有 AI / Pro 状态才使用紫色和彩色边框。
5. **为 Pro 搜索预留，但不提前实现业务逻辑**：当前只接 keyword 搜索，状态模型预留 semantic / AI ask。
6. **尊重可访问性与 Reduce Motion**：禁用 `.buttonStyle(.plain)` 的 focus ring 后，必须通过 hover、边框和清除按钮提供反馈；动画读取 `accessibilityReduceMotion`。

## 四、交互规格

### 4.1 状态

| 状态 | 说明 | UI |
|---|---|---|
| Collapsed | 默认状态，无搜索词 | 仅显示 28-30pt 放大镜图标 |
| Expanded Empty | 点击图标后展开，尚未输入 | 胶囊输入框 + placeholder |
| Expanded Query | 有搜索词 | 保持展开，右侧显示清空按钮 |
| Focused | 输入框获得焦点 | 边框增强，icon 使用 accent |
| AI Available | Pro / AI 搜索可用但未激活 | 右侧预留 `AI` chip 或 sparkle icon |
| AI Active | 语义搜索 / AI ask 激活 | 紫色或彩色边框，显示 AI 模式标识 |

### 4.2 鼠标与键盘行为

| 操作 | 行为 |
|---|---|
| 点击折叠态图标 | 展开搜索栏并聚焦输入框 |
| 输入文字 | 更新 `searchQuery`，触发现有 250ms debounce |
| 失焦且 query 非空 | 保持展开，不清空 |
| 失焦且 query 为空 | 延迟收起，避免焦点切换时闪烁 |
| `Esc` 且 query 非空 | 清空 query，保持展开并继续聚焦 |
| `Esc` 且 query 为空 | 收起搜索栏 |
| 点击清空按钮 | 清空 query；如果输入框未聚焦则重新聚焦 |
| 点击关闭按钮 | 仅在 query 为空时显示，收起搜索栏 |

### 4.3 宽度与布局

| 属性 | 建议值 | 说明 |
|---|---:|---|
| 折叠宽度 | 30pt | 与 toolbar 图标按钮接近 |
| 展开宽度 | 280pt | 比当前 220pt 更接近桌面搜索框 |
| 高度 | 30pt | 对齐 macOS toolbar 控件 |
| 圆角 | 10-12pt | 胶囊但不过度圆润 |
| 展开方向 | 向左 | 右侧固定在 toolbar 最右端 |

## 五、视觉设计

### 5.1 基础搜索态

基础 FTS5 搜索使用中性系统色：

- 背景：`thinMaterial` 贴合系统 toolbar 材质，再叠极低透明度 tint；不使用不透明 `controlBackgroundColor`，避免暗色模式出现突兀的深色输入底。
- 边框：未聚焦为 `Color.primary.opacity(0.08...0.12)`，聚焦为 `Color.accentColor.opacity(0.24...0.28)`。
- 图标：未激活 `.secondary`，聚焦或有 query 时使用 `accentColor`。
- placeholder：`搜索仓库、标签、笔记...`，后续接入 README 搜索后可扩展为 `搜索仓库、标签、笔记、README...`。

### 5.2 AI / Pro 状态

Pro / AI 状态只作为增强层，不影响基础搜索：

- `Brand.ai` 使用低饱和 purple。
- AI 可用但未激活：显示小型 sparkle / `AI` chip，提示可切换。
- AI 激活：使用彩色渐变边框或柔和 glow，类似 Apple AI 搜索栏的状态提醒。
- 未开通 Pro：显示锁形图标或 `Pro` chip，点击后进入订阅说明，不在普通搜索中弹突兀提示。

> 约束：基础搜索不常驻彩色发光。彩色边框是 AI 模式的语义状态，不是装饰。

## 六、状态模型预留

当前先实现 keyword 模式，但组件接口应预留以下概念：

```swift
enum SmartSearchMode {
    case keyword
    case semantic
    case aiAsk
}

enum SmartSearchEntitlement {
    case free
    case proAvailable
    case proLocked
}
```

当前落地时可以先不暴露完整 enum，只在组件内部保留 `showsAIAffordance` / `isAIModeActive` 这类轻量参数。等 Pro / AI 功能进入实现阶段，再把模式提升到 ViewModel 或专门的 SearchViewModel。

## 七、实施方案

### 7.1 第一阶段：改造右上角快速搜索栏

修改范围：

- `Starcat/Shared/Components/CollapsibleSearchBar.swift`
- `Starcat/Features/Home/RepoListView.swift`
- `Starcat/Resources/Localizable.xcstrings`
- `docs/Swift 学习索引.md`
- `docs/工程进度/功能实现总览.md`

实施点：

1. 将 `CollapsibleSearchBar` 改造成更稳定的搜索控件，保留原文件名以减少 project 文件变更。
2. 展开态改为左侧放大镜 + TextField + 右侧 clear / close 按钮。
3. 有 query 时失焦不自动收起。
4. 读取 `accessibilityReduceMotion`，Reduce Motion 开启时禁用位移动画。
5. 保留 `.buttonStyle(.plain).focusEffectDisabled()` 强制规则。

### 7.2 第二阶段：Search 页面与保存搜索

未来 `SidebarRootPage.search` 不再只是占位，而是独立的搜索工作区：

- 搜索历史
- 保存搜索
- 结构化过滤
- 命中原因解释
- 本地知识库 + Web 搜索混合候选流

### 7.3 第三阶段：Pro / AI 搜索

在 Pro / AI 功能接入后扩展：

- semantic search 模式
- AI ask 模式
- 彩色 AI 状态边框
- 查询意图解释
- 搜索结果命中原因
- 使用额度 / Pro 提示

## 八、验收标准

### 8.1 功能验收

- 默认只有搜索图标。
- 点击图标后展开，输入框自动获得焦点。
- 输入 query 后列表走现有 FTS5 搜索。
- query 非空时失焦不收起。
- clear 按钮可以清空 query。
- `Esc` 行为符合 4.2。
- 搜索栏不会挤出 toolbar overflow。

### 8.2 视觉验收

- Light / Dark 下背景、边框、placeholder 都可读。
- 展开态像一个稳定搜索输入区，而不是透明 toolbar item。
- 普通搜索无常驻彩色 glow。
- AI affordance 只作为预留，不喧宾夺主。

### 8.3 工程验收

- 不改搜索数据库和 FTS5 查询逻辑。
- 不引入第三方 UI 依赖。
- `buttonStyle(.plain)` 后必须有 `.focusEffectDisabled()`。
- `xcodebuild build` 通过。
- 完成后更新 `docs/工程进度/功能实现总览.md` 的实现说明。

## 十、结论

Starcat 右上角搜索栏应保留自定义 SwiftUI 路线，而不是直接替换成 `.searchable`。理由是：基础搜索需要贴合 toolbar 的紧凑入口，后续 Pro / AI 搜索又需要彩色状态、模式切换和权益提示。正确方向是把当前临时的折叠输入框升级为一个稳定的 Smart Search 组件：基础态克制、搜索态明确、AI 态有识别度，并且不提前污染搜索数据流。
