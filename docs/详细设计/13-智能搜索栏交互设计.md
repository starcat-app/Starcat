# 智能搜索栏交互设计

> 本文档定义 Starcat 右上角快速搜索栏的交互、视觉状态与后续 Pro / AI 搜索扩展方案。
> 创建：2026-06-02

---

## 一、背景

Starcat 右上角搜索栏第一版由 `CollapsibleSearchBar` 实现，位于中栏 `RepoListView` 的 toolbar 最右侧。它经历过两次方向修正：先从 `Button + TextField` 自绘展开态调整底色和边框，再尝试用 AppKit `NSSearchField` 包装还原 Finder 输入框。

从 dong4j 最新截图看，真正的问题不只是输入框内部样式，而是搜索入口被塞进 `ToolbarItem(placement: .primaryAction)` 后，和状态 / 排序 / 多选按钮被 macOS toolbar 视觉上归为同一组，外层胶囊、hover 层、focus ring 会相互叠加。最终方案应改为 SwiftUI 系统搜索能力：

- `RepoListView` 不再维护自定义 `CollapsibleSearchBar`。
- 使用 `.searchable(text:placement:.toolbar,prompt:)` 让 macOS 生成 Finder 风格 toolbar search item。
- 搜索项由系统独立分组、独立展开，不再混入 `primaryAction` 按钮组。

当前数据流是合理的：

- `RepoListView` 通过 `.searchable(text: $vm.searchQuery, placement: .toolbar, prompt: ...)` 绑定搜索词。
- `HomeView` 对 `viewModel.searchQuery` 做 250ms debounce。
- `HomeViewModel.reloadItems()` 在 `isSearching == true` 时走 `RepoRepository.searchFTS(query:)`。

因此本次改造只处理搜索入口的交互与视觉，不改 FTS5 查询、不改数据库 schema、不改搜索结果排序策略。

---

## 二、当前问题

### 2.1 视觉状态弱

展开态背景是透明的，只显示一条很淡的边框。用户点击后虽然出现了输入框，但视觉上不像进入了稳定的搜索模式。

### 2.2 失焦行为过急

当前实现中，输入框失焦后会立即收起并清空 `text`。这会带来两个问题：

- 用户只是切到列表或详情页查看结果时，搜索条件会消失。
- 列表已经处于搜索结果状态时，顶部没有稳定状态提示。

### 2.3 按钮语义不清

展开态右侧仍然是放大镜按钮，再点击会关闭并清空搜索。放大镜在用户认知里通常表示“搜索入口 / 执行搜索”，不适合作为“关闭搜索”的唯一控件。

### 2.4 后续 Pro / AI 搜索没有预留空间

Starcat 后续会加入语义搜索、AI 推荐、命中原因解释等 Pro 能力。当前组件只有一个普通文本框，没有明确的模式槽位、权益提示和 AI 状态视觉。

---

## 三、设计目标

1. **使用系统 toolbar search item**：搜索入口交给 `.searchable(..., placement: .toolbar)`，不再塞进 `primaryAction` 按钮组，也不手写整条假 toolbar。
2. **还原 Finder 的独立搜索语义**：默认和展开态由 macOS 控制，视觉上与状态 / 排序 / 多选按钮脱组。
3. **搜索状态可持续**：有 query 时即使失焦也保持展开，用户能看见当前列表被搜索过滤。
4. **普通搜索克制，AI 状态有识别度**：基础 FTS5 搜索用系统中性色；只有 AI / Pro 状态才使用紫色和彩色边框。
5. **为 Pro 搜索预留，但不提前实现业务逻辑**：当前只接 keyword 搜索；Pro / AI 搜索先在独立 Search 工作区和后续模式设计中承接，不在基础 toolbar 里硬塞自绘状态。
6. **保留系统行为，但弱化视觉噪音**：清空按钮、键盘行为和 Reduce Motion 由系统 search item 处理；外层蓝色 focus ring 通过 AppKit 窄范围禁用，避免暗色 toolbar 上过度抢眼。

## 四、交互规格

### 4.1 状态

| 状态 | 说明 | UI |
|---|---|---|
| System Idle | 系统 toolbar search item 默认态 | 由 macOS 按当前 toolbar 风格显示，目标效果参考 Finder 右上角放大镜入口 |
| System Editing | 点击系统搜索入口后进入输入 | 原生搜索框 + 当前 placeholder |
| Query Active | 有搜索词 | `searchQuery` 非空，列表保持 FTS5 过滤结果 |
| Focused | 输入框获得焦点 | 保留系统输入行为，不显示外层蓝色 focus ring |
| AI Available | Pro / AI 搜索可用但未激活 | 基础 toolbar 暂不展示，避免破坏 Finder 搜索基础态 |
| AI Active | 语义搜索 / AI ask 激活 | 后续优先放到 Search 工作区；若必须在 toolbar 表达，再评估替换系统 search item 的成本 |

### 4.2 鼠标与键盘行为

| 操作 | 行为 |
|---|---|
| 点击系统搜索入口 | 进入系统搜索编辑态并聚焦输入框 |
| 输入文字 | 更新 `searchQuery`，触发现有 250ms debounce |
| 失焦且 query 非空 | 保留 `searchQuery`，列表继续展示搜索结果 |
| 点击清空按钮 | 使用系统 clear 行为清空 `searchQuery` |
| `Esc` | 遵循系统 search field 行为；业务层不自定义抢键盘事件 |

### 4.3 宽度与布局

| 属性 | 建议值 | 说明 |
|---|---:|---|
| 宽度 | 系统控制 | 不再在 SwiftUI 里固定 280 / 320pt，避免出现窄输入框和外层重叠 |
| 高度 | 系统控制 | 跟随 macOS toolbar density |
| 圆角 | 系统控制 | 由系统 toolbar search item 绘制 |
| 分组 | 系统控制 | 通过 `.searchable(..., placement: .toolbar)` 独立成组，不混入 `primaryAction` |

## 五、视觉设计

### 5.1 基础搜索态

基础 FTS5 搜索使用中性系统色：

- 背景 / 圆角 / 内边距 / 清空按钮：交给系统 `.searchable` 生成的 toolbar search item，避免 SwiftUI 自绘在暗色 toolbar 上出现突兀底色。
- focus ring：`RepoListView` 通过不可见 `ToolbarSearchFocusRingDisabler` 查找系统生成的 `NSSearchField`，设置 `focusRingType = .none`，只去掉外层蓝色光圈，不替换搜索框。
- toolbar 分组：搜索项独立于状态 / 排序 / 多选按钮，不共享外层胶囊。
- placeholder：`搜索仓库、标签、笔记...`，后续接入 README 搜索后可扩展为 `搜索仓库、标签、笔记、README...`。

### 5.2 AI / Pro 状态

Pro / AI 状态只作为增强层，不影响基础搜索：

- `Brand.ai` 使用低饱和 purple。
- AI 可用但未激活：显示小型 sparkle / `AI` chip，提示可切换。
- AI 激活：使用彩色渐变边框或柔和 glow，类似 Apple AI 搜索栏的状态提醒。
- 未开通 Pro：显示锁形图标或 `Pro` chip，点击后进入订阅说明，不在普通搜索中弹突兀提示。

> 约束：基础搜索不常驻彩色发光。彩色边框是 AI 模式的语义状态，不是装饰。

## 六、状态模型预留

当前先实现 keyword 模式，但组件接口应预留以下概念：

```swift
enum SmartSearchMode {
    case keyword
    case semantic
    case aiAsk
}

enum SmartSearchEntitlement {
    case free
    case proAvailable
    case proLocked
}
```

当前落地时不在 toolbar search item 上提前暴露完整 enum。等 Pro / AI 功能进入实现阶段，再把模式提升到 ViewModel 或专门的 SearchViewModel；若系统 search item 无法承载 AI 状态，再以明确需求替换为自定义控件，而不是现在提前自绘。

## 七、实施方案

### 7.1 第一阶段：改造右上角快速搜索栏

修改范围：

- `Starcat/Features/Home/RepoListView.swift`
- `Starcat/Resources/Localizable.xcstrings`
- `docs/Swift 学习索引.md`
- `docs/工程进度/功能实现总览.md`

实施点：

1. 删除 `CollapsibleSearchBar.swift`，避免继续维护自绘搜索状态机。
2. `RepoListView` 从 `.toolbar { ToolbarItem(placement: .primaryAction) { ... } }` 移除搜索入口。
3. 在视图外层追加 `.searchable(text: $vm.searchQuery, placement: .toolbar, prompt: Text("search.repoPlaceholder"))`。
4. 用小型 `repoToolbarSearch(enabled:text:)` helper 保持“仅 Manage 页启用搜索”的现有产品语义。
5. 追加私有 `ToolbarSearchFocusRingDisabler: NSViewRepresentable`，在 window 层查找 toolbar 里的 `NSSearchField` 并关闭 `focusRingType`。
6. 删除自绘搜索栏引入的空壳本地化 key，保留 `search.repoPlaceholder` 当前提示文案。

### 7.2 第二阶段：Search 页面与保存搜索

未来 `SidebarRootPage.search` 不再只是占位，而是独立的搜索工作区：

- 搜索历史
- 保存搜索
- 结构化过滤
- 命中原因解释
- 本地知识库 + Web 搜索混合候选流

### 7.3 第三阶段：Pro / AI 搜索

在 Pro / AI 功能接入后扩展：

- semantic search 模式
- AI ask 模式
- 彩色 AI 状态边框
- 查询意图解释
- 搜索结果命中原因
- 使用额度 / Pro 提示

## 八、验收标准

### 8.1 功能验收

- 默认搜索入口按 macOS 系统 toolbar search item 呈现。
- 点击系统搜索入口后进入编辑态，输入框自动获得焦点。
- 输入 query 后列表走现有 FTS5 搜索。
- query 非空时 `searchQuery` 保持，列表仍为搜索结果。
- 系统 clear 按钮可以清空 query。
- 搜索项不再和状态 / 排序 / 多选按钮共享外层胶囊。

### 8.2 视觉验收

- Light / Dark 下背景、边框、placeholder 都可读。
- 展开态接近 Finder 右上角系统搜索输入区，而不是透明或自绘 toolbar item。
- 普通搜索无常驻彩色 glow。
- AI affordance 只作为预留，不喧宾夺主。

### 8.3 工程验收

- 不改搜索数据库和 FTS5 查询逻辑。
- 不引入第三方 UI 依赖。
- 不新增自定义 `.buttonStyle(.plain)` 搜索按钮，避免额外 focus ring 规则负担。
- `xcodebuild build` 通过。
- 完成后更新 `docs/工程进度/功能实现总览.md` 的实现说明。

## 十、结论

Starcat 右上角搜索栏最终应直接使用 `.searchable(..., placement: .toolbar)`，而不是继续自绘 `CollapsibleSearchBar` 或手动包装 `NSSearchField`。理由是 dong4j 截图暴露的主要问题发生在 toolbar 分组层：搜索入口不该和状态 / 排序 / 多选按钮共享 `primaryAction` 外层胶囊。系统 search item 负责 Finder 外观、独立分组、清空按钮和暗色主题协调；外层蓝色 focus ring 作为 Starcat 当前视觉里的噪音，用 `NSSearchField.focusRingType = .none` 做窄范围修正。后续 Pro / AI 搜索如果需要彩色提醒，应优先在独立 Search 工作区承接；只有系统 search item 明确无法满足时，再带着完整交互约束重做自定义控件。
