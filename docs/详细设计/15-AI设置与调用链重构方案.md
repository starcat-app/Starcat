# AI 设置与调用链重构方案

> 创建：2026-06-04
> 状态：落地中
> 背景：旧版 AI 设置把 provider、摘要/标签模型、Embedding 模型绑定在同一组配置里，无法满足“摘要/标签和 Embedding 分别使用不同服务商”的需求。

---

## 1. 问题定义

旧实现只有一组 `AIServiceProvider + Base URL + API Key + Chat Model + Embedding Model`：

- 切换 provider 会覆盖 Base URL、摘要/标签模型和 Embedding 模型。
- API Key 只有一个存储槽，无法同时配置 LM Studio + OpenAI / OpenRouter。
- 连接测试只做 Embedding 调用，不能展示可用模型，也不能让用户启用/禁用模型。
- 摘要和推荐标签共用一次 JSON Chat 调用。只要模型把内容写进 `reasoning_content`、返回空 `content` 或 JSON 解析失败，摘要和标签会一起失败。
- Prompt 固定在代码中，用户无法针对本地模型调整提示词。

目标是把 AI 配置拆成“服务商配置”“模型任务选择”“参数与 Prompt”“业务调用”四层，让每个任务可以选择不同 provider 和模型。

---

## 2. 技术选型

### 2.1 服务商协议

继续使用 OpenAI-compatible 协议与 `MacPaw/OpenAI` SDK：

- OpenAI、DeepSeek、OpenRouter、LM Studio、Ollama 都提供 OpenAI-compatible Chat / Embedding 能力。
- 这些服务的模型列表接口普遍存在，但路径和返回字段略有差异：
  - OpenAI：`GET /v1/models`
  - DeepSeek：`GET /models`
  - OpenRouter：`GET /api/v1/models`
  - LM Studio：`GET /v1/models`
  - Ollama OpenAI compatibility：`GET /v1/models`
- MacPaw/OpenAI 已支持 `models()`、`chatsStream()`、`embeddings()`，适合继续作为第一版 adapter。

结论：Starcat 内部新增自己的 AI 配置模型与 client protocol，不把 provider 差异扩散到业务层。

### 2.2 配置存储

第一版使用 `UserDefaults` 存 JSON 配置，API Key 继续走 `KeychainManager` 的本地加密文件：

- Provider profile、启用模型、任务模型选择、参数、Prompt 属于用户偏好，体量小、无需数据库迁移。
- API Key 必须按 provider profile ID 存储，不能再只有一个全局 Key。
- 旧版 `ai_api_key` 保留读取兼容，默认迁移给第一个 legacy profile 使用。

后续如果要同步设置到 CloudKit，再把非敏感配置从 UserDefaults 迁到专门 settings 表；API Key 仍不同步。

## 3. 新配置模型

### 3.1 Provider Profile

```swift
struct AIProviderProfile: Codable, Identifiable, Equatable, Sendable {
    var id: String
    var provider: AIServiceProvider
    var displayName: String
    var baseURL: String
    var isEnabled: Bool
    var models: [AIModelDescriptor]
    var lastTestedAt: String?
    var lastTestStatus: AIProviderTestStatus
}
```

每个 profile 只表示一个“可调用的服务端”。例如：

- `LM Studio - Mac mini`
- `OpenAI`
- `OpenRouter`
- `Ollama Local`

### 3.2 Model Descriptor

```swift
struct AIModelDescriptor: Codable, Identifiable, Equatable, Sendable {
    var id: String
    var providerID: String
    var name: String
    var ownedBy: String?
    var capability: AIModelCapability
    var isEnabled: Bool
    var isCustom: Bool
}
```

模型能力只分三类：

- `chat`
- `embedding`
- `unknown`

模型列表 API 对能力标注不稳定，所以第一版只做启发式推断：

- 名称包含 `embedding` / `embed` / `nomic` / `bge` / `text-embedding` → `embedding`
- 其他默认 `chat`
- UI 允许用户手动修正能力和启用状态

**需审计确认，但已按最佳方案实现**：不强依赖 provider API 的模型能力字段。原因是 OpenAI-compatible 生态没有统一 capability schema，自动识别失败后让模型不可选，比允许用户修正更差。

### 3.3 Task Configuration

```swift
struct AIModelTaskConfiguration: Codable, Equatable, Sendable {
    var providerID: String
    var modelID: String
    var customModelName: String
    var useCustomModel: Bool
    var parameters: AIModelParameters
    var prompt: AIPromptConfiguration
}
```

Starcat 内置三个任务：

- `summary`：详情页 AI 摘要，优先流式。
- `tags`：推荐标签，JSON 解析。
- `embedding`：语义搜索向量化。

### 3.4 Parameters

```swift
struct AIModelParameters: Codable, Equatable, Sendable {
    var temperature: Double
    var topP: Double
    var topK: Int
    var maxCompletionTokens: Int
    var timeoutSeconds: Double
    var streamEnabled: Bool
}
```

约束：

- `temperature` / `topP` / `maxCompletionTokens` 走标准 Chat Completions 字段。
- `timeoutSeconds` 映射到 URLSession / SDK timeout。
- `topK` 不是 OpenAI Chat Completions 标准字段。第一版先持久化并展示，业务调用不强行发送；后续针对 LM Studio / Ollama 增加 raw JSON extra body 时再启用。

**需审计确认，但已按最佳方案实现**：`topK` 第一版只做配置留存，不发送到 MacPaw/OpenAI。原因是 SDK 的 `ChatQuery` 没有标准 `top_k` 字段，硬塞会破坏 OpenAI / DeepSeek / OpenRouter 兼容性。

## 4. 设置页 UI

设置页拆为四块：

1. **AI 服务商**
   - 左侧选择 provider profile。
   - 可新增 / 删除 / 启用 profile。
   - Provider 类型选择后自动填默认 Base URL。
   - API Key 单独保存到本机加密文件。
   - “测试并获取模型”按钮调用模型列表接口。
   - 成功后展示模型列表，用户可启用 / 禁用模型、修正模型能力。

2. **模型设置**
   - 摘要模型、推荐标签模型、Embedding 模型分别选择 provider + model。
   - 下拉框按 provider 分组展示已启用模型。
   - 支持自定义模型名，适配 LM Studio / Ollama 临时加载模型。

3. **参数**
   - 按任务配置 temperature、topP、topK、max tokens、timeout、是否流式。

4. **Prompt**
   - 摘要和标签分别配置 system prompt / user prompt。
   - 初始展示默认 prompt。
   - 支持恢复默认。
   - 运行时代码必须优先使用用户设置。

## 5. 业务调用链

### 5.1 AI 摘要

摘要使用独立 prompt 和 summary task 配置：

- 优先调用 `chatStream`。
- UI 展示流式文本。
- 流式完成后缓存摘要结果。
- 如果 provider 不支持流式或用户关闭流式，回退到普通 chat。

摘要输出改成自然语言 Markdown 文本，不再强制塞进完整 `RepoAIInsight` JSON。这样本地 reasoning 模型即使 JSON 能力弱，也能先给用户可读摘要。

### 5.2 推荐标签

推荐标签使用独立 prompt 和 tags task 配置：

- 与摘要并行调用。
- 仍要求 JSON。
- 只解析 `suggestedTags` 或数组形式标签结果。
- 失败时只显示标签错误，不影响摘要展示。
- 用户确认后才写入本地标签。

### 5.3 Embedding

语义搜索只读取 embedding task：

- 使用该 task 的 provider / model / timeout。
- 不使用 chat prompt。
- 继续写入 SQLite BLOB 缓存。

---

## 6. 迁移策略

旧设置迁移为默认 profile：

- `settings.ai.provider` → 默认 provider type
- `settings.ai.baseURL` → 默认 profile baseURL
- `settings.ai.chatModel` → summary/tags 默认 chat model
- `settings.ai.embeddingModel` → embedding 默认 model
- 旧 `ai_api_key` → profile scoped key fallback

旧字段暂时保留只读兼容一版，避免已经写入 UserDefaults 的用户配置丢失。
