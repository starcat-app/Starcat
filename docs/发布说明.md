# 发布说明

## 前提

1. 已安装 `flyctl` 并登录：`fly auth login`
2. 四个 API 目录里各有填好的 `.env`（从 `.env.example` 复制）：

```bash
cp supports/starcat-sharing-api/.env.example supports/starcat-sharing-api/.env
cp supports/starcat-trending-api/.env.example supports/starcat-trending-api/.env
cp supports/starcat-weekly-api/.env.example supports/starcat-weekly-api/.env
cp supports/starcat-wiki-api/.env.example supports/starcat-wiki-api/.env
```

3. `.env` 里至少填好：
   - 四个服务：`API_KEYS=sk-starcat-...`
   - trending / weekly：`GITHUB_TOKENS=ghp_...`

---

## 一、首次配置（推荐顺序）

### 1. 生成 API Key

```bash
bash supports/scripts/gen-api-key.sh
# 输出类似：sk-starcat-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

把**同一把 key** 写进四个 `.env` 的 `API_KEYS=`（可以四份都用同一个）。

### 2. 推到 Fly.io

在 Starcat 主仓库根目录：

```bash
make sync-fly-secrets
```

或在 `supports/` 目录：

```bash
cd supports
make fly-secrets-all
```

脚本会：
- 从各 `.env` 读密钥
- 自动设生产路径（如 `/data/trending.db`）
- sharing 的 `BASE_URL` 强制为 `https://starcat-sharing-api.fly.dev`（不用本地 localhost）

### 3. 验证 Fly 后端

```bash
make -C supports fly-health-all
```

四个都应输出 `ok`。

也可在 App 里：**设置 → 服务** → 各服务点「测试连接」。

### 4. 配置 Starcat 发版用的默认 Key（baked-in）

```bash
make setup-production-api-key KEY=sk-starcat-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

会写入 `Configs/Secrets.xcconfig`（已 gitignore，不会进仓库）。

之后用 Xcode / `make build-dmg` 构建的 App，会自带这把 key，用户不用先填。

> 这把 key 必须和 Fly 上四个 App 的 `API_KEYS` 一致（第 2 步已同步的话就对齐了）。

## 二、日常运维命令

在 `supports/` 目录执行（或主仓库用 `make -C supports <target>`）：

| 你想做什么 | 命令 |
|-----------|------|
| 看所有命令 | `make help` |
| 只同步某一个服务 secrets | `make fly-secrets-trending`（sharing / weekly / wiki 同理） |
| 看 Fly 上配了哪些 secret 名 | `make fly-secrets-list` |
| 看 4 个 App 状态 | `make fly-status-all` |
| 健康检查 | `make fly-health-all` |
| 部署 4 个 App | `make fly-deploy-all` |
| 只部署一个 | `make fly-deploy-trending` |
| 清空数据库重建 | `make fly-wipe-data-all`（或 `fly-wipe-data-weekly` 等） |

主仓库根目录额外有两个：

```bash
make sync-fly-secrets              # = supports 的 fly-secrets-all
make setup-production-api-key KEY=sk-starcat-...   # 写客户端 baked-in key
```

## 三、改密钥后怎么更新

1. 改四个 `.env` 里的 `API_KEYS`（或 `GITHUB_TOKENS` 等）
2. 同步到 Fly：

```bash
make sync-fly-secrets
```

3. 若改了客户端用的 production key，再执行：

```bash
make setup-production-api-key KEY=新的key
```

4. 重新构建 / 发版 Starcat App

Fly 设 secrets 后会自动滚动重启 Machine，一般不用手动重启。

## 四、本地开发 vs 生产

| 场景 | 怎么做 |
|------|--------|
| 本地跑四个 API | `make start-supports` |
| 本地 Starcat 连本地 API | **设置 → 服务** 改各服务 URL 为 `http://127.0.0.1:500x` |
| 本地 Starcat 连 Fly 生产 | URL 留空（默认 `*.fly.dev`），Key 用 baked-in 或设置页填写 |
| 只改 Fly 配置文档 | 看 `supports/docs/fly-io-环境变量.md` |

## 五、发版前快速检查（对应上架清单 §2.2）

```bash
# 1. Fly 四端健康
make -C supports fly-health-all

# 2. secrets 已同步
make -C supports fly-secrets-list

# 3. 客户端有 baked-in key（若走 A 方案）
test -f Configs/Secrets.xcconfig && grep STARCAT_PRODUCTION_API_KEY Configs/Secrets.xcconfig
```

## 六、常见问题

**Q：App 打开 Trending 报 401？**  
→ Fly 上缺 `API_KEYS`，或客户端 key 不在白名单。跑 `make sync-fly-secrets`，并确认 `setup-production-api-key` 用的是同一把 key。

**Q：`make sync-fly-secrets` 报某 `.env` 缺字段？**  
→ 打开对应 `.env`，按 `supports/docs/fly-io-环境变量.md` §5 补必填项。

**Q：分享链接域名不对？**  
→ sharing 的 Fly `BASE_URL` 必须是公网 URL；`fly-secrets-sync.sh` 会自动设 `https://starcat-sharing-api.fly.dev`，不要用手写 localhost。

**Q：schema 变了要清库？**  
→ `make -C supports fly-wipe-data-all`，服务重启后会自动 `createSchema` 建新库。
