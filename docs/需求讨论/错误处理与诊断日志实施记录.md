# 错误处理与诊断日志实施记录

> 创建：2026-06-20  
> 分支：`codex/diagnostics-error-handling`

## 1. 背景

Starcat 依赖 GitHub、自建 Trending/Weekly/Wiki/Sharing 服务、AI provider、StoreKit、Keychain 和本地 SQLite。外部服务不可用、网络中断、API Key 失效、后端响应格式变化、本地数据库打不开时，用户需要看到可理解的提示；dong4j 需要用户可导出的调试日志来快速定位问题。

本次目标不是引入 analytics，也不是把所有 OSLog 暴露给用户，而是补齐三件事：

1. 关键错误不导致 App 崩溃。
2. UI 展示用户友好的错误说明和建议操作。
3. 用户可主动导出本机诊断包，便于排查。

## 2. 实施内容

### 2.1 诊断日志基础设施

新增 `Starcat/Shared/Diagnostics/DiagnosticEvent.swift` 与 `DiagnosticLogStore.swift`。

- 诊断日志采用 JSONL，位置在 Application Support 的 `diagnostics/diagnostic-log.jsonl`。
- 文件超过 2 MB 后滚动到 `diagnostic-log.1.jsonl`，避免无限增长。
- 只记录关键 warning/error/critical 和少量用户主动排障动作。
- 事件字段包含时间、level、category、operation、service、statusCode、errorCode、underlying、context。
- 写入失败只记 OSLog，不影响主业务。

### 2.2 用户友好错误映射

新增 `Starcat/Shared/Diagnostics/UserFacingError.swift`。

它把底层错误分成稳定的用户语义：

- 网络连接失败
- 鉴权失败
- 请求限流
- 资源不存在
- 服务暂时不可用
- 响应格式不支持
- 本地数据不可用
- 安全存储不可用
- AI 配置问题
- AI 服务响应异常
- 未知错误

UI 展示标题、说明和建议操作；诊断包记录底层错误、状态码和后端错误码。这样避免把 `URLError.localizedDescription`、`[CODE] message`、解码栈等信息直接暴露给普通用户。

### 2.3 启动期崩溃兜底

`AppDependencies.init()` 改为 `throws`。数据库初始化失败时不再 `fatalError`，而是由 `StarcatApp` 捕获并显示 `StartupFailureView`。

启动失败页提供：

- 用户友好错误说明。
- 导出调试日志按钮。
- 退出 Starcat 按钮。

这样能避免半初始化依赖树继续读写本地数据，同时保留排障出口。

### 2.4 诊断包导出

新增 `Starcat/Shared/Diagnostics/DiagnosticBundleExporter.swift`。

设置页新增 `Diagnostics` 标签，用户可导出 zip。启动失败页也复用同一导出器。

导出包包含：

- `diagnostic-log.jsonl`
- `diagnostic-log.1.jsonl`（如存在）
- `app-info.json`
- `settings-snapshot.json`
- `README.txt`

设计上不包含：

- GitHub token
- API Key
- AI prompt
- README 正文
- 私有笔记

诊断事件会对 `Bearer ...`、`token=...`、`api_key=...`、`authorization=...` 做最小脱敏。

### 2.5 已接入路径

本次接入的关键路径：

- App 启动期数据库初始化失败。
- GitHub Stars 同步失败、401、限流。
- Home 列表加载失败。
- Trending 加载失败。
- Weekly 分页/远端加载失败。
- Activity events、GitHub Blog RSS、Security Advisory 后台失败。
- AI Chat 流式失败。
- AI 摘要加载/生成/标签应用失败。
- README 翻译失败。
- 设置页 Service Health Check 失败。

## 3. 约束

- 诊断日志不是 analytics，不自动上传。
- 不记录高频 UI 生命周期，避免性能和噪音问题。
- 不记录外部服务原始响应 body。
- AI HTTP 原始响应调试仍保留 DEBUG-only `DebugAIHTTPLogging`，Release 不启用。
- 对有缓存兜底的功能，后台失败只写诊断日志，不强行打断用户浏览。
