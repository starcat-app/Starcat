## 1. 最终目标

Starcat 长期提供两个构建产物：

| 渠道 | 包 | 更新机制 | 支付入口 |
|------|----|----------|----------|
| App Store | Mac App Store archive | App Store 更新 | StoreKit |
| Direct | 官网 DMG | Sparkle appcast 自动更新 | Direct 支付网关 |

两个包共享核心业务代码，但审核边界必须清晰。

---

## 2. 核心需求

### 2.1 App Store 版本

App Store 版本必须：

1. 只走 App Store 打包和提审流程。
2. 只走 App Store 更新机制。
3. 不链接 Sparkle。
4. 不打包 Sparkle helper / XPC service。
5. 不包含 `SUFeedURL`、`SUPublicEDKey` 等 Sparkle `Info.plist` key。
6. 不展示 Direct 更新、官网购买、license key 激活入口。

### 2.2 Direct 版本

Direct 版本必须：

1. 生成 Developer ID 签名的 app。
2. 生成 notarized + stapled DMG。
3. 集成 Sparkle 2 自动更新。
4. 使用 `https://starcat.ink/appcast.xml` 作为 appcast 地址。
5. 支持手动检查更新。
6. 后续支持后台自动检查更新。
7. 提供便捷打包脚本和打包教程。

---

## 3. 为什么先做分发渠道

Sparkle 和 Direct 支付都依赖构建渠道分离：

```text
DistributionChannel
  -> App Store build
      -> StoreKit
      -> App Store update
  -> Direct build
      -> Direct payment provider
      -> Sparkle update
```

如果先把 Creem 写进现有单一 App target，后续容易污染 App Store 包；如果先接 Sparkle 而不拆渠道，也有同样审核风险。

因此实施顺序应为：

1. 构建渠道分离。
2. Direct 集成 Sparkle。
3. App Store / Direct 打包脚本。
4. Direct 支付 provider 接入。

---

## 4. 打包脚本需求

### 4.1 App Store 打包脚本

目标脚本：

```bash
./scripts/package-appstore.sh
```

职责：

1. 校验渠道为 App Store。
2. 运行 `xcodegen generate`。
3. archive App Store target。
4. 导出用于 Transporter / Xcode Organizer 上传的产物。
5. 自检 App Store 包不含 Sparkle 和 Direct 支付入口。

### 4.2 Direct 打包脚本

目标脚本：

```bash
./scripts/package-direct.sh
```

职责：

1. 校验渠道为 Direct。
2. 运行 `xcodegen generate`。
3. archive Direct target。
4. Developer ID 签名。
5. notarize + staple。
6. 生成 DMG。
7. Sparkle 签名更新包。
8. 更新或生成 appcast。
9. 自检 Direct 包含 Sparkle 且不包含 StoreKit 购买入口。
