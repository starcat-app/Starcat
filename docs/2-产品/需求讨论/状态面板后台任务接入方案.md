# 状态面板后台任务接入方案

> 状态：前三批已确认，开发中；P3 候选仍待独立讨论
> 梳理日期：2026-11-10
> 已完成基线：仓库搜索索引已接入并经人工验证，提交 `0204d594`
> 本文范围：梳理设置页及其他入口的任务，确定接入优先级、实施批次与验收标准

## 1. 背景与目标

仓库搜索索引此前只能在设置页查看进度，现已接入状态面板。其他耗时操作也存在类似问题：用户离开操作入口后，难以判断任务是否仍在执行、是否失败，以及如何回到对应页面。

后续接入继续复用现有任务投影，让状态面板提供统一的任务入口和真实执行状态。设置页保留配置、重建和详细操作；面板只展示任务摘要、入口与任务本身已经支持的操作。

依据：[开发前问题清单：状态面板后台任务总览](../../1-立项/开发前问题清单.md)。dong4j 已于 2026-11-10 确认在独立 worktree 实施前三批，按批次与功能分别提交；本文不代表候选任务已经完成接入。

## 2. 已有覆盖与边界

当前后台任务投影已覆盖以下八类：

| 任务 | 展示与计数约束 |
|------|----------------|
| AI 分组 | 按当前执行批次展示，包括待确认等阶段 |
| AI 标签整理 | 批处理已覆盖相关自动整理工作，不再新增 AutoTidy 父任务 |
| 首次预热 | 作为父任务展示 |
| README 预拉 | 首次预热持有该工作时不重复计数 |
| OpenSSF 刷新 | 复用已有刷新任务状态 |
| 仓库健康刷新 | 复用已有刷新任务状态 |
| 知识库内容索引 | 与仓库搜索索引独立计数 |
| 仓库搜索索引 | 运行、暂停及失败摘要；正常完成或取消后移除，点击进入搜索与索引设置 |

状态面板还已有 Stars 同步卡片、本地 AI 内存与推理状态、MCP、浏览器插件、API 服务可用性和 Undo Star 清理摘要。这些区域各有职责，不因本次梳理重复计入后台任务。

## 3. 接入优先级

优先级衡量用户价值与信息缺口，实施批次同时考虑已有状态能否直接复用。P1 表示优先补齐；P2 表示随后完善；P3 表示需要独立讨论生命周期。本次不安排发布阻断级 P0，也不预估未经验证的工期。

| 顺序 | 优先级 | 候选任务 | 用户价值与现状 | 接入成本 / 关键依赖 | 建议批次 |
|------|--------|----------|----------------|----------------------|----------|
| 1 | P1 | 本地模型下载，含 Laya | 下载时间长，已有真实字节与速度，当前本地 AI 状态区不能替代下载进度 | 中：复用全局管理器；任务 ID 需支持多个模型并存 | 第一批 |
| 2 | P1 | Runtime 下载与安装 | Codex App Server、DeepSeek Harness、CodebaseMemory 的安装过程应可持续查看 | 较高：进度和句柄目前由按钮持有，离开页面会取消；需先确认并调整生命周期 | 第二批 |
| 3 | P1 | 屏保头像预取 | 已有完成数与总数，可补齐离开设置后的可见性 | 低：已有全局状态；仅 Direct，暂无独立停止能力 | 第一批 |
| 4 | P2 | 对话历史存储迁移 | JSON / SQLite 切换耗时期间需要明确反馈 | 低：已有全局迁移标记；只显示不确定进度，无取消入口 | 第一批 |
| 5 | P2 | “我的项目”同步 | 离开列表后仍能发现同步与失败 | 低至中：已有全局状态，需明确列表跳转；无实时数量进度 | 第三批 |
| 6 | P2 | GitHub 通知同步 | 补齐实际同步期间的状态与入口 | 低至中：复用 inbox 同步状态，处理短任务展示与错误归属 | 第三批 |
| 7 | P3 | 仓库文件、Release 附件下载 | 下载需要跨页面可见、可回到结果位置 | 较高：任务由页面持有，需设计共享所有权、多实例和关闭行为 | 后续独立方案 |
| 8 | P3 | CodeFlow / CodebaseMemory 分析 | 耗时分析适合提供跨页面入口 | 较高：面板关闭会取消，需明确后台执行和重新打开的语义 | 后续独立方案 |
| 9 | P3 | Agent 执行 | 执行与等待确认值得全局提醒 | 较高：会话由工作台窗口持有，需确定活动 run 的访问与窗口生命周期 | 后续独立方案 |

Runtime 的产品优先级高，但不是简单增加一行投影。建议先交付已经具备全局状态的任务，再单独处理 Runtime 的生命周期，避免在一次接入中改变多类任务的关闭行为。

## 4. 分批实施范围

### 第一批：复用已有全局状态

建议范围：本地模型下载（含 Laya）、屏保头像预取、对话历史迁移。

1. 本地模型下载按模型实例展示，复用真实下载进度、设置入口和已有暂停能力。下载后自动加载属于同一轮安装流程，不另计一个任务
2. 屏保头像预取显示已完成数与总数，点击进入屏保设置；第一版只提供查看入口
3. 对话历史迁移显示“迁移中”等不确定进度，点击进入数据与存储；保留原迁移与错误恢复流程

本地模型管理器的暂停目前会把准备或下载状态恢复为 `.idle`，没有独立的持久 `.paused` 状态。第一版按已有状态移除暂停后的活动行，继续下载仍走设置页现有入口，不另外维护暂停任务记录。

对话迁移不提供人为百分比或任意取消，不能为了面板展示改动 staging 校验、最终交换及失败恢复逻辑。

### 第二批：Runtime 下载与安装

建议范围：Codex App Server、DeepSeek Harness、CodebaseMemory 三种 Runtime。

当前 `RuntimeDownloadButton` 通过 `@State` 持有任务与进度，并在 `.onDisappear` 取消。建议改为共享持有活动安装，使离开设置页后仍可继续；这是需要确认的行为变化，确认前不实施。

接入时保留下载、校验、解压、安装和配置写入的阶段边界。配置仍在安装成功后按现有流程写入；保留已有确认与校验。停止能力必须按安装器的真实取消边界提供，不能仅让任务行消失，也不能宣称已经写入的配置会自动回滚。

按 Runtime 标识活动任务，继续复用现有按 Runtime 去重能力，不新增另一套下载器。

### 第三批：补齐业务同步

建议范围：“我的项目”同步、GitHub 通知同步。

- “我的项目”复用 `UserProjectSyncService.state` 展示同步与失败，点击进入项目列表；没有实时处理数时只显示阶段
- GitHub 通知复用 `GitHubNotificationInboxService.isSyncing` 展示实际请求，点击进入通知列表；失败提示需确认属于哪一轮请求，不能把历史错误永久挂成活动任务
- 两类任务均先不加停止按钮：当前没有独立的“仅停止本轮”能力，不能调用关闭周期调度的方法代替

### 后续独立讨论

文件下载、代码分析与 Agent 执行均需要先回答：关闭原页面后是否继续、谁持有任务、点击任务后如何回到同一执行实例。明确这些行为后再设计接入，不在前三批顺带改造。

## 5. 共用展示与操作规则

### 任务身份与计数

目前 `AppBackgroundTask.id` 使用 `Kind`，适合每类只有一项的任务。本地模型可同时下载，接入前需最小扩展为“任务类型 + 实例标识”；具体实例用模型 ID 或 Runtime ID，既有单例任务保持稳定身份。

徽章、卡片和列表继续读取同一份投影。计数按执行实例，不按下载文件数、仓库数量、安装阶段或等待执行的队列项目数量计算。保留首次预热与 README、自动整理与已有批处理的去重关系。

### 状态来源与进度

只读取现有管理器的真实状态，不在视图中维护第二套任务真值，不新增调度、数据库表、持久化或通用任务历史。

有真实完成数或字节数时显示数字，没有时显示阶段。任务行沿用单行摘要，不添加进度条。正常完成后从活动列表移除；失败、暂停与待确认依各任务现有状态处理，不能将“服务已启动”或“周期轮询已启用”解释为“任务正在执行”。

不为缺少失败或暂停状态的管理器自行补造记录。若某类任务确需完成后保留错误，应在该批次明确其来源、清除和重试语义，再实现。

### 入口与操作

点击进入对应设置区、列表或原执行页面，并在浮层关闭后重新确认任务仍存在。具体设置路由在实施时核对现有路由，不能依赖显示标题定位。

暂停、停止和取消只调用该任务已有且语义匹配的能力。没有能力就只提供查看入口；不把清缓存、停调度、关闭服务或回滚结果放进“停止本轮”操作。

## 6. 暂不接入的项目

| 项目 | 原因与处理 |
|------|------------|
| AutoTidyScheduler | 触发已有分组与批处理工作，单独计数会重复 |
| ReleasePoller | `isRunning` 表示周期调度已启用，尚无适合直接投影的本轮扫描状态 |
| GitHubNotificationPoller | 调度状态不代表正在同步，应使用 inbox 的实际请求状态 |
| Stars 同步 | 已有独立同步卡片，保留现有入口 |
| 本地 AI 内存加载、卸载与推理 | 已有专属状态区域；模型磁盘下载按第一批单独补齐 |
| MCP、浏览器插件、API 健康检查 | 属于服务状态，不作为持续活动任务计数 |
| 系统翻译语言包下载 | 由 `TranslationSession.prepareTranslation()` 驱动，应用没有真实字节进度与完整取消控制，暂不承诺统一管理 |
| 缓存清理、恢复出厂、短导出、连接测试 | 暂不为这些操作扩大后台任务系统；后续若出现明确的长耗时与跨页面需求再评估 |
| CodebaseMemory 常驻 UI 进程 | 进程存活不代表分析正在执行 |

## 7. 验收标准

| 批次 | 必须验证的行为 |
|------|----------------|
| 第一批 | 多模型同时下载具有独立身份，更新和暂停互不影响；离开设置后仍显示真实活动状态；暂停不伪造持久记录；屏保预取只在 Direct 展示；迁移只显示真实阶段且不提供取消 |
| 第二批 | 关闭设置后安装按确认后的行为继续；重新进入能恢复同一安装进度；同一 Runtime 不重复启动；校验、安装或配置失败可定位；停止遵守真实阶段边界 |
| 第三批 | 只在实际同步时出现；开启周期调度不产生常驻任务；点击到正确列表；短请求结束后无残留；历史错误不误计为新任务 |
| 全部批次 | 徽章与列表计数一致；父子工作不重复；完成与取消后按既定语义移除；操作只影响所选任务；App Store / Direct 构建通过 |

新增或修改文案必须覆盖当前全部支持语言，以 `AppLocale` 与本地化项目语言清单为准，并如实保留 AI 初稿审核状态。检查窄面板、长译文和不同语言方向下的单行摘要。

自动验证重点放在任务投影、实例身份、计数和操作映射；生命周期变化另做真实运行验收。方案落档本身只需校验文档与引用，不代表上述运行验收已完成。
