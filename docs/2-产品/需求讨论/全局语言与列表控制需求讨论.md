# 全局语言与列表控制需求讨论

> 日期: 2026-07-03
> 状态: 需求确认, 进入正式方案与详细设计
> 范围: 全局语言筛选、探索 Weekly 迁移、中栏顶部排序与模块筛选语义整理

## 1. 背景

Starcat 当前的列表控制能力分布较散:

- 星标模块左侧有语言筛选,中栏顶部有排序,toolbar 中还有筛选。
- 探索模块下的发现 / 热门 / 新发布中栏顶部曾显示“筛选”,但实际只有排序。
- 探索趋势同时存在语言、周期和排序,其中周期不应被归入排序。
- 活动周刊当前在 Activity 下,中栏顶部同时包含筛选、排序和独立语言筛选。

这些入口都能工作,但用户理解成本偏高。更重要的是,用户希望在 Starcat 中形成“只看我感兴趣语言”的全局使用习惯,而不是每个模块重新找一遍语言入口。

## 2. 讨论结论

本次确认的方向:

1. 项目名为“全局语言与列表控制专项”。
2. Weekly 从 Activity 迁移到 Explore,成为探索模块下的子分类;Activity 不保留双入口兼容。
3. 语言筛选放在左侧 Sidebar,切换星标 / 探索子分类 / Weekly 时,语言列表随当前模块切换。
4. 排序保留在中栏顶部,不放到 window toolbar。
5. 排序使用统一组件外观,但排序状态按模块保存,不做跨模块共享的全局排序值。
6. 模块专属筛选仍放在中栏顶部,只展示当前模块真实有效的条件。
7. 语言、排序、筛选和 Explore 默认子分类属于“列表偏好”,按 GitHub 账号本地保存。
8. 提供统一的“重置列表偏好”入口,避免用户忘记自己选中过滤条件后误以为数据异常。

一句话原则:

> 全局的是语言筛选入口和列表控制体验,不是把所有模块强行套进同一组筛选 / 排序字段。

## 3. 目标信息架构

### 3.1 探索模块

探索模块最终包含:

- 发现
- 趋势
- 热门
- 新发布
- 周刊

Weekly 迁移到 Explore 后,它与趋势 / 热门 / 新发布一样属于“发现外部项目”的内容,而不再混在 Activity 的动态流中。

### 3.2 左侧语言筛选

左侧 Sidebar 承担当前模块的语言筛选:

- 星标: 使用本地 DB 语言统计。
- 探索趋势: 使用 Trending 语言列表。
- 探索热门 / 新发布 / 发现: 使用 Discovery catalog / bulk 语言列表。
- 探索周刊: 使用 Weekly 语言列表。

语言列表随当前模块切换。当前模块没有的语言不展示,避免用户选中后列表必然为空。

第一版仍按单选语言设计: `All Languages` + 单个语言。多选语言属于后续增强,不进入本轮默认目标。

`All Languages` 是固定哨兵项,不依赖接口返回。具体语言列表按当前模块 / Explore 子分类的数据源加载:有缓存时优先用缓存,接口刷新失败时保留已有列表或使用 fallback,语言列表失败不阻断主列表展示。

### 3.3 中栏顶部控制区

中栏顶部保留为“列表控制区”:

- 排序: 独立显示为“排序”。
- 周期: 趋势独有,独立显示为“周期”。
- 筛选: 只放当前模块的业务筛选,例如 Weekly 来源 / 覆盖 / 仓库状态 / Stars / 活跃度。
- 刷新 / 新鲜度: 保持在中栏顶部右侧。

不把排序放进 window toolbar,也不把所有筛选都塞进一个全局按钮。

## 4. 不做范围

第一版不做以下内容:

- 不做 Weekly 在 Activity 和 Explore 的双入口兼容。
- 不做多选语言。
- 不做跨所有模块共享同一个排序状态。
- 不把阅读状态、知识库状态这类星标专属筛选暴露到探索 / 周刊。
- 不把 Activity 普通分类的“活动时间排序”伪装成 repo 排序。
- 不在本轮重做全部 Sidebar 视觉结构。

## 5. 初步拆分

后续可拆为四条主线:

1. Weekly 迁移: 把 Weekly 从 Activity 移到 Explore,保留详情、多选、入库、README 等能力。
2. 语言左移: 将 Weekly 语言筛选迁到 Sidebar,并统一当前模块语言列表切换机制。
3. 中栏排序统一: 抽象中栏顶部排序组件,各模块按自身数据暴露可用排序项。
4. 模块筛选整理: 将 Weekly 筛选与排序拆开,保留模块专属筛选,清理“筛选其实是排序”的文案和结构。
5. 列表偏好重置: 在设置页、菜单栏图标右键菜单和 Dock 菜单提供统一“重置列表偏好”动作。
