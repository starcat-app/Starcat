# Starcat 自研相似仓库推荐算法设计方案

> 目标：为 Starcat 设计一套可从 MVP 逐步演进到生产级的「GitHub 相似仓库推荐系统」，用于支持仓库详情页相似项目推荐、技术选型候选扩展、用户兴趣推荐和 AI Repo Research Agent。

> 2026-08-24 修订：本文件是早期总体草案。已确认的生产方向综合 SimRepo v2 时间衰减 co-star 与 Puzer Metric Learning；训练由 `starcat-recsys-trainer` 承担，在线查询统一由 `starcat-recommend-api` 提供 v1 SimRepo / v2 自研双路契约，不再创建 `starcat-recsys-api`。最终可实施契约以 [61-Starcat自研仓库推荐系统详细设计](../../../3-设计/详细设计/61-Starcat自研仓库推荐系统详细设计.md) 为准；客户端数据上报以 [60-Starcat数据贡献与数据平台详细设计](../../../3-设计/详细设计/60-Starcat数据贡献与数据平台详细设计.md) 为准。

---

## 1. 背景与目标

Starcat 当前的定位可以概括为：

> macOS 原生的 GitHub 项目发现、阅读、AI 分析与技术调研工作台。

在这个定位下，「相似仓库推荐」不是一个孤立功能，而是整个产品链路中的关键能力：

```text
发现 Repo → 阅读 README → AI 摘要 → 相似项目推荐 → 横向对比 → 技术选型报告 → 收藏/跟踪
```

例如用户打开：

```text
langchain-ai/langchain
```

Starcat 应该能推荐：

```text
run-llama/llama_index
microsoft/semantic-kernel
deepseek-ai/DeepSeek-Coder
deepseek-ai/DeepSeek-V3
deepseek-ai/awesome-deepseek-integration
deepseek-ai/DeepSeek-R1
crewAIInc/crewAI
deepseek-ai/DeepSeek-R1-Distill-Qwen
```

推荐结果不应该只是「看起来相关」，而应该服务于真实工作流：

- 帮用户发现同类项目；
- 帮用户做技术选型候选集扩展；
- 帮用户找到同生态、同场景、同技术栈的仓库；
- 帮用户将多个候选项目交给 AI 做横向对比；
- 为后续 Repo Research Agent 提供候选项目召回能力。

## 2. 推荐系统目标定义

### 2.1 核心输入

推荐系统需要支持三类输入：

| 输入类型 | 示例 | 输出目标 |
|---|---|---|
| 单仓库 | `langchain-ai/langchain` | 相似仓库列表 |
| 多仓库 | `langchain` + `llama_index` + `haystack` | 更多技术选型候选 |
| 用户行为 | 用户收藏、浏览、AI 分析过的 repo | 个性化推荐 |

### 2.2 核心输出

推荐结果应包含：

```json
{
  "repo_id": 123456,
  "full_name": "run-llama/llama_index",
  "description": "...",
  "language": "Python",
  "stars": 42000,
  "forks": 5000,
  "score": 0.92,
  "sources": {
    "content": 0.88,
    "collaborative": 0.91,
    "topic": 0.76,
    "activity": 0.66
  },
  "reasons": [
    "README 语义相似",
    "同属 LLM/RAG 框架",
    "topics 重叠：llm、rag、agents",
    "被相似 GitHub 用户共同 star"
  ]
}
```

### 2.3 推荐系统设计原则

1. **不要只做 star 共现**：GitHub star 是强信号，但冷启动差，也容易受异常 star 影响。
2. **不要只做 README embedding**：内容相似对新项目友好，但无法捕捉真实开发者兴趣关系。
3. **要混合推荐**：内容、行为、元数据、活跃度、用户反馈都要进入推荐链路。
4. **先上线 MVP，再逐步训练模型**：不要一开始就做全量 GitHub 推荐系统。
5. **推荐必须可解释**：Starcat 面向技术调研，用户需要知道为什么推荐。

## 3. 与 SimRepo 的关系

SimRepo 的核心思路是：

```text
GitHub stars 数据
    ↓
repo-user 交互矩阵
    ↓
repo embedding
    ↓
Qdrant 向量检索
    ↓
相似仓库推荐
```

补充复核：SimRepo 当前公开说明已区分 v1/v2。v1 是 100 维 `TruncatedSVD` embedding + Qdrant cosine；v2 是时间衰减 shared-stargazer overlap 的预计算协同过滤。公开仓库没有 v2 完整训练流水线，因此本文件后续将 SimRepo 统一描述为 embedding 的段落属于早期理解，不能作为最终实现依据。

SimRepo README 中提到，它使用超过 3 亿 GitHub stars 训练出的向量空间，为 100 stars 以上的仓库提供相似仓库推荐。它的浏览器扩展端调用 Qdrant Recommend API，根据当前 GitHub repo id 作为 positive example 返回相似仓库。

Starcat 可以借鉴 SimRepo 的方向，但不应该完全照搬：

| 维度 | SimRepo | Starcat 自研方向 |
|---|---|---|
| 核心目标 | GitHub 页面侧边栏相似仓库 | 技术调研工作台中的推荐引擎 |
| 核心信号 | GitHub star 行为 | 内容 + star + topic + 用户行为 + AI 分类 |
| 冷启动 | 较弱 | README / topics / metadata 兜底 |
| 推荐解释 | 较弱 | 必须输出推荐原因 |
| 技术选型 | 不直接支持 | 重点支持 |
| 多数据源 | GitHub 为主 | GitHub + Show HN + Product Hunt + Starcat 用户行为 |

## 4. 整体架构

推荐系统建议采用「多路召回 + 混合排序 + 可解释输出」架构。

```text
                 GitHub / Starcat 数据源
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
   Repo 元数据        README/代码文本      用户行为 / Stargazers
       │                 │                 │
       ▼                 ▼                 ▼
 Metadata Feature   Text Embedding   Collaborative Signal
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
                  多路召回 Recall
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
 Content Recall     Co-star Recall    ALS / LightFM Recall
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
                  Candidate Merge
                         │
                         ▼
                  Feature Builder
                         │
                         ▼
                  Ranking / Re-ranking
                         │
                         ▼
                  Explanation Generator
                         │
                         ▼
                  Starcat API / UI
```

## 5. 分阶段建设路线

推荐系统不要一口气做完整模型，建议分四个阶段。

### 阶段 1：内容相似推荐 MVP

目标：最快上线可用的「相似仓库」功能。

核心信号：

- repo name；
- description；
- topics；
- primary language；
- README；
- AI 生成的 README summary。

推荐方法：

```text
repo_text = repo_name + description + topics + language + README summary
    ↓
embedding(repo_text)
    ↓
Qdrant / pgvector cosine similarity
    ↓
过滤 archived / disabled / 过低质量仓库
    ↓
按 similarity + stars + activity 排序
```

阶段 1 不做：

- 全量 stargazer 抓取；
- ALS 训练；
- 个性化推荐；
- Learning-to-Rank；
- 深度模型。

适合理由：

- 对新项目友好；
- 数据容易获取；
- 不依赖大规模 GitHub star 数据；
- 工程复杂度低；
- 能快速在 Starcat 详情页产生明显产品价值。

---

### 阶段 2：局部 co-star 共现推荐

目标：在 Starcat 已收录的仓库范围内，引入真实用户兴趣相似信号。

数据范围不做 GitHub 全量，只采：

- GitHub Trending；
- Starcat 用户收藏过的 repo；
- Starcat 用户打开过详情的 repo；
- Show HN 中带 GitHub 链接的 repo；
- Product Hunt 中带 GitHub 链接的 repo；
- AI 分类频道内的 repo；
- 手动维护的种子 repo。

共现思路：

```text
userA starred repo1, repo2, repo3
userB starred repo1, repo2
userC starred repo2, repo4

repo1 - repo2: co_star = 2
repo1 - repo3: co_star = 1
repo2 - repo4: co_star = 1
```

相似度公式：

```text
cosine_similarity(A, B) = co_stars(A, B) / sqrt(stars(A) * stars(B))
```

或使用采样后归一化：

```text
score(A, B) = co_stars(A, B) / sqrt(sampled_stars(A) * sampled_stars(B))
```

阶段 2 价值：

- 可以捕捉 README 语义之外的真实用户兴趣；
- 对成熟项目推荐更准；
- 成本远低于全量 GitHub stars；
- 为后续 ALS 训练准备数据。

---

### 阶段 3：训练协同过滤 embedding

目标：真正训练出 Starcat 自己的 repo collaborative embedding。

推荐第一版模型：**Implicit ALS**。

GitHub star、Starcat 收藏、详情页浏览、AI 分析、加入对比等都属于 implicit feedback。Python `implicit` 库专门面向 implicit feedback datasets，包含 ALS、BPR 等常见推荐算法实现。

训练数据：

| 行为 | 权重建议 |
|---|---:|
| GitHub star | 1.0 |
| Starcat 收藏 | 3.0 |
| Starcat 打开详情 | 0.3 |
| Starcat AI 分析 | 1.5 |
| Starcat 加入技术选型对比 | 4.0 |
| Starcat 隐藏 / 不感兴趣 | negative signal |

矩阵形式：

```text
R[user_id, repo_id] = confidence
```

训练输出：

```text
item_factors[repo_id] = repo collaborative embedding
```

将 `item_factors` 写入 Qdrant：

```json
{
  "id": 41881900,
  "vector": [0.12, -0.03, 0.44, ...],
  "payload": {
    "full_name": "microsoft/vscode",
    "language": "TypeScript",
    "stars": 170000,
    "topics": ["editor", "typescript", "electron"],
    "archived": false
  }
}
```

---

### 阶段 4：混合推荐 + Learning-to-Rank

目标：将 Starcat 推荐系统升级为完整推荐引擎。

多路召回：

| 召回通道 | 说明 |
|---|---|
| content_embedding_recall | README / description / topics 相似 |
| collaborative_embedding_recall | ALS / LightFM item vector 相似 |
| topic_recall | topics 重叠 |
| language_recall | 同语言同主题 |
| co_star_recall | stargazer 共现 |
| user_behavior_recall | Starcat 内部用户收藏 / 点击 |
| trending_recall | 同分类近期热门 |
| external_provider_recall | SimRepo 非官方接口，可作为补充 |

排序模型初期可以手写公式，后期用 Learning-to-Rank。

手写排序公式：

```text
final_score =
  0.35 * content_similarity
+ 0.30 * collab_similarity
+ 0.10 * topic_overlap
+ 0.08 * activity_score
+ 0.07 * star_log_score
+ 0.05 * language_match
+ 0.05 * freshness_score
- 0.30 * archived_penalty
- 0.20 * suspicious_penalty
```

后期排序模型：

- LightGBM LambdaRank；
- XGBoost ranker；
- CatBoost ranker。

训练标签来自 Starcat 用户行为：

| 行为 | label |
|---|---:|
| 展示未点击 | 0 |
| 点击 repo | 1 |
| 收藏 repo | 3 |
| AI 分析 repo | 4 |
| 加入对比 | 5 |
| 隐藏 / 不感兴趣 | -2 |

## 6. 数据源设计

### 6.1 GitHub Repo 元数据

需要同步字段：

| 字段 | 说明 |
|---|---|
| id | GitHub repository id |
| full_name | owner/repo |
| owner | owner login |
| name | repo name |
| description | 仓库描述 |
| language | 主语言 |
| topics | GitHub topics |
| stars | stargazers_count |
| forks | forks_count |
| watchers | watchers_count |
| open_issues | open_issues_count |
| license | license key |
| archived | 是否归档 |
| disabled | 是否禁用 |
| pushed_at | 最近 push 时间 |
| updated_at | 最近更新时间 |
| created_at | 创建时间 |

### 6.2 README / 文本内容

需要存储：

- README 原文；
- README HTML 渲染结果，可复用 Starcat 现有 README 缓存；
- README 摘要；
- AI 分类；
- 技术栈关键词；
- embedding 文本 hash。

推荐 embedding 文本构造：

```text
Repository: {owner}/{repo}
Description: {description}
Topics: {topics}
Language: {language}
README Summary: {summary}
Keywords: {keywords}
```

### 6.3 Stargazers

GitHub REST API 支持列出某个 repo 的 stargazers；如果请求特定 media type，还可以拿到 starred_at 时间。

采集建议：

| repo stars | 抓取数量 |
|---:|---:|
| 100～1k | 最多 500 |
| 1k～10k | 最多 2,000 |
| 10k～100k | 最多 5,000 |
| 100k+ | 最多 10,000 |

不要全量抓取所有 repo 的 stargazers，成本太高，也容易触发 GitHub API 限制。

### 6.4 Starcat 内部行为

Starcat 自己的用户行为是长期最有价值的数据：

| 行为 | 说明 |
|---|---|
| view | 打开 repo 详情页 |
| favorite | 收藏 repo |
| analyze | 触发 AI 分析 |
| compare | 加入技术选型对比 |
| hide | 不感兴趣 |
| open_github | 跳转 GitHub |
| open_deepwiki | 跳转 DeepWiki / Zread 等外部服务 |

这些行为后续可以直接用于个性化推荐和 Learning-to-Rank。

## 7. GitHub API 限流与采集策略

GitHub REST API 存在主限流和二级限流。官方文档说明，未认证 REST 请求通常为 60 次/小时；认证用户、OAuth App 或 GitHub App installation token 通常有更高额度；同时存在二级限制，例如并发请求不能超过 100，REST API 每分钟 points 也有限制。

因此采集任务必须做：

- 队列化；
- 限速；
- 断点续采；
- ETag / If-None-Match；
- 失败重试；
- 冷却时间；
- 优先级调度；
- 避免对同一 endpoint 过快请求。

建议采集优先级：

| 优先级 | repo 类型 |
|---|---|
| P0 | 用户收藏 / 用户打开 / AI 分析过的 repo |
| P0 | Trending / Show HN / Product Hunt AI 频道 repo |
| P1 | stars > 1k 且未采集 stargazers 的 repo |
| P2 | stars 100～1k 的 repo |
| P3 | stars < 100 的 repo，只做内容 embedding |

## 8. 数据库设计

### 8.1 repos

```sql
CREATE TABLE repos (
    id BIGINT PRIMARY KEY,
    full_name TEXT NOT NULL UNIQUE,
    owner TEXT NOT NULL,
    name TEXT NOT NULL,
    description TEXT,
    language TEXT,
    stars INTEGER DEFAULT 0,
    forks INTEGER DEFAULT 0,
    watchers INTEGER DEFAULT 0,
    open_issues INTEGER DEFAULT 0,
    license_key TEXT,
    archived BOOLEAN DEFAULT FALSE,
    disabled BOOLEAN DEFAULT FALSE,
    pushed_at TIMESTAMP,
    updated_at TIMESTAMP,
    created_at TIMESTAMP,
    collected_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

### 8.2 repo_topics

```sql
CREATE TABLE repo_topics (
    repo_id BIGINT NOT NULL REFERENCES repos(id),
    topic TEXT NOT NULL,
    PRIMARY KEY (repo_id, topic)
);
```

### 8.3 repo_readmes

```sql
CREATE TABLE repo_readmes (
    repo_id BIGINT PRIMARY KEY REFERENCES repos(id),
    readme_text TEXT,
    readme_summary TEXT,
    etag TEXT,
    content_hash TEXT,
    fetched_at TIMESTAMP
);
```

### 8.4 github_stargazers

```sql
CREATE TABLE github_stargazers (
    repo_id BIGINT NOT NULL REFERENCES repos(id),
    github_user_id BIGINT NOT NULL,
    login TEXT,
    starred_at TIMESTAMP,
    collected_at TIMESTAMP NOT NULL DEFAULT NOW(),
    PRIMARY KEY (repo_id, github_user_id)
);
```

### 8.5 stargazer_crawl_state

```sql
CREATE TABLE stargazer_crawl_state (
    repo_id BIGINT PRIMARY KEY REFERENCES repos(id),
    next_page INTEGER DEFAULT 1,
    last_etag TEXT,
    status TEXT NOT NULL DEFAULT 'pending',
    last_error TEXT,
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

### 8.6 repo_similarity_edges

```sql
CREATE TABLE repo_similarity_edges (
    source_repo_id BIGINT NOT NULL REFERENCES repos(id),
    target_repo_id BIGINT NOT NULL REFERENCES repos(id),
    score DOUBLE PRECISION NOT NULL,
    method TEXT NOT NULL,
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    PRIMARY KEY (source_repo_id, target_repo_id, method)
);
```

### 8.7 user_repo_events

```sql
CREATE TABLE user_repo_events (
    id BIGSERIAL PRIMARY KEY,
    user_id TEXT,
    repo_id BIGINT NOT NULL REFERENCES repos(id),
    event_type TEXT NOT NULL,
    weight DOUBLE PRECISION NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

### 8.8 repo_embeddings

```sql
CREATE TABLE repo_embeddings (
    repo_id BIGINT PRIMARY KEY REFERENCES repos(id),
    embedding_model TEXT NOT NULL,
    embedding_version TEXT NOT NULL,
    vector_dim INTEGER NOT NULL,
    qdrant_collection TEXT NOT NULL,
    qdrant_point_id TEXT,
    content_hash TEXT,
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

## 9. Qdrant 设计

Qdrant 是向量数据库，支持存储 points，即 vector + payload，并支持相似度检索、过滤和 recommend API。Qdrant recommend API 支持 positive / negative examples，examples 可以是 point id，也可以是 raw vectors。

### 9.1 Collections 设计

建议分 collection，不要把不同语义的向量混在一起：

```text
repo_content_v1
repo_collab_als_v1
repo_hybrid_v1
```

### 9.2 repo_content_v1

用于 README / metadata embedding。

```json
{
  "id": 41881900,
  "vector": [0.1, -0.2, 0.3],
  "payload": {
    "full_name": "microsoft/vscode",
    "language": "TypeScript",
    "stars": 170000,
    "archived": false,
    "topics": ["editor", "typescript", "electron"]
  }
}
```

### 9.3 repo_collab_als_v1

用于 ALS item factor。

```json
{
  "id": 41881900,
  "vector": [0.04, -0.12, 0.25],
  "payload": {
    "full_name": "microsoft/vscode",
    "language": "TypeScript",
    "stars": 170000
  }
}
```

### 9.4 repo_hybrid_v1

后期可以融合内容向量和协同过滤向量：

```text
hybrid_vector = normalize(concat(
  0.6 * content_vector,
  0.4 * collaborative_vector
))
```

## 10. Qdrant Recommend API 用法

### 10.1 单仓库推荐

```json
{
  "positive": [41881900],
  "limit": 20,
  "with_payload": true,
  "with_vector": false
}
```

### 10.2 多仓库技术选型推荐

```json
{
  "positive": [1262506, 18221276, 8514],
  "negative": [123456789],
  "strategy": "best_score",
  "limit": 30,
  "with_payload": true,
  "with_vector": false
}
```

### 10.3 带过滤条件

```json
{
  "positive": [41881900],
  "limit": 20,
  "filter": {
    "must": [
      { "key": "archived", "match": { "value": false } },
      { "key": "language", "match": { "value": "Python" } }
    ]
  },
  "with_payload": true
}
```

## 11. 训练 Pipeline 设计

### 11.1 Pipeline 总览

```text
repo_discovery_job
    ↓
repo_metadata_sync_job
    ↓
readme_fetch_job
    ↓
repo_embedding_job
    ↓
stargazer_collect_job
    ↓
co_star_graph_job
    ↓
als_train_job
    ↓
qdrant_upsert_job
    ↓
evaluation_job
    ↓
publish_model_job
```

---

### 11.2 repo_discovery_job

发现 repo 来源：

- GitHub Trending；
- GitHub Search；
- Starcat 用户收藏；
- Show HN；
- Product Hunt；
- AI 分类频道；
- 手动种子列表；
- Starcat Chrome 插件采集。

输出：写入 `repos`。

---

### 11.3 repo_metadata_sync_job

同步字段：

- stars；
- forks；
- language；
- topics；
- license；
- archived；
- pushed_at；
- updated_at。

同步频率建议：

| repo 类型 | 同步频率 |
|---|---:|
| 用户收藏 | 每天 |
| Trending | 每 6 小时 |
| 普通收录 | 每 7 天 |
| archived | 每 30 天 |

---

### 11.4 readme_fetch_job

复用 Starcat 现有 README 缓存链路：

```text
GitHub HTML / raw README
    ↓
ETag 缓存
    ↓
本地 readmes 表
    ↓
生成 README summary
    ↓
生成 embedding text
```

---

### 11.5 repo_embedding_job

输入：

```text
repo name + description + topics + language + README summary
```

输出：

- 写入 `repo_embeddings`；
- upsert 到 `repo_content_v1`。

MVP 推荐 embedding text：

```text
Repository: {full_name}
Description: {description}
Topics: {topics}
Language: {language}
README Summary: {readme_summary}
```

---

### 11.6 stargazer_collect_job

采集策略：

1. 只采 Starcat 收录 repo；
2. stars < 100 的 repo 暂不采 stargazers；
3. 每个 repo 有最大采样数量；
4. 断点续采；
5. 遇到限流进入冷却；
6. 使用 ETag 降低重复成本。

---

### 11.7 co_star_graph_job

输入：`github_stargazers`。

伪代码：

```python
for user in users:
    repos = get_starred_repos_in_starcat(user)
    repos = filter_valid_repos(repos)

    for a, b in combinations(repos, 2):
        edge_count[a, b] += user_weight(user)
```

归一化：

```python
score = co_count / sqrt(repo_a_sampled_stars * repo_b_sampled_stars)
```

输出：写入 `repo_similarity_edges`。

---

### 11.8 als_train_job

训练数据来自两部分：

1. GitHub stargazers；
2. Starcat 内部用户行为。

Python 训练示例：

```python
from scipy.sparse import coo_matrix
import implicit

rows = user_indices
cols = repo_indices
data = weights

matrix = coo_matrix((data, (rows, cols)), shape=(n_users, n_repos)).tocsr()

model = implicit.als.AlternatingLeastSquares(
    factors=128,
    regularization=0.05,
    iterations=30,
    alpha=40
)

model.fit(matrix)
repo_vectors = model.item_factors
```

参数建议：

| 参数 | MVP | 中期 |
|---|---:|---:|
| factors | 64 | 128 |
| iterations | 15 | 30 |
| regularization | 0.05 | 0.01～0.1 |
| alpha | 20 | 40～80 |

### 12.3 CandidateMerger

多路召回可能重复返回同一个 repo，需要合并：

```text
候选 repo = union(content candidates, collab candidates, topic candidates, co-star candidates)
```

合并规则：

- 同 repo_id 去重；
- 保留每个 source 的 score；
- 记录召回来源；
- 用 source coverage 作为排序特征。

## 16. 异常 star 与反作弊

GitHub star 是强信号，但也可能被刷。推荐系统不能完全依赖 star count。

建议对以下行为降权：

| 异常模式 | 处理 |
|---|---|
| 用户 star 数极高 | 用户权重降低 |
| 用户同一天批量 star 大量 repo | 降权 |
| 新注册用户只 star 某批 repo | 降权 |
| 某 repo 短期异常增长 | freshness 只加小权重，不直接拉满 |
| repo README 含可疑关键词 | 降权或进入人工审核 |
| archived / disabled | 大幅降权或过滤 |

用户权重示例：

```text
user_weight = 1 / log(2 + total_star_count_by_user)
```


## 25. 关键风险

| 风险 | 说明 | 应对 |
|---|---|---|
| GitHub API 限流 | stargazer 抓取成本高 | 队列、限速、ETag、采样 |
| 新项目冷启动 | 没有 star 行为 | README embedding + topics |
| fake stars | star 信号可能被污染 | 用户降权、异常检测 |
| 推荐不可解释 | 用户不信任 | 输出 reasons |
| 成本膨胀 | embedding / 抓取 / 训练成本 | 分层采集、缓存、离线批处理 |
| 结果同质化 | 总是推荐大项目 | diversity rerank |
| 商业依赖 | SimRepo API 非官方 | 只做补充，不做核心依赖 |
