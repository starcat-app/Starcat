# 本地推荐全链路验证指南

> 适用范围：Starcat Direct → Collection API → Trainer → Recommend API v2 → Starcat Direct  
> 验证基线：Starcat `dev`、Collection `main`、Trainer `main`、Recommend API `dev`  
> 数据范围：用户明确开启贡献后上传的公开 Star；不包含私有仓库、标签、笔记、浏览行为、GitHub Token 和身份信息

本文用于在一台 Apple Silicon Mac 上复现真实推荐全链路。终端中的服务编排、数据检查、训练、发布、API 验证和临时文件清理由交互式脚本完成；人工只负责在 Starcat Direct 中触发一次真实上传，以及最后验收推荐界面。

历史验证结果和数据处理细节见[公开 Star 自研推荐全链路最终测试报告](公开Star自研推荐全链路最终测试报告.md)。每次新验证都使用独立临时目录和模型版本，不复用历史产物。

## 1. 验证目标与通过标准

```text
Starcat dev / Direct
  └─ 用户开启“匿名贡献公开 Star 数据”并执行完整同步
       └─ starcat-collection-api
            └─ active snapshot NDJSON
                 └─ starcat-recsys-trainer
                      ├─ canonical / dataset / quality report
                      ├─ Popular / SVD / co-star / ablation
                      └─ ServingBundle
                           └─ starcat-recommend-api
                                ├─ /api/v1 保持 SimRepo 契约
                                └─ /api/v2 读取 active Bundle
                                     └─ Starcat Direct 推荐 UI
```

脚本满足以下全部条件才会生成最终报告：

- Collection active snapshot 与所选 Starcat 数据库的公开 Star 交集达到 80% 以上，测试 fixture 不能冒充真实快照。
- Trainer `final_rows > 0`，不能发布空数据集。
- ServingBundle 通过 checksum 和 SQLite `quick_check`，且 `recommendations > 0`。
- source repo 同时存在于推荐边、Bundle metadata 和 Starcat 本地已 Star 仓库中。
- Recommend API 的 v2 GET、v2 POST 均返回非空 items，active version 与本次模型一致。
- Starcat `RecommendAPILiveIntegrationTests` 强制执行并通过，不能因环境变量缺失而跳过。
- Recommend API 重启后恢复相同 active model。
- Starcat Direct 的“相似仓库”弹窗展示非空自研推荐结果。

只有一个匿名主体时，SVD 可以带明确原因标记为 `skipped`，离线评估指标也可能为 0。这是单主体数据的算法边界，不影响工程链路验收，但不能据此宣称模型已达到生产质量。

## 2. 一次性准备

### 2.1 检查四个独立仓库

```bash
export STARCAT_ROOT='/Users/dong4j/Developer/1.AI/ai-incubator/Starcat'

git -C "$STARCAT_ROOT" status --short --branch
git -C "$STARCAT_ROOT/supports/starcat-collection-api" status --short --branch
git -C "$STARCAT_ROOT/supports/starcat-recsys-trainer" status --short --branch
git -C "$STARCAT_ROOT/supports/starcat-recommend-api" status --short --branch
```

`supports/` 下三个服务均为独立 Git 仓库。脚本只调用它们的构建、测试和本地启动命令，不执行 pull、merge、push、reset 或远程部署；Trainer 向本机 Recommend API 发布临时模型属于验证流程的一部分。

### 2.2 配置 Starcat Direct 的 Collection 地址

打开已忽略的本地私密配置：

```bash
open -a TextEdit "$STARCAT_ROOT/Configs/Secrets.xcconfig"
```

设置：

```text
STARCAT_COLLECTION_API_KEY = local-collection-client-key
STARCAT_COLLECTION_API_BASE_URL = http:/$()/127.0.0.1:5011
```

`xcconfig` 会把普通 `//` 识别为注释，因此 URL 必须使用 `http:/$()/...` 写法。确认文件仍被 Git 忽略：

```bash
git -C "$STARCAT_ROOT" check-ignore Configs/Secrets.xcconfig
```

使用项目标准入口构建并启动 Direct：

```bash
cd "$STARCAT_ROOT"
make run-direct
```

不要使用 App Store scheme。Direct Debug 复用以下正式数据根目录中的现有登录态和 Star 数据：

```text
~/Library/Application Support/com.starcat.app/users/<github_user_id>/starcat.sqlite
```

### 2.3 配置 Recommend 客户端地址

在 Starcat Direct 的“设置 → 服务”中配置：

```text
Recommend URL: http://127.0.0.1:5005
Recommend API Key: local-recommend-client-key
```

服务尚未启动时“测试连接”失败是正常现象。脚本完成训练后会保持 Recommend API 运行，供最终 UI 验收。

### 2.4 工具链要求

脚本会检查以下命令，并在缺失时立即停止：

```text
bash curl find git go jq lsof make pgrep sed shasum sqlite3 uv xcodebuild xcodegen
```

其它约束：

- 稳定版 Xcode 位于 `/Applications/Xcode.app`。
- Collection 和 Recommend 使用项目当前声明的 Go 版本。
- Trainer 使用 `uv` 管理 Python 环境。
- 执行 Swift live test 前必须 Cmd+Q 退出 Xcode IDE；Starcat Direct 可以继续运行。

## 3. 启动交互式验证

在 Starcat 根目录执行：

```bash
cd "$STARCAT_ROOT"
./scripts/local-recommendation-e2e.sh
```

默认进入菜单：

```text
Starcat 本地推荐全链路验证

1. 开始新的全链路验证
2. 查看当前验证状态
3. 继续未完成的验证
4. 查看服务日志
5. 查看客户端验收指引
6. 停止本次验证服务
7. 清理本次临时文件
8. 清理历史验证文件
0. 退出
```

### 3.1 开始新的全链路验证

选择 `1` 后，脚本会：

1. 列出所有非匿名 Starcat 账号数据库及公开 Star 数量，由验证者明确选择。
2. 对 Collection、Recommend、Trainer 执行各自质量门禁并构建本地运行产物。
3. 检查 `5011`、`5005` 端口。如果发现旧进程，先显示 PID、启动时间和完整命令，再询问是否发送普通终止信号；不会使用 `SIGKILL`。
4. 创建带专用安全标识的临时运行目录并启动 Collection API。
5. 检查当前 Direct 构建产物是否指向本机 Collection，并检查所选账号是否已开启贡献。
6. 等待 Starcat 上传真实快照。
7. 收到有效快照后自动导出公开 metadata、启动 Recommend、执行 Trainer、发布 Bundle。
8. 检查数据集、推荐边、v2 GET/POST、Swift live test 和 Recommend 重启恢复。
9. 生成最终结果文件并展示客户端验收仓库。

构建和测试阶段耗时较长是正常现象。中途失败时保留运行目录和日志；重新进入菜单选择 `3`，脚本会根据阶段文件继续，不需要从头复制命令。

### 3.2 在客户端触发真实上传

脚本显示“等待 Starcat Direct 上传真实快照”后，在客户端执行：

1. 打开“设置 → 通用”。
2. 找到“隐私与推荐”。
3. 开启“匿名贡献公开 Star 数据”。
4. 回到 Manage/Stars。
5. 执行“刷新仓库列表/详情”，等待完整同步结束。

必须触发一次完整同步。启动期 TTL 命中、普通增量同步或 GitHub `304` 早退不会生成新的贡献快照。

上传是旁路逻辑，失败不会改变 Stars 同步结果，也不会在客户端展示错误。脚本每 30 秒输出一次当前最大快照数和主库交集数，最长等待 30 分钟。

## 4. 脚本自动验证的内容

### 4.1 Collection 真实性门禁

脚本使用全新的 Collection SQLite，不预置测试 fixture。收到快照后按 repo ID 与所选 Starcat 主库做只读关联：

```text
最低有效交集 = max(2, 所选数据库公开 Star 数 × 80%)
```

因此旧测试数据中的 repo ID `1～4` 即使能完成 create/chunk/commit，也不能进入训练阶段。

### 4.2 Metadata 与 Trainer

Collection 只提供匿名 `repo_id + starred_at` 行为快照。脚本从所选 Starcat 数据库只读导出已缓存的公开仓库 metadata，写入本次临时目录，然后生成唯一 `run_id/model_version` 的 Trainer 配置。

训练仍沿用当前基线参数：

```yaml
dataset:
  train_end: "2025-06-01T00:00:00Z"
  validation_end: "2026-01-01T00:00:00Z"
  minimum_repositories_per_subject: 2

training:
  reference_time: "2025-06-01T00:00:00Z"
  top_k: 20
  svd_components: 64
  half_life_days: 365
  shrinkage: 1
  maximum_repositories_per_subject: 100
```

`reference_time` 与 `train_end` 表示同一时刻，避免时间衰减使用未来信息。

### 4.3 空结果门禁

下列任一条件不满足，脚本立即失败并保留日志：

```text
quality-report.final_rows > 0
PRAGMA quick_check = ok
recommendations COUNT(*) > 0
GET /api/v2/repos/{id}/recommendations items > 0
POST /api/v2/recommendations/query items > 0
active model_version = 本次 model_version
```

source repo 不再通过两条互不校验的 SQL 拼接，而是同时关联：

- Bundle `recommendations.source_repo_id`；
- Bundle `repositories.full_name`；
- Starcat 本地 `repos.is_starred=1` 且 public、accessible。

### 4.4 Swift live integration test

REST 验证完成后，脚本使用稳定版 Xcode 和本次独立 DerivedData 执行：

```text
StarcatTests/RecommendAPILiveIntegrationTests
```

脚本固定设置 `STARCAT_RECOMMEND_LIVE_REQUIRED=1`，所以环境变量缺失时不能静默跳过。如果 Xcode IDE 仍在运行，脚本会停止并要求退出 Xcode；修正后从菜单选择 `3` 继续即可。

## 5. 结果文件与状态恢复

运行根目录位于：

```text
${TMPDIR:-/tmp}/starcat-recommend-e2e/
```

当前运行目录包含：

```text
run-<UTC时间>-<随机串>/
├── collection.sqlite
├── trainer.yaml
├── trainer-workspace/
├── trainer-registry/
├── recommend-registry/
├── result.env
├── result.json
├── validation-report.md
└── logs/
    ├── collection.log
    ├── recommend.log
    ├── trainer.log
    └── starcat-live-test.log
```

`result.env` 解决了原指南依赖当前 Terminal 环境变量的问题。需要在其它终端读取结果时执行：

```bash
RUNS_ROOT="${TMPDIR:-/tmp}/starcat-recommend-e2e"
CURRENT_RUN="$(sed -n '1p' "$RUNS_ROOT/current-run")"
source "$CURRENT_RUN/result.env"

printf 'SOURCE_REPO_ID=%s\nSOURCE_REPO_NAME=%s\n' \
  "$E2E_SOURCE_REPO_ID" "$E2E_SOURCE_REPO_NAME"
```

直接执行普通 Shell 脚本不能修改父 Shell 的环境变量，因此运行脚本后直接 `echo $E2E_SOURCE_REPO_NAME` 仍可能为空；应查看菜单“客户端验收指引”，或者显式 `source result.env`。

## 6. Starcat Direct 最终人工验收

脚本提示全链路完成后，保持 Recommend API 运行：

1. 打开 Starcat Direct。
2. 确认“设置 → 服务”的 Recommend URL 和 API Key 为本指南第 2.3 节的本地值。
3. 打开全局搜索。
4. 选择“本地”，搜索脚本输出的 `SOURCE_REPO_NAME`。
5. 打开仓库并点击“相似仓库”。
6. 确认出现非空推荐卡片，推荐理由为自研公开 Star 共现模型对应文案。

当前全局搜索范围是“全部 / 本地 / GitHub / Web”，不存在“仓库”Tab。“本地”表示 Starcat 本地仓库数据，是本次验收应选择的范围。

Direct target 使用 `/api/v2`；App Store target 仍使用 `/api/v1`。设置页“测试连接”只验证服务身份、鉴权与路由，最终仍必须打开“相似仓库”验证 v2 结果。

## 7. 状态、日志、停止与清理

### 7.1 查看状态和日志

重新运行脚本后选择：

- `2`：显示当前阶段、运行目录、Collection/Recommend PID 和最终 `result.json`。
- `4`：分别显示 Collection、Recommend、Trainer 最近 80 行日志。
- `5`：再次显示 source repo 和客户端验收步骤。

只需要在自动化环境读取状态时，也可以使用：

```bash
./scripts/local-recommendation-e2e.sh --status
```

### 7.2 停止服务

菜单 `6` 只停止当前运行目录记录的 Collection 和 Recommend。停止前同时校验 PID 存活，并确认完整可执行文件路径位于当前运行目录；PID 被系统复用时拒绝操作。

停止服务不会删除模型、数据库或报告。之后选择 `3`，脚本会从相同 Registry 重启服务并继续。

### 7.3 清理临时文件

- 菜单 `7`：显示当前目录和占用空间，再次确认后停止服务并删除当前运行。
- 菜单 `8`：列出所有历史运行，可选择单次或全部清理。

脚本只允许删除同时满足以下条件的目录：

1. 位于专用 `starcat-recommend-e2e` 根目录下；
2. 目录名以 `run-` 开头；
3. 不是符号链接；
4. 包含 `.starcat-recommend-e2e-run` 标识文件。

绝不会删除或修改：

```text
~/Library/Application Support/com.starcat.app
Configs/Secrets.xcconfig
任一 Git 仓库源码
没有脚本专用标识的手工临时目录
```

## 8. 常见问题

| 现象 | 原因和处理 |
|---|---|
| `healthz | jq` 报 `Invalid numeric literal` | 两个服务的 `/healthz` 都返回纯文本 `ok`，不是 JSON；脚本按纯文本校验 |
| 新启动进程立刻退出，但 ping 仍成功 | 端口上存在旧服务；脚本会展示监听 PID 并要求明确确认后才发送普通终止信号 |
| Collection 一直为 0 | 检查 Direct Info.plist 配置、贡献开关，并执行完整“刷新仓库列表/详情” |
| Collection 只有 2 个主体、7 个 repo | 这是旧 fixture，不是用户真实 Star；新脚本的 80% 主库交集门禁会拒绝它 |
| `E2E_SOURCE_REPO_NAME` 为空 | 可能是推荐表为空，也可能是换了 Terminal；先看 `result.json`，完成后再 `source result.env` |
| `public_repository_rows=0` | Collection repo ID 与 metadata 无交集，通常是测试 fixture 和真实主库混用 |
| `recommendations=0` | 数据集为空或所选模型未产出推荐边；脚本拒绝进入客户端验收 |
| 找不到“仓库”Tab | 当前名称是“本地”；选择“本地”搜索 source repo |
| Xcode IDE 正在运行 | Cmd+Q 退出 Xcode，再从菜单选择 `3` 继续 Swift live test |
| SVD skipped | 单主体或矩阵规模不足；确认 reason 后继续验收 co-star |
| UI 显示旧结果 | 等待 SWR 刷新，必要时清理推荐缓存；不要删除 Starcat 主数据库 |

## 9. 数据处理口径

| 阶段 | 输入 | 关键处理 | 输出 |
|---|---|---|---|
| Starcat | 当前账号已 Star 仓库 | 仅保留 public、accessible；按 repo ID 排序去重；完整同步成功后触发 | schema v1 snapshot |
| Collection | snapshot 元数据和 chunks | 请求期 HMAC；commit 校验总数、排序、重复和 content hash；每主体只导出最新 active | 匿名 NDJSON |
| Metadata | Starcat 主库公开 repo cache | 只读转换为 GitHub metadata envelope；不写回 Collection | `raw_repositories` JSONL |
| Canonical | Collection 行为 + metadata | 来源隔离、最新完整快照、subject/repo 唯一化 | Canonical Parquet |
| Dataset | Canonical records | public/active 过滤；train/validation/test 时间切分；资格只看 train | dataset + quality report |
| Training | train split | Popular、SVD、时间衰减 co-star、两个 ablation | model artifacts |
| Evaluation | validation split | Recall@K、NDCG@K、MRR@K、Coverage | metrics JSON |
| Bundle | 选定模型 + metadata + metrics | manifest、checksums、SQLite quick check、不可变版本 | ServingBundle |
| Recommend | active ServingBundle | v1/v2 Provider 隔离；v2 只读 SQLite | REST recommendation envelope |
| Starcat Direct | v2 envelope | 复用推荐 DTO、缓存和 UI | 相似仓库弹窗 |

隐私边界：

- Collection 允许：随机 `participant_id`、随机 `snapshot_id`、公开 `repo_id`、可空 `starred_at`、时间和 hash。
- Collection 禁止：GitHub login/email/user id、Token、private/internal repo、标签、笔记、搜索、点击、README/code、AI/RAG 内容和本地路径。
- Recommend API 只接收 ServingBundle，不读取 Collection SQLite、raw、canonical 或 dataset。
- 运行结果和报告不得记录客户端 key、Admin key、Publish key、HMAC key、GitHub Token 或匿名主体标识。
