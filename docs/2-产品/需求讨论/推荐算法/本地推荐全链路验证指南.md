# 本地推荐全链路验证指南

> 适用日期：2026-08-24  
> 适用范围：Starcat Direct → Collection API → Trainer → Recommend API v2 → Starcat Direct  
> 验证基线：Starcat `dev`、Collection `main`、Trainer `main`、Recommend API `dev`  
> 数据范围：用户明确开启贡献后上传的公开 Star；不包含私有仓库、标签、笔记、浏览行为、GitHub Token 和身份信息

本文用于在一台 Apple Silicon Mac 上复现真实推荐全链路。主流程复用 Starcat 正式数据目录中的现有登录态和 1000+ Star 数据，但 Collection 数据库、Trainer 工作区和 Recommend 模型 Registry 全部放在临时目录，不接触线上服务，不 push，不部署，也不修改主账户 SQLite。

已通过的历史结果和数据处理细节见[公开 Star 自研推荐全链路最终测试报告](公开Star自研推荐全链路最终测试报告.md)。本指南说明如何从当前 `dev` 重新执行一次，而不是复用报告中的旧临时目录或旧模型版本。

## 1. 验证目标与通过标准

```text
Starcat dev / Direct
  └─ 用户开启“匿名贡献公开 Star 数据”并强制完整同步
       └─ starcat-collection-api
            ├─ participant_id 请求期 HMAC 匿名化
            └─ active snapshot NDJSON
                 └─ starcat-recsys-trainer
                      ├─ canonical / dataset / quality report
                      ├─ Popular / SVD / co-star / ablation
                      └─ ServingBundle
                           └─ starcat-recommend-api
                                ├─ /api/v1 保持原 SimRepo 契约
                                └─ /api/v2 读取 active Bundle
                                     └─ Starcat Direct 推荐 UI
```

全部满足才算通过：

- Starcat 当前分支为 `dev`，使用 `StarcatDirect`，没有启动 App Store target。
- Collection 出现 1 个 committed active snapshot，item 数与本机当前公开 Star 数一致。
- Trainer 完成 Collection Pull、标准化、质量过滤、训练、评估和 Bundle 发布。
- Recommend API 显示本次唯一 `model_version` 已激活，进程重启后仍能恢复。
- `/api/v2` 返回 `source=starcat_trained`、正确的 `model_version` 和非空 items。
- Starcat Swift live test 强制执行且通过，没有因为缺少环境变量而跳过。
- Starcat Direct 的“相似仓库”弹窗能显示本机 v2 结果。

只有一个匿名主体时，SVD 被明确标记为 `skipped`、离线指标可能为 0，这是当前数据规模下的算法边界，不代表工程链路失败，也不能据此宣称模型达到生产质量。

## 4. 配置并启动 Starcat Direct

### 4.1 临时配置 Collection 地址和客户端 key

Collection 地址来自构建时 Info.plist，不能在 Starcat“第三方服务”页面配置。先备份本机已忽略的私密配置：

```bash
cd "$STARCAT_ROOT"

if [ -f Configs/Secrets.xcconfig ]; then
  export E2E_SECRETS_WAS_PRESENT=1
  cp -p Configs/Secrets.xcconfig "$E2E_DIR/Secrets.xcconfig.backup"
else
  export E2E_SECRETS_WAS_PRESENT=0
  cp Configs/Secrets.xcconfig.template Configs/Secrets.xcconfig
fi

open -a TextEdit Configs/Secrets.xcconfig
```

只修改下列两个现有配置项，其它真实本地配置保持原样：

```text
STARCAT_COLLECTION_API_KEY = local-collection-client-key
STARCAT_COLLECTION_API_BASE_URL = http:/$()/127.0.0.1:5011
```

`xcconfig` 中 `//` 会被解释为注释，所以本地 URL 必须写成 `http:/$()/...`；构建后的 Info.plist 才会得到正常的 `http://127.0.0.1:5011`。

确认该私密文件没有进入 Git：

```bash
git check-ignore Configs/Secrets.xcconfig
git status --short
```

### 4.2 使用 Direct target 启动

```bash

```

脚本必须输出：


Direct Debug 虽然使用独立 bundle id `com.starcat.app.direct.debug`，但当前数据库代码固定使用以下正式数据根目录，因此可以复用现有账号和 Star 数据，无需重新登录：

## 5. 开启贡献并触发真实上传

在 Starcat Direct 中执行：

1. 打开“设置 → 通用”。
2. 找到“隐私与推荐”。
3. 开启“匿名贡献公开 Star 数据”。
4. 回到 Manage/Stars 列表。
5. 执行“操作 → 刷新仓库列表/详情”，或使用列表对应的刷新命令。
6. 等待完整同步结束。

这里必须使用“刷新仓库列表/详情”触发 `force: true` 完整同步。启动期 TTL 命中、普通增量同步或 GitHub `304` 早退都不会生成新的贡献快照。

数据贡献是旁路逻辑：上传失败不会改变 Stars 同步的成功状态，客户端也不会显示上传数量、成功时间或错误弹窗。验证状态应在开发者终端进行，不应从产品 UI 增加诊断负担。

## 6. 验证 Collection 已收到真实快照

### 6.1 验证 SQLite 聚合状态

```bash
sqlite3 -readonly "$E2E_DIR/collection.sqlite" <<'SQL'
.headers on
.mode column
SELECT COUNT(*) AS committed_uploads
FROM snapshot_uploads
WHERE state = 'committed';

SELECT COUNT(*) AS active_snapshots
FROM active_snapshots;

SELECT COUNT(*) AS active_items
FROM active_snapshots a
JOIN snapshot_items i ON i.snapshot_id = a.snapshot_id;

SELECT u.repository_count, u.chunk_count, u.captured_at, u.committed_at
FROM active_snapshots a
JOIN snapshot_uploads u ON u.snapshot_id = a.snapshot_id;
SQL
```

1000+ Stars 的预期结果通常是：

- `committed_uploads = 1`
- `active_snapshots = 1`
- `active_items` 等于当前公开且仍可访问的已 Star 仓库数
- `chunk_count = ceil(active_items / 1000)`

不要在日志或报告中输出 `participant_key`、`subject_id` 等匿名主体值。

### 6.2 验证 Admin NDJSON 导出和 checksum

```bash
curl -fsS -D "$E2E_DIR/collection-export.headers" \
  -H "Authorization: Bearer $E2E_COLLECTION_ADMIN_KEY" \
  -H 'Accept: application/x-ndjson' \
  http://127.0.0.1:5011/internal/v1/training/recommendation-snapshots/export \
  -o "$E2E_DIR/collection-export.ndjson"

grep -iE '^(content-type|etag|x-starcat-export-checksum):' \
  "$E2E_DIR/collection-export.headers"

jq -s '{subjects: length, repositories: (map(.repositories | length) | add)}' \
  "$E2E_DIR/collection-export.ndjson"

printf 'sha256:%s\n' \
  "$(shasum -a 256 "$E2E_DIR/collection-export.ndjson" | awk '{print $1}')"
```

最后一行本地计算值必须与响应头 `X-Starcat-Export-Checksum` 一致。Admin 导出一行代表一个 active 匿名主体，不是一行代表一个 Star。

如果没有 committed snapshot，先查看 Collection 日志；不要因为没有 UI 错误就假设上传已成功：

```bash
tail -200 "$E2E_DIR/logs/collection.log"
```

## 7. 从 Starcat 主库只读导出公开 metadata

Collection 只保存 `repo_id + starred_at` 行为快照，不保存仓库描述、语言、Star 数等 metadata。生产训练可用 GitHub API 延迟补齐；本机验证为避免发起 1000+ 次 GitHub REST 请求，从同一 Starcat 主库只读导出已经缓存的公开 metadata。

### 7.1 选择当前主账号数据库

```bash
find "$HOME/Library/Application Support/com.starcat.app/users" \
  -mindepth 2 -maxdepth 2 -name starcat.sqlite -print
```

如果存在多个账号，不要自动取第一个。分别查看当前 Star 数：

```bash
while IFS= read -r database; do
  count="$(sqlite3 -readonly "$database" \
    "SELECT COUNT(*) FROM repos WHERE is_starred=1 AND is_private=0 AND access_state='accessible';")"
  printf '%6s  %s\n' "$count" "$database"
done < <(find "$HOME/Library/Application Support/com.starcat.app/users" \
  -mindepth 2 -maxdepth 2 -name starcat.sqlite -print)
```

把拥有 1000+ Stars 的真实账号路径填入变量；不要选择 `_anonymous`：

```bash
export STARCAT_DB="$HOME/Library/Application Support/com.starcat.app/users/<github_user_id>/starcat.sqlite"
test -f "$STARCAT_DB"
```

### 7.2 导出 Trainer `raw_repositories` JSONL

以下命令只读数据库，输出写入本次临时目录：

```bash
sqlite3 -readonly "$STARCAT_DB" <<'SQL' > "$E2E_DIR/github-repositories.jsonl"
.headers off
.mode list
SELECT json_object(
  'fetched_at', strftime('%Y-%m-%dT%H:%M:%fZ', 'now'),
  'repository', json_object(
    'id', id,
    'full_name', full_name,
    'description', description,
    'topics', json(CASE
      WHEN topics IS NOT NULL AND json_valid(topics) THEN topics
      ELSE '[]'
    END),
    'language', language,
    'license', json_object('spdx_id', license),
    'stargazers_count', stars_count,
    'forks_count', forks_count,
    'archived', is_archived,
    'disabled', 0,
    'private', is_private,
    'visibility', CASE WHEN is_private = 1 THEN 'private' ELSE 'public' END,
    'pushed_at', pushed_at
  )
)
FROM repos
WHERE is_starred = 1
  AND is_private = 0
  AND access_state = 'accessible'
ORDER BY id;
SQL

wc -l "$E2E_DIR/github-repositories.jsonl"
head -n 1 "$E2E_DIR/github-repositories.jsonl" | jq \
  '{fetched_at, repository: (.repository | {id, full_name, visibility})}'
```

行数应与 Collection active snapshot 的公开仓库数量接近。两者不一致时先判断是否在上传完成后又产生了 Star/Unstar，或本地存在 private/unavailable 仓库；不要直接修改训练器忽略差异。

此导出是本机验证输入，不是生产架构耦合。JSONL 位于 `/tmp`，不得提交 Git，也不得加入 Collection 存储。

## 10. 验证 Recommend API v2

### 10.1 确认模型已激活

```bash
curl -fsS \
  -H "Authorization: Bearer $E2E_RECOMMEND_PUBLISH_KEY" \
  http://127.0.0.1:5005/internal/v1/model-bundles/active | jq .
```

返回的 `model_version` 必须等于 `$E2E_MODEL_VERSION`。

### 10.2 从 Bundle 选择实际可查询的 source repo

不要假设任意 Star 都一定进入 co-star Top-K。直接从本次 Bundle 选择一个存在推荐边的 source：

```bash
export E2E_SOURCE_REPO_ID="$(sqlite3 -readonly "$E2E_BUNDLE_DIR/recommendations.sqlite" \
  "SELECT source_repo_id FROM recommendations GROUP BY source_repo_id ORDER BY COUNT(*) DESC, source_repo_id LIMIT 1;")"

export E2E_SOURCE_REPO_NAME="$(sqlite3 -readonly "$E2E_BUNDLE_DIR/recommendations.sqlite" \
  "SELECT full_name FROM repositories WHERE repo_id = $E2E_SOURCE_REPO_ID;")"

printf 'SOURCE_REPO_ID=%s\nSOURCE_REPO_NAME=%s\n' \
  "$E2E_SOURCE_REPO_ID" "$E2E_SOURCE_REPO_NAME"

uv run starcat-recsys bundle query "$E2E_BUNDLE_DIR" \
  --repo-id "$E2E_SOURCE_REPO_ID" \
  --limit 10
```

### 10.3 验证单仓 GET 和多 seed POST

```bash
curl -fsS \
  -H "Authorization: Bearer $E2E_RECOMMEND_CLIENT_KEY" \
```

## 12. 数据处理口径

| 阶段 | 输入 | 关键处理 | 输出 |
|---|---|---|---|
| Starcat | 当前账号已 Star 仓库 | 仅保留 public、accessible；按 repo ID 排序去重；完整同步成功边沿触发 | schema v1 snapshot |
| Collection | `participant_id`、snapshot 元数据和 chunks | 请求期 HMAC；commit 校验总数、排序、重复和 content hash；每主体只导出最新 active | 匿名 NDJSON |
| Metadata | Starcat 主库公开 repo cache | 只读转换为 GitHub metadata envelope；不上传 Collection | `raw_repositories` JSONL |
| Canonical | Collection 行为 + metadata | 来源隔离、最新完整快照、subject/repo 唯一化 | Canonical Parquet |
| Dataset | Canonical records | public/active 过滤；train/validation/test 时间切分；资格只看 train | dataset + quality report |
| Training | train split | Popular、SVD、时间衰减 co-star、两个 ablation；单主体 SVD 可降级 | model artifacts |
| Evaluation | validation split | Recall@K、NDCG@K、MRR@K、Coverage | metrics JSON |
| Bundle | 选定模型 + metadata + metrics | manifest、checksums、SQLite quick check、不可变版本 | ServingBundle |
| Recommend | active ServingBundle | v1/v2 Provider 隔离；v2 只读 SQLite，不读原始快照 | REST recommendation envelope |
| Starcat Direct | v2 envelope | 复用现有推荐 DTO、缓存和 UI | 相似仓库弹窗 |

隐私核对：

- Collection payload 允许：随机 `participant_id`、随机 `snapshot_id`、公开 `repo_id`、可空 `starred_at`、时间和 hash。
- 禁止：GitHub login/email/user id、Token、private/internal repo、标签、笔记、搜索、点击、README/code、AI/RAG 内容、本地路径。
- Recommend API 只能接收 ServingBundle，不能读取 Collection SQLite、raw、canonical 或 dataset。

## 13. 常见问题

| 现象 | 原因和处理 |
|---|---|
| Collection 一直没有 committed snapshot | 检查 Toggle、Collection build settings 和 `collection.log`；必须执行强制完整同步 |
| 普通同步成功但没有上传 | 增量或 `304` 早退不触发贡献；使用“刷新仓库列表/详情” |
| Direct 启动后未复用登录态 | 确认运行的是脚本产物，并核对脚本输出的数据根目录；不要启动 App Store target |
| `content_hash` 或 chunk 校验失败 | 不手工修 payload；保留 Collection 日志，重新执行一次完整同步 |
| metadata 行数与 snapshot 数不一致 | 检查 private/unavailable、同步后 Star/Unstar 和账号 DB 是否选错 |
| `run_id 已存在` / `model version already exists` | 新建 `E2E_DIR` 并生成新的 `E2E_MODEL_VERSION`，不要覆盖 Registry |
| SVD skipped | 单主体/单仓库不满足矩阵分解条件；确认 reason 后继续验收 co-star |
| validation 指标为 0 | 单主体无法证明跨用户协同泛化；工程链路可通过，生产质量不通过 |
| Trainer 发布失败 | 检查 Recommend 是否运行、Publish key 是否一致、Bundle 上限和服务日志 |
| v2 返回 `MODEL_UNAVAILABLE` | Trainer 尚未发布成功，或 Recommend 使用了错误的 Registry 目录 |
| Swift live test 被跳过 | 必须设置 `STARCAT_RECOMMEND_LIVE_REQUIRED=1` 及四个 live 变量 |
| `testmanagerd` 挂起 | 退出 Xcode IDE；检查是否出现 Keychain 授权弹窗；保持测试期签名覆盖 |
| UI 仍显示旧结果 | 等待 SWR、换 source repo 或清推荐缓存；不要删主库 |

## 14. 清理与恢复

先退出 Starcat Direct，再停止两个本地服务：

```bash
kill "$COLLECTION_PID" "$RECOMMEND_PID" 2>/dev/null || true
wait "$COLLECTION_PID" 2>/dev/null || true
wait "$RECOMMEND_PID" 2>/dev/null || true
```

恢复 `Configs/Secrets.xcconfig`：

```bash
cd "$STARCAT_ROOT"
if [ "$E2E_SECRETS_WAS_PRESENT" = '1' ]; then
  cp -p "$E2E_DIR/Secrets.xcconfig.backup" Configs/Secrets.xcconfig
else
  rm -f Configs/Secrets.xcconfig
fi
```

在 Starcat 设置中：

- “服务 → Recommend”重置自定义 URL 和 API Key，避免下一次启动仍指向已停止的本机服务。
- 是否关闭“匿名贡献公开 Star 数据”由本次测试者决定；它是按账号隔离、默认关闭的明确授权开关。

确认不再需要证据后才能删除本次临时目录：

```bash
printf '即将删除本次临时验证目录：%s\n' "$E2E_DIR"
case "$E2E_DIR" in
  /tmp/starcat-recommend-local.??????) ;;
  *) printf '目录不符合本指南的临时目录格式，拒绝删除\n' >&2; exit 1 ;;
esac
rm -rf -- "$E2E_DIR"
```

该删除只应指向由本指南创建的 `/tmp/starcat-recommend-local.XXXXXX`。绝对不要删除：

```text
~/Library/Application Support/com.starcat.app
```

