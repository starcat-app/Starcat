# Skill 管理工作台 · 产品需求与原型

2026-11-19 · Direct · 设计评审稿

从[离线交互原型](原型/Skill管理工作台.html)进入主窗口，或在 [Pencil 源文件](原型/Skill管理工作台.pen)中并排查看导览和 16 张场景画板。[主窗口预览图](原型/我的Skill.png)可单独用于讨论。条目、项目、提交和统计均为演示数据。安装、复制、导出和发布草稿只更新当前预览。

Pencil 画板默认使用 `CJK = Review`。当前导出器会把部分中文渲染成方框，因此每张画板附了一层中文显示稿。选中画板、切换到 `CJK = Edit` 即可编辑原始文字图层。修改文案或文字位置后，需同步更新对应的显示稿。移动设计文件时，请把 `.pen` 和同级的 `中文字形` 目录一起带走。离线 HTML 可直接使用系统字体。

**建议走两次完整流程**

1. **看看 Starcat 会动哪些本机文件。** 从「本机盘点 → 外部资料库」打开 `review-notes`，复制到我的库，再预览分配。查看共享目录影响哪两个 Agent，确认后只重试需处理项。打开「查看分配」，暂停并恢复共享入口。回到说明移除受管副本，可以继续在列表中找到外部原件。
2. **把收藏变成可追踪的安装。** 从「我的 Stars」选 `issue-triage`，阅读原文和中文，核对来源、子目录和提交后入库。可先预览分配。再从同一候选页订阅更新，打开收件箱逐文件比较，尝试备份后更新和回退。

沿窗口内的按钮跳转会保留本轮的副本、分配和订阅状态。「画板」目录和「重置」会恢复目标画板的独立示例，适合单独讨论一个场景。可用 Tab 和 Enter 操作，用 Esc 取消确认。

## 1. 用户来这里做什么

一位同时用 Codex 与 Claude Code 的开发者，从自己的 GitHub Stars 发现一个 Skill，想先读懂它、给一个项目试用，之后还能知道上游改了哪些文件。另一位用户的机器上已有外部管理器与手工安装的版本，他首先需要看清「哪个工具能发现哪一份，Starcat 能改动哪一份」。

日常入口为 **显示 → Skill 管理**。复用 Direct 独立窗口，重复打开激活原窗口。仓库详情里的 Skill 面板继续服务于当前仓库，可带来源和子目录跳到工作台，并在这里接上安装或更新。内容质量、兼容性、安全扫描和评估报告由 SkillEvaluator 专项负责。本专题只使用文件事实，如入口是否存在、目标是否被占用及本地是否改过。

本轮交付是可评审的设计。已有私有库、扫描、文件事务、分配回执、更新与回退构成开发基线。Stars 发现、项目级分配、订阅收件箱、组合、趋势、发布以及面向 Agent 的新动作均按目标体验绘制，实施前分别核对能力。

## 2. 窗口与画板

左栏切换数据范围，中栏选对象或勾选批量目标，右栏读正文、核对磁盘事实并作决定。一个详情保持一个主要操作。窗口初始 `1440 × 860`，采用侧栏 220、中栏 400、阅读区 820 的参考比例。沿用现有原生 sidebar 及 detail 内的 `HSplitView`，栏宽允许拖动。中栏下限 280，右栏下限 480。`1040 × 640` 示例收起左栏，工具栏可恢复侧栏，长路径可复制全值。

| 画板 | 入口与用户问题 | 可见反馈与去向 |
|---|---|---|
| S01 我的 Skill | 从「显示」打开，选中 `release-notes` | 同名不同来源分行，显示受管身份、来源和当前分配。文件 → S16，分配 → S06，版本 → S10，给 Agent 使用 → S11 |
| S02 首次盘点 | 首次进入或重新选择扫描范围 | 显示允许读取的根目录及结果。选择外部条目 → S03。不可读的根可单独重试 |
| S03 外部条目与纳管 | 选择来自其他管理器的 `review-notes` | 并列原位置与私有副本目标。确认后副本进入库，再选择是否分配 → S04 |
| S04 分配预览 | 从单个条目、批量选择或项目组合发起 | 归并共享物理路径，列出可写、已满足和外部只读目标。确认所选计划 → S05 |
| S05 操作结果 | 提交冻结的分配计划 | 逐项展示已创建、已满足、需处理。示例中有一个项目入口在执行前被外部工具占用。只重试需处理项 → S04，查看现有分配 → S06 |
| S06 分配与暂停 | 选择详情「分配」 | 显示各入口的所有者、作用域和现场状态。暂停/恢复自有入口，外部副本只给位置，断链进入修复预览 |
| S07 发现 | 打开「我的 Stars」或「外部目录」 | 一个仓库中的多个子目录可分别选取。外部目录标注来源、缓存时间及局部故障。阅读 → S08 |
| S08 阅读与安装 | 从候选详情预览安装 | 原文、翻译和文件数同屏。固定提交、显示子目录、写入私有库，成功后可分配 → S04 或订阅 → S09 |
| S09 订阅收件箱 | 左栏「订阅更新」 | 按子目录区分待审核、已处理与来源不可达。可单独重试来源或取消订阅。取消最后一项后出现空态。打开待审核项 → S10 |
| S10 版本审核 | 从版本 Tab 或收件箱打开 | 对照基线、本地、上游及逐文件差异。确认后留在审核页看结果，可继续回退或手动返回收件箱 |
| S11 给 Agent 使用 | 详情「给 Agent 使用」 | 选择使用说明、原始正文、固定来源安装请求或完整文件包。可复制前三项或导出文件包。有固定来源的安装请求可进入分配预览 |
| S12 项目组合 | 左栏「项目组合」选中 `Starcat Docs` | 按条目显示固定版本、目标与漂移。选择项目后预览所选项 → S04 |
| S13 趋势 | 左栏「趋势」 | 周、月、年可切换，指标、来源、样本覆盖可见。历史不足显示缺失，可进入候选详情 |
| S14 发布草稿 | 自有条目「发布到 GitHub」 | 选择目标仓库、分支与文件，生成可编辑的本地草稿并模拟复制。正式创建远端 PR 属于后续独立动作 |
| S15 紧凑暗色 | 窄窗与暗色外观验收 | 同一选择与阅读状态，侧栏折叠，关键动作仍可达。可回到 S01 对照 |
| S16 文件 | 已选条目的「文件」Tab | 按相对路径预览正文、引用和脚本，显示复制相对路径入口，返回说明时保持所选条目 |

## 3. 本机库、共享根与所有权

| 对象 | 产品规则 |
|---|---|
| 来源 | GitHub 用仓库稳定标识和仓内相对路径标识条目。所跟踪的 ref 单独保存，完整 commit 标识一次版本。纯本地内容使用本机身份，迁移来源需要用户选择。UI 始终保留同名异源。 |
| 受管内容 | 导入时将完整 Skill 子树写入当前渠道的 `Application Support/<bundle-id>/skill-library/managed/<entry-id>/content/<manifestName>/`。保留原件。入库成功与 Agent 分配分别给出回执。 |
| 分配 | 保存用户意图、Agent/项目作用域、目标路径、实际链接目标和本机回执。对同一物理路径只写一次，预览列出共同读取它的 Agent。其他管理器的真实目录、实体副本或链接只读。 |
| 观察到的位置 | 首扫只读，按已知根及用户选择的项目扫描。不可访问的根保留上次观察并标为待刷新。区分「发现文件」「已分配」「实际调用」三类证据。 |
| 状态与回收 | 暂停只移除 Starcat 持有且仍匹配回执的分配入口，保留内容与目标意图。恢复时重验目标。共享路径无法单独暂停时，按钮写清共同影响，允许取消。 |
| 本地与账号 | 私有库随本机存在。切换 GitHub 账号重新计算 Stars 和仓库访问权限，保留本地副本。组合可导出来源、子目录、完整 SHA 和目标角色，绝对路径与本机回执留在本机。 |

**写入规则**　预览列出 Skill、具体目标、作用域、动作和原因。打开预览时冻结所选项。执行时重新检查目标身份与权限，若现场变化，该项转「需处理」。已成功项保留回执，重试只针对失败项。外部目录被占用时可保留现状或改选目标。需要独立控制时可另选支持的工具专用根，不能靠改名共享 `SKILL.md` 实现单工具停用。

**删除规则**　从库移除先展示所有自有分配，再按回执解除，最后把受管内容送入系统废纸篓。解除失败时保留对应内容，明确列出剩余分配。可能指向该内容的外部入口只提示影响，由其所有者处理。外部条目可隐藏或在 Finder 中查看。

## 4. 从 Star 到更新

1. **发现**　优先从已同步的 Stars、现有标签与仓库上下文寻找 Skill。按「仓库 / 子目录」显示候选。第三方列表作为额外发现来源，保留提供方和最后成功时间，某个来源失败时继续展示其他来源及可用缓存。
2. **理解与安装**　复用 README 翻译组件及其状态。翻译用于阅读，安装、导出、版本指纹均基于原始完整子树。安装预览展示仓库、子目录、解析后的 commit、文件数和本机目标。引用的脚本作为文件保存。安装当前提交和追踪后续更新是两次独立选择。
3. **订阅**　跟踪所选 ref 中的子树。轮询合并同仓请求，只有子树内容变化才进入收件箱。仓库只改其他文件时保持已是最新。离线或遇到访问限制时保留条目与上次检查时间，可手动重试。
4. **更新**　比较安装基线 B、本地 L、远端 R。`B=L` 且远端有改动时可预览更新，`B≠L` 时明确列出用户改过的文件。冲突默认保留本地，可显式备份并采用上游。来源迁移、删除或路径改名时保留现有版本，等待重新关联。
5. **回退**　展示将恢复的版本与涉及分配。回退改变受管内容，保留订阅选择。已经产生的新本地改动再次走预览与备份。通知点击后直接定位到对应子目录的差异。

## 5. 给 Agent 使用、排行与发布

- **给 Agent 使用**　「复制使用说明」输出可粘贴的任务提示与当前条目标识。「复制原文」只复制当前文件。「复制安装请求」包含仓库、子目录和完整 SHA。需要完整引用文件时选择「导出完整包」。剪贴板成功反馈用 `CopyFeedbackButton`。支持来源不明的本地条目复制使用说明与正文，远端安装请求需先关联来源。
- **CLI / MCP**　列表、详情、文件目录、分配现场、更新差异和生成预览可按 `read` 提供。入库、分配、暂停/恢复、订阅变更、应用更新或回退统一走现有服务及 `write` 门控。写权限默认关闭。Agent 获得待确认计划与逐项结果，在 App 核对实际目标后执行。接口名需在公共能力目录中核实后登记。
- **项目组合**　展示「组合期望」与「本机现场」，固定每项版本，仅选中用户授权的项目作用域。组合部分失败时继续显示各条状态。导入他人的组合先预览，工作树移动后需重新定位项目。
- **趋势**　默认展示 GitHub 仓库在选定样本内的新增 Stars，明确标注仓库级口径。同仓多个 Skill 共享仓库数字，在榜单中只占一个仓库名次。第三方安装量若有独立窗口与可用数据，另列来源和时间。本机实际调用只有取得相应数据才展示。历史不足显示可用区间。原型使用示例数据。
- **发布**　先在本地选择文件、复核相对路径、预览目标仓库与分支。第一步生成本地草稿，可复制或导出。需要创建远端分支或 PR 的未来能力单独请求 GitHub 写权限，提交前再次明确将公开的文件。默认排除本机回执、绝对路径和私有笔记。

## 6. 可实施的验收

| 场景 | 通过条件 |
|---|---|
| 首次扫描、切换账号与未授权根 | 扫描前后外部目录内容及链接身份一致。切换账号后本机库仍在。不可读根明确显示上次结果的时间。 |
| 导入同名异源 | 两项拥有独立身份和来源，原件仍存在。入库后列表可直接定位受管副本，未选择的 Agent 无新入口。 |
| 两个 Agent 读同一物理根 | 预览中共同影响有明确名称，执行后只有一次磁盘写入。取消或仅选择只读项时没有写入。 |
| 暂停、断链、外部占用及批量重试 | 能区分已暂停、链接失效、外部占用和无回执。只移除自有入口，外部换链导致操作中止。重试保持已完成项。 |
| 从 Stars 安装并订阅 | 多 Skill 仓库只安装所选子树。译文显示时也安装对应 commit 原文。上游只改仓库 README 不产生 Skill 更新。 |
| 本地与上游同时改动 | 确认前可看逐文件差异，取消保留现场，备份采用上游后能回退，已分配的自有入口保持可解析。 |
| Agent 请求与发布草稿 | 禁用写权限时仍可预览。复制原文与完整包有明确区别。生成本地草稿后远端仓库状态保持原样。 |
| 外部来源离线、排行历史不足 | 仍可使用本机库和可用缓存，列出失败来源与时间。历史不足的年份不提供虚构增幅。 |
| 原生体验与渠道 | Direct 通过菜单打开同一窗口。App Store 隐藏入口并在动作层门控。1440 与 1040 两档、明暗、键盘、长路径及放大字号下均可完成主流程。 |

交互细节沿用 `DESIGN.md`、列表与详情切换规范。列表单选与批量勾选分开，刷新保留已有内容，初载按需给骨架。详情随选择就绪切换，Reduce Motion 下简化过渡。关闭、刷新、复制复用已有控件。原型中的按钮位置、文案和去向是交互契约，原生控件以系统动态颜色、字号和键盘可用性为准。

## 7. 开发交接

| 优先级 | 交付切片 | 复用入口与交付界线 |
|---|---|---|
| P0 | S01–S06、S16 本机治理 | `SkillLibraryStore`、`SkillImportService`、`SkillAssignmentCoordinator`，补清晰的来源、目标和逐项反馈。先在已支持写入的用户根验收，新增 Agent 或项目根须有独立适配证据。 |
| P1 | S07–S11 发现、翻译、订阅及 Agent | 接 GitHub Stars 与仓库 Skill 探测，复用 README 翻译、固定提交导入与 `SkillContentUpdateService`。公共能力先查目录，补预览、确认和回读契约。 |
| P2 | S12–S14 组合、趋势、发布草稿 | 以 P0 的分配计划、P1 的来源身份及可用历史样本为依赖，每个功能可独立评审与交付。 |
| 横向 | S15 窄窗与深色 | 与每个切片同时验收。保持已有栏宽记忆、可收起侧栏与稳定的主阅读区。 |
