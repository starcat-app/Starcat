## 2. 结论先读

1. **参考 SkillDeck 的能力地图，重新设计 Starcat 的产品与数据模型。** 上游已经覆盖多工具目录发现、软链接分配、本地导入、仓库安装、更新、停用、编辑和使用证据统计，值得借鉴；其同名合并与共享目录开关语义不宜沿用。
2. **新窗口是本机管理工作台。** 左栏为库、Agent 与来源；中栏为 Skill 列表；右栏为说明、文件、安装位置和版本。使用现有 Starcat 分栏、标题栏、图标、Markdown 和状态反馈体系。
3. **先分清四件事：来源、内容、物理位置、Agent 可见性。** 同名不同来源保持独立；多个 Agent 读取同一目录时，明确显示共同影响范围。
4. **外部发现不等于接管。** 首次扫描只读。用户从外部 Skill 导入受管副本后，Starcat 才能更新、编辑和管理自己的副本及分配链接。
5. **受管库不放在所有 Agent 自动读取的共享目录。** 建议使用 Starcat 自有 Application Support 目录，只有分配成功才进入目标工具读取路径。
6. **不承诺虚假的“全局关闭”。** 首版提供暂停 Starcat 受管分配；外部副本、项目目录、插件及第三方配置可能继续使 Skill 可见，界面必须表达这一事实。
7. **文件事务优先于功能数量。** 复用现有 `RepoSkillInstaller` 的校验、暂存、回执和恢复经验；新增本机安装、分配事务，避免另造一个“先删再复制”的写入器。
8. **使用统计、市场、项目同步分阶段。** 首版完成本机管理闭环，再做编辑与使用证据，最后扩展市场和项目作用域；MCP 管理与规则同步另立产品范围。

相关事实及限制见 [证据索引](11-证据索引与核查记录.md)。

## 5. 待评审的默认建议

| 编号 | 建议 | 影响与取舍 |
|---|---|---|
| D01 | 独立 `SkillWorkspace` 单例 Window Scene | 不依赖仓库详情 sheet；可在主窗口关闭后继续使用 |
| D02 | 仅 Direct，暂不新增 Pro 限制 | 用户只指定渠道限制；新增商业门槛需另行确认 |
| D03 | 本机库与 GitHub 账号隔离，独立本地数据库 | 多账号切换不丢本机目录；远端授权仍随账号变化 |
| D04 | 私有受管库 + 按目标逐 Skill 分配 | 多一份受管存储，换取明确的所有权与可暂停分配 |
| D05 | 外部 Skill 默认只读，允许导入副本 | 不能一键修改所有外部目录；降低误接管风险 |
| D06 | 首版“暂停分配”，不伪装通用全局禁用 | 语义真实；外部继承可见时仍需解释 |
| D07 | 完整 YAML 只用于解析／校验，原始文本用于保存 | 如引入 Yams，需另审依赖版本、许可及致谢；不使用 typed encoder 重写全文 |
| D08 | 首版不共同写第三方 lock、不同步规则文件 | 减少与其他安装器争用；互操作以只读识别开始 |
| D09 | 使用证据默认关闭，选择 Agent 后本地扫描 | 读取会话历史属于不同于目录发现的授权范围 |
| D10 | MVP 不接管整个项目 skills 目录 | 项目级同步单独设计；保留逐项冲突和回退能力 |

以上最初为研究阶段的默认建议。2026-11-14 dong4j 授权按照开发清单推进，实施采用这些默认值，仍需按里程碑验收；D07 引入新依赖等需另行确认的事项不因此自动获授权。实施时若改变 D01–D10，必须同步调整相关细案和验收用例。

## 6. 成功标准

- 用户可以在独立三栏窗口找到本机 Skill，辨认来源、物理位置与哪些 Agent 能读到它。
- 用户可以导入本地或 GitHub Skill，逐目标分配、暂停、恢复、检查和执行更新，看到部分失败及下一步。
- 同名不同源不会合并，外部目录不会因删除库条目被删，修改过的文件不会被静默覆盖。
- 首次扫描、失败、部分覆盖、离线、取消、重启恢复、账号切换和 Direct/App Store 门控都有可验证行为。
- UI 遵循 Starcat 规范，全部新增文案覆盖当前 17 种语言，AI 翻译审核状态如实保留。
- 测试、构建、人工 GUI 验收分别记录；“方案写完”不等于“功能完成”。
