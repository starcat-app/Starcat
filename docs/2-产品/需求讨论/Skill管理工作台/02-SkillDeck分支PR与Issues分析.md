## 3. 真正未合入的 PR #59

### 3.1 状态

标题方向为项目级 Skill 与规则同步。来自 `ivoidcat/SkillDeck:feat/project-rule-sync`，不在主仓远端分支列表中。head 为 `4117584850e6be5fb43fe268b3d5e808b8d055d2`；2026-07-15 创建，最后更新时间为 2026-07-28，核查时仍 open。API 未提供确定可合并结论，本轮没有尝试合并。

变更规模为 47 个文件，+3386 / -955。作者报告测试通过和打包验证属于作者证据，本轮没有复跑。不能将其表述为“即将发布”或“近期正在活跃开发”。

### 3.2 产品与技术改动

| 内容 | 实际变化 | 对 Starcat 的判断 |
|---|---|---|
| 项目 Skill 源 | 项目 `.agents/skills` 作为源 | 值得扩展为显式项目作用域 |
| 项目分配 | 其他工具整个 skills 目录链接到源 | 与逐 Skill 分配不同；首版不采用整目录接管 |
| 规则同步 | `.agents/AGENTS.md` 映射至多个规则入口；Cursor 包装 `.mdc` | 已跨出 Skill 管理范围 |
| 全局配置 | 可自定义全局源目录并同步 | 来源目录与工具读取目录应分开 |
| 停用／恢复 | 将内容移到中心 disabled store，记录原始位置 | 借鉴可恢复操作；还需处理文件移动与索引提交之间的失败 |
| watcher | 串行处理状态，移除重复 close | 可作为主线缺陷的旁证 |
| 交互模型 | 删除旧逐工具 Toggle 及相关测试 | 不是可无缝套用的小功能补丁 |

### 3.3 讨论中的真实反馈

维护者 2026-07-20 要求补充场景说明与中英文内容；7 月 21 日运行后表达了界面不易理解、下一步不明确的困惑。作者随后补充流程说明。这些反馈支持“项目／全局／规则／Skill 同时进入一个流程会造成认知负担”的判断，**不支持**“维护者已拒绝该功能”或“已批准合并”的结论。

Starcat 的对应设计应做到：先选择作用域，再展示预览清单、冲突与影响目标，最后执行。项目同步细案见 [09](09-使用统计与生态扩展方案.md#6-项目作用域后续阶段)。
