# 安装、分配、禁用与文件事务方案

> 状态：拟议写入协议。所有路径示例均为设计，不应据此直接操作用户目录。首版默认“受管内容 + 已验证支持 symlink 的目标”；实体副本适配另行验收。

## 1. 先统一操作词汇

| 用词 | 精确定义 | 不包含 |
|---|---|---|
| 导入库 | 复制完整 Skill 到 Starcat 自有受管目录并建立回执 | 自动向全部 Agent 暴露 |
| 分配 | 在一个明确目标位置创建受管链接，或未来受支持的受管副本 | 接管整个 skills 根 |
| 暂停分配 | 移除当前验证仍属于 Starcat 的分配链接，保留目标意图 | 禁用外部副本、其他项目或插件中的内容 |
| 恢复分配 | 对暂停目标重新预检并创建分配 | 覆盖后来出现的同名目录 |
| 卸载分配 | 删除自有分配关系与对应自有链接 | 删除 canonical 外部内容 |
| 移除库条目 | 清理自有分配后移除受管内容与索引 | 删除用户原始导入目录 |
| 工具级禁用 | 通过该 Agent 官方配置关闭指定 Skill | 任意工具都支持的通用开关 |

首版主交互使用“暂停／恢复分配”。暂不提供含糊的“全局开／关”。工具级配置禁用留到适配器有版本和无损配置编辑证据后实施。

## 2. 对象权限表

| 对象 | 可预览 | 可分配 | 可编辑／更新 | 可删除内容 |
|---|---|---|---|---|
| Starcat 自有受管内容 | 是 | 是 | 是，需内容校验 | 是，先处理分配 |
| 自有分配 symlink | 是 | 不重复创建 | 只更新关系／重新验证 | 仅 unlink 本链接 |
| 有旧 Starcat receipt 的现有仓库安装 | 是 | 导入受管副本后分配 | 保留旧流程验证与权限 | 首版不自动接管；旧卸载流程仍有效 |
| 外部实体目录 | 是 | 首版先导入副本 | 首版不直接写 | 否 |
| 外部 symlink／未知 canonical | 是，限边界内文件 | 先导入副本 | 否 | 否 |
| 插件／系统／组织管理目录 | 是，按已配置范围 | 不改插件源 | 否 | 否 |
| broken symlink | 展示链接及诊断 | 只可新建独立受管项 | 不假造原内容 | 未证明归属不得删 |
| 第三方 lock／Agent 配置 | 已支持格式可读 | 不因可读获得写权限 | 首版只读 | 否 |

用户选了“删除”不能扩大对象权限；必须显示当前操作能影响的对象，无法安全处理时给出 Finder 路径与原因。

## 3. 预检输出是可评审计划

拟议接口：

```swift
protocol SkillOperating: Sendable {
    func plan(_ request: SkillOperationRequest) async throws -> SkillOperationPlan
    func execute(_ plan: SkillOperationPlan) async -> SkillOperationResult
}
```

计划包含 operationID、entryID、期望内容 revision、来源版本、原始与解析路径、每目标动作、预期影响 Agent、冲突、预计字节、是否需要用户决策，以及 plan 建立时的指纹。

执行必须重新核对计划前提；计划不是跳过检查的授权 Token。源文件、目标或账号上下文改变时返回 `planOutdated`，重新生成预览，不静默扩大覆盖范围。

每目标结果：`succeeded / alreadySatisfied / skipped / conflict / failed / cancelled`，附错误代码、阶段、可重试性及实际状态。聚合结果是 `allSucceeded / partiallySucceeded / failed / cancelled / needsRecovery`，不可将部分失败简化为成功 toast。

## 4. 文件事务协议

### 4.1 标准步骤

1. **Gate**：执行层验证 Direct 能力，不因从内部 API 调用而放过。
2. **Preflight**：验证源、receipt、当前完整 digest、路径边界、目标类型、可写性与需要的空间；确认这不是目录级接管。
3. **Stage**：在实际提交目标同卷创建唯一暂存目录；复制／下载；不执行任何脚本。
4. **Verify**：校验文件完整集合、内容 hash、类型、执行位、manifest、未支持 symlink 与超限。
5. **Journal**：原子记录阶段、old/new digest、stage／backup／destination、旧新 receipt；记录里不放正文和凭据。
6. **Commit**：短同步区间完成备份和 rename，不响应取消；任一步失败恢复已知旧状态。
7. **Metadata**：内容成功后写 receipt 和索引；失败保留 journal，不能回报全部完成。
8. **Reconcile**：重读内容与目标链接，发布新快照，形成逐项结果；清理可证明无用的临时文件。

同卷目录 rename 保证单次切换的文件系统行为；“旧目录移到备份，再移入新目录”的两步之间可能短暂不可读。方案不承诺跨目录、数据库与多个 Agent 目标的全局原子性，也不为此引入分布式事务。

### 4.2 最小持久化记录

```json
{
  "version": 1,
  "operationID": "<uuid>",
  "kind": "replaceContent",
  "entryID": "<uuid>",
  "phase": "staged",
  "destination": "<managed content path>",
  "stage": "<same-volume stage path>",
  "backup": "<same-volume backup path>",
  "oldDigest": "<sha256>",
  "newDigest": "<sha256>"
}
```

实现还需记录 receipt 版本及索引需补写的字段。独立 receipt 与数据库不能声称和目录 rename 同时提交；恢复流程依照实际 digest 补齐二者。

## 5. 导入和首次分配

本地导入不搬走原目录；GitHub 导入按固定 commit 获取完整 Skill。导入成功可处于“已入库，未分配”，这是正常结果。

对选择的目标：

| 当前目标 | 动作 |
|---|---|
| 不存在，父目录可写 | 创建临时链接，再 rename 至最终名字 |
| 已有经过验证的同一自有分配 | `alreadySatisfied` |
| 已有外部同名实体／链接 | `conflict`，默认跳过；不先删再建 |
| 共享根被多个 Agent 共用 | 一次物理计划，列出共同影响，不重复创建 |
| 工具读取／symlink 行为未验证 | 不提供可写分配，只读显示或给导出路径 |
| 根是用户配置的 symlink | 先解析真实父目录并显示实际路径，预检变化则中止 |

M2 仅为经官方规则和 fixture 验证的 symlink 目标提供自动分配；其余工具保持发现能力。旧仓库流程的实体安装不因此消失。实体副本模式需另有更新、修改检测和暂停恢复协议后开放。

内容导入成功、部分目标分配失败时保留内容并报告部分成功。用户可以只重试失败目标，不重复下载或删除已成功的分配。

## 6. 暂停、恢复与共享目录

暂停先读取最新分配 receipt，再核对链接类型、链接值、解析目标和可用的文件 identity；目标已经变成外部实体或指向其他内容时，标 `ownershipChanged`，不删除。

暂停成功将 desired state 设为 paused；observed state 仍来源于实际检查。若删除链接成功但索引更新失败，journal 支持补写，不在刷新时自动重新创建链接。

恢复时重新执行普通分配预检。若暂停后目标被用户占用，保留 paused 并显示 conflict，不把“恢复”解释为覆盖授权。

从 `~/.agents/skills` 暂停一个 Starcat 分配会影响所有读取该物理根的工具。若某 Agent 仍有独立副本，显示 remaining exposure；不能用一个成功 unlink 证明它已完全不可用。

不重命名外部 `SKILL.md` 为隐藏文件，不移动用户项目内容到中心禁用库，不写通用 `disabled` 字段并声称所有工具都理解。

## 7. 移除与卸载

单目标卸载只 unlink 已验证的自有链接，并移除 assignment。绝不对解析后的外部 canonicalURL 调用递归删除。

移除库条目：

1. 列出自有分配、外部可见位置、未完成操作和本地修改。
2. 先清理可验证的自有分配；某目标冲突或不可读时保留受管内容，返回 `blockedByAssignments`。
3. 所有自有分配处理完成后，将自有条目目录（含 receipt）移到系统废纸篓；再更新索引。
4. 元数据失败时保留 journal；外部导入原目录与第三方副本始终保留。

已经解除的部分分配不自动反向重建以追求表面原子；结果说明哪些已处理、为何库内容仍保留。用户再次操作会重新预检。

“外部发现”支持隐藏列表记录，但隐藏不等于卸载。重新扫描不自动取消用户隐藏偏好。

## 8. 更新与编辑发布

更新和编辑保存都以受管 content 目录为事务目标。保留稳定目标路径，使已分配链接在更新后读到新内容。

如果当前 digest 与安装基线不同，默认 `localChanges`；先展示差异，用户选择另存、跳过或备份覆盖。更新不能为了消除错误而删除未知附件。

更新后保留一份上一已知成功版本及恢复记录；清理前确认不属于未完成事务。备份保留策略应有界，不能每次失败无限积累，也不能启动时盲删所有 `.backup-*`。

对运行中的 Agent 只提示“内容已更新，工具可能需要重新加载／新建会话”；除非适配器明确证明，否则不保证即时生效。

## 9. 取消与恢复矩阵

| 中断位置 | 下次动作 |
|---|---|
| 只有未验证 stage | 删除本操作明确拥有的 stage，保留旧内容 |
| stage 已验证，尚未提交 | 用户取消则清 stage；重试重新核对前提 |
| 旧内容已进 backup，新内容未就位 | 若目标未被外部占用，恢复 backup；否则 needsRecovery |
| 新内容已就位，receipt／数据库未补齐 | 新 digest 匹配计划则补 receipt／索引 |
| receipt 显示新版，内容实际旧版 | 依据 journal 和 digest 恢复一致状态，不信单一字段 |
| 内容／backup 都不符合计划 | 保留现场并提示，不推测删除 |
| 部分目标已成功 | 单项结果保留，未提交目标 cancelled；不谎报全部回滚 |

恢复只访问 journal 中通过库边界和所有权校验的路径。损坏或来源不明的 journal 进入人工处理，不用 `rm -rf` 兜底。

正常退出应用时取消尚未提交的准备任务，短暂等待已经进入提交区间的操作完成或恢复；不启动脱离应用的后台写入进程。系统强制终止无法保证正常退出流程，下一次启动按 journal 和实际 digest 恢复，不能承诺“强退也一定已经保存”。

## 10. 并发与测试重点

同一 entry 的编辑、更新、删除串行；同一物理目标的分配操作串行。不同条目可受限并发准备，提交按受影响路径排队。外部安装器不受 Starcat 锁约束，所以执行前重读；不宣称锁住整个 Agent 生态。

必须注入复制、rename、链接、receipt、数据库和取消失败，验证旧内容、权限、临时目录及逐目标结果。重点覆盖外部改指向、目标根解析变化、本地附件新增、共享根重复计划、跨卷 stage 和崩溃恢复。用例见 [10](10-开发任务拆解与验收矩阵.md)。
