# 开发任务拆解与验收矩阵

> 状态：实施任务规格；2026-11-14 dong4j 已授权按 checklist 开发并逐小功能提交，真实进度见 [12](12-开发Checklist与实施记录.md)。首版为 M0–M3；M4/M5 单独验收。所有拟新增路径先核对现有同名组件，避免重复造轮子。

## 1. AI 开工协议

1. 读取当前 `AGENTS.md、RTK.md、LESSONS.md、DESIGN.md` 及本目录 `00、03、04`，确认代码实施授权和 D01–D10。
2. 读取 `BRANCH.md` 与分支规范，核对 refs／worktree／脏状态；保留并行任务修改。按本轮授权逐小功能本地 commit，不自行 push、发布或操作桌面。
3. 图工具优先发现符号，检查索引覆盖；partial 或工作区已变时读真实源码，不把研究时的脏文件当 HEAD。
4. 选择下述一个任务包，写清允许文件、输入输出、可验证完成条件；需要 GitHub／Multica 关联时按现有任务规范执行，不复用无关 Issue。
5. 代码改动必须有解释约束的必要注释；新文件补模块、关键类型和关键方法说明。
6. 完成定向测试和适用构建后报告真实状态；总览、Changelog、外部发布各遵守单独授权。

本目录不是授权一次性实施全部远期功能的替代物。

## 9. Given / When / Then 验收矩阵

| 编号 | Given / When | Then |
|---|---|---|

## 10. 验证命令与执行边界

代码阶段先确认 Xcode IDE 已关闭；不得在未授权的情况下用 GUI 自动关闭。用进程检查核实，必要时请 dong4j 关闭后再测试。

示例定向回归：

```bash
make test TEST_ARGS="-only-testing:StarcatTests/RepoSkillTests"
make test TEST_ARGS="-only-testing:StarcatTests/AgentWorkspaceColumnLayoutTests -only-testing:StarcatTests/RAGWorkspaceColumnLayoutTests"
```

新增 Suite 以真实名称加入定向命令；完整功能跨 UI、状态、存储、网络并新增 Swift 文件，需要工程生成和双渠道标准构建：

```bash
xcodegen generate
make build-direct
make build-appstore
git diff --check
```

实际执行 shell 时遵守当前 RTK 包装规则。`make test` 自身会生成测试工程并使用测试专用缓存；不要裸 `xcodebuild` 借用固定 DerivedData，不执行打包／发布脚本。

仅文档研究无需运行这些构建；本轮报告不会把以上未来命令列为已经通过的验证。
