# Skill 管理工作台总体方案

> 状态：推荐方案，待产品与技术评审；未实施。适用：Starcat Direct，macOS 15+。研究日期：2026-11-14。

## 1. 产品定义

提供独立的“Skill 管理”工作台，让用户回答：

1. 我本机有哪些 Skill，分别来自哪里？
2. 哪些由 Starcat 管理，哪些只是外部发现？
3. 哪些 Agent 能读到它，原因是什么？
4. 如何导入、分配、暂停、更新、编辑及安全移除？
5. 哪些位置、更新或操作需要我处理？

默认离线可管理本机内容，联网只用于明确的来源操作。管理窗口本身不执行 Skill 指令、不运行仓库脚本、不自动启动 Agent。

## 2. 两个并列入口

| 入口 | 起点 | 对象 | 生命周期 |
|---|---|---|---|
| 现有仓库 Skill sheet | GitHub 仓库详情 | 固定 commit 的候选 Skill | 当前仓库阅读／安装会话 |
| 新 Skill 工作台 | 显示菜单／工作台入口 | 本机受管条目和外部安装实例 | App 级、跨仓库、跨账号 |

后续可以从旧 sheet 通过“添加到 Skill 库”进入受管导入，也可以在安装后“在管理器中查看”。保留现有直接安装方式；没有发生所有权验证时，旧安装只作为带 Starcat 回执的外部位置被发现，不自动搬家。

## 3. MVP、后续与范围外

| 阶段 | 必须交付 | 退出条件 |
|---|---|---|
| M0：可验收界面骨架 | 独立三栏、菜单、Direct 门控、真实状态模型的样例数据 | dong4j 可评审布局；不能标记功能完成 |
| M1：本机只读库 | 已知根发现、受管库索引、身份、来源、Markdown、文件、位置与诊断 | 无写入即可准确解释现有安装 |
| M2：管理闭环 | 本地／GitHub 导入、逐目标分配、暂停／恢复、移除、批量结果、事务恢复 | 外部内容不被误删，失败可恢复 |
| M3：来源维护 | 更新检查、差异、本地修改保护、单项／批量更新、旧入口回归 | 安装至更新形成可追溯闭环 |
| M4：增强管理 | 原文编辑、自定义根、个人标签／集合、可选使用证据 | 增强能力有独立测试与覆盖说明 |
| M5：生态扩展 | 市场 provider、项目作用域、可选逐工具配置禁用 | 每个 provider／工具单独验收 |

**首版功能范围为 M0–M3。** 不应把 M4/M5 未做项伪装成已完成，也不应为了赶 M2 放弃文件事务。若需要更小的公开试用，M1 可以独立作为“只读预览版”，明确禁止称为完整管理器。

暂不包含：MCP 服务管理、AGENTS/CLAUDE 等规则同步、整个项目目录接管、CloudKit 同步本机安装状态、后台自动更新、自动执行 Skill、自动上传使用日志、独立后端或新支持仓库。

## 4. 总体结构

| 层 | 拟新增职责 | 约束 |
|---|---|---|
| Scene / UI | `SkillWorkspaceSceneRoot`、导航、列表、详情、操作预览 | `@MainActor @Observable`，只持有 UI 状态与 DTO |
| 本机组合点 | `SkillLibraryEnvironment` | app 级惰性创建，统一 Direct gate |
| 读模型 | `SkillLibraryStore` | 合并扫描、receipt、索引；发布带 revision 的快照 |
| 本机发现 | `LocalSkillScanner`、`SkillRootWatcher` | 有界扫描与补扫；根错误不能变成空库 |
| 来源 | `SkillSourceService`，GitHub／本地 provider | 固定内容版本；网络和文件访问不在主线程 |
| 写入 | `SkillOperationCoordinator`、`SkillFileTransaction` | 明确所有权、预检、stage、提交、恢复 |
| 元数据存储 | `SkillLibraryDatabase` | GRDB，独立于账号主库，文件内容不进数据库 |
| 可选统计 | `SkillUsageService` 与 Agent providers | opt-in，本地聚合，与目录扫描权限分开 |

这些是拟议模块名，不是当前已经存在的 API。目录和最小接口见 [06](06-领域模型本机扫描与存储方案.md) 与 [10](10-开发任务拆解与验收矩阵.md)。

## 5. 三个真源

- **文件系统是真实存在与内容的真源。** 链接消失、目录被外部修改后，数据库不能强行宣称它仍有效。
- **Starcat receipt 与操作记录是所有权的真源。** 仅目录名字、第三方 lock 或同一 hash 都不能授予删除权限。
- **数据库是用户组织与查询索引的真源。** 标签、收藏、来源关联及用户配置不能因为重扫或换账号被丢掉。

索引可以重新对账，用户标签不能靠重新扫描“恢复”。数据库损坏时保留库文件和回执，进入只读恢复状态，不自动删库重建。

## 6. 身份与状态原则

同名不同源分别展示；同一来源的不同物理副本可以归属一个来源，但不得隐藏内容分叉。多个路径解析到同一个真实目录时，可折叠为一个物理对象，同时保留每条访问路径。

“安装了几个 Agent”拆成：

- Starcat 受管分配；
- 已发现的外部副本／链接；
- 通过共享根或项目继承可能可读；
- 工具配置明确禁用；
- 未验证或存在冲突。

用户暂停一个受管链接后，如果另有共享根仍使 Agent 可读，应显示“受管分配已暂停，仍可从其他位置读取”，不能显示“已关闭”。

## 7. 操作契约

| 操作 | 默认结果 | 必须让用户知道 |
|---|---|---|
| 发现／刷新 | 读取配置根并对账，不改 Skill | 覆盖范围、失败根、上次成功时间 |
| 导入库 | 建立独立受管副本，默认尚未分配 | 原目录保留，选择目标后才影响 Agent |
| 分配 | 在受支持目标建立逐 Skill 链接或受管副本 | 实际路径、共享影响、冲突、重载提示 |
| 暂停分配 | 移除经过验证的自有链接；保留期望记录 | 外部副本不会被关闭 |
| 恢复分配 | 对暂停目标重新预检后创建 | 路径后来被占用时不覆盖 |
| 移除库条目 | 先处理分配，再删除自有库内容 | 与仅取消分配、从列表隐藏区别 |
| 检查更新 | 只取来源版本，不改现有内容 | 检查失败不是已经最新 |
| 更新 | 预览、保护本地修改、事务替换 | 逐条结果、取消边界、受影响的目标 |
| 编辑 | 仅受管副本，保存前核对 base hash | 保存会影响已分配的 Agent 所读内容 |

完整权限表及状态机见 [07](07-安装分配禁用与文件事务方案.md)。

## 8. 故障与状态反馈

操作分为 `planned → preparing → readyToCommit → committing → reconciling → finished`，以及 `cancelled / failed / needsRecovery`。任务级取消停止尚未提交的项；正在提交的单项完成提交或恢复后再返回。

库级状态至少有 `loading / ready / partiallyAvailable / unavailable`。单项解析错误不阻塞整个库；失败根保留上次已知项并标记陈旧。没有成功扫描过的根显示“无法读取”，不能计作零个。

错误展示采用“发生了什么、影响哪个 Skill／目标、已经保留什么、下一步”四项。详细日志记录 operationID、阶段、错误类别与脱敏路径；不写 Skill 正文、会话正文或 Token。

## 9. 数据与隐私

本机 Skill 库不依赖登录，不通过 CloudKit 同步路径、工具存在性或使用日志。远端 GitHub 私有来源使用当前账号；登出或换账号时取消旧权限请求，保留本机内容，来源状态转为需要授权。

目录发现只读已配置的根，不扫描整个 Home。使用历史扫描另行选择工具并启用，默认关闭；退出授权时取消、停止监听并允许清空聚合缓存。

受管内容不等于已审计可信内容。界面展示来源、版本和文件，安装只搬运与校验；可执行权限按文件清单处理，不在管理流程中运行代码。

## 10. 实施前必须收口的产品决策

推荐默认值见 [00 的 D01–D10](00-阅读导航与决策摘要.md#5-待评审的默认建议)。评审重点是：

1. 接受“受管库 + 外部只读”的所有权模型。
2. 接受首版暂停受管分配，而不是承诺任意 Agent 的通用开关。
3. 接受 M0–M3 的首版范围，M4/M5 后续交付。
4. 明确入口文案与布局尺寸，使用 Starcat 原生视觉。
5. 需要完整 YAML 校验时，确认依赖方案及致谢。

这不是阻止继续做研究的权限问题；它是避免后续编码把方案建议误认为用户已经确认的产品事实。实际开工要求与验收矩阵见 [10](10-开发任务拆解与验收矩阵.md)。
