# 来源、导入、更新与编辑方案

> 状态：待实施细案。首版来源为本地目录和 GitHub；市场及任意 Git 远端留到独立 provider 验收。

## 1. 来源 provider 契约

建议保持一个来源协议和少量实现，不为两个来源引入插件运行时。

| 操作 | 输入 | 输出与限制 |
|---|---|---|
| `resolve` | 用户 URL／目录、当前授权上下文 | 规范来源、版本选择、可访问性；不能自动写入 |
| `discover` | 已解析来源、版本 | candidates、complete、warnings、可重试游标／预算信息 |
| `fetch` | candidate + 固定 revision | 完整 staged payload、文件清单、来源证据 |
| `checkUpdate` | entry + 已安装版本 | upToDate／available／unreachable／unsupported／sourceMissing |
| `diff` | installed baseline、当前内容、远端 payload | local diff、remote diff、权限位与文件集合变化 |

返回 `Sendable` 值；网络复用现有 Starcat 网络／鉴权／限流能力，文件操作交给统一事务。Registry 搜索返回的是候选线索，不直接授予安装和更新权限。

## 2. 本地导入

允许选择一个 Skill 目录或一个包含多 Skill 的目录。前者校验完整结构，后者有界发现并给候选列表，不能递归复制整个用户选择的父目录。

导入预览包含 manifest、来源路径、文件数、总大小、可执行文件、点文件、symlink／嵌套结构诊断和不支持项。未知文件不因扩展名被擅自丢弃。

建议默认预算：单 Skill 最多 10000 个文件、200MiB、manifest 最多 1MiB；超限给明确结果并停止自动导入。预算是初始产品值，可按真实样本评审调整，不是 Agent Skills 官方限制。

本地来源是一次快照，不默认建立“持续双向同步”。原目录之后变化可以显式“重新导入／比较来源”，不能悄悄覆盖受管内容。

同一来源与 digest 已入库时定位已有条目；同名不同源创建独立条目。不要为了绕过工具目录同名冲突改写 manifest name；分配时让用户处理冲突。

## 3. GitHub URL 与来源版本

首版支持：

- 仓库 URL；
- 带分支／commit 与子目录的 GitHub tree URL；
- 现有 RepoSkill 候选的结构化输入。

分支名可以包含 `/`，不能简单把 URL 的第一个 path segment 当 ref。优先使用已知结构化 repo／ref／directory；粘贴 tree URL 时通过 GitHub refs／路径解析，并对歧义让用户明确选择。

查询时 resolve 到固定 commit，保存 repo identity、subdirectory、选用 ref、resolved commit、tree/blob 证据与读取时间。安装与预览必须对应同一 commit；分支在预览后变化不应悄悄改变即将安装的内容。

复用现有 `RepoSkillScanner` 的 tree／有界 BFS、目录索引和 `RepoFileDownloader`，不重新实现一套 shell clone 作为默认下载方式。首次请求不默认执行 git、npm 或安装仓库依赖。

私有仓库需要当前账号授权；显示授权错误和可重试入口，不把 403／404 都解释为仓库删除。匿名公开来源可在未登录状态使用。

## 4. 内容校验与预览

Agent Skills 官方格式以目录中的 `SKILL.md`、YAML frontmatter 与 Markdown 正文为基础。规范还存在可选 `license、compatibility、metadata、allowed-tools`；扩展字段和工具专有语法不能因 Starcat 未建模就被删除。[官方格式证据](11-证据索引与核查记录.md#官方生态证据)

建议用完整 YAML parser 进行只读解析／语法校验，保存时保留原始 UTF-8 文本。当前轻量 parser 继续服务已有流程；新编辑能力若需要 Yams，应先核对可用版本、Swift 支持、许可并登记 AboutDependency，不能未经验证直接升级现有流程。

基础字段校验复用项目规则；高级字段不认识时显示“扩展字段”，不伪装成错误。真正语法失败保留原文并阻断需要有效 manifest 的新安装；已存在的外部损坏项仍能查看。

文件预览按 MIME／已支持类型限量加载；二进制显示大小、类型和 Finder 入口。Markdown 相对资源只解析到当前 Skill 目录，不能通过链接读出包外文件。外部链接交给用户主动打开。

原有远端 Markdown 渲染不能假定直接支持任意本机 base URL。实施时给渲染组件增加受控内容适配及资源边界测试，复用主题、代码块和阅读工具，不把远端网络生命周期引入本机详情。

## 5. 更新检查

检查状态必须持久化或可稳定恢复：

`neverChecked / checking / upToDate / updateAvailable / sourceUnavailable / unsupported / localChanges / stale`。

“未检查”不能显示已是最新；网络失败不能清除之前已知有更新的证据，而应标记旧结果和检查失败时间。

版本比较以来源内容树／完整 digest 为准，不只看 manifest 中的人类版本号：

- repo commit 变但 Skill 子目录内容不变：无 Skill 更新。
- 同一内容换 metadata.version：按实际内容变化展示，而非假定语义版本升级。
- 子目录从默认分支消失：`sourceMissing`，不自动卸载。
- 来源路径被迁移：建议用户重定位，经预览确认后更新来源关联。
- 没有可验证来源的外部／本地快照：`unsupported` 或手动比较，不能猜测对应 GitHub 仓库。

同源多个 Skill 共享一次 ref／tree 获取。尊重 GitHub 缓存和限流；检查后台任务可取消，UI 不因刷新本机列表丢失 update 状态。

## 6. 三方差异与更新决策

比较三个版本：安装基线 B、当前本地 L、远端候选 R。

| 条件 | 默认行为 |
|---|---|
| L = B，R = B | 已是最新 |
| L = B，R ≠ B | 可更新，展示远端差异 |
| L ≠ B，R = B | 只有本地修改，不显示可自动更新 |
| L ≠ B，R ≠ B | 本地与远端均变化，标冲突 |
| B 不可信／缺失 | 不允许自动覆盖；先恢复来源或导入新条目 |

首版不自动三方合并文件。冲突时提供跳过、导入为独立本地副本、备份后使用远端；每个选择明确显示受影响分配。后续若引入自动合并，另立需求及测试。

差异 UI 列出文件新增／修改／删除、执行位变化及 manifest 文本差异。执行前再次校验 L，避免用户预览期间手动编辑后被覆盖。

## 7. 批量更新

批量流程先检查或复用仍有效的检查结果，再生成冻结计划。按来源聚合 fetch，按 entry 独立提交；默认只勾选无本地修改、来源可信、事务可恢复的条目。

进度采用“已处理 / 总数 + 当前项”，结果逐项列出：更新成功、已最新、本地修改跳过、来源失败、目标失败、取消。仅失败项重试不会重复更新成功项。

用户取消后，尚未提交项 cancelled，提交中的项完成提交／恢复。不要为一次批量操作保留跨全部条目的长事务或承诺全部回滚。

## 8. 原文编辑

M4 首版编辑范围为受管条目的 `SKILL.md`；附件只读。新增／删除／重命名附件和工具执行不纳入首次编辑器，避免和文件管理、manifest name 同步改名混在一起。

编辑器输入包括 entryID、base revision、原始 bytes、编码／换行信息；返回草稿和 diagnostics。草稿原文是唯一可保存内容，解析视图不得反过来重排 YAML。

保存流程：

1. 保存前检查语法、必需字段与目录名约束。
2. 重新读取当前文件与 base hash；不同则显示外部修改冲突。
3. stage 完整内容目录，仅替换 manifest；重新计算 digest。
4. 通过统一事务发布，产生 local revision，保留远端基线 B。
5. 刷新本机详情与更新状态；标记本地修改，不清掉来源。

不允许改名表单只改 `name` 却不改父目录。首版将 manifest name 设为受约束字段，改名需另行设计完整目录与分配重定位事务。

raw round-trip 测试必须覆盖未知字段、注释、字段顺序、引号、Unicode、BOM、CRLF、多行字符串、嵌套 metadata 和 `---`/`...`。用户不改任何内容保存，文件应字节不变。

## 9. 离线、限流与错误

本机阅读、分配、暂停、编辑不依赖网络；远端操作分别报错。错误码建议至少包含：

`authorizationRequired、rateLimited、networkUnavailable、sourceMissing、ambiguousRef、scanIncomplete、invalidManifest、unsupportedLayout、contentChanged、localChanges、planOutdated`。

来源错误附可执行下一步；Retry-After 不到期不自动高频重试。历史下载缓存可用于查看，但旧缓存不能冒充“刚检查过的最新版本”。

## 10. 现有仓库入口整合

在原 RepoSkill 候选基础上增加结构化 `addToLibrary` 请求；网络下载与目录校验共享，目标管理分离。旧直接安装继续写现有 receipt，不偷偷变成指向私有库的新链接。

如果用户显式选择迁入库，应先验证旧 receipt 和完整内容，再导入副本并预览目标替换；该“接管旧安装”属于后续独立迁移任务，首版默认不执行。

App Store 保留原来的授权目录导出，不暴露 `addToLibrary` 或管理器服务。回归用例及文件落点见 [10](10-开发任务拆解与验收矩阵.md)。
