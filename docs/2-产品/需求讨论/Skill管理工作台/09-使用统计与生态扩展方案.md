# 使用统计与生态扩展方案

> 状态：M4/M5 详细方案，不属于 M0–M3 首版阻塞范围。工具行为以实施时官方版本与 fixture 为准。

## 1. 先建立 Agent 能力描述

现有工具目录 catalog 可作为发现种子，但“知道路径”不等于“支持该工具所有管理操作”。建议每个 `SkillAgentProfile` 描述：

| 字段 | 例子／含义 |
|---|---|
| identity | 稳定 agentID、显示名称、检测证据 |
| roots | 用户／共享／项目／插件根及优先级证据 |
| discoveryPolicy | 深度、点目录、symlink、嵌套目录规则 |
| assignmentModes | 已验证 symlink／copy／只读 |
| disableCapability | 无、仅暂停自有分配、官方逐 Skill 配置 |
| reloadBehavior | 自动发现、需要新会话、未知 |
| usageProvider | providerID、已验证日志版本、支持状态 |
| verification | 官方来源、测试日期、版本范围、已知限制 |

第一批重点验证 Codex、Claude Code 与共享根配置；其他工具可以先只读发现。不能因上游有 15 个 Agent 枚举、当前 Starcat catalog 列表更长，就宣传同等深度的管理支持。

## 2. 官方行为核查及当前限制

本轮读取 Agent Skills 官方仓库格式规范，并通过官方 Codex 源码及文档索引核对以下事实：

- Codex 来源并非一个硬编码目录；包含用户、项目、系统、插件及额外配置根。
- 当前官方源码用户根包含 `~/.agents/skills`，并保留被标为 deprecated 的 `$CODEX_HOME/skills`。
- 项目 `.agents/skills`、项目 `.codex/skills`、插件根等存在不同规则；不能把用户根映射直接用于项目。
- 官方存在逐 Skill `skills.config` 配置，选择器可按路径／名称；这不是所有 Agent 的通用设置。
- 发现有遍历限制和 scope-specific symlink 策略，不能无限递归或假设所有根一致。

固定来源及获取限制见 [官方生态证据](11-证据索引与核查记录.md#官方生态证据)。本轮未运行具体 Codex 版本验证，不把 main 行为自动当成本机已安装二进制的保证。

Claude Code 等工具的官方网页本轮未能直接取回完整内容；已知路径来自其生态及两个项目的源码映射，**逐工具的继承、重载、配置禁用行为仍需实施时官方核验**。未核验能力保持只读／unverified，不以补一个路径常量替代验证。

## 3. 使用统计的产品口径

功能名称建议“使用证据”，列表简写可用“检测次数”，避免承诺“真实调用总数”。区分：

| 证据 | 可否累计为使用证据 | 说明 |
|---|---|---|
| Agent 明确的 Skill 调用事件 | 是 | 最强事件证据，仍受日志覆盖影响 |
| 受信工具读取确切 SKILL.md | 是，标注 manifestRead | 证明读取，不证明成功执行全部流程 |
| 普通对话提到 Skill 名称 | 否 | 可能只是讨论或推荐 |
| 搜索命中／文件列表包含名称 | 否 | 不是实际读取或使用 |
| 按名称猜测同名条目 | 否 | 应归为未归属证据 |

显示每 Agent 的证据数、最后检测时间、覆盖状态和扫描时间。不做“最近 0 次就自动卸载”等自动决策。

默认关闭。首次启用先选择 Agent，并解释读取哪些本地历史位置、只保留哪些聚合信息。启用目录扫描不自动授权读取所有会话历史；不上传会话正文或使用结果。

## 4. Provider 与聚合契约

拟议 `SkillUsageProviding` 返回：

- providerID、schemaVersion、已读范围；
- 事件证据或增量聚合，包含稳定事件键、时间、候选 canonical path／来源；
- 完整／部分／陈旧／无来源／失败状态；
- 已读、缓存命中、保留旧值、跳过与失败的日志数量。

最强关联是日志中的明确物理路径，映射到 location／entry。只有 Skill name 时，若存在同名多个来源，保留 ambiguous，不平均分配也不随机归属。

稳定去重键优先 `provider + sessionID + toolCallID + eventKind + skillIdentity`；缺少事件 ID 时可使用日志身份、记录位置和内容摘要，但要标注其去重限制。日志轮转、重复输出、同一次调用多行结果不能重复累计。

缓存保存文件指纹、增量位置、聚合和必要的事件键，不保存对话文本。日志删除后，在完整枚举证明已删除时移除对应聚合；枚举失败则保留并标 stale。

### 4.1 状态表

| 状态 | 展示 |
|---|---|
| disabled | 未启用 |
| notScanned | 尚未扫描 |
| scanning | 扫描中；已有值可显示为上次结果 |
| complete | 显示证据与覆盖范围，0 只代表该范围未检测到 |
| partial | 显示结果及缺失数量 |
| stale | 保留旧值并明确不是本次新数据 |
| unavailable | 未发现历史来源 |
| failed | 有来源但无法读，不显示伪造的 0 |

### 4.2 实施顺序

先 Codex 单 provider，完成 schema fixture 与性能验证，再补 Claude Code；其他工具独立任务逐个加入。上游工厂已有 Codex、Claude Code、Copilot、CodeBuddy、Qoder、OpenCode、Pi 共 7 个，但不能未经适配直接复制。

JSONL 使用流式读取、后台解析和取消检查，单行超预算给诊断。增量缓存必须处理追加、截断、同路径替换和 schema 变化；schemaVersion 变化只重建统计缓存，不影响 Skill 库。

SQLite provider 优先使用受支持的只读访问或一致快照，不复制单个 `.db` 后漏掉 WAL，也不为支持一个工具直接实现通用 WAL 解析器。取不到可信快照时给 partial／unsupported，先收集真实版本证据。

## 5. 自定义 Agent 与自定义目录

分开两个入口：

1. **添加发现目录**：名称、路径、作用域、遍历策略；只读扫描，不声称属于某工具。
2. **配置 Agent 目标**：选择已验证 profile、目标根与分配模式；有能力证据才允许写入。

这能覆盖 Hermes 二级目录和非常规路径，也避免把任意目录自动变成可写安装目标。路径重复、父子重叠和 symlink 指向同处时，保留逻辑归属、去重物理扫描。

对用户自定义的通用工具，默认只读发现；明确显示“读取规则未验证”。允许用户管理目录不等于 Starcat 保证对应 Agent 会加载它。

## 6. 项目作用域后续阶段

借鉴 PR #59 的项目场景，采用用户显式添加项目根：

- 发现项目内的各工具 Skill 根，显示 Git 工作区与未跟踪／已修改文件影响。
- 生成逐 Skill、逐目标计划，不把整个 `.claude/skills` 等目录替换为链接。
- 先预览创建、保持、冲突、跳过；不改 AGENTS、CLAUDE、GEMINI 或 Cursor rules。
- 项目分支切换后重新对账，不把暂时消失当永久卸载。
- 项目移走／磁盘未挂载时标 unavailable，保留配置。
- 外部项目 Skill 仍只读；用户显式选择受管副本分配后才有 Starcat 所有权。

作用域影响 Agent 可见性，不能只在导航加一个“项目”标题。配置根与当前运行会话的 cwd 不同，界面只展示已知上下文，不宣称所有项目会话一定加载。

## 7. 市场 provider

M5 可加入 skills.sh、ClawHub 等来源浏览：

| 层 | 规则 |
|---|---|
| 搜索 | 独立超时、限流和缓存；失败不影响本机库 |
| 详情 | 标注提供者、作者、来源、可验证版本与许可 |
| 安装 | 解析到固定来源／包版本后进入统一 import 事务 |
| 解包 | 拒绝绝对路径、父目录逃逸、未支持链接与超限内容 |
| 更新 | 使用该 provider 的 revision/digest，不能当成 GitHub commit |
| 下架 | 标记来源不可用，不自动删除本机内容 |

上游 skills.sh 排行存在提取页面内数据的实现；这是脆弱性边界，应作为可失效 provider，不作为应用启动依赖。没有稳定下载 hash 时只记录本次内容指纹，不伪造上游签名或可信声明。

## 8. 官方逐工具禁用

如后续支持 Codex `skills.config`，必须：

- 核验目标版本的选择器、路径格式、配置层级与优先级；
- 保留配置注释和未知字段；不能重新序列化整份配置覆盖用户设置；
- 读当前有效状态，预览将改动的精确条目；
- 外部编辑导致 base hash 变化时重新规划；
- 区分配置禁用与移除链接，恢复只撤销自己创建的配置效果。

这是不同于 M2 暂停分配的新写入能力，不能在首版顺手增加。其测试需覆盖共享目录只禁用某 Agent、项目覆盖用户设置和多个规则冲突。

## 9. 未来不应自动扩大的范围

MCP 服务管理、规则同步、后台自动更新、CloudKit 安装同步、Skill 自动执行与排行榜推荐都不是当前方案必需项。若新增，应单独定义对象、权限和失败恢复，不塞进一个泛化的“AI 工具管理器”抽象。

扩展成功标准：新 provider 或 Agent 的失败不会使本机库不可用，能力声明有对应 fixture 和官方证据，移除扩展不丢用户受管内容。
