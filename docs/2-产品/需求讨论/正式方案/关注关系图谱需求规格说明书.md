## 视觉优化决议（2026-11-09）

- 方向使用屏幕固定长度 6pt 的开口箭头，放在线段可见部分约 70% 处；连接超过 12 条时仅主路径和悬停关系显示方向，避免头像边缘堆积箭头。邻接关系细化、降低透明度。
- 主路径为青绿色细线，少量亮点带渐隐拖尾沿真实关注方向移动，到达节点时短暂点亮轮廓；选择切换和取消时流光在 180ms 内淡换。减少动态效果保留静态线和方向，后台停止动画。
- 资料卡底部为两行：“路径 + 定位”和“加载状态 + 加载更多”。长路径换行，操作按钮不缩小。
- 刷新和停止共用首个按钮：加载时悬停或键盘聚焦显示红色停止，其余时间显示蓝色旋转刷新，加载中点击均停止。停止后立即恢复刷新；继续加载仍有独立入口，运行中禁用并保留占位，防止刷新按钮移动出鼠标位置。图标以 120ms 淡换。

## Followers 扩展决议（2026-11-08）

本节覆盖此前仅 following 的范围约定，已获实施授权；不改变既有全窗口、头像、右下资料卡和自动收起工具栏。

| 入口 | 真实边与路径方向 | 默认采集 | 手动展开 |
|---|---|---|---|
| 正在关注 | 本人 → 关注对象 → 对象关注的人 | 本人全部一级，每位一级首批 20 条 | 加载所选用户的 following |
| 关注者 | 关注者 → 本人；更深路径为所选用户 → … → 本人 | 仅完整分页本人首层，受配额与容量限制 | 资料卡加载所选用户的 followers，每次一页 |

- 不增加工具栏模式切换；每次从侧栏入口进入时重新初始化画布。
- Followers 点击节点只选中并展示卡片，不自动加载二层；缓存中更深层关系也默认收起。
- 图中的边始终表示真实关注方向，入场顺序与探索层级可以沿入边计算；选中路径流水沿真实边播放。
- 两方向分页、刷新和快照独立；共享头像缓存和公开资料缓存。
- 卡片关注 / 取消关注操作仍是本人出边。回关形成两条反向边，取消回关不移除关注者边；已确认操作同步至已有两方向快照。
- 设置页分别展示两方向的缓存统计，不提供图谱清理按钮。

验收补充：同一账户打开两个入口得到方向不同的关系；Followers 首层分页完成后不自动请求其他用户；手动展开路径正确连回本人；回关再取消不丢失粉丝；刷新删除仅影响被刷新的入边；切换方向不串页、不受迟到响应污染；重开、头像、动画与原 Following 行为无回归。

## 1. 产品目标

关注关系图谱将当前 GitHub 账户可访问的 following / followers 关系组织为可交互的 2D 工作区，帮助用户：

1. 了解自己关注了哪些人，以及这些人进一步关注谁
2. 发现通过多个关注对象连接到的开发者
3. 查看自己与某位用户之间在已加载数据内的关注路径
4. 沿感兴趣的用户继续探索关系网络

图谱呈现的是分批获取的本地关系快照。它不保证覆盖整个 GitHub 网络，不把关系接近程度解释为推荐评分，也不评价用户影响力。

## 2. 范围与边界

### 2.1 首版包含

权益边界：App Store / Direct 两渠道均免费开放，不要求 Pro 订阅。

| 编号 | 能力 | 交付要求 |
|---|---|---|
| FG-01 | 图谱工作区 | 复用左侧「正在关注」与「关注者」入口，按对应方向打开全窗口图谱 |
| FG-02 | 当前账户根节点 | 以当前登录用户为起点，不提供任意替换根节点 |
| FG-03 | 按方向加载 | Following 默认两层样本；Followers 默认仅本人首层 |
| FG-04 | 按需展开 | 手动加载任意已显示用户的关注关系 |
| FG-05 | 用户与关系去重 | 按 GitHub 用户 ID 合并节点，保留真实有向边 |
| FG-06 | 节点选中与详情 | 在右下角固定资料卡查看用户资料、贡献草坪、路径与操作 |
| FG-07 | 路径高亮 | Following 高亮本人到选中用户；Followers 高亮选中用户到本人的已加载最短有向路径 |
| FG-08 | 图谱交互 | 缩放、平移、拖动节点、重置视角 |
| FG-09 | 已加载用户查找 | 按用户名或显示名称定位当前图中的节点 |
| FG-10 | 请求控制 | 取消加载、限流等待、失败重试、预算控制 |
| FG-11 | 本地缓存 | 按账户恢复关系快照，支持离线查看与手动刷新 |
| FG-12 | 渠道与可访问性 | App Store / Direct 核心行为一致，支持键盘和文本查看 |
| FG-13 | 关注操作 | 卡片内关注 / 取消关注，成功后同步本人出边、路径与本地快照 |

### 2.2 首版不包含

- 替换根节点或查看任意用户的完整关注网络
- 自动无限递归抓取
- 粉丝关系全量反向采集
- AI 人脉分析、影响力评分、用户推荐
- 关注关系历史变化与时间回放
- 云端存储、CloudKit 同步或图谱分享
- 图片、视频或关系数据导出
- 与「为你推荐」、每日热点或推荐训练数据联动

即使图中存在多条进入某个节点的边，也只能说明当前图中已观察到这些关注关系，不能作为该用户的全局粉丝统计。

## 3. 核心概念

| 概念 | 定义 |
|---|---|
| 根节点 | 当前登录的 GitHub 用户 |
| 一级关系 | Following 为本人关注的用户；Followers 为关注本人的用户 |
| 二级关系 | 沿当前探索方向与一级用户相邻的用户 |
| 有向边 | `A → B` 表示 A 关注 B |
| 展开用户 | 按当前方向获取该用户 following 或 followers 分页 |
| 已加载图 | 当前已取得并纳入工作区的用户与关系 |
| 完整加载 | 某用户在当前方向的关系列表已读到末页；不代表整张图完整 |
| 本地快照 | 各用户关系在不同时间获取后组成的缓存 |
| 关系层级 | 从本人沿当前探索方向计算的最短距离，Followers 沿入边 |

同一个用户可以经多条路径出现，但只显示为一个节点。新增关系后，节点层级可能缩短。

## 4. 入口与工作区

### 4.1 入口

复用左侧面板现有两个统计入口：

- 入口名称保持「正在关注」和「关注者」，分别展示 following 和 followers
- 点击后不再打开对应的 GitHub 网页
- 弹出覆盖整个应用窗口的图谱遮盖层，覆盖原侧栏、列表与详情区域
- 图谱以当前登录用户为根节点

两个入口复用同一图谱工作区，由入口指定方向；不新增导航项或工具栏切换。

遮盖层铺满应用窗口，随窗口尺寸调整，不要求进入 macOS 系统全屏模式，也不打开独立窗口。底层页面不可见且不接收鼠标或键盘操作；关闭后恢复打开前的页面状态。

### 4.2 工作区组成

| 区域 | 内容 |
|---|---|
| 全窗口图谱画布 | 铺满遮盖层，展示头像节点、关系连线、选中状态与路径高亮 |
| 顶部悬浮工具栏 | 默认顶部居中短横线，悬停或点击展开查找、刷新、停止加载、重置视角、定位自己；不显示标题、状态行或数量 |
| 节点信息浮层 | 选中用户后在右下角固定展示紧凑资料卡，平移缩放不改变卡片位置 |
| 右上角关闭按钮 | 关闭遮盖层，恢复底层页面 |

不保留左侧导航或右侧详情面板，也不为工具栏、资料卡预留固定分栏。工具栏使用半透明系统材质；资料卡使用适配主题的实色底，保证图谱线不干扰文字和草坪。均叠加在画布上，不挤压画布尺寸；未选中节点时隐藏资料卡。

工具栏默认收起，短横线提供 96 × 28pt 感应区。鼠标移入或点击立即展开；鼠标离开工具栏及搜索结果区域 1.5 秒后收起。搜索框、操作按钮或结果持有键盘焦点，以及鼠标正在操作搜索结果时保持展开，选中结果后释放输入焦点；未选中的查找内容随工具栏收起保留，重新展开可继续查找。展开 / 收起使用约 200ms 淡入淡出和轻微位移，减少动态效果时仅淡换内容；变化只影响原生悬浮区域，不重建画布或改变镜头。刷新失败说明保留在刷新按钮的悬浮提示中，不恢复状态行。

窄窗口优先保留必要操作，通过紧凑布局与按需展开承载长路径及辅助信息，不通过缩小字体或恢复侧面板解决空间不足。悬浮控件与关闭按钮不能越出窗口或互相遮挡；点击、滚动悬浮区域不穿透到图谱画布。

关闭支持右上角关闭按钮和 Esc，按钮复用项目统一关闭样式。Esc 依次清除查找、取消节点选中、关闭图谱；点击画布空白处只取消选中，不关闭遮盖层。

### 4.3 首次进入

1. 展示根节点与轻量加载状态
2. 获取一级关系，按页逐步显示
3. Following 在预算内继续加载二层样本；Followers 在本人首层完成后停止自动加载
4. 获取一批数据就更新一批，不等待所有请求完成
5. 用户可在加载期间平移、选择节点或停止加载

只要已经获得有效结果，就保留可用画布，不持续显示全屏等待状态。

## 5. 关系加载规则

### 5.1 默认加载范围

Following 默认探索两层样本，不代表完整抓取所有两层关系；Followers 默认仅完整分页本人首层，更深层通过资料卡手动展开。以下二层调度规则仅适用于 Following。

- 一级关系按分页读取，受总体预算限制
- 二级关系对每个一级用户设置初始加载额度
- 请求调度避免某一个关注数量极大的用户占满预算
- 默认不自动展开二级用户的关注列表
- 用户手动展开后可以看到第三层及更深关系，但不触发进一步递归

初始每用户额度、并发数、节点上限、边数上限和请求预算在可行性验证后确定。首版将其作为内部策略，不新增复杂配置表单。

### 5.2 节点展开

单击节点选中并展示详情和路径。Following 对未加载节点继续使用点击首批加载；Followers 单击不触发采集，必须在资料卡点击「加载更多」。

| 节点状态 | 点击节点后的行为 | 详情操作 |
|---|---|---|
| 尚未加载 | Following 选中并加载首批；Followers 仅选中 | Followers 提供「加载更多」 |
| 正在加载 | 仅选中，不重复请求 | 可停止 |
| 部分加载 | 仅选中 | 「加载更多」 |
| 已完整加载 | 仅选中 | 不再提供「加载更多」 |
| 上次失败 | 选中并显示失败原因 | 「重试」 |
| 限流或预算耗尽 | 选中并说明原因 | 条件恢复后继续 |

拖动节点不能被误识别为点击，不触发加载。通过查找定位或键盘切换选中节点时，只定位和查看，不自动请求。

### 5.3 去重与环路

- 用户身份以稳定的 GitHub 用户 ID 识别，用户名变化不生成新节点
- 关系以「来源用户 ID + 目标用户 ID」唯一识别
- `A → B` 与 `B → A` 是两条不同关系
- 重复分页或重试不增加重复节点和边
- 保留真实的互相关注和环路
- 图遍历与路径计算必须能够处理环路

### 5.4 达到规模限制

达到任一预算后：

- 停止自动扩展
- 保留已加载内容和交互
- 显示「已达到本次加载上限，部分关系尚未加载」
- 对无法继续展开的节点解释原因
- 不把被截断的列表标记为完整

「继续加载」不能绕过硬性节点、边数或资源上限。

## 6. 图谱交互与视觉

### 6.1 基本操作

| 操作 | 行为 |
|---|---|
| 拖动画布空白区域 | 平移视野 |
| 滚轮或触控板缩放手势 | 缩放 |
| 平移操作 | 拖动画布空白区域移动视野 |
| 拖动节点 | 调整节点位置，不产生业务数据修改 |
| 点击节点 | 选中、展示路径，并按加载规则展开 |
| 点击空白处或关系线 | 取消当前选中与路径高亮；拖拽不触发取消 |
| 重置视角 | 回到能理解当前图的默认视角，不清除数据 |
| 回到本人 | 定位根节点，不重载网络数据 |
| 关闭按钮 / Esc | 按关闭层级退出遮盖层，恢复原页面 |

节点拖动后的固定或释放规则在样板中统一，不将布局拖动误解为编辑关注关系。

### 6.2 增量布局

- 打开时先显示与图谱主题一致的底色；主题及本人节点的首个真实绘制帧完成后，画布淡入 120ms。减少动态效果时直接显示，不露出 WebView 默认空白页面。

- 新节点加入时，已有节点位置尽量稳定
- 不因每批数据到达而重新打散整张图
- 用户正在拖拽或查看详情时，不强制移动视口
- 打开时以本人为中心确定一次初始镜头（默认缩放 0.8）；节点增加、布局结束和窗口尺寸变化不自动缩放或重新居中，仅主动重置视角才执行全图适配。查找定位、回到本人仍响应用户操作。
- 布局稳定后减少计算，避免持续无意义运动
- 本人头像先出现，一级、二级节点按层级逐个弹出；新头像从关联用户附近进入力布局，并以短暂缩放 / 淡入 / 轻回弹呈现。缓存恢复也使用相同展示队列，大图逐渐加速。
- 只将已出现的节点及双端均已出现的关系交给画布；查找定位可立即显示目标的完整已知路径。每批数据到达不重播旧头像，已有节点仍可操作。
- 加载过程及加载完成后均保持当前镜头，头像到达不改变视角。“减少动态效果”使用相同初始镜头并直接展示节点，后台暂停展示队列且不消耗等待时间。

### 6.3 视觉语义

- 节点默认使用圆形 GitHub 用户头像，而非纯色圆点；头像加载中或失败时回退为 identicon 或首字母占位，不阻塞关系展示
- 头像复用应用现有图片缓存，重建画布不清除头像；缓存命中直接显示，未命中下载成功后才从字母占位以 280ms 渐入，保留占位底图避免闪白；减少动态效果时直接替换。断网可继续使用仍有效的本地头像。
- 本人首帧先完成本地缓存探测，不等待网络；其他节点限量提前读取，尽量带头像弹出。缓存探测不被慢下载阻塞，不为全图一次性解码头像。
- 节点可复用同用户、同头像版本的卡片等常用较大尺寸缓存，缩绘为节点头像。卡片头像成功后通知对应节点重读缓存，不移动镜头或重新布局；快速切换用户、关闭重开后的旧回调不更新新画布。
- 图谱头像下载最多同时 8 张，选中节点排到队首，保持总上限；失败后再次点击节点可重试，不在绘制循环中自动无限重试。本地缓存探测队列独立，关系 API 请求并发保持原策略。
- 根节点始终容易辨认
- 所有节点按当前展示图中已加载的入边与出边总数调整大小，采用对数缩放并限制最大尺寸；不代表 GitHub 全网影响力。本人用青绿色轮廓与常驻用户名辨认，选中不改变节点几何尺寸。
- 选中节点的全部已加载入边、出边适度强调，相邻头像保持清晰，其余关系弱化；完整有向路径用青绿色细线和流光区别于普通邻接边，方向标记遵循上述密集关系规则
- 其他节点与边适度弱化，但保留明暗主题下的可辨识度
- 默认仅显示根节点、选中节点及必要的悬停标签，避免大量文字叠加
- 当前路径必须能辨认方向；全部关系不要求同时显示密集箭头
- 装饰性发光不是必需能力，不影响性能与可读性目标
- 缩放较远时允许将头像降级为圆点以保证性能，放大后恢复头像；降级只改变呈现，不移除节点、关系或可选中能力

叠加在图谱上的悬浮工具栏、选中信息栏和状态反馈沿用 `DESIGN.md` 与项目 UI 规范的原生工具风格，适配明暗主题。

## 7. 用户详情与查找

### 7.1 用户详情

选中节点后在窗口右下角固定展示紧凑原生资料卡，建议宽度 370pt，右侧和底部间距 20pt，不占用固定侧栏。复用详情页 OwnerCardView 的资料内容与服务，将头像缩为 56pt；卡片不随节点移动或因节点移出视野而隐藏。内容包括：

- 头像、显示名称、GitHub 用户名、简介和公开社交链接
- 关注者 / 正在关注数，以及可用的近一年贡献草坪
- 当前图中的关系层级
- 从本人到该用户的已知路径
- 该用户关注列表已加载数量
- 部分加载、完整加载、失败或不可用状态
- 关系采集时间
- 「加载更多 / 重试」「定位节点」「在 GitHub 打开」操作

资料缺失时先展示图谱中的身份信息，再按需补全资料；不为全图预取草坪，组织或不可用时不预留草坪空白。小窗口限制卡片高度并允许内部滚动，长路径换行且可复制。快速切换用户必须取消旧加载，避免串资料。

卡片出现 / 关闭使用约 160–220ms 的轻微位移与淡入淡出，切换节点只淡换内部内容；减少动态效果时仅淡入淡出。点击空白、关闭按钮或 Esc 取消选中后收起卡片。用户详情不展示凭据、内部分页游标或原始调试数据。

关注操作复用现有用户 OAuth 与 OwnerFollowService，不引入新授权流程。本人不显示关注按钮；其他用户显示“关注 / 已关注”，已关注时悬停提示取消关注。状态未知时与写请求期间锁定按钮，失败在卡片内提示并允许重试，不改变已知关系。查询失败只重查状态，写入失败才重试原操作。快速切换节点不能重复提交同一用户的写请求，迟到的状态查询不能回滚成功写入。

仅在 GitHub 确认成功后添加或移除 `本人 → 该用户` 的真实边，重新计算路径、流水高亮与计数，并保存本账户快照。取消关注后保留仍通过其他用户可达的节点；仍被选中且可达时保留完整路径展示，不能因二层样本限制而突然丢失。失去根路径的节点与分量移出图谱。操作前已开始的分页 / 刷新不得覆盖刚确认的变更，操作后重新发起的刷新以 GitHub 最新响应为准。关闭卡片不撤销正在提交的操作；切换账户后不得写入新账户的图谱状态。

### 7.2 已加载用户查找

- 只搜索当前图中已经加载的用户
- 支持用户名和显示名称，不区分大小写
- 结果选中后定位节点并显示详情
- 无结果时提示「在已加载用户中未找到」
- 不暗示已搜索整个 GitHub，也不自动发起全站搜索

查找结果列表同时提供键盘访问图中用户的途径。

## 8. 路径高亮

### 8.1 计算规则

在当前已加载图中按真实关注方向计算路径：Following 从本人到选中节点；Followers 从选中节点到本人。

示例：`我 → Alice → Bob → Carol` 只表示已取得的关系支持这条路径，不表示它是 GitHub 全网最短路径。

### 8.2 多路径与更新

- 存在多条等长路径时，使用稳定规则选择一条
- 图数据不变时，重复选中得到相同结果
- 后续加载发现更短路径时可以更新，并同步详情文字
- 首版不枚举全部路径
- 无有效路径时显示「当前已加载关系中没有可达路径」

路径既要在画布高亮，也要提供可阅读的文本形式，不能仅靠颜色表达。

完整路径的每一跳必须连接回本人；沿 source → target 方向显示连续流光拖尾，其他邻接线保持次级强调。取消选中后短暂淡出，后台或关闭时停止流水；“减少动态效果”保留静态完整路径。

## 9. 页面状态与失败恢复

| 状态 | 用户可见行为 |
|---|---|
| 未登录或授权失效 | 提示登录或恢复授权 |
| 首次加载 | 先显示根节点和分阶段进度 |
| 正常加载 | 保持画布可操作，显示已加载数量 |
| 部分失败 | 保留成功结果，在相关用户处标记失败 |
| 请求限流 | 暂停请求，说明等待原因；有明确恢复时间时展示 |
| 用户停止 | 保留结果，明确加载已停止 |
| 预算耗尽 | 标记部分加载，停止自动扩展 |
| 离线且有缓存 | 显示缓存图谱、采集时间与离线提示 |
| 离线且无缓存 | 显示恢复操作，不构造虚假关系 |
| 用户不可访问 | 保留必要节点身份，标记资料或关系不可用 |
| 渲染失败 | 提供重新加载图谱视图的操作，不要求删除业务数据 |

只有成功确认某个关注列表为空时，才能显示「暂无关注关系」。鉴权失败、超时、限流和数据不可访问不能被解释为空列表。

## 10. 缓存、刷新与账户隔离

### 10.1 缓存内容

按账户隔离缓存：

- 用户基础资料
- 有向关系
- 各用户的分页进度与完整性状态
- 各批关系的采集时间
- 必要的快照版本信息

同一会话内离开页面再返回，应保留视角、选择与展开进度。跨应用重启至少恢复关系快照；持久化精确 2D 布局不作为首版必需项。

缓存有效期在验证后确定。超过有效期的数据仍可用于展示，但必须标记为旧快照，不能伪装成刚刚获取的数据。

### 10.2 刷新语义

顶部刷新只更新当前已探索范围，不自动扩大探索深度。

- 新会话从缓存恢复展示时，保留本人已加载的全部一级关注，每位一级用户默认最多选取 20 个二层对象；先按稳定 ID 取样，再保留可见节点之间的全部已知边。默认展示软上限 5,000，显式展开仍受 10,000 节点硬上限约束。
- 磁盘缓存与画布展示范围分离；大缓存不再全部塞进画布，读取时不删除已获取的关系。顶部不展示计数，设置页统计仍表示整个账户缓存。
- 「加载更多」优先逐批展示缓存中的关系，缓存不足时才发起单页请求。每次重开清除显式展开范围，按当前方向恢复默认展示；关系缓存保留。
- 刷新不追到每个用户的关注列表末页：本人按当前已展示数量刷新，一级用户默认最多刷新 20 条，显式展开后按其展示预算刷新。只有真正到达末页才能替换旧边；样本刷新保持部分加载语义。

- 刷新期间保留旧图，成功数据逐步替换
- 单用户在当前方向的分页完整读取成功后，才能删除对应旧边：Following 替换出边，Followers 替换入边
- 部分分页成功、失败或中止，不删除尚未重新确认的旧关系
- 成功完成替换后，移除当前快照中已不可达的孤立显示内容
- 如果选中用户因刷新被移除，关闭其详情并提供简短说明

不同用户的关系采集时间可能不同，页面应说明这是分批快照，不能用一个「更新时间」暗示全部关系同时更新。

### 10.3 生命周期

- 关闭遮盖层时停止新请求调度，取消不再需要的在途工作，暂停图谱渲染与布局计算
- 关闭后恢复底层页面与输入焦点；重新打开后展示已保存结果及同一会话的视角、选择，由用户继续未完成的加载
- 切换账户时取消旧账户任务，清除旧账户画面
- 旧请求迟到的结果不能写入新账户状态
- 登出后的缓存处理沿用项目账户数据策略，但不得展示给其他账户

### 10.4 设置页缓存统计

首版在设置页展示图谱缓存统计，不提供图谱缓存清理入口。统计展示当前账户的快照占用空间、节点数、关系数与快照保存时间；无缓存时明确显示无缓存。快照保存时间不代表所有关系同时更新。

## 11. 数据与隐私约束

- 只获取当前凭据可以访问的 GitHub 关系
- 不绕过访问限制，不依据不可见结果推断真实关系
- GitHub 凭据保留在原生侧，不传入 WebView
- WebView 仅接收展示所需的数据与受控操作结果
- 不向 Starcat 服务端上传关注图谱
- 不将关系用于推荐训练或自动开启数据贡献
- 日志不记录 Token，不批量打印完整关注网络
- 不在后台常驻采集；关系更新由工作区使用与明确操作触发

## 12. 技术实现约束

本节规定实现边界，不锁定具体代码结构。

| 层级 | 职责 |
|---|---|
| 原生界面 | 全窗口遮盖层、悬浮工具栏与信息栏、关闭与输入隔离、状态提示、账户生命周期 |
| 原生数据层 | GitHub 请求、分页、限流、缓存、取消与去重 |
| 图数据处理 | 图合并、层级、路径计算与增量更新 |
| WebView | 2D Canvas 渲染、节点拾取、平移缩放和图形交互 |
| 原生与页面通信 | 受控消息、数据批次、会话身份与错误恢复 |

补充约束：

- 图谱脚本、字体及其他必需渲染资源随 App 离线打包，不依赖运行时 CDN
- GitHub API 选择、权限与分页契约在技术设计阶段核验
- 页面不能通过任意消息调用原生网络或打开任意协议
- 原生侧校验消息类型、用户 ID、会话身份与参数范围
- 重建 WebView 后能够重新注入已有快照，避免重新采集关系
- 第三方库锁定版本并登记开源致谢
- 如果新增持久化表，遵循已发布数据库的追加迁移规则

2D MVP 使用锁定版本的 `force-graph 1.52.0` 与 `d3-force-3d 3.0.6` 离线资源，后者仅运行二维力计算与碰撞检测；移除 Three.js 与 3D 渲染资源，同步登记开源致谢。不把历史节点数量估算当作固定性能事实。

## 13. 性能与可访问性

### 13.1 性能原则

- 网络、图合并和路径计算不能长时间阻塞主界面
- 渲染资源随视图生命周期释放
- 窗口隐藏或页面不可见时暂停持续渲染和布局计算
- 重复进入页面不得持续累积 WebView、任务或图数据
- 加载量上升时允许减少标签、头像和装饰效果，但不能静默丢弃关系而仍显示完整状态

### 13.2 验证规模

| 场景 | 验证重点 |
|---|---|
| 小图 | 完整交互、视觉与路径正确性 |
| 500 个一级关注用户 | 二级调度公平性、分页与请求预算 |
| 约 5,000 个节点 | 增量布局、选中、路径、内存与响应 |
| 约 10,000 个节点 | 平移缩放、点选、路径高亮和必要降级 |
| 高密度关系 | 边数增加时的渲染、路径计算及预算保护 |

测试记录节点数、边数、硬件、系统、缓存状态与网络条件。「完整两层在 10 秒内加载」不作为硬性验收要求；技术样板完成后再确定首个可交互画面、操作延迟、帧率与内存门槛。

500 个一级关注用户的真实测试账号使用 dong4j 当前登录账户，测试时记录实际 following 数量，不另行索要测试账号；大图压力场景另用合成数据补充。

### 13.3 可访问性与国际化

- 新文案覆盖当前全部 17 种界面语言
- 支持长用户名、长译文、明暗主题与大字号
- 工具栏、查找结果、用户详情和路径可通过键盘操作
- 关键控件提供可访问性标签
- 提供文本关系与路径信息，避免 2D 画布成为唯一使用方式
- 遵循减少动态效果偏好，关闭非必要视口动画和持续运动
