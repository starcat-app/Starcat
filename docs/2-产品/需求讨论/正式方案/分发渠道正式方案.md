> 创建：2026-07-04
> 状态：方案已确认，分阶段实施
> 用途：Starcat App Store / Direct 双构建渠道、Sparkle 自动更新和双打包流程正式方案
> 需求入口：`docs/2-产品/需求讨论/分发渠道.md`

## 1. 方案结论

Starcat 必须构建出两个审核边界清晰的产物：

```text
Starcat App Store
  -> Mac App Store archive
  -> StoreKit
  -> App Store updates

Starcat Direct
  -> Developer ID app
  -> notarized DMG
  -> Sparkle appcast updates
  -> Direct payment / license
```

Sparkle 只进入 Direct build。App Store build 不是“禁用 Sparkle”，而是完全不链接、不打包、不配置、不展示。

---

## 2. 构建渠道

建议新增显式渠道：

```swift
enum DistributionChannel {
    case appStore
    case direct
}
```

渠道来源：

| Build | 配置 |
|-------|------|
| App Store | `STARCAT_DISTRIBUTION=appstore` |
| Direct | `STARCAT_DISTRIBUTION=direct` |

渠道只能来自 build setting / Info.plist 注入，不允许运行时猜测。

---

## 3. Target / Scheme 策略

推荐拆 target / scheme：

```text
Starcat              # App Store / 默认 target
StarcatDirect        # Direct target
StarcatTests         # 单测 target
```

拆分理由：

1. App Store archive 天然不包含 Sparkle。
2. Direct target 可独立配置 entitlements、Info.plist、Sparkle package。
3. Direct 支付入口可以和 Sparkle 共用同一个渠道边界。
4. 打包脚本更容易做产物自检。

---

## 4. Sparkle 策略

Direct build 集成 Sparkle 2：

| 项 | 值 |
|----|----|
| appcast | `https://starcat.ink/appcast.xml` |
| 更新包 | notarized DMG |
| 签名 | Sparkle EdDSA |
| UI | 首期使用 Sparkle 标准 UI |
| 入口 | App 菜单 `Check for Updates...` |

App Store build 必须满足：

1. `otool -L` 无 Sparkle。
2. app bundle 内无 Sparkle framework / helper。
3. `Info.plist` 无 `SUFeedURL` / `SUPublicEDKey` / `SUEnableInstallerLauncherService`。
4. 字符串中无 `appcast` / `Check for Updates` / `Sparkle`。

## 5. 打包脚本

### 5.1 App Store

目标：

```bash
./scripts/package-appstore.sh
```

输出：

```text
dist/appstore/
  Starcat.xcarchive
  export/
  package-report.md
```

脚本必须执行 App Store 自检，确认无 Direct / Sparkle 污染。

### 5.2 Direct

目标：

```bash
./scripts/package-direct.sh
```

输出：

```text
dist/direct/
  Starcat-<version>.app
  Starcat-<version>.dmg
  appcast.xml
  package-report.md
```

脚本必须执行 Direct 自检，确认 Sparkle 配置齐全、DMG 已 notarize、appcast 可生成。
