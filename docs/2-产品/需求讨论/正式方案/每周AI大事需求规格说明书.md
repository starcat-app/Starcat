# Starcat 每周 AI 大事需求规格说明书

> 状态：核心范围已确认，待内容样板与技术方案验证，尚未实施  
> 版本：v0.1  
> 日期：2026-11-04  
> 所属版本：Starcat 2.0.0  
> 优先级：P2，作为每日热点收口后的并行开发项，不阻塞 2.0.0 正式发布  
> 关联规划：[2.0.0 版本规划 §8.4](../v2.0.0-版本规划.md)

## 1. 产品目标

将运营提供的每周 AI 事件清单整理为经过来源核实、包含原文配图的中英文周报，让用户在 Starcat「每日热点」中阅读本期内容、查看出处和相关项目，并回看往期报告。

标题级事件清单是选题输入，不是已核实的事实。Skill 负责查找来源、整理文字和图片，运营负责审阅与确认发布。

本说明书是「每周 AI 大事」的独立需求依据；实现方式在后续技术方案中确定，不将方案讨论视为代码实施或生产发布授权。

## 3. 首版范围

### 3.1 功能清单

| 编号 | 能力 | 交付要求 |
|---|---|---|
| WE-01 | Skill 录入 | 接收期次信息、事件清单及可选视频或文章链接 |
| WE-02 | 来源核实 | 逐条核实事件主体、日期、实际发布状态与来源 |
| WE-03 | 原文配图 | 获取对应来源文章中的相关图片，保留出处与归属 |
| WE-04 | 双语编排 | 生成事件一致、来源一致的中文与英文 Markdown |
| WE-05 | 人工审核 | 提供完整草稿、配图预览、来源清单与未解决问题 |
| WE-06 | 内容留档 | 将确认后的稿件及来源、图片记录保存在指定内容仓库 |
| WE-07 | 发布与修订 | 复用日报内容分发能力，支持幂等发布和同一期修订 |
| WE-08 | 周报子分类 | 展示本期、往期和真实业务日期，周期为周报 |
| WE-09 | 阅读与项目 | 复用现有阅读页、来源链接、相关 GitHub 项目和返回行为 |

### 3.2 首版不包含

- 自动订阅或批量下载视频、语音转写、自动从视频提取全部选题
- 独立后台编辑器、完整 CMS 或多人在线协同编辑
- 无人工确认的定时自动发布
- 正文生图、用无关图库图片凑数，或以程序化封面代替正文配图
- 基于用户 Stars 的个性化周报
- 与「为你推荐」或关注关系图谱交换数据
- 新建周报对话、全文搜索或通知系统

## 4. 运营流程

### 4.1 录入

运营调用 Skill，提供一期事件清单。首版支持直接粘贴文本，不要求先制作 JSON 或表格。

| 输入 | 要求 |
|---|---|
| 期次或业务日期 | 用于区分本期与历史期次；缺失时在生成前补齐，不静默使用执行当天 |
| 事件清单 | 每条至少有标题；可附一句补充说明 |
| 原始选题来源 | 可提供视频链接、文章链接、栏目与期次说明 |
| 已知资料 | 可附官方公告、论文、仓库或配图来源链接 |
| 编辑备注 | 可说明删选、重点事件、需要更正的名称等 |

视频栏目提供选题线索，报告正文必须经过独立核实。事件数量按实际输入与核实结果确定，不固定为 12 条，也不为凑数量增加事件。

### 4.2 核实与整理

1. 拆分事件，合并指向同一发布或进展的重复选题
2. 为每条事件查找一手来源，核对产品、机构、模型或项目名称
3. 区分正式发布、预览、论文结果、传闻与评论，不把“宣布”写成“已经可用”
4. 核实事件发生时间；历史事件的本周更新应说明新增进展
5. 从对应来源文章获取相关图片，并整理图注和出处
6. 生成中文稿与英文稿，检查事件顺序、数字、链接和图片一致性
7. 展示完整草稿与问题清单，进入人工审核

未找到可靠来源的事件进入待核实清单，不以确定事实写入正文。人工可要求继续查证、移除事件，或明确以未核实状态保留；不得自动掩盖证据缺失。

### 4.3 审核与发布

Skill 在发布前展示：

- 中文全文、英文全文及各自预览
- 本期日期、标题、摘要、事件数量与选题来源
- 每条事件的证据链接、实际选用图片及图注
- 缺图、来源不明、翻译存疑或被剔除的事件
- 本次属于新一期还是已有期次的修订

运营确认后，才进入内容提交和发布步骤。确认绑定本次稿件与图片版本；确认后发生正文、事实或配图变更，需要重新展示变化并确认。

Skill 默认生成和校验草稿，不能仅因接收到事件清单就上传、推送或发布。生成草稿与发布是两个可单独执行的阶段，允许先修改稿件再继续。

## 5. 内容质量与报告结构

### 5.1 单条事件

每条事件应包括：

- 清晰、准确的标题
- 简短介绍：发生了什么、关键变化是什么、为何值得关注
- 对应文章来源中的相关图片及图注
- 可打开的来源链接
- 有实际关联时提供 GitHub 仓库链接，不强行附加项目

篇幅按事件复杂度调整，不机械复制宣传语或来源文章全文。模型生成内容不得凭空补充性能数字、价格、版本、发布日期或可用范围。

### 5.2 整期结构

推荐结构如下，样板阶段可调整排版，但必须保留来源与图片归属：

```markdown
# 每周 AI 大事 · <本期日期>

<本期摘要>

> 根据本期事件清单整理，AI 辅助核实与编写，经人工审核

## 1. <事件标题>

<事件介绍>

![<图片替代文本>](<已验证的图片地址>)

<图注及图片来源>

来源：<文章链接>
相关项目：<确有对应仓库时提供链接>

## 2. <事件标题>

...

## 本期选题来源

<原始视频或选题资料链接>
```

“经人工审核”仅用于已完成审核的发布稿，草稿不得提前标记。样板不把未经核实的输入标题当作已发生的真实新闻。

## 6. 正文配图

### 6.1 选图要求

封面与正文配图是两项独立要求：

- 封面可以继续使用本地程序化绘制
- 正文图片从对应文章来源网站获取，优先选用能解释事件的产品截图、原图、效果示例或图表
- 不使用网站广告、推荐阅读缩略图或不相关装饰图
- 不用 AI 生成图、任意图库图或封面替代来源图片
- 不擅自修改图表数据、移除署名、水印或误导性裁切

同一图片可在中英文稿中复用；图中文字不自动重绘或替换，必要说明通过对应语言图注表达。

### 6.2 来源与资产记录

每张选用图片保留：

| 字段 | 用途 |
|---|---|
| 关联事件 | 说明图片服务于哪条新闻 |
| 文章来源 URL | 允许编辑与读者回查上下文 |
| 原图 URL | 保留原始获取位置，包括来源站实际使用的 CDN |
| 归属与使用说明 | 记录原文提供的作者、机构、署名与使用条件 |
| 中英文图注与替代文本 | 保证双语阅读与无障碍表达一致 |
| 文件类型、尺寸与内容标识 | 验证图片有效，支持去重及不可变引用 |
| 分发地址 | 发布稿实际引用的图片地址 |

按既有规划将图片保存到受控存储，经不可变 CDN 地址引用，避免报告长期依赖来源站的临时链接。具体存储服务、上传方式与压缩预算在技术方案中确定；不预设当前没有可用存储设施。

### 6.3 缺图与失败

- 原文无合适图片、下载失败或用途不明确时，记录具体问题，进入人工处理
- 可继续查找该事件的其他可靠原始报道，不能从无关文章取图
- 不自动把报告降级为无配图版本，不通过生成图片消除缺图状态
- 上传后须验证实际地址可读取且返回有效图片，失败时不能标记发布就绪
- 修订图片使用新的不可变地址，不覆盖旧稿引用的资产
- 失败重试复用已成功取得的图片，不无条件重抓或重复上传全部资产

## 7. 中文与英文双版

- 中英双版均为首版必交付内容，不能以单语言发布作为默认成功状态
- 两版对应同一期、同一组已确认事件和图片，事实、数字、顺序与引用保持一致
- 产品名、模型名、仓库名保留官方写法；翻译不得创造新事实或强化原文结论
- 两版分别编写标题、摘要、正文、图注与替代文本
- 任一语言尚未完成或校验失败时，不进入本期正式发布确认
- 服务端部分发布失败时必须明确标记部分成功，不能把单语言成功宣称为整期完成

两版发布如何保证成套可见、失败后如何补齐，在技术方案中根据现有导入队列能力确定。不能仅凭一次请求包含两份稿件就宣称具备原子发布。

## 8. 内容仓库、期次与修订

### 8.1 仓库职责

`starcat-app/ai-weekly-events` 是独立内容仓库，用于保存：

- 已确认的中文与英文 Markdown
- 本期来源、事件核实与配图记录
- 图片资产清单与分发引用
- 发布所需的期次和版本元数据
- 内容贡献、编辑与发布说明

仓库可见性、目录结构和图片原件存放位置在技术方案中落实，不将大型图片默认全部写入 Git。模型凭据、上传凭据和服务端管理 Key 不进入稿件、资产记录或仓库。

### 8.2 期次身份

- 同一期中英文是语言变体，不算两期报告
- 周报周期与日报分开，使用明确业务日期，不随补发或任务重跑改变
- 同一期修改标题、文字、翻译或图片，产生新修订，不新增重复期次
- 已发布版本保留来源与固定内容提交，支持追查当时稿件
- 不覆盖正在阅读的固定修订，不因内容仓库文件删除而自动删除已发布历史

既有 `ai-weekly` 为历史归档，不应被悄悄改成新栏目。新分类技术 ID、来源标识和报告 ID 在技术方案中明确，不能让独立内容仓库在归因上被错误标成上游 agents-radar 稿件。

## 9. 发布与恢复要求

复用每日热点的管理导入、项目核验、持久队列、目录版本与不可变修订能力；新增适配仅服务于本栏目，不改变已正常运行的日报调度与来源模式。

- 草稿与发布稿分离；未确认内容不进入公开目录
- 发布依据是明确的内容版本，不从运行中的工作目录随意读取未确认修改
- 重复提交同一版本不得生成重复报告或重复修订
- 修改内容后使用新的修订身份；旧请求迟到不能覆盖新版本
- 提交超时、图片上传失败、导入部分失败时，保留已成功成果并提供可继续操作的状态
- 发布成功必须回读中英文报告、图片与分类目录，确认真实可读
- 周报发布不自动写入用户 Stars、知识库、周刊仓库来源或推荐训练数据

首版由运营按期触发，不新增固定每周定时器。视频更新延迟时允许延后发布，不发布空稿或把旧内容标成当期。

## 10. 客户端需求

### 10.1 入口与列表

- 「每日热点」新增「每周 AI 大事」子分类，沿用现有分类偏好与显示方式
- 分类按周报周期读取，进入时展示该栏目的最新可用期次
- 日期选择与往期列表使用本栏目真实存在的期次，不套用全站最新日报日期
- 保留当前总分类的周期规则，不为本项擅自将全部日报和周报混排
- 封面复用本地绘制能力，卡片展示标题、摘要、真实日期和阅读信息
- 无内容、请求失败、加载中与已有缓存分别呈现，不伪造样稿

### 10.2 阅读

- 复用每日热点阅读页，图片随正文排列，不新增独立阅读窗口
- 图片保持比例并适配可用宽度，不遮挡正文或撑出横向滚动
- 展示原文出处及图片归属，链接沿用安全打开规则
- 相关项目复用现有 GitHub 链接核验、项目卡片与详情返回逻辑
- 文章与项目往返、分类切换、期次切换沿用已有状态隔离要求
- 正文缓存沿用现有能力；正文图片离线缓存不预先宣称已支持。图片不可用时保留图注、替代文本和正文阅读，不出现空白覆盖层

### 10.3 语言与渠道

报告提供中英双版；UI 新增文案覆盖当前全部支持语言，不能把双语正文等同于全语言界面。

沿用每日热点现有渠道与权益边界，不借用仅 Direct 的「每日热点对话」限制，也不在本项新增付费门槛。长标题、长译文、大字号及明暗主题需要随功能验证。

## 11. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| WE-A01 | 文本录入 | 可从一期粘贴事件清单生成草稿，不要求先手工整理结构化文件 |
| WE-A02 | 重复或错误标题 | 重复事件合并；名称和事实以核实来源为准，保留处理说明 |
| WE-A03 | 来源不足 | 事件进入待核实清单，不编造发布状态、日期或数据 |
| WE-A04 | 选图 | 使用对应文章来源中的相关图片，原文和原图出处可回查 |
| WE-A05 | 图片缺失 | 明确待补图，不能用生成图替代或自动交付无图报告 |
| WE-A06 | 双语 | 两版事件、事实、链接与图片一致，图注和替代文本对应语言完整 |
| WE-A07 | 审核 | 未确认不能发布；确认后修改内容会重新进入审核 |
| WE-A08 | 发布重试 | 同版本重试不重复入库，部分失败可定位和恢复 |
| WE-A09 | 双语发布失败 | 只成功一版时报告部分失败，不宣称整期发布完成 |
| WE-A10 | 修订 | 同一期更正生成新修订，旧请求不覆盖新版，旧阅读会话不被替换 |
| WE-A11 | 分类与期次 | 周报最新期次、日期索引、历史列表正确，不与日报周期混计 |
| WE-A12 | 阅读图片 | 图文比例与布局正常，失效图片不阻断正文阅读 |
| WE-A13 | 项目往返 | 项目核验与返回位置正确，分类切换不残留上一文章详情 |
| WE-A14 | 归因 | 能区分选题来源、文章来源、图片来源与内容发布仓库 |
| WE-A15 | 用户数据 | 阅读和发布不自动修改 Stars、知识库或推荐数据 |
| WE-A16 | 客户端交付 | 对应测试、双渠道构建、UI 文案覆盖通过；视觉验收单独记录 |

内容样板至少覆盖：有可靠来源与图片的事件、重复事件、无法核实的事件、来源文章无合适图片的事件。异常样本只用于验证编辑流程，不要求全部混入公开首期。

## 12. 实施准备与交付顺序

| 阶段 | 产物 | 完成标准 |
|---|---|---|
| 内容样板 | 一期中英文 Markdown、真实来源图片预览与核实清单 | 内容与排版获确认，未解决问题明确 |
| 技术方案 | 仓库结构、来源身份、分类契约、图床复用、双语发布与修订机制 | 明确改动范围与失败恢复，不放宽既有来源校验 |
| Skill 与内容流程 | 输入、核实、抓图、预览、确认及发布步骤 | 草稿生成与发布可分开执行，离线校验与失败分支有测试 |
| 服务端与客户端接入 | 分类、来源适配、双语阅读与项目复用 | 契约测试和客户端验证通过，不影响日报更新 |
| 首期发布验收 | 固定版本内容与发布结果 | 按授权执行，回读双语、图片、目录与历史 |

下一阶段需落实的技术事项是存储上传复用、来源标识与校验、稳定期次序列、双语发布一致性、图片预算及缓存策略。正式名称、内容仓库选择、Skill 优先、中英双版与原文配图要求均已确定，不再作为待确认选项。

本轮交付为需求说明书，不包含创建远端仓库、代码修改、安装 Skill、抓取真实新闻、上传图片、生产部署或报告发布。
