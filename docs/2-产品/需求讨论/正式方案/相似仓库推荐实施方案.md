# 相似仓库推荐实施方案

> 状态: 已确认, 进入实现
> 日期: 2026-06-28
> 范围: starcat-recommend-api 后端 + Starcat macOS 客户端详情页推荐入口

## 1. 目标

在 Starcat 仓库详情页提供相似仓库推荐能力。第一版不自研推荐算法, 通过新增 `starcat-recommend-api` 中转 SimRepo 的非官方 Qdrant Recommend API; Starcat 客户端只对接 Starcat 自己的稳定推荐接口, 为后续替换成自研内容向量 / 行为混合推荐保留边界。

## 2. 核心决策

1. **客户端不直连 SimRepo**: SimRepo endpoint、api-key、Qdrant payload 结构都留在后端, 避免客户端泄露 key 或被上游字段变化绑死。
2. **新增独立后端 `supports/starcat-recommend-api`**: 按现有 `weekly/trending/sharing/wiki` 四个 API 的规范和结构实现, 包含必要开源文件、Docker/Makefile/deploy docs、`/healthz`、`/api/v1/ping`、Bearer API key 授权和统一 envelope。
3. **首版只实现 SimRepoProvider**: 不接 Meilisearch, 不搭 Starcat 自研 Qdrant, 不做用户行为训练, 不做个性化推荐。
4. **推荐 DTO endpoint-specific**: 客户端新增 `RecommendAPI` / `RecommendModels`, 不扩写 `StarcatRepoCardDTO`。
5. **UI 只在有数据时显示入口**: 详情页右下角浮动推荐按钮仅在推荐结果非空时出现, 避免空能力占位。
6. **本地已 star 直接打开详情, 未 star 打开 GitHub**: 点击推荐卡片后先查本地 starred repo, 命中则切换右侧详情; 未命中则用系统浏览器打开 GitHub 页面。

## 3. 后端规范

### 3.1 目录结构

`starcat-recommend-api` 必须与现有 4 个 API 对齐:

```text
supports/starcat-recommend-api/
  .dockerignore
  .env.example
  .gitattributes
  .github/
    FUNDING.yml
    PULL_REQUEST_TEMPLATE.md
    dependabot.yml
    workflows/
      docker.yml
      fly-deploy.yml
      go.yml
      release.yml
  .gitignore
  CHANGELOG.md
  CONTRIBUTING.md
  Dockerfile
  Makefile
  README.md
  TODO.md
  docs/
    custom-domain.md
    DEPLOY_FLY.md
    DEPLOY_RENDER.md
    deploy-env.md
  fly.toml
  go.mod
  go.sum
  scripts/deploy.sh
  cmd/server/main.go
  internal/handler/
  internal/middleware/
  internal/model/
  internal/provider/
  internal/version/
```

首版没有数据库, 所以不创建 `internal/store`。缓存先用进程内 TTL cache, 后续需要跨实例缓存时再加 Redis 或 SQLite, 不提前写空仓储层。

### 3.2 环境变量

| 变量 | 必填 | 默认值 | 说明 |
|---|---:|---|---|
| `PORT` | 否 | `5005` | 本地监听端口 |
| `API_KEYS` | 是 | 无 | Starcat 客户端 Bearer key 白名单, 逗号分隔 |
| `SIMREPO_API_KEY` | 是 | 无 | SimRepo Qdrant 只读 key, 仅后端持有 |
| `SIMREPO_ENDPOINT` | 否 | `https://simrepo.dera.page/collections/repos/points/recommend` | 上游 recommend endpoint |
| `CACHE_TTL_SUCCESS_SECONDS` | 否 | `604800` | 正常结果缓存 7 天 |
| `CACHE_TTL_EMPTY_SECONDS` | 否 | `21600` | 空结果缓存 6 小时 |
| `CACHE_TTL_ERROR_SECONDS` | 否 | `600` | 上游错误短缓存 10 分钟 |

### 3.3 路由

| Method | Path | 鉴权 | 说明 |
|---|---|---:|---|
| `GET` | `/healthz` | 否 | Fly/状态栏轻量健康检查, 返回 `ok` |
| `GET` | `/api/v1/ping` | 是 | 设置页测试连接, 返回 `{ service: "recommend", ok: true }` |
| `GET` | `/api/v1/repos/{repo_id}/recommendations?limit=10&offset=0` | 是 | 单仓相似推荐 |

推荐列表路径故意放在 `/api/v1/repos/{repo_id}/recommendations`, 与已有后端的 `/api/v1/repos` 命名空间保持一致, 也便于未来同一 repo 资源下扩展更多详情子资源。

### 3.4 响应契约

成功响应统一走 Starcat envelope:

```json
{
  "schema_version": 1,
  "data": {
    "source": "simrepo",
    "fallback": false,
    "repo_id": 41881900,
    "items": [
      {
        "repo_id": 123,
        "full_name": "owner/repo",
        "description": "Repository description",
        "language": "Swift",
        "stars": 1200,
        "forks": 80,
        "archived": false,
        "score": 0.87,
        "source": "simrepo",
        "reasons": ["被相似 GitHub 用户共同 star"]
      }
    ],
    "has_more": true,
    "next_offset": 10
  },
  "meta": {
    "page_size": 10,
    "total": 10,
    "source": "simrepo",
    "cache_status": "fresh"
  }
}
```

错误响应沿用现有 API 格式:

```json
{
  "schema_version": 1,
  "error": {
    "code": "BAD_REQUEST",
    "message": "repo_id must be positive"
  }
}
```

## 4. 后端实现细节

`SimRepoProvider` 将 Starcat 请求映射为 Qdrant recommend body:

```json
{
  "limit": 10,
  "positive": [41881900],
  "filter": { "must": [] },
  "offset": 0,
  "with_payload": true,
  "with_vector": false
}
```

映射规则:

- `result[].id` 或 `payload.id` -> `repo_id`
- `payload.full_name` -> `full_name`
- `payload.description` -> `description`
- `payload.language` -> `language`
- `payload.stargazers_count` / `payload.stars` -> `stars`
- `payload.forks_count` / `payload.forks` -> `forks`
- `payload.archived` -> `archived`
- `result[].score` -> `score`

`has_more` 第一版按 `len(items) == limit` 推断。SimRepo/Qdrant recommend 响应不保证 total, 所以 `total` 只表示当前返回数量。

## 5. 客户端实现

### 5.1 服务配置

新增第五个自建服务:

- `ThirdPartyService.recommend`
- `AppEndpoints.Recommend`
- `RecommendAPI`
- `AppDependencies.recommendAPI`

设置页服务 Tab 和状态栏服务可用性使用 `ThirdPartyService.allCases`, 加 case 后自动出现。需要补齐 i18n 文案和 Info.plist production key 名:

```text
STARCAT_PRODUCTION_API_KEY_RECOMMEND
```

### 5.2 详情页 UI

在 `RepoDetailScaffold` 根容器增加推荐浮层入口:

- `.task(id: repo.id)` 加载推荐第一页。
- 结果为空时不显示按钮。
- 结果非空时在详情页内部右下角显示 icon-only 按钮。
- 点击按钮弹出可滚动 popover。
- popover 首屏 10 条, 底部有更多时显示“更多”按钮。

浮层按钮必须避开 `ReadmeStateView.cacheFooter` 的刷新/翻译按钮视觉语义: 不使用 `SyncIconButton`, 不使用刷新图标, 不接管 README 的 footer。

### 5.3 点击行为

点击推荐卡片:

1. 用 `repo_id` 查本地 `RepoRepository`。
2. 如果命中且 `isStarred == true`, 调用现有详情切换路径打开本地 repo。
3. 如果未命中, 打开 `https://github.com/{full_name}`。

第一版不做“一键 star”、“加入对比”、“隐藏不感兴趣”。这些需要用户行为数据模型, 放到自研推荐阶段再设计。

## 6. 验收标准

### 6.1 后端

- `go test ./...` 通过。
- `go test -race ./...` 通过。
- `go vet ./...` 通过。
- `go build ./...` 通过。
- `/healthz` 无鉴权返回 200。
- `/api/v1/ping` 无 key 返回 401, 正确 key 返回 200。
- `/api/v1/repos/{repo_id}/recommendations` 无 key 返回 401, 非法 repo_id 返回 400, 正常 mock provider 返回 envelope。

### 6.2 客户端

- 设置页出现 Recommend 服务, 可配置 URL 和 API key。
- 状态栏 API 服务数量包含 Recommend。
- 打开有推荐数据的 repo 时右下角出现推荐按钮。
- 点击按钮展示推荐卡片列表, 支持更多分页。
- 点击本地已 star repo 直接切换到详情。
- 点击非本地 repo 打开 GitHub 页面。
- 推荐服务失败或空结果不影响详情页 README / tags / notes / release 展示。

## 7. 后续演进

后续自研推荐时只替换后端 Provider:

```text
SimRepoProvider
ContentEmbeddingProvider
StarcatBehaviorProvider
HybridProvider
```

客户端继续消费同一个 `/api/v1/repos/{repo_id}/recommendations` 契约。等后端能输出解释性 reasons 后, UI 卡片再展示更细的推荐原因。
