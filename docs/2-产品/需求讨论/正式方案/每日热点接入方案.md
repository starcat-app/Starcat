## 1. 目标与范围

在「探索」下新增「每日热点」，提供 AI 与开源生态的每日内容和历史回看。
使用「每日热点」区别于现有「热门」仓库榜单，首期不扩展为全行业新闻产品。

本方案包含三项交付：

1. 导入 `duanyytop/agents-radar` 已有历史报告。
2. 默认同步 agents-radar 上游当日报告，保留 Starcat 自生成接管路径。
3. 通过服务端统一分发，客户端读取同一份日报并缓存历史正文。

2026-10-29 确认采用类似 App Store 专题的阅读体验：每篇内容具备封面，阅读顺序为封面、文章、相关项目；左栏保留，中栏与右栏合并为专题区域，详情从该区域底部上滑展开。下文替代最初“中栏报告列表、右栏阅读”的布局草案。封面生产和文章相关仓库成为本期范围，关联仓库不自动桥接周刊。

日常同步不调用模型；自生成接管使用运营侧配置，不依赖每位用户的 AI 配置，也不因用户打开页面而触发模型调用。
历史导入、上游日常同步与自生成接管共用内容目录、校验和发布契约；同次运行的上游同步与自生成路径互斥。

首期不包含：个性化新闻生成、推荐模型训练、强制系统通知、全文搜索中心及新增正文翻译服务。
2026-10-29 的 Debug 固定样例用于确认视觉与交互。2026-10-30 已将现有界面接入独立日报 API，移除示例兜底与入口的 Debug 限制，支持真实目录、日期、语言策略、分页和固定修订阅读；界面累计 28 个 key 已补齐 18 语言，AI 译文保留待审核。本轮完成本地实现与验证，功能总览和更新日志不在改动范围。

正文改为安全 Markdown AST 渲染，支持表格和允许的折叠结构，并与原生相关项目列表保持单一纵向滚动。相关项目复用 `UnifiedRepoRow`，直接消费服务端已核验的修订快照；项目详情沿用独立 `DiscoveryDetailView`，提供 README、Star、翻译与分享，返回保留文章位置。打开项目不会自动 Star 或入库；主动 Star 才走原有用户操作。账号或服务切换隔离状态并拒绝迟到结果。客户端定向测试、双渠道构建及编译本地化资源检查已通过；生产 API 联调见下节，客户端 GUI 验收仍未执行。

服务端交付读取接口、持久化导入队列、项目核验、不可变修订、版本分页与缓存，以及默认 dry-run 的固定 Git 历史导入命令；SQLite 追加 migration v3。受控发布仓库与凭据已落实，当前来源模式与调度见第 5.2 节。封面由客户端本地绘制，不再把专属生图或 CDN 上传列为待完成项。

历史导入不能只枚举 manifest：

- manifest 生成器采用文件白名单，早期 `openclaw.md`、`index.md` 和各工具报告可能未列入。
- `ai-cli.md` 可能已经嵌入各工具完整报告，聚合稿与子报告不能重复占据主日报列表。
- `digests/web-state.json` 是采集状态，不是正文，不作为日报保存或展示。
- `highlights.json` 并非每天存在；缺失时从正文提取短摘要，不强制调用模型补写历史。

### 3.1 专题首页与内容区阅读覆盖层

![已确认方向的专题首页与展开阅读概念图](assets/daily-radar/editorial-concept.png)

效果图为视觉样例，文稿与项目关联不是生产数据。专题页采用大封面与编辑式排版，作为本功能明确的视觉选择；窗口 chrome、侧栏、按钮与其他页面仍遵守 Starcat 的原生规范。

| 位置 | 内容与行为 |
|---|---|
| 左栏 | 「探索 → 每日热点」，主题子分类与「全部」入口；保持可见、可用 |
| 中栏 + 右栏 | 合并为无内部竖分隔线的专题首页；顶部为日期、历史、内容语言与刷新，下面为一张主推封面、其他专题卡片和往期内容 |
| 展开阅读 | 点击卡片后，阅读覆盖层只在合并内容区内从底部进入，顶部固定关闭入口，内容依次为封面、标题 / 元信息、正文、来源、相关项目 |
| 项目详情 | 在阅读页顶部横条及分隔线下方，从内容宿主底部弹出窄幅详情，面板与遮罩均不越过该边界，左右可见文章；顶部拖拽、关闭或 Esc 收起，恢复文章位置 |

首页只在当前筛选结果中选择主推内容；首版按后端固定的主题优先级、实际出刊日和稳定 ID 选择，不依赖人工每日运营。主推与普通卡片使用同一份报告摘要，列表数量只算一次；历史筛选优先按日期浏览，不强制每个历史日期都设主推。

封面可铺满内容区，正文居中并限制约 680–760pt 阅读宽度。相关项目位于正文末尾，复用中栏仓库卡片组成纵向列表，默认显示前 6 项并可展开全部；点击后从内容区底部展开完整仓库详情，面板约占内容宽度的 64%、最大 760pt，高度仅占阅读页顶部横条及分隔线下方的剩余区域，底部贴齐工作区，关闭回到文章原位置。遮罩和滑入动画使用相同顶部边界，不覆盖横条。窄窗口按可用宽度缩小面板并保留左右边距。没有可信关联时不显示该区，不用无关热门项目填充。窗口变窄时首页从双列变单列，正文和项目仍按纵向排列。

首期类型映射依据固定版本的 manifest 白名单、README 和 `REPORT_LABELS`；中文文件名加 `-en` 对应英文版本，不新增主题。

不是每一天都必须有每个主题；没有对应报告的日期不制造空稿。
「全部」默认列日报；选择 Hugging Face 模型时使用周报周期；停更的汇总周/月报通过历史归档筛选进入。

默认打开当前主题、周期与内容语言条件下的最新可用日期，明确显示该日期；没有今天的稿件时不把昨天标成「今日」。切到周报主题时使用该主题实际出刊日，不沿用全站最新日报日期造成假空态。
日期选择器只开放服务端实际存在的日期，并支持按日期区间回看历史。
日历中的日期含义为内容业务日期，生成时间和入库时间另行展示。

### 3.2 进入、退出与阅读状态

- 整张封面卡片可点击；进入阅读的动画建议约 0.25–0.35 秒，具体时长以原生样板为准。启用减少动态效果时以淡入替代长距离移动。
- 阅读态右上角使用共享关闭组件，Esc 返回首页并恢复原滚动位置；相关项目态 Esc 返回原文章，输入框或系统菜单优先消费 Esc。切换左栏分类关闭阅读层，保留每篇报告的阅读锚点。
- 覆盖层启用期间，底层仓库列表 / 详情不接受点击、键盘焦点或无障碍导航；左栏仍可操作，不给整个窗口加模态遮罩。
- 使用内容区共同祖先的覆盖层，按中栏与右栏实际几何范围定位；宽度随侧栏折叠、拖动与窗口变化更新，禁止硬编码减去侧栏宽度。
- 筛选与操作按钮保持单行；空间不足时截断文字并提供 tooltip，不靠缩小字号容纳。
- 刷新使用 `SyncIconButton`，正文状态不改变顶部工具栏的高度。
- 首次无缓存时展示加载态；已有缓存时保留列表与正文，后台更新。
- 请求失败时保留已读内容，给出重试入口；无稿、无匹配结果和网络失败分别表达。
- 系统通知默认关闭；用户启用后，只通知新发布的当期日报，每个业务日期合并一次。
- 通知去重状态持久化；历史补录、正文修订、离线恢复和任务恢复不补发提醒。

点击卡片后先用已缓存的封面与标题展开，再加载正文；正文加载失败在阅读层内重试，不关闭面板或清空首页。阅读期间固定所选报告修订，后台发现新版仅标记可更新，不自动替换正文导致跳动。关闭后再打开可采用最新修订。

## 4. 服务职责与部署边界

建议在现有 `starcat-weekly-api` 增加独立日报模块和表，经 `starcat-api` 聚合入口提供只读访问。
这沿用开发前问题清单 §4.11 的服务边界，不恢复已取消的独立 `starcat-intelligence-api`。
既有 `ai_intelligence` 表示核验后的仓库收录；本功能表示完整 Markdown 报告和历史阅读。
两者可以共用服务进程，但不共用列表身份、存储模型或数量口径，也不把日报混入周刊仓库列表。
内容同步和自生成接管均在受控 GitHub Actions 中运行，与在线读取隔离；客户端封面不依赖图片存储账号或生图预算。
首期从日报中提取并核验相关仓库，只保存文章关联和必要的公共项目卡片元数据；桥接周刊仍属后续可选能力，不自动写 `repo_source_events` 或加入推荐训练数据。

| 职责 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| 历史导入器 | 固定 commit 的 manifest、Git tree、Markdown | 校验后的历史报告候选 | 可恢复、可重跑，不执行上游脚本 |
| 每日同步 / 自生成接管 | 上游固定 Git 提交；或运营侧 agents-radar 配置、数据源和模型 | 当日报告候选、来源与运行记录 | 来源模式互斥；上游同步不调用模型，自生成不在补拉轮次运行 |
| 相关仓库处理 | 正文中的明确仓库链接及上下文 | 已核验公开仓库 ID、卡片元数据与证据 | 自动识别、缓存核验，不新增人工逐项审核 |
| 内容发布模块 | 报告候选、来源、封面元数据与校验结果 | 正文 / 关联项目的发布修订、当前目录版本 | 封面 URL 可空，不等待图片生成或上传 |
| 在线读取服务 | 日期、主题、语言、分页参数 | 日期索引、报告列表、正文 | 不运行模型，不阻塞于生成任务 |
| 客户端 | API 响应与本地缓存 | 本地封面、专题首页、阅读覆盖层、项目详情与历史回看 | 不要求用户配置生成服务密钥，不请求远程封面 |

复用上游生成能力时记录使用的代码版本；模型凭据仅由生成环境管理，不进入客户端或报告元数据。
在线服务可以继续提供昨日和历史内容，不依赖当天生成任务是否正常。

当前在受控 fork `starcat-app/agents-radar` 中运行每日工作流，默认读取上游固定提交，必要时切换运营侧 GLM 自生成；两条路径使用独立管理凭据提交到同一后台队列。封面已改用本地绘制，不再部署独立图像生产与上传链路。

后端改动集中于以下位置。在线服务、历史导入代码与受控生成适配器已落地，生产启用和验收结果以「生产接通记录」为准：

| 仓库 / 模块 | 改动 |
|---|---|
| `supports/starcat-weekly-api/internal/store` | 追加日报表迁移、幂等导入、修订发布、相关仓库引用及查询；复用公共仓库元数据，不写周刊来源事件 |
| `supports/starcat-weekly-api/internal/dailyradar` | 日报读取与内部导入 handler、worker、独立 DTO、历史扫描和分页错误契约 |
| `supports/starcat-weekly-api` 后台 worker 与 `server` | 独立导入任务、启动恢复、有限重试与停机处理；沿用既有服务生命周期、管理员鉴权与 Options 配置 |
| `supports/starcat-api` | 继续使用 `X-SC-Svc: weekly` 装配，新增配置经 `WEEKLY_*` 注入；仅按实际需要更新模块依赖和配置，回归鉴权与缓存头透传 |

这些 supports 目录为独立 Git 仓库，后续实现和提交按仓库分别处理。

## 5. 历史回填与每日生产

### 5.1 历史回填

1. 固定上游 commit，保存 manifest 与 Git tree 快照，枚举目标日期下 Markdown 候选。
2. 按映射表识别业务日期、报告类型、语言、聚合/子报告关系及未知文件。
3. 获取正文并校验内容 hash、必要标题、非空正文及来源链接结构。
4. 原始候选幂等入库，更新逻辑报告的公开版本，保存批次 checkpoint。
5. 校验各日期、类型、语言的覆盖率，再开放历史目录。

未知文件记录为待识别候选，不按猜测强行归类，也不直接丢弃。
`index.md` 等早期文件需结合实际内容映射；文件名相同不代表内容类型始终相同。
聚合稿作为主要阅读单元时，工具子报告保留来源关系，不再次作为同一日报显示。

checkpoint 至少记录 commit、候选路径、hash、处理状态、失败原因和尝试次数。
中断后只恢复未完成或内容已变化的项；同批次重跑不会增加重复报告。
服务端长期保存已收录内容，不因上游 RSS 滚动、manifest 缩减或文件删除而同步删除。

历史完整性分别统计「日期覆盖」「类型覆盖」「语言覆盖」，不能用文件总数替代验证。
248 个日期连续只证明每个日期有数据，不证明每个主题和每种语言每天都有稿。

### 5.2 上游同步与自生成接管

现行流程以 `supports/starcat-weekly-api/scripts/daily-radar-pipeline/README.md` 及同目录适配器、workflow 为准；已接通使用，本轮不改动流水线。

- 仓库变量 `DAILY_RADAR_SOURCE_MODE` 默认 `upstream`，手动 dispatch 可通过 `source_mode` 覆盖。上游模式只读取 `duanyytop/agents-radar` 固定提交中的当日标准 Markdown，不安装依赖、执行上游代码或调用模型。
- 同主题中英文成对后提交；定时运行遇到尚未就绪时记录待补拉，手动触发或最后一轮仍缺稿则失败。正文损坏、Git 读取或 API 错误直接失败，不伪装为等待。
- 上海时间 07:30 首轮同步，08:30–12:30 每小时补拉；对应 UTC cron 为 `30 23 * * *`、`30 0-3 * * *`、`30 4 * * *`。触发时间不等于完成时间，12:30 之后到稿可手动指定日期补拉。
- `starcat` 模式保留为运营接管路径，使用 GLM OpenAI-compatible 配置；自动生成只在首轮运行，补拉轮次不重复付费生成。成功生成先提交并推送到受控 fork，再按固定生成记录发布；重跑复用成功产物。
- 两条路径共用 `/internal/daily-radar/imports`、持久队列、批次轮询、项目核验与不可变修订；相同快照重跑保持幂等，失败不清空既有内容或已发布历史。上游同步不会修改 fork 默认分支或合并上游代码。

当天未就绪时继续展示最近可用日期，不用占位稿冒充成功。发布适配器不会因为某个主题当天整体缺席而伪造内容；已出现主题必须中英文配齐。

### 5.3 本地程序化封面

封面已由客户端统一绘制，不再依赖生成侧生图、分类图库或 CDN 上传。

- `DailyRadarCoverView` 统一调用 `DailyRadarProgrammaticCover`，首页、往期和阅读页均以报告 ID 为 seed，分类影响构图权重与配色；同一报告跨语言、跨重启稳定。
- `DailyRadarCoverComposition` 提供六类构图，几何与纹理使用独立确定性随机流；绘制细节按尺寸分档且有上限，不使用逐帧随机、动画或无界图形数量。
- 主推卡通过文字安全区保护标题与摘要，缩略图和阅读页沿用同一构图身份；封面不含文字，标题由原生界面叠加。
- 服务端仍保留 `cover` 契约，URL 可空；当前客户端不请求 `card_url` / `hero_url`，仅使用 `alt` 提供无障碍描述。正文图片与未来周报配图不属于此封面策略。
- 历史导入、正文修订和离线阅读均不触发图像模型或封面下载；不能把旧方案中的专属封面生产、对象存储或上传预算继续列为本期缺口。

### 5.4 相关项目自动识别

上游 AI CLI 报告已有明确 GitHub 仓库链接，首版按 Markdown 链接与出现语境提取，不要求训练推荐模型，也不让 LLM 凭空列项目。

1. 解析标题、项目小节和正文链接，标准化 GitHub owner/repo；排除站点导航、作者主页、图片 / 徽章和引用模板中的无关链接。
2. 将明确讨论的 Issue / PR / Release 链接关联到其所属仓库时保留原链接证据；正文点击仍打开原 Issue / PR / Release，不擅自改成仓库首页。
3. 后台使用缓存与 GitHub API 核验公开仓库身份、仓库 ID 与当前 canonical 名称。歧义或已不可访问项跳过，限流项退避重试；不在用户打开文章时逐个查询。
4. 以仓库 ID 去重，优先正文明确介绍的小节与覆盖工具清单，再按首次有效出现排序。保存 `evidence_url`、章节锚点和简短引用位置，供故障排查与来源追溯。
5. 发布关联项目卡片，包括名称、描述、头像、语言等必要字段；Star 状态由客户端账户数据叠加，不写公共响应。

关联处理采用有限重试；正文可在核验超时后先发布，`related_projects_status` 标记 pending / complete / partial，客户端只显示已核验项目。后续补齐形成新修订并更新目录计数，正在阅读的旧修订不混入新列表。零可信项目是合法结果，不自动搜索名字相似的仓库凑数。

复用 Weekly 的 GitHub 元数据缓存与核验客户端，关联可引用 `github_repos`，但发布不得调用现有 `CompleteIngestItem`：该函数会创建 `repo_source_events`，导致文章项目进入周刊。新增日报关联写入路径，保持现有周刊总数与来源计数不变。现有 Weekly 仓库详情查询也要求来源事件，因此日报详情直接提供已核验 RepoCard，客户端走普通公共仓库详情能力，不依赖 Weekly `/repos/{id}` 一定能查到该项目。

## 6. 存储模型与版本选择

以下为逻辑模型草案；首版沿用 Weekly 的 SQLite，具体表名与索引按现有存储约定实现。

| 实体 | 建议字段 | 用途 |
|---|---|---|
| 来源报告 | `source`、`source_date`、`report_type`、`language`、`source_url`、`source_commit`、`source_path` | 追溯上游历史或 Starcat 自生成来源 |
| 内容修订 | `revision_id`、`content_hash`、`title`、`summary`、`markdown`、`reading_minutes`、`cover_id`、`generated_at`、`ingested_at` | 正文、封面引用与关联项目组成完整发布版本；原始文稿另保留追溯 |
| 逻辑报告 | `report_id`、`edition_date`、`report_type`、`period`、`category_id` | 用户看到的一份内容与稳定链接 |
| 语言发布版本 | `report_id`、`language`、`canonical_source`、`canonical_revision` | 同一报告按语言分别选择公开版本，避免语言间覆盖 |
| 封面资源 | `cover_id`、`content_hash`、`card_url`、`hero_url`、`width`、`height`、`focal_point`、`kind` | 跨语言复用、分尺寸缓存；kind 区分专属生成与分类封面 |
| 修订关联仓库 | `revision_id`、`repo_id`、`position`、`evidence_url`、`section_anchor`、卡片快照 | 与正文版本绑定、稳定排序；不创建周刊来源事件 |
| 目录版本 | `catalog_revision`、`published_at` | 首页、日期、计数和分页使用一致版本；版本变化明确重载 |
| 生成运行 | `run_id`、`edition_date`、`status`、`attempt`、`started_at`、`finished_at`、`error` | 防重、补跑和运行诊断 |
| 导入批次 | `batch_id`、`source_commit`、`checkpoint`、`status` | 历史回填恢复与覆盖率审计 |

`period` 区分日、周、月；周/月内容还需记录覆盖区间，不把发布日期误作全天范围。
类型映射表沿用 §3.1 的主题名称，并补充稳定 `report_type`、周期、语言识别规则、聚合关系和映射版本。
历史文件使用逐期内容识别，不能将当前文件名和周期规则无条件回套全部旧报告。

### 6.1 幂等与修订

- 来源报告以 `(source, date, report_type, language)` 为幂等身份；原始路径另行保存。
- 提交幂等与报告身份分开：同一提交 key、相同规范化 payload hash 返回原批次；同 key 不同 hash 返回 `409 IDEMPOTENCY_CONFLICT`。新正文、主动换图或其他修订使用新提交 key，仍更新同一来源身份和 `report_id`。后台补齐关联同样生成新修订，不覆写已发布 payload。
- 原文 hash 相同则跳过重复正文处理；公开标题、封面或已核验关联变化同样产生新的内容修订，发布 hash 覆盖完整可见 payload。
- 客户端链接使用稳定 `report_id`，不把易变 hash 当作报告身份。
- 同一逻辑报告的多语言正文分别保存，但列表计数只算一份逻辑报告。
- 删除或替换公开内容需要明确的内容管理操作，不由抓取清单的缺失自动触发。

### 6.2 历史与自生成内容重叠

对同一业务日期、报告类型和语言，默认优先选择通过校验并已发布的 Starcat 自生成版本。
没有自生成接管版本时使用已导入或日常同步的上游版本；生成失败不覆盖仍可用的上游内容。同日已由自生成接管后再同步上游不会切回上游指针，需从次日起恢复默认上游模式。
该选择按 `(report_id, language)` 保存 canonical 指针，保留所有来源证据，用户列表不出现两份相同日报。
中文与英文公开版本互不覆盖；切换语言时读取该语言指针，回退语言必须在响应中明确。

同一语言有多个成功修订时选择最新已发布版本，更新时间与 ETag 同步变化。
若需撤回错误修订，可切回此前有效版本，并更新目录版本；不得静默混拼不同来源的正文。

### 6.3 发布事务与恢复

内容状态按 `queued → processing → ready → published` 推进，失败记录可重试原因；运行、导入批次与报告状态分别管理，不能因一个主题失败回滚所有主题。

先在事务外完成正文规范化、封面元数据校验与项目核验，再在一个短事务内写内容修订、修订关联、语言指针并推进目录版本。已有目录始终指向可读取的完整内容；网络调用不得持有 SQLite 写事务，当前发布不执行封面上传。

源日期与受控生成序号用于防止迟到的旧任务覆盖新修订；历史批次使用固定 commit 与导入序号，不能按 commit hash 字符串大小判新旧，入库时间也不作为唯一依据。公开内容撤回通过显式状态完成，RSS / manifest 缺席不触发删除。私有化或确认失效的仓库卡片可强制失效，避免长期显示旧公共元数据。

首版继续使用既有服务 SQLite 和卷备份机制，报告文本与关联以独立 `daily_radar_*` 表存储，图片文件放对象存储。在实际迁移实现时追加现有 migration，不预占编号，不改已发布 schema。任务日志只保留阶段、数量与脱敏错误；不记录模型 Key 或发布凭据。

## 7. API 与读取契约

2026-10-30 实施时，以 [每日热点 API 契约](../../../3-设计/详细设计/每日热点-API契约.md) 固定双方字段、参数、错误、缓存与导入语义。下述段落保留产品约束；具体路由及 JSON 按共同契约实施，变更需同步两端。

以下路由已随 2026-10-30 生产聚合服务部署。使用现有聚合 Host、`X-SC-Svc: weekly` 与对应读取鉴权，路径按现有 `/api/v1` 前缀组织；日报保持独立 DTO，不改变周刊 `/repos` / `/repos/bulk` 的语义。

| 接口 | 参数/返回重点 |
|---|---|
| `GET /api/v1/daily-radar/catalog` | 主题、周期、可用语言、`latest_available_date`、目录版本 |
| `GET /api/v1/daily-radar/dates` | 按主题/周期/内容语言及回退策略筛选的可用日期、日期范围与报告计数，支持按月获取 |
| `GET /api/v1/daily-radar/reports` | `category`、`period`、日期区间、语言策略、`cursor`、`limit`；返回摘要、封面、`featured_id`、总数与分页信息 |
| `GET /api/v1/daily-radar/reports/{id}` | 所选语言正文、封面、相关仓库、来源、实际语言；可用 `revision` 获取已选修订 |
| `POST /internal/daily-radar/imports` | 受保护的历史 / 每日候选入库入口；请求带幂等键、source commit / run、文稿和封面引用；持久化入队后返回 batch ID |
| `GET /internal/daily-radar/imports/{id}` | 批次进度、失败项与发布结果，供生成任务恢复；不提供给普通客户端 |

读取沿用 `Authorization: Bearer` 和 `schema_version / data / error` envelope，分页字段位于日报独立 `data` 中。内部写入复用 `ADMIN_API_KEYS` 权限隔离，持久化成功返回 `202`；部署时配置仅供生成端使用的发布凭据，不把它放进 App。服务端只接受受控来源与封面域名，限制批次大小和正文体积；不抓取写入请求任意提供的内网 URL。

列表摘要至少包含 `id / revision / edition_date / category / period / title / summary / reading_minutes / cover / related_project_count / content_language / available_languages`；完整 Markdown 和完整项目列表只在详情返回。`featured_id` 仅在第一页返回，并指向该页 items 中的一条，客户端把它移到大封面位置，不能重复展示或重复计数。

详情包含摘要的全部字段，另加 `source / markdown / related_projects / related_projects_status / generated_at / updated_at`；报告身份为 `id`，实际正文语言为 `content_language`。相关项目使用既有仓库卡片核心字段，并把文章证据放在日报专属扩展中；不向通用仓库 DTO 添加封面、日报日期等字段。

列表和日期索引使用相同筛选语义，先筛选再计数；默认仅列日报。
默认内容语言使用界面语言偏好匹配中文或英文，缺稿时回退到该报告实际可用语言。
显式选择「仅中文/仅英文」时只返回确有该语言的报告，不能隐式回退使计数失真。
每份逻辑报告只出现一次，响应明确 `requested_language`、`content_language` 和 `available_languages`。

列表采用稳定的日期倒序，再按报告类型和 ID 排序；游标绑定目录 revision、筛选摘要、limit 和排序位置。同一请求中，计数与结果基于一致的目录快照生成。

首版不新增历史目录快照存储。翻页发现目录版本变化返回 `CATALOG_CHANGED`，客户端合并同条件的重载请求，保留旧列表直到新首屏准备好，再替换分页会话并恢复仍存在的滚动锚点；旧页不能直接拼入新版本。主题、日期、语言变化则立即建立新请求身份，丢弃迟到响应。详情按 revision 可读取旧内容；已撤回返回明确不可用状态，不把不存在、网络失败和语言缺失统一成空正文。

`catalog / dates / reports` 都返回 `catalog_revision`；日期与列表请求可携带预期目录版本，版本不符同样返回 `CATALOG_CHANGED`。客户端跨请求得到不同版本时合并重载，不把旧日期计数和新列表拼成一个已同步页面。

## 8. 两级缓存与正文安全

### 8.1 服务端缓存

- 目录和日期索引按目录版本生成 ETag，内容按公开正文 revision 生成 ETag。
- 缓存键包含 `catalog_revision`、日期 / 主题 / 周期 / 语言策略 / 游标等查询身份，不能遗漏筛选条件。读取鉴权后先验证预期目录 / cursor 版本，再命中缓存或比较 `If-None-Match`；失效游标不能以旧缓存或 `304` 绕过 `CATALOG_CHANGED`。
- 目录发布与正文可读性保持一致，先保存正文，再公开引用该版本的目录。
- 支持条件请求和 `304`；来源修订后只失效受影响正文及相关目录缓存。
- 生成失败不清空在线缓存，历史报告不设置与 RSS 滚动窗口绑定的保留期。
- 首版目录重验证建议 10 分钟，客户端启动 / 进入页面遵守此预算，手动刷新主动条件请求；服务端同条件并发请求合并。此 TTL 是实现起点，可按日更节奏与实测调整。
- 无 Star 状态的公共报告可在服务内跨用户复用缓存，但保留服务鉴权；封面本地绘制，头像沿用现有元数据缓存规则。生成或入库接口不参与公共缓存。
- 当前 Weekly `BulkCache` 只有全量仓库快照，不能直接承载日报的主题 / 日期 / 语言分页；新增独立缓存，复用既有 ETag / gzip 处理。聚合层验收 `If-None-Match`、`ETag`、`Cache-Control`、`Content-Encoding` 与 `304` 透传，不另加一层相互冲突的缓存有效期。

### 8.2 客户端缓存

- 缓存首屏目录、日期索引、列表和按需读取的历史正文，打开时先读缓存再验证更新。
- 缓存命名空间包含服务地址与 API 契约版本；目录/列表身份包含目录版本、分类、日期、周期和语言策略。
- 正文缓存身份包含 `report_id`、实际正文语言和 revision，避免语言回退、服务切换或修订导致串读。
- 切换主题、日期或语言时重置分页身份，复用 `ListPaginationPolicy` 与 `automaticListPagination`。
- 新正文修订写独立缓存并更新 latest 指针；当前阅读和返回栈引用的旧 revision 暂不被淘汰，退出会话后恢复正常回收。断网时继续阅读已缓存正文，并显示最后同步时间。
- `304` 更新成功校验时间并保留内容；失败回退仅标记缓存可用，不把“刚刚尝试”显示为“刚刚同步成功”。
- 正文缓存设可控空间上限和最近使用淘汰策略；本地淘汰不删除服务端历史。
- 用户账户相关的已读 / 阅读位置与 Star 状态单独保存；公共内容按服务地址 / 契约 / 凭据作用域隔离，切账号或服务后不得把旧私人状态带入。
- 已选正文和相关项目使用同一 revision；屏幕外的文章不全部预加载，打开文章时按需读取正文；封面按可见尺寸本地绘制，不下载缩略图或大图。
- 若新增持久化表，按已发布数据库规则追加迁移，禁止回写旧迁移或要求用户删库。

### 8.3 客户端模块与导航状态

| 层 | 拟新增 / 修改位置 | 职责与复用边界 |
|---|---|---|
| 网络 | `Core/Network/DailyRadarAPI.swift`、`DailyRadarModels.swift` | 目录、日期、列表、revision 详情及条件请求；读取服务配置由依赖注入提供 |
| 缓存 | `Core/Sync/DailyRadarRepository.swift` | actor 串行管理目录 / 正文磁盘缓存与请求合并，沿用缓存回退结果表达；不复用 Weekly 全表替换语义 |
| 状态 | `Features/DailyRadar/DailyRadarWorkspaceViewModel.swift` | 主线程发布首页与阅读状态，管理筛选、分页身份、错误、路由和滚动锚点 |
| 展示 | `Features/DailyRadar/` 下的首页、阅读器与工作区 | SwiftUI 原生首页 / toolbar / 覆盖层，专用正文渲染适配；不复制 HomeView 的仓库业务状态 |
| 导航接入 | `ExploreModels`、`ExploreCatalogPreferences`、`SidebarView`、`HomeView` | 新增 `.dailyRadar`、侧栏显示偏好与内容区宿主；主题 / 日期 / 正文语言不套用仓库许可证等筛选 |
| 装配 | `AppDependencies`、本地化目录、必要追加迁移 | 注入服务，保存个人阅读位置 / 偏好，覆盖当前全部 17 种语言；不改已有 Stars / 知识库表语义 |

上述文件名是实施建议，遵循现有模块边界，不要求为了满足表格数量拆空壳文件。

浏览状态明确为「首页 → 阅读文章 → 相关仓库详情 → 原文章 → 原首页」：

- 首页保存主题、日期区间、正文语言策略、目录版本、分页会话与卡片锚点。
- 阅读会话保存 `report_id + content_language + revision`、章节锚点与局部滚动偏移。窗口宽度变化后按章节优先恢复，不只依赖绝对像素位置。
- 项目详情在热点工作区内以窄幅底部面板呈现，高度限于阅读页顶部横条及分隔线下方，遮罩和动画同样受此边界裁切；复用既有公共仓库详情组件和服务，文章持续挂载但暂停命中与辅助功能导航。拖动仅限顶部，避免争抢 README 滚动；Esc 先收起项目面板，再关闭文章。
- 不直接调用 `HomeView.openCompanionRepository`：现有入口会切换至全部 Stars、清搜索并重载主列表，与保留文章上下文冲突。
- 进入热点前保存主窗口原仓库选择；退出热点不覆盖原选择。热点正文缓存可共享，私人阅读状态与偏好按账号隔离。

当前 `NavigationSplitView` 的中栏与右栏是独立宿主；在 `HomeView.navigationWithOverlays` 共同父层承载 `DailyRadarWorkspace`，用实际几何锚点确定两栏联合区域。热点激活时底层两栏保留布局占位，业务状态留在外层，避免被遮挡的 WebView 继续加载；覆盖区域裁剪到内容边界，遮住中右分隔线。不得只把阅读器挂到 `detailColumn`，也不得拖动被覆盖的内部 divider。左侧 divider 仍可调整宽度。

底层交互隔离需同时处理鼠标命中、焦点、快捷键与辅助功能树，不能只加 `allowsHitTesting(false)`。退出热点后恢复正常路由；渲染细节先用原生样板验证，不重构其他分类布局。

### 8.4 渲染和仓库链接

首期建议使用专用 `WKWebView` 阅读器，复用现有 Markdown → HTML、安全处理、主题与图片能力，独立适配日报内容。上游含 GFM 表格和原始 HTML `<details>`；选择 Web 阅读器主要为保留允许的 HTML 结构与折叠交互。若改用 MarkdownUI 等原生方案，必须先验证其 HTML 转换与交互规则，不能静默丢弃折叠内容；不把这一约束误解为原生方案均不支持 GFM 表格。

整篇只有一个纵向滚动容器：封面、文章、来源和相关项目均在受控阅读 HTML 中，关闭 / 返回等固定操作保持原生。相关项目区使用通用 RepoCard 数据绘制一致样式，通过限定回调进入原生仓库详情。不能把整个 `ReadmeWebView` 放进 SwiftUI 外层 `ScrollView`：现有组件还绑定仓库加载、工具栏和详情命令路由，需要抽取或适配可共享渲染部分，不继承不相关业务行为。

来源 Markdown 按不可信内容处理，表格和折叠区通过允许列表支持。来源脚本、事件属性与非允许 HTML 不执行；只有应用自己的受控脚本负责锚点和交互。项目事件仅接受当前 revision 已核验的仓库 ID，校验主 frame 与文档会话；不把脚本桥开放为任意本地操作接口。图片和外链遵循既有网络及 URL 策略，不注入新闻站整页 HTML。

正文中的 GitHub 根仓库链接若已关联核验 ID，则进入同一热点详情路由；其他链接可按原始外链打开，不在点击时阻塞于批量仓库识别。Issue、Release、新闻和非仓库链接保留原始语义。阅读日报或打开项目不自动 Star、不加入知识库、不写标签，不混入用户贡献数据；用户主动 Star 才走现有写入流程。

## 9. 国际化与归因

UI 文案必须完成当前全部 17 种支持语言，包括日期筛选、错误状态、语言回退和来源说明。
实施验收同时检查长文案、窄中栏和字号倍率，不能以英文兜底代替翻译完成。

报告正文语言与界面语言分开管理：首期保留来源和自生成的中文/英文内容，并标出实际语言。
历史缺失语言不伪装为翻译完成；新增其他正文语言或按需翻译属于后续单独确认范围。
AI 生成说明、引用来源和原文入口持续可见，摘要不能替代原文归因。

## 10. 分阶段交付与验收

| 阶段 | 待实现内容 | 进入下一阶段的条件 |
|---|---|---|
| A：契约与样板 | 选取真实长文、表格、无相关项目、缺语言等样本，固定 DTO、类型映射和原生覆盖层样板 | 中右联合范围、单滚动、项目返回和数据身份可验证；样例不冒充生产数据 |
| B：后端读取闭环 | 追加迁移、导入队列、版本发布、目录 / 日期 / 详情、ETag 与分页；先跑少量样本 | 重跑、失败恢复与公开查询通过，Weekly 原目录与计数不变 |
| C：历史与内容生产 | Git tree 全量盘点、历史断点导入、上游同步 / 自生成接管、关联仓库核验；封面由客户端绘制 | 覆盖率可解释，来源与修订一致；不等待生图或上传 |
| D：客户端接入 | 专题首页、阅读覆盖层、相关仓库返回、筛选 / 历史 / 分页、磁盘缓存和当前 17 种语言 | 双渠道构建、状态与缓存测试通过，真实 UI 验收完成 |
| E：日常自动化与发布验收 | 已接通上游同步、分时补拉与自生成接管；按现行记录维护 | 正常发布、重复触发和失败恢复结果分别记录；不重复启用或改动现有生产任务 |

上述 A–E 为实施阶段划分，已完成的读取链路、历史导入和日常自动化不重复执行；当前按下方清单回归客户端交互、缓存与性能。后续历史补录仍逐批验证，避免阻塞线上读取。每日热点不等待推荐模型或第三方依赖全量升级；若调整本功能使用的渲染依赖，先锁定其兼容版本。

历史可用性不等待推荐模型训练；每日热点与项目推荐分别验收和上线。
以下为回归验收清单；已有交付与生产接通结果见前文，不再整体标为待实现。未执行的 GUI 验收仍须单独取证：

- 固定快照的日期覆盖可复核，3,885 份文件按语言/周期/类型拆分统计。
- 同一批历史重复导入数量不变，中断可恢复，上游清单缩减不删除既有报告。
- 旧版 `index/openclaw` 可解释归类，聚合稿与工具子报告不重复占据主列表。
- 同日来源重叠只展示 canonical 版本；正文修订会更新 ETag 和客户端缓存。
- 缺少 highlights、英文、某主题稿件时正确降级，不生成虚假内容或错误计数。
- 调度重复、模型超时、网络失败及发布中断后可恢复，不覆盖已有正文。
- 目录版本与正文一致；筛选、计数和跨页加载不混入其他日期或语言。
- 发布期间翻页正确处理 `CATALOG_CHANGED`；首次分页、刷新与语言回退的日期计数一致，主推不重复计数。
- 本地封面在同一报告跨语言、重启及不同尺寸下保持构图身份，文字安全区与绘制预算有效；离线阅读不依赖远程封面。
- 相关项目按仓库 ID 去重；更名、404、限流和零结果可解释；日报导入前后 Weekly / AI 情报来源计数不变。
- 断网可读缓存，最新日期真实；通知默认关闭，启用后当期新日报每天合并一次，补录/修订/恢复不提醒。
- 外部 Markdown 脚本不可执行；仓库链接跳转不产生 Star 或用户数据写入。
- 首页 → 文章 → 项目 → 文章 → 首页恢复原位置；后台新修订不替换正在阅读的正文，快速切换丢弃迟到响应。
- 拖动侧栏、折叠侧栏、窗口缩放时覆盖层仍仅占中右区域；中右分隔线不可拖动，左侧分隔线正常；底层无隐藏焦点或快捷键误触。
- 浅色 / 深色、减少动态效果、键盘 / VoiceOver 和正文表格 / 折叠区均可使用，单一纵向滚动且正常恢复锚点。
- 当前 17 种 UI 语言完整，窄中栏与长文案不造成按钮换行或布局跳动。

后端以单测、SQLite 集成测试和经聚合入口的 HTTP 契约测试验证；客户端通过标准 `make test`、`make build-appstore`、`make build-direct` 验证，构建不等于 UI 验收。GUI 验收仍需单独授权与取证；本轮只执行本地定向测试与构建，不调用图像模型，也不重复执行生产历史导入或启用已运行的定时任务。

受控仓库、来源模式、模型接管配置与调度已落实；封面不依赖对象存储或生图预算。后续按实际问题维护现有发布链路，客户端交互与性能继续按回归清单验收。
