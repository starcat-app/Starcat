# 全局语言与列表控制正式方案

> 日期: 2026-07-03
> 状态: 正式方案
> 范围: Explore 信息架构、全局语言筛选、中栏顶部排序与模块筛选整理

## 1. 方案目标

将 Starcat 的语言筛选、排序和模块筛选整理成稳定的信息架构:

- 左侧 Sidebar 负责当前模块的语言筛选。
- 中栏顶部负责当前列表的排序、周期、业务筛选和刷新。
- Weekly 从 Activity 迁移到 Explore,作为探索内容源的一部分。
- 各模块只展示真实可生效的筛选 / 排序条件。

目标不是减少功能,而是让用户在切换模块时仍能保持一致的操作模型。

## 2. 产品原则

1. 语言筛选是用户兴趣范围,应放在左侧导航筛选区域。
2. 排序只改变列表顺序,不缩小结果集合,必须独立命名为“排序”。
3. 周期是趋势的数据范围,不是排序条件,必须独立显示。
4. 模块筛选只展示当前模块真实支持的条件。
5. 排序状态按模块保存,不做跨模块共享的全局排序值。
6. Weekly 属于探索内容,不再作为 Activity 的动态分类。

## 3. 最终信息架构

### 3.1 Sidebar

Sidebar 保留模块导航,并在当前模块支持语言时展示语言筛选。

| 当前模块 | Sidebar 语言来源 | 说明 |
|---|---|---|
| 星标 | 本地 DB `languageStats` / `knowledgeLanguageStats` | 语言来自用户本地 repo |
| 探索-发现 | Discovery catalog / bulk | 后续补齐语言筛选 |
| 探索-趋势 | Trending language store | 当前已有语言入口 |
| 探索-热门 | Discovery catalog / bulk | 当前已有语言入口 |
| 探索-新发布 | Discovery catalog / bulk | 当前已有语言入口 |
| 探索-周刊 | Weekly language store | 从 Weekly 中栏迁出 |
| Activity 普通分类 | 第一版不提供语言筛选 | Activity 含公告、关注、Release 等非 repo 流 |

第一版语言是单选:

- `All Languages`
- 一个具体语言
- 未分类语言按现有 `uncategorized` 语义处理

多选语言暂不进入第一版,避免同时扩大数据查询、空态解释和 Trending 多语言合并语义。

### 3.2 Explore

Explore 子分类调整为:

1. 发现
2. 趋势
3. 热门
4. 新发布
5. 周刊

Weekly 迁移后:

- Activity 不再显示 Weekly 入口。
- Weekly 不做双入口兼容。
- Weekly 详情页、列表、多选、入库状态、README 渲染等能力保留。

### 3.3 中栏顶部

中栏顶部是当前列表控制区。

| 模块 | 中栏顶部控件 |
|---|---|
| 星标 | 排序 + 星标同步状态 / 刷新 |
| 探索-发现 | 排序 + 新鲜度 / 刷新 |
| 探索-趋势 | 周期 + 排序 + 新鲜度 / 刷新 |
| 探索-热门 | 排序 + 新鲜度 / 刷新 |
| 探索-新发布 | 排序 + 新鲜度 / 刷新 |
| 探索-周刊 | 筛选 + 排序 + 刷新 |
| Activity 普通分类 | 排序 + 刷新 |

## 4. 排序方案

排序统一 UI,不统一状态。

公共排序项:

- 名称 A-Z / Z-A
- Stars 高-低 / 低-高
- 更新时间新-旧 / 旧-新
- 创建时间新-旧 / 旧-新

模块专属排序:

| 模块 | 专属排序 |
|---|---|
| 星标 | Star 时间、健康分 |
| 探索-发现 | 推荐 |
| 探索-趋势 | 推荐 / 官方榜单顺序 |
| 探索-热门 | 热门 |
| 探索-新发布 | 新发布、Release 时间 |
| 探索-周刊 | 最新事件 |
| Activity 普通分类 | 活动时间 |

实现上可以使用统一排序菜单组件,但每个模块传入自己的可选项。切换模块时,如果之前的排序项不适用于新模块,回落到该模块默认排序。

## 5. 筛选方案

模块筛选不做全局化。

星标筛选:

- 阅读状态
- 知识库状态
- Archived / Fork
- 其它本地 repo 专属条件

Weekly 筛选:

- 来源
- 覆盖
- 仓库状态
- Stars
- 活跃度

探索趋势:

- 周期独立为“周期”,不放入筛选。

Activity 普通分类:

- 第一版保持活动时间排序和刷新,不额外引入 repo 语言筛选。

## 6. Weekly 迁移规则

Weekly 迁移到 Explore 时必须保留:

- 中栏列表。
- 右栏详情。
- 列表选中策略。
- 多选能力。
- 已入库心形标识和详情页入库动作。
- README / AI / 外链等现有详情能力。
- Weekly total 计数。

必须移除或调整:

- Activity Sidebar 中的 Weekly 分类入口。
- Activity 专属 `selectedActivityCategory == .weekly` 路由判断。
- Weekly 中栏内部语言选择器。
- Activity 分类计数中对 Weekly total 的绑定。

## 7. 不做范围

- 不做 Activity 与 Explore 双入口。
- 不做多选语言。
- 不做跨模块全局排序状态。
- 不把星标的阅读状态暴露到探索 / 周刊。
- 不把 Activity 普通分类纳入语言筛选第一版。
- 不改 GitHub / Weekly / Discovery 后端接口语义,第一版优先使用现有缓存和本地筛选。
