# AI 个人笔记生成正式方案

> 日期: 2026-07-22
> 状态: 正式方案
> 范围: 仓库详情页私有笔记、README Markdown 按需准备、AI 流式草稿、确认写入与流程可视化

## 1. 背景

Starcat 已具备私有笔记、README 原文缓存、单仓 AI 摘要和流式响应能力，但用户仍需从空白编辑器开始整理仓库使用笔记。现有 AI 摘要面向“理解项目”，不能直接替代“以后怎么用、哪里容易踩坑、还要补什么”的个人笔记。

本方案为私有笔记增加 AI 起草与优化能力：AI 根据 README Markdown 生成快速上手和可继续填写的大纲；已有笔记不丢失，而是作为独立上下文参与优化。生成过程完整可视化，用户能看到正在读取或下载 README、准备现有笔记、生成草稿、等待确认和保存等步骤，也能定位失败发生在哪一步。

## 2. 目标

1. 空笔记可以根据 README Markdown 生成一份简洁、可继续维护的 Markdown 笔记。
2. 已有笔记可以在保留用户事实、链接、命令、代码片段、TODO 和个人判断的前提下优化结构与表达。
3. AI 只消费 README Markdown；已有笔记不为空时，额外消费当前笔记快照。不得注入 HTML、仓库代码、RepoContext、External Search、标签或 AI 摘要。
4. README Markdown 未缓存时按需下载，下载结果复用现有本地缓存。
5. 生成使用流式响应，但流式内容只进入独立草稿，用户确认前不得覆盖或自动保存正式笔记。
6. 折叠标题行右侧展示紧凑流程状态，完成、跳过、失败、取消和当前步骤都可见。
7. 用户点击“应用到笔记”后才一次性保存，并沿用现有语义索引刷新链路。

## 3. 产品原则

1. **AI 先建议、用户后确认**：生成草稿和正式笔记必须是两份状态。
2. **用户内容优先**：AI 不得删除已有笔记中的用户事实性内容；模型仍可能出错，因此必须保留确认门。
3. **上下文最小化**：只发送完成任务必需的 README Markdown 和可选现有笔记。
4. **过程可解释**：失败必须落到具体步骤，不能统一显示为“生成失败”。
5. **本地优先**：README 和笔记继续保存在当前本地数据库；仅在用户主动生成时把必要文本发送给其配置的 AI Provider。
6. **不制造事实**：README 未提供的安装命令、环境变量、配置值和兼容性信息必须标为待补充，禁止猜测。
7. **复用现有能力**：复用 AI 摘要任务的 Provider、模型、流式参数、Pro 门控和取消语义，不新增第六个 AI 设置任务页。

## 4. 输入边界

### 4.1 README

输入使用 `readme_contents.content`：它来自 GitHub README Raw API 的 Markdown 响应，并在落库前经过现有安全清洗。该内容仍是 Markdown 数据源，不允许从 `rendered_html` 反向提取或降级生成。

准备顺序：

1. 读取本地 `readme_contents.content`。
2. 非空命中时，标记“读取 README”完成、“下载 README”跳过。
3. 未命中时，确保 README 主缓存记录存在，再请求 Raw Markdown。
4. 下载成功后重新读取本地 Markdown，作为本次冻结输入。
5. GitHub 返回 404、内容为空、网络失败或落库失败时停止流程，并把错误归属到“下载 README”。

不允许使用 HTML fallback。这样可以保证“只传 README.md，不传 HTML”的产品承诺为真实执行路径，而不是提示词层面的口号。

### 4.2 现有笔记

生成按钮点击瞬间冻结当前 UI 的 `editingContent`，而不是只读取数据库中的上一次已保存值。这样即使 800ms 自动保存尚未触发，用户刚输入的内容也不会遗漏。

- 空白快照：进入“生成笔记”模式。
- 非空快照：进入“优化笔记”模式，并完整注入提示词的独立 `<existing_note>` 数据区。
- 生成期间用户继续编辑：允许继续编辑，但应用草稿前必须比较当前内容与冻结快照；不一致时阻止静默覆盖。

### 4.3 明确禁止的上下文

- `rendered_html`
- repo metadata
- RepoContext / ZIP / 源码 XML
- External Search
- Tags / Tag hints
- 已缓存 AI 摘要
- RAG 检索结果
- 其他仓库的笔记

## 5. 输出契约

### 5.1 空笔记

默认生成以下结构；只有“快速上手”优先从 README 提取可执行信息，其他章节保持简短引导，留给用户继续填写：

```markdown
## 快速上手

从 README 提取的最短安装、配置和运行步骤。

## 核心能力

> 记录这个项目解决什么问题，以及最值得关注的能力。

## 常用配置

> 记录环境变量、配置文件和常用参数。

## 使用心得

> 补充适用场景、优缺点和个人评价。

## 踩坑与排查

> 记录遇到的问题、原因和解决办法。

## 待办

- [ ] 后续需要验证或补充的内容
```

如果 README 没有快速上手信息，应写明“README 未提供可验证的快速上手步骤，请补充”，不能编造命令。

### 5.2 已有笔记

AI 可以：

- 调整标题和段落顺序；
- 合并重复表达；
- 修正文句；
- 将零散命令整理进代码块；
- 在不改变含义的前提下补充章节标题和待填写说明。

AI 不可以：

- 删除用户记录的事实、链接、命令、代码、TODO 或主观判断；
- 把用户未确认的推断写成事实；
- 用 README 内容覆盖用户明确写下的相反经验；
- 输出解释、前言或 Markdown 围栏之外的包装文本。

## 6. 流程可视化

流程固定为七步：

| 顺序 | 步骤 | 说明 |
|---:|---|---|
| 1 | 检查 AI | 校验 Pro 权限、Provider、模型和 API Key；在任何 README 网络请求之前完成 |
| 2 | 读取 README | 查询本地 Markdown 缓存 |
| 3 | 下载 README | 缓存未命中时下载 Raw Markdown；命中时标记跳过 |
| 4 | 准备笔记 | 冻结当前编辑缓冲并选择生成/优化模式 |
| 5 | AI 生成 | 构造最小上下文并流式接收 Markdown 草稿 |
| 6 | 等待确认 | 草稿已完成，等待用户应用、重新生成或放弃 |
| 7 | 保存笔记 | 冲突检查通过后一次性保存并调度语义索引刷新 |

每一步支持以下状态：

- `pending`：尚未开始；
- `running`：当前进行中；
- `completed`：已完成；
- `skipped`：无需执行，例如 README 已有缓存；
- `failed`：该步骤失败，并保留用户可理解的错误；
- `cancelled`：用户取消后停在发生取消的步骤。

### 6.1 折叠标题行

私有笔记折叠标题行右侧是紧凑状态入口：

- 空闲时显示 `sparkles` AI 操作按钮，文案按笔记是否为空切换为“AI 生成笔记”或“AI 优化笔记”。
- 运行时显示七个紧凑状态点、当前步骤名称和 `当前序号/7`。
- 已完成步骤显示成功标识，跳过步骤使用弱化标识，失败步骤使用错误标识。
- 当前步骤提供停止入口；停止后保留已完成步骤，不伪装成失败。
- 生成完成后保留“等待确认”状态，直到用户应用、放弃、重新生成或切换仓库。
- 保存完成后保留整条完成状态，下一次生成或切换仓库时重置。

标题行继续满足整行展开/折叠契约。实现上使用“全行展开按钮作为底层命中面 + 右侧 AI 操作作为同级覆盖控件”，禁止把 Button 嵌套进 Button；被动状态点不拦截标题行点击。

### 6.2 展开内容

生成期间在笔记编辑器下方展示完整步骤列表和独立草稿区：

- 完整步骤列表负责显示每一步的状态和错误详情；
- 草稿区流式展示 AI Markdown，不绑定正式 `editingContent`；
- 完成后显示“应用到笔记”“重新生成”“放弃草稿”；
- 失败后显示失败步骤、错误说明和“重试”；
- 取消后保留已完成步骤，可重新生成；
- 草稿可选择 Markdown 预览，但不自动进入正式笔记预览 Tab。

## 7. 状态与并发

1. 每次生成绑定 `repo.id + generationID`，所有 `await` 返回和流式 delta 回写前都验证身份。
2. 切换仓库、视图销毁或用户停止时取消当前 Task，旧任务不得写入新仓库状态。
3. 流式草稿独立于 `editingContent`，不会触发 800ms 自动保存，也不会在生成中反复触发 embedding。
4. 应用时比较 `editingContent` 与生成前快照：
   - 相同：允许一次性应用；
   - 不同：显示冲突，要求基于最新内容重新生成或主动放弃草稿；首版不提供强制覆盖。
5. 保存成功后才把步骤标记为完成；保存失败时正式编辑缓冲保持原样，失败归属到“保存笔记”。
6. AI Provider 在取消后仍可能返回尾包，Task cancellation 和 generationID 双门禁共同阻止尾包覆盖状态。

## 8. AI 配置与 Prompt

首版复用 `aiSummaryTask` 的 Provider、模型、参数和 `streamEnabled`，但使用独立的内置个人笔记 Prompt：

- 不复用摘要 Prompt 的 `{metadata}`、`{codeContext}`、`{externalContext}`；
- Prompt 只支持 `{outputLanguage}`、`{readme}`、`{existingNote}`；
- README 和现有笔记都被标记为不可信数据，不能改变 system 指令；
- 输出必须是纯 Markdown；
- 输出语言继续跟随当前 AI 输出语言策略；
- AI 用量归因新增稳定 feature `repo_note`，phase 使用 `generation`。

首版不增加独立模型任务配置页，避免设置页任务分段继续膨胀。后续只有在用户明确需要“个人笔记使用不同 Provider/模型/Prompt”时再独立配置。

## 9. 权限与隐私

- 个人笔记 AI 生成属于 Pro AI 能力，沿用单仓 AI 摘要门禁。
- 无可用 AI 配置时先失败，不下载 README，不产生多余网络开销。
- 发起生成前在 UI 明示：README 和当前个人笔记会发送到用户配置的 AI Provider。
- 本地诊断日志不得记录 README、笔记、完整 Prompt、模型响应、API Key 或 Token。
- AI 用量统计只记录 provider/model/feature/phase/status/token 等元数据，不保存正文。

## 10. 数据与迁移

`repo_notes` 已存在 `is_ai_generated` 字段，本期不新增数据库 schema，也不修改已发布的 `v1-initial`。

首版把该字段解释为“当前正文最近一次整体应用是否来自 AI 草稿”：

- 应用 AI 草稿时写 `true`；
- 用户随后手工修改并保存时写 `false`；
- 仅修改阅读状态或知识库状态不改变该字段。

因此需要扩展 Repository 的内容更新语义，但不需要追加迁移。

## 11. 错误与恢复

| 失败位置 | 用户可见行为 | 恢复方式 |
|---|---|---|
| 检查 AI | 显示缺少权限或配置 | 打开设置或付费墙，重新生成 |
| 读取 README | 显示本地缓存读取失败 | 重试 |
| 下载 README | 显示 404、网络或落库失败 | 重试；不使用 HTML 降级 |
| 准备笔记 | 保留正式笔记 | 重试 |
| AI 生成 | 保留已收到草稿和具体错误 | 重试生成；不得应用不完整草稿 |
| 等待确认 | 当前笔记发生变化时显示冲突 | 基于最新笔记重新生成 |
| 保存笔记 | 正式笔记保持原内容 | 重试应用 |

## 12. 不做范围

- 不自动保存 AI 草稿。
- 不自动覆盖已有笔记。
- 不做 AI 草稿历史版本库。
- 不做逐段 diff 合并或三方合并。
- 不允许使用 HTML、代码上下文或外部搜索补充笔记。
- 不新增数据库表或 migration。
- 不新增第六个 AI 任务设置 Tab。
- 不在后台批量生成个人笔记。

## 13. 验收标准

1. README 已缓存时不发 GitHub Raw 请求，流程明确显示下载步骤已跳过。
2. README 未缓存时能够下载 Raw Markdown、落库并继续生成。
3. HTML 存在但 Markdown 缺失、两者都缺失、404 和网络失败都有明确结果。
4. AI 请求中不包含 HTML、repo metadata、代码上下文、外部搜索、标签或 AI 摘要。
5. 已有笔记按点击瞬间的编辑缓冲完整注入。
6. 流式草稿不会写入数据库，不触发笔记自动保存或语义索引刷新。
7. 用户停止、切仓库或关闭视图后，旧流不得继续更新 UI 或笔记。
8. 生成期间修改原笔记时，应用操作被冲突门禁拦截。
9. 应用成功后只保存一次，并触发一次语义索引刷新。
10. 折叠标题行和展开区域都能识别当前、完成、跳过、失败和取消步骤。
11. en / zh-Hans、明暗主题、Reduce Motion、键盘焦点和辅助功能通过检查。
12. 专项单测、相关回归测试、Debug build、静态规范检查和文档一致性审查通过。

## 14. 交付流程

1. 新增详细设计，明确类型、调用链、Prompt、UI 和测试结构。
2. 在 `docs/4-工程进度/AI个人笔记生成专项/` 建立专题 Checklist。
3. 每个可验证的小功能单独中文 commit，不 push。
4. 每轮审查先新增审查报告并提交，再按报告修复并单独提交。
5. 多轮审查无未关闭问题后，新增结果报告。
6. `docs/功能实现总览.md` 和 Changelog 继续遵守单独授权门禁，不在专项实现过程中擅自写入。
