# 外部搜索服务集成方案

> 日期: 2026-07-02
> 状态: 正式方案
> 范围: Starcat 外部搜索服务抽象、Provider 配置、全局搜索 Web 来源、AI 功能外部上下文
> 相关旧方案: [`starcat-anysearch-integration-plan.md`](../_archive/starcat-anysearch-integration-plan.md)

## 1. 背景

Starcat 当前已经集成 AnySearch,用于两个场景:

- 全局搜索中的 Web 搜索来源。
- AI 摘要生成时的外部网页上下文。

AnySearch 的返回结构适合交给 LLM 作为上下文,但它不应该成为 Starcat 对外部搜索能力的唯一抽象。当前可选服务已经包括 Tavily、Exa、Brave LLM Context 等面向 LLM / Agent 的搜索 API。继续把设置页、全局搜索筛选、AI 上下文都绑定到 AnySearch 会带来几个问题:

1. Provider 替换成本高,后续每加一个服务都要横向改设置页、SearchCenter、AI context。
2. 用户无法按自己的 API Key、额度、偏好选择外部搜索服务。
3. AI 摘要上下文来源不清晰,多个服务同时可用时缺少默认选择策略。
4. AnySearch 专属缓存、错误文案、设置项会污染更通用的外部搜索概念。

因此,本方案将 AnySearch 降级为一个外部搜索 Provider,在 Starcat 内部新增中立的 `ExternalSearch` 域。

## 2. 目标与非目标

### 2.1 目标

- 支持 4 个外部搜索 Provider: AnySearch、Tavily、Exa、Brave LLM Context。
- External Search Provider 统一通过 Starcat 内部 `ExternalSearchProvider` 接口接入。
- 设置页不再出现单一 AnySearch 大面板,而是改成外部搜索总设置 + 各 External Search Provider 设置组。
- 全局搜索保留 `Web` scope,但允许在 Web scope 内切换 Provider。
- AI 功能外部上下文可以选择默认 Provider,也可以使用 `Automatic` 自动选择。第一版只接入 AI 摘要。
- AnySearch 继续支持匿名额度;Tavily、Exa、Brave 没有 API Key 时不可用。
- 外部搜索失败不得阻断本地搜索、GitHub 搜索或 AI 摘要生成。
- 单 Provider External Context 对所有用户开放;Aggregate External Context Search 为 Pro-only。
- 全局搜索 Web tab 对所有用户开放,只受 Provider enabled、credential 和匿名能力约束。

### 2.2 非目标

- 第一版不在全局搜索 Web tab 中并发调用 4 个 External Search Provider 做聚合搜索。
- 第一版不做 Provider 结果质量评分或 LLM rerank。
- 第一版不做自托管 SearXNG / Jina / Kagi / Perplexity / Firecrawl。
- 第一版不把 Provider-specific 所有高级参数都暴露到 UI。
- 第一版不做“自动购买额度 / 自动申请 API Key / 自动保存上游返回 key”。

## 3. Provider 能力边界

### 3.1 能力对比

| Provider | 是否需要 API Key | 匿名可用 | 返回形态 | 适合场景 | Starcat v1 定位 |
|---|---:|---:|---|---|---|
| AnySearch | 可选 | 是 | `results[]` 结构化网页结果 | 匿名兜底、通用 Web 搜索 | 保留现有能力并纳入统一抽象 |
| Tavily | 必需 | 否 | `results[]` + 可选 `answer/raw_content` | Agent / RAG 通用搜索 | 通用外部搜索 Provider |
| Exa | 必需 | 否 | `results[]` + `text/highlights/summary` | 语义搜索、技术/研究类搜索 | AI 上下文优先候选 |
| Brave LLM Context | 必需 | 否 | `grounding.generic[].snippets[]` | 直接给 LLM 的上下文块 | LLM context Provider |

### 3.2 官方接入资料

| Provider | 官方文档 | 关键接口 |
|---|---|---|
| AnySearch | https://www.anysearch.com/docs | `POST https://api.anysearch.com/v1/search` |
| Tavily | https://docs.tavily.com/documentation/api-reference/endpoint/search | `POST https://api.tavily.com/search` |
| Exa | https://exa.ai/docs/reference/search | `POST https://api.exa.ai/search` |
| Brave LLM Context | https://api-dashboard.search.brave.com/documentation/services/llm-context | `POST https://api.search.brave.com/res/v1/llm/context` |

### 3.3 鉴权方式

| Provider | Header | 说明 |
|---|---|---|
| AnySearch | `Authorization: Bearer <key>` | 匿名模式不传 Authorization |
| Tavily | `Authorization: Bearer <key>` | 无 key 不发请求 |
| Exa | `x-api-key: <key>` | 无 key 不发请求 |
| Brave LLM Context | `X-Subscription-Token: <key>` | 无 key 不发请求 |

## 4. 产品原则

1. 外部搜索是补充来源,不能替代本地搜索。
2. Provider 选择是用户配置,不是写死在业务链路里的供应商决策。
3. `.all` scope 只跑一个默认 External Search Provider,避免成本、延迟和重复结果失控。
4. 手动 Web 搜索允许切换 Provider,方便用户比较不同服务效果。
5. AI 功能默认只使用一个 External Search Provider;用户显式开启聚合搜索后,External Context 可以调用多个可用 Provider。
6. AnySearch 匿名额度只作为 AnySearch 自身能力,不推广成所有 Provider 的通用特性。
7. 私有仓库默认不发送外部搜索查询;必须由用户显式开启。
8. 外部搜索错误只降级,不得让 AI 摘要、本地搜索、GitHub 搜索整体失败。
9. 私有仓库即使允许外部上下文,也只允许发送 repo fullName,不发送 README、notes、tags、code context 或 description。

## 5. 领域模型

新增中立命名空间:

```text
Starcat/Features/ExternalSearch/
├── ExternalSearchModels.swift
├── ExternalSearchProvider.swift
├── ExternalSearchRegistry.swift
├── ExternalSearchWebProvider.swift
├── ExternalSearchContextProvider.swift
├── ExternalSearchErrors.swift
├── Providers/
│   ├── AnySearchExternalSearchProvider.swift
│   ├── TavilySearchProvider.swift
│   ├── ExaSearchProvider.swift
│   └── BraveLLMContextSearchProvider.swift
└── Cache/
    └── DiskExternalSearchCache.swift
```

### 5.1 Provider ID

```swift
enum ExternalSearchProviderID: String, CaseIterable, Codable, Sendable {
    case anySearch
    case tavily
    case exa
    case braveLLMContext
}
```

### 5.2 Provider 协议

```swift
protocol ExternalSearchProvider: Sendable {
    var id: ExternalSearchProviderID { get }
    var capabilities: ExternalSearchCapabilities { get }
    func search(_ request: ExternalSearchRequest) async throws -> ExternalSearchResponse
}
```

关键约束:

- 协议只暴露 Starcat 需要的能力,不透传上游原始 DTO。
- Provider-specific 请求参数必须封装在 `ExternalSearchProviderFilters` 内。
- Provider 不直接读取 SwiftUI 状态,只读取调用方传入的配置快照。

### 5.3 统一请求

```swift
struct ExternalSearchRequest: Equatable, Hashable, Sendable {
    let query: String
    let maxResults: Int
    let freshness: ExternalSearchFreshness?
    let includeDomains: [String]
    let excludeDomains: [String]
    let purpose: ExternalSearchPurpose
    let filters: ExternalSearchProviderFilters
}
```

`purpose` 用于区分调用场景:

| Purpose | 用途 | Provider 参数倾向 |
|---|---|---|
| `globalSearch` | 全局搜索 Web tab | 返回可点击结果,控制结果数量 |
| `aiContext` | AI 功能外部上下文 | 优先拿 `raw_content` / `text` / `snippets` |

### 5.4 统一响应

```swift
struct ExternalSearchHit: Identifiable, Codable, Hashable, Sendable {
    let title: String
    let url: URL
    let snippet: String?
    let extractedText: String?
    let score: Double?
    let publishedAt: Date?
    let faviconURL: URL?
    let provider: ExternalSearchProviderID
}

struct ExternalSearchResponse: Codable, Equatable, Sendable {
    let hits: [ExternalSearchHit]
    let metadata: ExternalSearchMetadata?
}
```

外部搜索结果第一版只映射为 `ReferenceCandidate`,不自动识别为 `RepositoryCandidate`,也不自动写入 Starcat 本地 repo 数据库。即使结果 URL 是 GitHub repo 页面,也必须等用户显式导入、star 或加入知识库后才写入本地数据。

Brave LLM Context 没有传统 `results[]`,映射规则如下:

- `grounding.generic[].title` -> `ExternalSearchHit.title`
- `grounding.generic[].url` -> `ExternalSearchHit.url`
- `grounding.generic[].snippets.joined(separator: "\n\n")` -> `snippet`
- 完整 snippets 合并文本 -> `extractedText`
- `sources[url].hostname` 只作为 metadata,不覆盖 URL host

## 6. 设置模型

### 6.1 全局设置

`AppSettings` 新增中立设置:

```swift
var externalSearchIncludeInAll: Bool
var externalContextEnabled: Bool
var externalSearchAllowPrivateRepos: Bool
var externalSearchDefaultProvider: ExternalSearchProviderID
var externalContextProviderSelection: ExternalSearchProviderSelection
var aggregateExternalContextSearchEnabled: Bool
```

```swift
enum ExternalSearchProviderSelection: Codable, Equatable, Sendable {
    case automatic
    case provider(ExternalSearchProviderID)
}
```

默认值:

| 设置项 | 默认值 | 原因 |
---|---|---|
| `externalSearchIncludeInAll` | `false` | 避免 `.all` 默认消耗外部搜索额度 |
| `externalContextEnabled` | `false` | 避免用户未确认时把 repo 信息发给第三方 |
| `externalSearchAllowPrivateRepos` | `false` | 私有仓库默认不外发 |
| `externalSearchDefaultProvider` | `.anySearch` | 启用外部搜索后默认选 AnySearch;不代表默认发请求 |
| `externalContextProviderSelection` | `.automatic` | 自动选择最适合 AI 上下文的可用 Provider |
| `aggregateExternalContextSearchEnabled` | `false` | 默认不增加额外外部请求、成本和延迟 |

显式 Provider 选择不做静默 fallback。只有 `externalContextProviderSelection == .automatic` 时,才在用户已启用的 Provider 中按 Starcat 的 Provider 优先级选择第一个可用服务;Automatic 不会自动启用 AnySearch 匿名搜索。`aggregateExternalContextSearchEnabled == true` 时,External Context 改为聚合所有 enabled 且 credential 可用的 External Search Provider。

### 6.2 Provider 设置

```swift
struct ExternalSearchProviderSettings: Codable, Equatable, Sendable {
    var isEnabled: Bool
    var anonymousMode: Bool
    var defaultMaxResults: Int
    var credentialVerifiedAt: Date?
}
```

约束:

- `anonymousMode` 只对 AnySearch 生效。
- AnySearch 默认 `isEnabled = false`,`anonymousMode = true`;匿名能力不等于默认启用。
- Tavily、Exa、Brave 没有 API Key 时即使 `isEnabled == true` 也不可用。
- API Key 存在不代表 Provider enabled;Provider disabled 时不参与 Web 默认搜索、Automatic 或聚合。
- 关闭 Provider 不删除 API Key,方便用户临时停用后恢复。
- Test 成功后记录本机 `credentialVerifiedAt`;重启后仍视为已验证,直到用户编辑/删除 Key 或上游返回 invalid key。
- `credentialVerifiedAt` 是本机状态,不进入 CloudKit。
- API Key 不进 UserDefaults,继续走现有加密凭据存储。
- API Key 是本机凭据,不进入 CloudKit,不跨设备同步。
- 第一版 Provider enabled/default selection 也作为本机偏好处理,不做 CloudKit 同步。

API Key service id:

| Provider | Service ID |
---|---|
| AnySearch | `external-search.anysearch` |
| Tavily | `external-search.tavily` |
| Exa | `external-search.exa` |
| Brave LLM Context | `external-search.brave-llm-context` |

通用方法:

```swift
func externalSearchAPIKey(for provider: ExternalSearchProviderID) -> String?
func setExternalSearchAPIKey(_ value: String?, for provider: ExternalSearchProviderID)
```

项目未上线,不做旧字段兼容迁移。落地时可以删除 AnySearch 专属 setting 字段,直接收敛到 `ExternalSearch` 设置。

多设备约束:

- Mac A 配置的 Tavily / Exa / Brave API Key 不会自动出现在 Mac B。
- 如果未来同步外部搜索偏好,也只能同步非敏感 Provider 选择;目标设备缺少 API Key 时必须显示配置提示。

## 7. 设置页方案

设置页 `集成` Tab 拆成两层。

### 7.1 External Search 总设置组

字段:

- `Include external web results in All`
- `Use external web context in AI features`
- `Aggregate external context search`
- `Allow external context for private repositories`
- `Default provider for global search`
- `External context provider`

`Aggregate external context search` 需要在设置页展示说明文案,但不弹二次确认。说明必须表达:

- 默认关闭。
- 该能力仅 Pro 用户可用。
- 开启后 AI 功能会同时查询所有已启用且可用的 External Search Provider。
- 这会增加外部请求次数、等待时间和第三方服务用量。
- 全局搜索 Web tab 不受影响。

非 Pro 用户仍能看到该开关,但开关禁用并显示 Pro 标识;禁用态不保存开启值,也不发起聚合请求。设置页不在点击禁用开关时强弹付费墙。

如果用户曾在 Pro 状态下开启聚合,后续 Pro 过期,保留 `aggregateExternalContextSearchEnabled = true` 作为用户偏好,但运行时按非 Pro 禁用聚合请求;恢复 Pro 后该偏好自动重新生效。

`External context provider` 选项:

- `Automatic`
- `AnySearch`
- `Tavily`
- `Exa`
- `Brave LLM Context`

### 7.2 Provider 设置组

每个 Provider 一个独立 group:

| Provider | 字段 |
|---|---|
| AnySearch | Enable / Anonymous mode / API Key / Test |
| Tavily | Enable / API Key / Test |
| Exa | Enable / API Key / Test |
| Brave LLM Context | Enable / API Key / Test |

交互规则:

- API Key 输入框默认 secure,保留显示/隐藏按钮。
- Test 按钮使用输入框中的未保存 Key 发起最小请求,成功后保存 Key 并自动启用该 Provider。
- AnySearch 匿名模式开启时,API Key 不发送,但仍允许保存备用 Key。
- Tavily、Exa、Brave 未填写 Key 时 Test 按钮不可用。
- Tavily、Exa、Brave 必须 Test 成功后才能启用;Enable toggle 在没有已验证 Key 时禁用。
- 用户编辑 API Key 草稿不会影响已保存 Key;只有 Test 成功才替换保存值。
- Provider disabled 时,全局搜索 Web tab 中对应 Provider 显示不可用提示。

## 8. 全局搜索方案

### 8.1 Scope 不扩展

顶层 scope 保持:

```text
All / Local / GitHub / Web
```

不新增 `Tavily`、`Exa`、`Brave` 顶层 tab。原因:

- 顶层 scope 表达搜索对象类型,不是供应商。
- Provider 属于 Web scope 的内部选择。
- 如果顶层 tab 横向扩张,后续每加 Provider 都要改主导航和键盘选择逻辑。

### 8.2 Web scope 内 provider selector

`Web` scope 内新增 segmented control:

```text
AnySearch | Tavily | Exa | Brave
```

规则:

- Web scope 是当前 Provider 视图,不是跨 Provider 聚合视图。
- 默认选中 `externalSearchDefaultProvider`。
- 如果默认 Provider 不可用,Web scope 显示配置提示,不自动切换到其它 Provider。
- 切换 Provider 后,重跑当前已提交 query。
- 当前 Provider 不可用时,结果区显示 provider-specific 空态。
- Provider 未启用时不发请求,即使 AnySearch 支持匿名也必须先由用户启用。
- AnySearch 无 Key 但匿名开启时可用。
- Tavily、Exa、Brave 无 Key 时提示去设置页配置 API Key。
- Web scope 的外部搜索结果只作为 reference 展示和打开,不自动入库。

### 8.3 `.all` 行为

`.all` scope 下如果 `externalSearchIncludeInAll == true`,只运行 `externalSearchDefaultProvider` 对应的 Web Provider。

不同时运行所有 Provider。原因:

- 成本不可控。
- 延迟取最慢 Provider。
- 重复结果多,去重和来源归因复杂。
- 错误 footer 会被多个 Provider 噪音污染。

## 9. SearchCenter 数据流改造

当前 `SearchCoordinator` 只需要知道 `SearchSource.web`,不需要感知具体 Provider。

保留:

```swift
enum SearchSource {
    case localKeyword
    case localSemantic
    case github
    case web
}
```

替换:

```swift
let anySearchFilters: AnySearchFilters
```

为:

```swift
let externalSearchProvider: ExternalSearchProviderID
let externalSearchFilters: ExternalSearchFilters
```

`ExternalSearchWebProvider` 负责:

1. 从 `SearchRequest.externalSearchProvider` 找到具体 Provider。
2. 读取该 Provider 的配置快照。
3. 检查是否 enabled / credential 可用。
4. 查询 `DiskExternalSearchCache`。
5. 调用具体 Provider。
6. 将 `ExternalSearchHit` 映射为 `ReferenceCandidate`。

## 10. Filter 设计

### 10.1 公共 Filter

第一版公共 filter:

- `maxResults`
- `freshness`
- `includeDomains`
- `excludeDomains`

### 10.2 Provider Advanced Filter

Provider-specific filter 第一版只完整保留 AnySearch 现有能力,其它 Provider 可以先只走默认参数。

| Provider | 第一版 UI | 后续可补 |
|---|---|---|
| AnySearch | domain / contentTypes / zone / maxResults | tag / params |
| Tavily | maxResults | topic / searchDepth / includeRawContent / timeRange |
| Exa | maxResults | searchType / category / contentsMode / date / domain |
| Brave | maxResults | contextThresholdMode / tokenBudget / freshness / local |

这样做可以避免第一轮同时改大量 UI 控件和 i18n 文案,先完成抽象与 Provider 接入。

## 11. AI 功能外部上下文

### 11.1 Provider 选择

`AnySearchContextProvider` 改为 `ExternalSearchContextProvider`。

选择流程:

1. `externalContextEnabled == false` -> 返回 nil。
2. repo 是 private 且 `externalSearchAllowPrivateRepos == false` -> 返回 nil。
3. `aggregateExternalContextSearchEnabled == true` -> Pro 用户调用所有 enabled 且 credential 可用的 External Search Provider,再合并结果。
4. 聚合未开启且用户选择具体 Provider -> 只检查该 Provider 是否可用,不可用时不 fallback。
5. 聚合未开启且用户选择 `Automatic` -> 按优先级选择第一个可用 Provider。
6. 没有可用 Provider -> 返回 nil,AI 摘要继续生成。

`Automatic` 优先级:

```text
Exa -> Tavily -> Brave LLM Context -> AnySearch
```

原因:

- Exa 更适合语义化技术搜索和项目文档发现。
- Tavily 通用性强,适合作为 Agent / RAG web search。
- Brave LLM Context 输出适合直接给 LLM,但不是传统结果列表。
- AnySearch 支持匿名,适合作为兜底。

聚合模式执行规则:

- 聚合模式是 Pro-only;非 Pro 用户看到付费墙或禁用态,不发起聚合请求。
- 单 Provider External Context 不做 Pro 门控,只受 Provider enabled、credential 和隐私设置限制。
- External Search Provider 之间并发执行。
- 单个 External Search Provider 内部最多执行 2 条 repo query,并且串行执行。
- 任一 Provider 失败只影响该 Provider,不取消其它 Provider。
- 上层等待所有 Provider 完成后再做去重和结果预算裁剪;用户取消 AI 任务时整体取消。

### 11.2 Query 生成

沿用当前两条 repo query:

```text
{owner}/{name} documentation release notes
{owner}/{name} alternatives review {description}
```

约束:

- 每个 repo 最多 2 条 query。
- 单 Provider 模式下每条 query 默认取 5 条结果,去重后最多 6 条 source 进入 prompt。
- 聚合模式下每个 External Search Provider 每条 query 取 3 条结果,合并去重后最多 8 条 source 进入 prompt。
- 聚合结果先按 URL 去重;同 URL 优先保留带 `extractedText` 的结果,再按 Exa -> Tavily -> Brave LLM Context -> AnySearch 的 Provider 优先级取舍。
- 私有 repo 未授权时不发送给外部搜索。
- 私有 repo 已授权时只发送 repo fullName,不附带 description、README、notes、tags 或代码上下文。

### 11.3 Prompt 注入

保留 `<external_context>` 包裹,但 source 改为真实 Provider:

```xml
<external_context source="Exa">
- [Title](https://example.com)
  Snippet...
</external_context>
```

聚合模式使用一个 block,source 写 `Aggregate`,每条条目前缀 External Search Provider 名称:

```xml
<external_context source="Aggregate">
- [Exa] [Title](https://example.com)
  Snippet...
- [Tavily] [Title](https://example.org)
  Snippet...
</external_context>
```

如果 Provider 返回 `extractedText`,优先截断后放入条目正文;否则使用 `snippet`。

## 12. 缓存方案

新增 `DiskExternalSearchCache`,不要继续扩展 `DiskAnySearchCache` 命名。

目录:

```text
external-search-cache/
├── global/
│   ├── anySearch/
│   ├── tavily/
│   ├── exa/
│   └── braveLLMContext/
└── ai-summary/
    ├── anySearch/
    ├── tavily/
    ├── exa/
    └── braveLLMContext/
```

Key 规则:

| 缓存 | Key | TTL |
|---|---|---|
| global | SHA256(provider + normalized request JSON) | 6 小时 |
| ai-summary | provider + repo id + query fingerprint | 24 小时 |

关键约束:

- External Context cache 必须纳入 provider,否则 AnySearch 结果会串给 Exa / Tavily / Brave。
- External Context cache 必须纳入 query fingerprint,避免 repo description 或 query 策略变化后继续复用旧上下文。
- 聚合模式不缓存合并后的整体结果;只缓存各 External Search Provider 成功且有命中的独立结果。
- Provider 失败不写缓存;第一版 0 结果也不写缓存。
- global cache 必须纳入 provider 和 filter fingerprint。
- rate limit / credential / API Key hash 不落盘。
- cache 失败静默降级,不能阻断搜索结果展示。
- 设置页 Storage 文案改为 `External Search cache`,不再写 AnySearch cache。

## 13. 错误模型

统一错误:

```swift
enum ExternalSearchError: LocalizedError, Equatable {
    case disabled(provider: ExternalSearchProviderID)
    case missingAPIKey(provider: ExternalSearchProviderID)
    case invalidAPIKey(provider: ExternalSearchProviderID)
    case quotaExhausted(provider: ExternalSearchProviderID)
    case rateLimited(provider: ExternalSearchProviderID, retryAfter: Int?)
    case serviceUnavailable(provider: ExternalSearchProviderID, message: String?)
    case decoding(provider: ExternalSearchProviderID)
    case transport(provider: ExternalSearchProviderID, message: String)
}
```

Provider 原始错误只在对应 client 内解析,上层 UI 只消费 `ExternalSearchError`。

降级规则:

| 场景 | 行为 |
|---|---|
| Web tab 当前 Provider disabled | 显示启用提示 |
| Web tab 当前 Provider missing key | 显示去设置页配置 API Key |
| `.all` 的外部 Provider 失败 | 本地/GitHub 结果照常展示,footer 显示 Web 失败 |
| External Context Provider 失败 | 摘要继续生成,记录 degradation reason |
| 聚合模式下部分 Provider 失败 | 使用成功 Provider 的结果,失败 Provider 只记录 degradation reason |
| 聚合模式下全部 Provider 失败或 0 结果 | 不注入 External Context,AI 功能继续执行 |
| AnySearch 匿名额度耗尽 | 提示绑定 API Key |
| Tavily/Exa/Brave quota 耗尽 | 提示检查对应服务额度 |

## 17. 风险与取舍

### 17.1 全局搜索不并发调用多个 Provider

这是明确取舍。全局搜索 Web tab 中多个 Provider 同时搜索看似更全面,但会带来:

- 成本叠加。
- 延迟取最慢服务。
- 结果重复去重复杂。
- AI prompt 噪音增加。
- 用户很难理解“到底用了哪个服务的额度”。

全局搜索第一版只允许手动切换和默认选择。External Context 的聚合搜索是独立开关,只服务 AI 功能上下文,不改变 Web tab 的 Provider View 语义。

### 17.2 Provider-specific filter 延后

Tavily、Exa、Brave 的高级参数差异很大。第一版只开放公共 filter,把 AnySearch 现有 filter 保留下来。这样可以先完成架构替换,避免 UI 和能力矩阵一次性膨胀。

### 17.3 不做旧字段兼容

项目未上线,无线上用户、无线上数据。AnySearch 专属字段可以直接改为 External Search 字段,不写兼容旧字段或数据迁移代码。

## 18. 推荐首轮实施范围

首轮建议只做:

1. `ExternalSearch` 中立模型。
2. AnySearch 迁移到统一 Provider。
3. Tavily / Exa / Brave 最小 client。
4. 设置页 Provider API Key 配置与测试。
5. External Context Provider 选择和缓存 key provider-aware。

全局搜索 provider-specific advanced filters 放到第二轮。

这个范围可以先解决“Starcat 不再绑定 AnySearch”的核心问题,同时避免一次性改动 SearchCenter UI、缓存、AI、设置页四条链路导致风险过大。
