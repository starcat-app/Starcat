> 创建：2026-07-04
> 状态：首期已实现，真实支付环境待联调
> 用途：Starcat App Store / Direct 双支付路径、可替换支付网关抽象和统一 Pro 权益方案
> 需求入口：`docs/2-产品/需求讨论/支付对接.md`

## 1. 方案结论

Starcat 支付体系分为两条渠道：

```text
App Store build
  -> SubscriptionManager
  -> Apple IAP / subscription

Direct build
  -> DirectLicenseManager
  -> Starcat License API
  -> PaymentProvider / LicenseProvider
      -> StaticPaymentProvider + CreemProvider（首期实现）
      -> LemonSqueezyProvider（备选）
      -> PaddleProvider（备选）
      -> StripeProvider（备选）
```

客户端业务层只依赖：

```text
EntitlementGate
  -> CompositeProEntitlementProvider
  -> ProEntitlement
```

不得在 AI、Release、Search、Settings 等业务模块里直接判断 StoreKit、Creem 或 license provider。

---

## 2. 渠道边界

### 2.1 App Store build

App Store build 必须保持 StoreKit-only：

1. 商品购买、恢复购买、订阅管理都走 StoreKit / Apple。
2. 不显示外部支付 provider。
3. 不显示 license key 输入。
4. 不显示官网购买链接。
5. 不允许外部 license 解锁 App Store build。

### 2.2 Direct build

Direct build 必须保持 Direct-only：

1. 不显示 StoreKit 商品购买入口。
2. 展示 license 激活、解绑、官网订阅管理入口。
3. 可打开 Direct provider checkout / customer portal。
4. 通过 Starcat License API 获取统一权益快照。

---

## 3. Provider 抽象

### 3.1 DirectPaymentProvider

负责购买和订阅管理：

```text
Checkout(ctx, request)
CustomerPortal(ctx, request)
```

首期实现为后端 `PaymentProvider` 接口和 `StaticPaymentProvider`，从环境变量读取 Creem hosted checkout / customer portal URL。这样先保留多 provider 边界，避免在尚未完成真实支付联调前过度绑定某一家网关的动态 session API。

### 3.2 DirectLicenseProvider

负责 license 设备实例：

```text
activateLicense(key, instanceName)
validateLicense(key, instanceId)
deactivateLicense(key, instanceId)
```

### 3.3 DirectEntitlementProvider

负责把 provider-specific 状态转换为 Starcat 统一权益：

```text
Provider response
  -> DirectEntitlementSnapshot
  -> ProEntitlement
```

首期客户端实现名是 `DirectLicenseManager`，它同时负责 Direct license 激活 / 校验 / 解绑和 `ProEntitlementProviding` 输出。

---

## 4. Creem 首期策略

Creem 作为 Direct v1 候选 provider，原因：

1. 支持 Merchant of Record，降低全球税务处理压力。
2. 支持 subscriptions。
3. 支持 license keys。
4. 支持 activate / validate / deactivate。
5. 支持 webhook 和 customer portal。
6. 支持 test mode。

但 Starcat 不绑定 Creem：

1. 客户端命名不出现 `CreemLicenseManager` 作为业务核心类型。
2. 后续如果接 Creem 动态 checkout session，可新增 Creem 专属 payment adapter；首期先使用 `StaticPaymentProvider` 暴露 Creem hosted URL。
3. API response 必须转成 provider-neutral DTO。
4. 文案尽量写“官网订阅 / 授权码”，不直接把 provider 作为产品概念。

---

## 5. 服务端边界

客户端不能直连 Creem / Lemon Squeezy / Paddle / Stripe 的私密 API。

Direct v1 后端最小接口：

```text
POST /v1/direct/checkout
POST /v1/direct/licenses/activate
POST /v1/direct/licenses/validate
POST /v1/direct/licenses/deactivate
POST /v1/direct/customer-portal
POST /v1/webhooks/direct/{provider}
```

后端职责：

1. 通过 provider-neutral DTO 屏蔽 Creem 响应差异。
2. 校验 webhook 签名。
3. 处理退款、过期、取消、争议等事件。
4. 生成 Starcat entitlement snapshot。
5. 给客户端提供 provider-neutral 状态。

首期实现范围：License activate / validate / deactivate、checkout URL、customer portal URL、Creem webhook 验签与事件回显。数据库化保存 customer / subscription 映射留到真实支付联调阶段。

---

## 6. 本地存储

Direct 客户端只保存必要信息：

| 字段 | 存储 | 说明 |
|------|------|------|
| license key | Keychain | 敏感 |
| license instance id | Keychain | 敏感 |
| entitlement snapshot | 内存态 `ProEntitlement` | 当前运行期权益 |
| last validated at | 暂不持久化 | 首期不启用离线宽限放行 |
| provider display name | UserDefaults / JSON | UI 展示用，不参与授权 |

新增任何启动期 Keychain 访问都必须继续遵守 `TestEnvironment.isRunning` 门控。

## 8. 验收标准

### App Store

- [x] App Store build 无 Direct payment / license 入口，不渲染 Direct License section。
- [x] StoreKit 购买 / 恢复 / 管理订阅保留原路径。
- [x] App Store build 不包含 Direct License 设置入口。

说明：App Store 与 Direct 共享 `Localizable.strings` 资源，产物中可能包含未使用的 Direct 授权码 key；验收重点是 UI 不渲染、业务路径不可达、外部支付和外部授权不能解锁 App Store build。

### Direct

- [x] Direct build 无 StoreKit 商品购买入口。
- [x] license 激活后 Pro 生效。
- [x] 首期不启用离线宽限；validate 失败不放行新的 Pro 状态。
- [x] license 过期 / 退款 / 禁用后 Pro 失效。
- [x] customer portal endpoint 可返回配置的官网订阅管理 URL。

### 架构

- [x] AI / Release / Search 等业务模块不直接 import StoreKit 或 provider adapter。
- [x] provider API key 只存在服务端。
- [x] webhook 先验签后处理。
