# 第三方依赖升级与兼容性验证方案

> 状态：首批依赖升级与锁定已实施，自动化回归通过，完整兼容性验收仍在进行。
> 初始方案：2026-10-29；实施核对：2026-11-09。
> 范围：Agent 外部 Runtime、第三方二进制、SPM 依赖、vendored 源码与静态资源。

关联：[2.0.0 版本规划](../v2.0.0-版本规划.md)、[开发前问题清单 §4.19](../../../1-立项/开发前问题清单.md)、[开源致谢规则](../../../5-规范/开源致谢同步-规范.md)。

实施结果见 [依赖审计与验证记录](../../../4-工程进度/第三方依赖升级专项/依赖审计与验证记录.md)。当前构建锁定源为 `Configs/SwiftPackages.resolved`；下文 §3 保留初始清单用于比较，不能把历史版本当成当前版本。#193 保持 Open，真实模型、旧数据、GUI、受支持系统与最终分发验收尚未全部完成。

## 1. 目标与范围

2.0.0 对实际交付或调用的第三方组件进行一次完整版本审计，升级有明确收益且通过兼容验证的组件，并冻结可复现的发布组合。
完成标准包含应用行为、旧用户数据、两渠道产物和真实 Runtime 验证，不能只看依赖解析与编译成功。

| 类别 | 初始范围 | 升级交付 |
|---|---|---|
| 外部 Agent Runtime | DeepSeek Harness、Codex CLI / App Server 与配套 Host | 已验证版本、安装形态、协议适配、能力边界和失败恢复 |
| 第三方二进制 | CodebaseMemory，以及 Runtime 附带的可执行文件 | 来源、版本、校验和、架构、渠道装配和可执行性证据 |
| SPM 依赖 | `project.yml` 的直接包及 `Package.resolved` 的传递依赖 | 可复现锁定、变更影响、相关功能回归与两渠道构建 |
| Vendored 与静态资源 | CodeFlow、Mermaid、两套本地 UI 包、图标与生成数据 | 上游版本、本地补丁保留、渲染 / 交互 / 数据语义回归及归因 |

该专项列为 2.0.0 的 P1 工作，与推荐、每日热点等功能共用最终回归窗口，不重新建立 Runtime 架构。升级引入的兼容性问题阻断正式发布，需解决或撤回对应升级，不能转入仅收集问题的 P2 清单。
每项都必须得到“升级 / 保留现版并说明原因 / 已不使用并经确认移除”的结论；不为了版本号更大而升级。
2026-10-29 仅获方案授权；2026-11-09 dong4j 已授权实施升级与兼容验证。GUI、打包、发布与部署仍按各自授权边界执行。

## 2. 版本账本与来源依据

本文件是初始审计快照，不替代已有配置源。正式版本事实联合以下文件核对：

- [project.yml](../../../../project.yml)：直接依赖约束、渠道资源规则、部署目标与编译设置。
- [Configs/SwiftPackages.resolved](../../../../Configs/SwiftPackages.resolved)：受版本控制的完整版本与 revision；生成目录的 `Package.resolved` 由它恢复，不反向覆盖源锁。
- 各组件 `VENDOR.md`、`STARCAT-INTEGRATION.md`、安装脚本及资源旁许可证：复制来源与本地改动。
- [THIRD_PARTY_NOTICES.md](../../../../THIRD_PARTY_NOTICES.md)指定 `AboutView.AboutDependency.all` 为开源致谢正式登记。
- [第三方资源使用记录](../../../7-工具与脚本/第三方资源使用记录.md)是历史补充，当前仅登记语言 logo，不能当作完整现状。

实施阶段为每项补齐以下信息，再选择目标版本：

| 字段 | 记录要求 |
|---|---|
| 组件身份 | 官方项目、用途、直接 / 传递依赖、内嵌 / 外部安装 |
| 当前基线 | 文件路径、版本 / 完整 commit、锁文件 revision、已存在本地补丁 |
| 候选目标 | 官方 release / tag / commit、查询日期、变更说明；尚未核验则写待核验 |
| 交付范围 | App Store / Direct、架构、最低系统、是否属于运行时下载 |
| 产物证据 | 下载资产名称、归档和可执行文件各自的 SHA-256、签名及动态库依赖 |
| 兼容结论 | 受影响功能、自动化与真实运行结果、未验收项、保留旧版本的理由 |
| 恢复依据 | 上一锁定版本、原始资源、本地补丁、数据可回退范围 |

初始状态中 `Starcat.xcodeproj/` 与 `Package.resolved` 被 Git 忽略，32 个 pin 仅存在于本机。实施已选择单一源锁 `Configs/SwiftPackages.resolved`，XcodeGen 生成工程后恢复，标准构建和单测严格使用该版本组合并在成功后检查漂移。
本轮未修改 `.gitignore`；直接约束、源锁、锁文件脚本和构建入口按同批审阅。隔离解析与完整干净机器构建的证据边界见实施记录。

下列版本是初始方案时的本地快照；已核验候选、实际升级与保留理由见实施记录及其 JSON 账本，不表示所有候选均已通过运行验收。
分支依赖以完整 resolved revision 记录本机基线；升级时冻结具体 commit，不能只记录 `main` / `master`。
二进制检查同时核对归档与解压后的文件，不混用两类校验和；不以文件名推断版本。
签名前后的文件分别记录身份与校验结果；重新签名会改变二进制，不能要求签名后 hash 与上游原始 hash 相等。

## 4. Agent Runtime 升级方案

### 4.1 版本与安装验证

沿用 `ExternalAgentRuntimeHost + Provider Adapter`，不替换 Starcat 原生工作台或内置 Loop。
现有 §4.19 以 Direct arm64 为外部 Runtime 验证边界；当前 Starcat 的 DeepSeek 0.1.1rc1 安装方案仍限定 arm64。新候选 0.2.1rc2 已提供 macOS x64 资产，不代表 Starcat Intel 集成已经验证。
Codex 或其他工具即使提供 Intel 产物，也必须独立取得可运行证据，不能从主 App 的架构支持推断外部工具同样可用。

- DeepSeek 同步核对脚本版本、adapter 常量、三个 carrier 文件和专用 Cordis 配置；新的安装目录与旧版本并存验证后再切换。
- Codex 核对 CLI、独立 App Server、包根目录 / `bin` 和旧文件路径。独立形态必须校验配套 Code Mode Host，不能只检查主文件存在。
- 当前 Codex 路径解析主要验证路径与可执行性，缺少显式版本兼容门禁；补充实际版本 / 能力探测、已验证范围与不可用原因。
- 不静默覆盖用户的全局 Codex 安装、登录配置或第三方 Provider；候选版本在隔离目录验证，保留原配置恢复路径。
- 明确未知版本策略与错误提示；检测结果必须来自当前执行文件，不能拿安装器版本冒充运行版本。

### 4.2 协议与能力验证

| 链路 | 现有契约 | 新版本必须验证 |
|---|---|---|
| Codex | `initialize → thread/start → turn/start`、`model/list`、`dynamicTools` | 握手字段、模型与 reasoning、工具调用 / 返回、流式和最终消息、usage / 错误事件 |
| Codex 终止 | `turn/interrupt`，终态后回收专属进程 | 取消响应、迟到事件、无输出超时、异常退出与子进程清理 |
| DeepSeek | `initialize / session/prompt / shutdown`，一 Run 一 Sidecar | session 关联、block / message 合并、工具事件、MCP 冷启动和结束原因 |
| DeepSeek 终止 | 当前无可靠 turn cancel，以进程回收停止 | 不残留 carrier，不误标为完成；升级能力需真实验证后再更新 capability |

Fixture 需包含正常、错误、未知事件、重复 / 乱序增量和终态；新版本字段不能造成回答重复、工具结果丢失或界面一直运行。
不因上游新增 resume、approval、subagent 或文件编辑能力而自动开放；保持当前只读业务工具边界。

### 4.3 权限与凭据回归

- Codex 使用只读沙盒与临时 thread，检查继承的 MCP、plugins、hooks、apps 仍按配置关闭；不能只依赖 prompt。
- Host 继续二次验证工具 allowlist、schema 和自动只读权限；外部 Runtime 不直接读取 Starcat SQLite。
- DeepSeek 保留专用 Cordis profile、禁止未授权 Shell / subprocess，检查临时 MCP token 与仓库作用域。
- 环境变量过滤、日志脱敏、临时文件清理和凭据不落盘必须覆盖成功、失败、取消与重试。
- 更新后拒绝未经授权工具的证据与成功执行只读工具的证据都要保留，不能只测 happy path。

## 5. 旧用户数据、本地补丁与模型兼容

### 5.1 数据与索引

已发布的用户数据库不得随依赖升级重建。GRDB 或相关访问层变化必须使用旧库样本验证，必要 schema 变化追加 `registerVN`，不回写已发布 migration。
覆盖 Stars、标签、笔记、智能集合、列表分组关系与 CloudKit 同步状态，检验事务失败不会留下部分写入。

Codebase / RAG / 本地模型缓存属于不同数据域，需分别说明索引格式、兼容检测与重建范围。
如工具新版索引不能被旧版读取，应使用独立版本目录或明确可重建缓存迁移；不得把用户笔记、配置或模型文件一并删除。
模型权重不因库升级自动重新下载；先验证已缓存模型、tokenizer / 模板与旧配置能否继续使用。
MLX 升级还需覆盖 Embedding 维度 / 归一化和 Rerank 结果契约，变更需触发正确的索引失效而非静默混用。

### 5.2 本地补丁与资源语义

每个 vendor 升级前保存“旧上游 → 本地”的补丁，再比较“旧上游 → 新上游”，逐项决定重放或删除。
CodeFlow 三项 ZIP 接入改动必须逐项验收；上游功能变化不能破坏本地仓库导入或把资源 URL 注入转为任意脚本执行。
ThinkingOrbsKit 缺少上游 golden/spec 测试资源，要补项目实际调用场景验证，不把不存在的上游测试写成已通过。
图标和 Linguist 更新须验证名称匹配、颜色、缺省图标和语言分类 / 筛选语义；资源升级不附带重新设计布局。

|---|---|---|
| A：基线与目标选择 | 完整盘点、官方候选与变更说明、当前测试基线、资源 / 补丁留档 | 每项目标或保留理由明确，未知来源与版本有待办 |
| B：静态与 vendored | Mermaid、CodeFlow、图标 / 生成数据、本地 UI 包，按受影响功能再拆小批 | 资源和补丁比对、相关功能测试、两渠道构建 |
| C：普通 SPM | 图片、Markdown、ZIP、遥测等；数据层单独批次 | lock diff 可解释，相关回归通过，旧库样本通过 |
| D：AI 与协议依赖 | OpenAI、MCP、MLX / Hugging Face / tokenizer 作为配套组合 | 流式 / 工具 / 模型兼容、资源占用与失败恢复 |
| E：外部工具与 Runtime | Codebase、DeepSeek、Codex 分别升级与验证 | 真实指定版本执行、渠道隔离、索引 / 进程 / 权限结果 |
| F：版本冻结 | 完整 lock / commit / hash、全量回归、系统和升级矩阵 | 形成可发布的固定依赖组合与已知限制 |

同批只改相关依赖、适配和证据，避免把所有包一起升到最高版本后再排查。
每批完成相关测试和构建；不对每个小补丁反复运行全量测试。全量测试放在基线和冻结阶段，新增失败或跨模块影响再扩测。
批次之间保留可审阅的独立 diff；提交、push、打包和发布仍按届时授权执行。

## 7. 验证入口与证据层级

实施命令沿用以下 Makefile 标准入口，先退出 Xcode IDE。具体已执行结果与未覆盖项见实施记录。

```bash
rtk proxy make build-appstore
rtk proxy make build-direct
rtk proxy make test TEST_ARGS="-only-testing:StarcatTests/ExternalAgentProtocolAdapterTests -only-testing:StarcatTests/ExternalAgentRuntimeHostTests"
rtk proxy make test
```

当前 [adapter 测试](../../../../StarcatTests/ExternalAgentProtocolAdapterTests.swift)默认只跑协议 fixture；真实 turn 需显式启用 `STARCAT_RUN_CODEX_INTEGRATION` / `STARCAT_RUN_DEEPSEEK_INTEGRATION`。
Xcode 测试宿主不会自动继承任意 shell 环境变量，实施时确认现有入口的变量 / 编译标志传递，不能只在命令前加变量便宣称真实测试已执行。
真实集成前明确运行版本、模型、凭据来源、调用预算和网络范围，取得实施授权后经标准入口验证；缺少统一入口时先补 Makefile / 脚本入口。
不使用裸 `xcodebuild` 写入固定 DerivedData，不运行打包脚本替代普通构建。

| 证据层级 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 静态核验 | 版本、来源、补丁、锁文件、架构和配置关系 | 实际功能兼容 |
| 单元 / fixture | 本地协议状态机、解析、缓存、迁移和错误处理 | 新版 Runtime 的真实握手与真实工具调用 |
| 指定版本集成 | 真实进程、模型目录、turn、只读工具与取消 | 所有系统 / 架构与 GUI 验收 |
| 双渠道构建 | 编译、资源装配和构建期产物校验 | 公证、安装升级、用户界面与长期运行 |
| 发布阶段验收 | 最终签名产物、安装 / 更新与分发链路 | 尚未执行的系统或硬件组合 |

GUI 验收单独授权，当前不操作屏幕；自动化与人工未覆盖的项必须如实标为待验收。

## 8. 兼容性矩阵

工程配置当前最低 macOS 为 15.0，Swift 6.0、`SWIFT_STRICT_CONCURRENCY=complete`，`xcodeVersion` 声明为 26.5。
这些是配置事实，不证明实际构建使用的 Xcode / SDK 或用户系统已验证；执行时记录标准入口使用的真实版本。

| 维度 | 必须覆盖的场景 |
|---|---|
| 渠道 | App Store / Direct 独立构建与资源检查；外部 Runtime 仅 Direct，Sparkle 不在 App Store 启用 |
| 架构 | 主 App 实际支持的 arm64 / x86_64 分别核验；arm64-only 工具在不支持环境明确不可用，不靠 Rosetta 推断兼容 |
| 系统 | 最低支持 macOS 15 与实施时当前稳定 macOS；记录具体版本，Beta 不作为唯一依据 |
| 用户状态 | 新安装、已有 1.9.x 数据升级、已有 Runtime 路径 / Provider / 模型、缺资源和损坏资源 |
| 环境 | 在线 / 离线、CDN 不可达、代理、权限不足、路径含空格 / 非 ASCII、模型或 Runtime 不可用 |
| 生命周期 | 启动、切换 Provider / 模型、长回答、关闭窗口、取消、超时、App 退出与重启恢复 |
| 数据 | 旧库事务 / 迁移、索引兼容、缓存失效、用户配置保留；不要求删库重建 |
| UI | 明暗主题、窄中栏、大字号、减少动态效果；新增或修改文案完成全部 18 种语言 |
| 性能 | 首次响应、解析 / 渲染耗时、内存峰值、CPU、模型加载、后台资源释放与包体积；与同设备基线比较 |

新增译文必须核对语言覆盖、占位符与编译资源；长文案 / RTL 的布局验收独立记录，不能以英文 fallback 冒充完成。
无法执行的 Intel、最低系统或真实 Runtime 场景标记未验证，并影响相应支持 / 发布结论，不能用开发机通过代替。

## 9. 冻结、恢复与发布阶段

冻结时记录每个目标 tag / commit、受版本控制的完整 lock 或等价精确约束、二进制资产与 hash、vendor 补丁和许可；候选更新不能在发版构建中重新解析成另一份产物。
使用独立干净环境验证标准构建入口恢复同一版本组合，补上当前锁文件被忽略留下的可复现缺口。
构建后检查真实 Bundle：哪些二进制进入哪个渠道、架构 slice、依赖库路径、资源与许可证是否齐全，不能只查看源码 excludes。

升级失败按批次恢复依赖锁和资源；Runtime 切回上一验证目录 / 配置，不覆盖用户全局安装。
源码回退不等于用户数据可以降级：已经执行的新迁移或新索引格式必须遵守各自恢复约束，不尝试逆向改写用户数据库。

最终签名、嵌套可执行文件签名、Hardened Runtime、公证、Gatekeeper、安装升级和 Sparkle 更新链路留到正式发布授权后执行。
本专项先提供冻结版本、风险与验证证据，不把未执行的打包、公证或双渠道上传写成已完成。
正式交付附升级清单、保留版本与原因、测试矩阵、未覆盖项和恢复说明；开源致谢继续同步 About 正式登记与资源旁声明。
