## 用户在洞察页要看什么

打开「我的洞察」，用户可以回答三个问题：我收藏的项目集中在哪些主题？哪些主题下已经有项目标记为在用、写下过笔记？最近收藏的项目和以前相比有什么变化？点击每个主题能看到支撑数字的仓库，接着阅读、整理或补充笔记。收藏量说明关注方向，用户手动标记和笔记分别说明使用与整理行为。

到了年底，同一个人可以在报告里看到当年收藏节奏、主题分布，以及有时间记录的后续行动。两处共用统计口径。洞察默认展示当前事实，报告同时注明自然年、时区、数据截至日，以及哪些历史记录可用。

## 首版指标与年报用法

| 需求 | 洞察页中的问题 | 年报能说什么 | 证据与限制 |
| --- | --- | --- | --- |
| R1 收藏节奏 | 最近收藏了多少个不同的项目？ | 按月呈现记录到的收藏次数和涉及仓库数 | 复用 Star／Unstar 账本。重新收藏可产生新动作，同一仓库在同一统计范围去重。只有当前收藏记录时标为「目前仍收藏」 |
| R2 关注主题 | 某个用户标签或 GitHub Topic 下有哪些项目？ | 按月或季度比较各期收藏项目在报告生成时的主题分布 | 区分用户标签、GitHub Topics 和主语言。一个项目可属多个主题。分类缺失也要能看到对应仓库 |
| R3 从收藏到使用 | 一个主题下有多少仓库目前标记为在用？ | 已有日期的记录可以串起「收藏 → 标记在用」 | 「在用」由用户显式标记。「已读」表示 README 加载完成。轨迹须对应同一账号、仓库，并能确认先后 |
| R4 知识沉淀 | 哪些主题下有项目入库、有非空笔记或有 AI 摘要？ | 展示年内记录到的入库、正文写入，以及代表仓库 | 当前非空笔记按仓库计，并区分系统标记的 AI 生成笔记。AI 摘要单列。历史不足时只展示可证明的现状 |
| R5 证据与解读 | 点击数字能否找到对应项目，并理解取数范围？ | AI、WebView 和分享封面能否引用同一份统计？ | 每条结论带指标、单位、时间语义、覆盖说明和代表记录。基础画像离线可读，AI 解读由用户主动触发 |

「全部收藏」与「知识库」沿用洞察现有两个范围。历史账本另标「期间记录到的动作」，保留已经取消收藏的项目。作为主题代表展示的仓库只是样本，用户仍可以打开完整匹配列表。

## 对用户可见的验收样例

- 一个用户在同一季度对 A 执行 Star → Unstar → Star，另收藏 B。若三次 Star 均已记录，报告显示「收藏 3 次，涉及 2 个仓库」。点开仓库数只显示 A、B 各一行。
- A、B 都属于「本地 AI」，只有 A 目前标记为在用且有一条人工笔记。画像显示「2 个项目，1 个在用，1 个有人工笔记」，两个数字都可下钻到 A。仅凭当前状态，年报可写「当年收藏的项目中，A 截至生成时仍标记为在用」。若另有年内标记事件，年报可展示动作日期。
- 用户在年中启用动作记录。上半年显示「该时段缺少记录」，已覆盖且数据完整的月份才显示零。只有知识库数据的用户仍能读到相应章节。分享预览默认排除私仓标识和笔记正文，用户能看清将要分享的每一项。

## 交付边界

本专项交付原生洞察画像、本地动作记录、可下钻统计及供年报使用的事实样例。主题归类沿用已有标签和 Topics，AI 解释使用统计与经选择的证据，标签写入沿用用户确认流程。

年报专项负责自然年 GitHub 开发贡献查询、跨源贡献关联、正式报告留存与重生成、WebView 展示和分享载体。双方以相同输入能否复现同一数字为交接条件。年报章节和分享方案继续在[版本规划 §12.5](../v2.0.0-版本规划.md#annual-report-presentation-sharing)维护。
