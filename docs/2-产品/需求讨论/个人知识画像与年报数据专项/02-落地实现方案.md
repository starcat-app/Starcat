> 方案评审稿。需求编号与验收场景见 [01 需求方案](01-需求方案.md)，实施顺序见 [03 任务 Checklist](03-任务Checklist.md)。

## 1. 复用现有读取链路

由 App 在当前账号的 GRDB 读事务中选出仓库与动作，再做去重、主题交叉统计和证据查询。知识库范围沿用 RAG 与洞察共用的事实来源，当前收藏范围沿用「我的洞察」的数据提供者。先聚合完整集合，最后才截取页面展示数量。年报和外部工具调用同一查询，避免用界面 Top 列表反推全量分布。[洞察数据提供者](../../../../Starcat/Features/Insights/MyInsightsSnapshotProvider.swift) · [知识库事实快照](../../../../Starcat/Features/RAG/Core/KnowledgeBaseMetadataSnapshot.swift)

| 数据 | 取数与统计方法 | 时间解释 |
| --- | --- | --- |
| 收藏事件 | 按账号读取 `user_repo_activity` 的 Star／Unstar，分开计算事件数和不同 `repoId` 数。当前收藏回退按 `starredAt` 过滤，并标明限定范围 | 账本回填沿用可见收藏的原时间。网页取消收藏可能只有全量同步发现时间。两来源重合时同一动作只计一次 |
| 主题与语言 | 用户标签和 Topics 分别按来源、名称归组，同一仓库在同一组只计一次。主语言独立展示。对组内仓库分别统计当前在用、含非空笔记、含 AI 摘要 | 月／季度归属由收藏事件时间决定。主题、标签名称和使用状态取本次快照，并标注分类日期。`setTags` 会重建关联 |
| 入库与在用 | `library_state` 和 `status` 描述现状。`in_library` 配合 `library_updated_at` 可选出仍在库且最近一次入库落在区间内的项目 | 「首次入库」「年内开始使用」需要相应事件。标记在用还可能触发自动入库，两者保留各自含义 |
| 笔记与 AI 摘要 | 与编辑器使用相同的空白判断。非空笔记按仓库计，用 `is_ai_generated` 区分当前记录来源。`ai_summaries` 按仓库去重，可按留存摘要的 `generated_at` 筛选 | `repo_notes.edited_at` 也随状态写入更新。年内正文写入取新动作记录。摘要缓存只描述留存结果，生成请求次数另有语义 |

源码入口：[收藏账本与回填](../../../../Starcat/Core/Sync/UserRepoActivityRepository.swift) · [全量同步](../../../../Starcat/Core/Sync/SyncManager.swift) · [笔记与状态写入](../../../../Starcat/Core/Sync/RepoNoteRepository.swift) · [标签写入](../../../../Starcat/Core/Sync/RepoTagRepository.swift) · [摘要记录](../../../../Starcat/Core/Database/Models/AISummaryRecord.swift)。

## 2. 为未来年度记录动作

建议用一个本地附加事件表保存入库／移出、进入／退出在用、非空正文写入或变更。沿用账号库隔离，每条记录能确定账号、仓库、动作、时间和来源。只保存统计所需元数据，正文仍由原笔记保存。收藏动作继续读既有账本。迁移按已发布数据库规则追加，在原数据库上验证升级及已有内容保留。

在实际写入事务中比较旧值和新值。正文从空变为非空记录一次写入，内容实质变化且结果非空记录一次编辑。清空属于删除，之后重写可记录新写入。年度主指标按有写入的仓库去重。历史记录起点之后首次观测到写入，只能表述为「记录期内首次」。纯状态更新、自动加载 README、同值保存和失败事务均不产生写作事件。

进入在用且确实触发入库时，同一事务写一条在用事件和一条自动入库事件。按项目计算「采取过行动」时两者合并为一个仓库。UI、CLI、浏览器等入口复用同一写入层。导入或 CloudKit 合并只有状态快照时，保留来源与可见状态，避免把重放时刻当作用户操作时刻。首版覆盖按账号和本机可观测区间标注，跨设备动作合并能力在真实数据走查后确认。

## 3. 查询、下钻与年报交接

| 契约项 | 建议约定 |
| --- | --- |
| 查询输入 | 账号、范围、统计窗口、时区、数据截至时刻。当前集合和期间事件分别声明成员依据。自然年使用本地日历的 `[1 月 1 日, 次年 1 月 1 日)`，当前年截止生成时刻 |
| 输出事实 | 指标 ID、值、单位、分母（有占比时）、计数对象、期间和来源。逐指标给出可用覆盖区间及完整／部分／未知状态。完整覆盖才能将无记录展示为零 |
| 证据查询 | 指标与下钻共用筛选条件。仓库数返回去重集合，事件数可查看同一仓库的多次动作。代表仓库按最近相关动作选取，同时间用稳定仓库 ID 排序。缺少主题归入「未分类」，归属未知的私有性按保守规则处理 |
| 缓存与冻结 | 画像沿用现有刷新与切号机制，查询身份纳入范围、窗口、时区、统计规则版本及数据修订。年报接收生成时的事实副本、覆盖说明及代表证据。对已生成的报告再次展示时读取该副本 |

交付给年报的样例包含同一账号对 A 的两次 Star、对 B 的一次 Star、两个项目的当前主题、A 的在用事件和正文写入，以及下半年才开始记录动作的覆盖说明。同一截止时刻下，画像、年报适配器、CLI 三方应得到「3 次收藏、2 个项目、1 个有正文写入的项目」。在样例生成后改变主题，新的画像反映最新分类，旧报告样例保持原数字和分类。年报未来按自然年补取 GitHub 开发活动，跨源轨迹须同时具备仓库身份与动作日期。[已有贡献查询](../../../../Starcat/Core/Network/GitHubAPI/ContributionsAPI.swift)

## 4. 洞察、AI 与公共能力

「我的洞察」新增主题行，展示项目数、在用数、笔记覆盖和趋势入口。点击对应指标打开完整匹配仓库。刷新保留可读内容，跨账号或跨范围加载使用新查询身份。基础事实可离线读取。AI 输入限于所选指标、单位、覆盖范围及允许引用的代表记录，输出关联指标与证据。分享版由年报按用户选择构造数据，私有仓库和笔记正文默认排除，AI 调用前独立检查可发送内容。

| 动作 | App 执行与公共入口 | 权限、副作用及验收 |
| --- | --- | --- |
| 读画像、查询期间统计、下钻证据 | 本次拟开放。公共目录登记同一 App 查询服务，通用 CLI 和 MCP 读取同一 schema | `read`，遵循当前账号和范围。与 GUI 对比值和仓库集合 |
| 主动生成或刷新 AI 解读 | 接入画像生成用例时同步开放，按 App 的模型和权益执行 | `write` 默认关闭。用户开启后才发起可能产生费用的调用，执行后可读回结果。模型失败时仍能读取基础事实 |
| 记录整理动作 | 由现有写操作在业务事务内产生 | 无独立事件写入口。通过已有笔记、状态、入库操作验收事件归因和去重 |
| 生成年度报告、预览及分享 | 在年报专项确定留存和分享载体后登记动作 | 年报负责验证读写权限、分享前选择及实际输出内容 |
