## 1. 最终目标

Starcat 长期提供两套商业化路径：

| 渠道 | 支付 | 授权 | 用户入口 |
|------|------|------|----------|
| App Store | StoreKit / Apple IAP | Apple transaction entitlement | 订阅、恢复购买、管理 Apple 订阅 |
| Direct | 第三方支付网关 | license key / server entitlement | 购买、输入授权码、激活、解绑、管理官网订阅 |

两套路径都解锁 Starcat Pro，但购买、退款、续费、授权验证链路必须分离。

---

## 2. 核心需求

### 2.1 App Store 支付

App Store 版本只允许：

1. StoreKit 2 订阅购买。
2. Apple 账户订阅管理。
3. App Store 恢复购买。
4. App Store 审核可接受的订阅说明、隐私政策和 EULA。

App Store 版本不允许：

1. 展示 Direct license key 激活入口。
2. 展示 Creem / Lemon Squeezy / Paddle / Stripe 等外部购买入口。
3. 展示官网购买链接。
4. 用外部授权解锁 App Store 版本 Pro。

### 2.2 Direct 支付

Direct 版本允许：

1. 官网购买 Starcat Pro。
2. 打开第三方 checkout / customer portal。
3. 输入 license key 激活本机。
4. 解绑本机授权。
5. 通过 Starcat License API 校验最近一次服务端授权状态。

首期 Direct 支付网关选择 Creem，已完成 License API adapter 和静态 checkout / customer portal URL provider；真实产品、回调、test/live 环境仍需上线前联调。

### 2.3 多支付网关抽象

Direct 后续可能接入多家支付 / MoR / license provider：

| Provider | 定位 | 状态 |
|----------|------|------|
| Creem | 首期 provider：subscription、license、webhook、customer portal | License API adapter 已实现，支付环境待联调 |
| Lemon Squeezy | 早期方案参考，保留为可选 provider | 待评估 |
| Paddle | 可选 MoR provider | 待评估 |
| Stripe | 可选 payment processor；税务和 MoR 责任需另行处理 | 待评估 |

因此客户端和后端都必须抽象成 provider-neutral 接口：

```text
DirectPaymentProvider
DirectLicenseProvider
DirectEntitlementProvider
```

业务层只消费统一 `EntitlementGate`，不感知 StoreKit、Creem 或其他 provider。

首期代码实现名如下：

| 抽象职责 | 当前实现 |
|----------|----------|
| StoreKit 权益 provider | `SubscriptionManager` |
| Direct 权益 provider | `DirectLicenseManager` |
| 多来源聚合 | `CompositeProEntitlementProvider` |
| Direct license API client | `DirectLicenseAPI` |
| Direct 本地凭据 | `DirectLicenseStore` |
| 后端支付 provider | `PaymentProvider` / `StaticPaymentProvider` |
| 后端授权 provider | `LicenseProvider` / `CreemProvider` |

## 3. Creem 调研结论

Creem 官方能力覆盖 Direct 首期需要的关键链路：

1. subscriptions：月订 / 年订等 recurring billing。
2. license keys：购买后生成 license key。
3. license activate / validate / deactivate：设备激活、启动验证、解绑。
4. webhooks：订阅取消、过期、退款、争议等事件推送。
5. customer portal：用户自助管理订阅、发票和退款。
6. test mode：测试环境与生产环境隔离。

关键约束：

1. Creem API key 不能放进 macOS 客户端。
2. macOS 客户端只调用 Starcat 自己的 License API。
3. Starcat License API 再调用 Creem 或其他 provider。
4. Webhook 必须验签后才能更新授权快照。

## 4. 用户流程

### 4.1 App Store 购买

```text
用户打开 Pro 设置
  -> StoreKit 加载商品
  -> 用户购买 / 恢复购买
  -> SubscriptionManager 刷新 Apple entitlement
  -> EntitlementGate 解锁 Pro
```

### 4.2 Direct 购买与激活

```text
用户打开官网购买
  -> 第三方 checkout 完成付款
  -> provider 生成 license key
  -> 用户在 Starcat Direct 输入 license key
  -> Starcat License API activate
  -> 后端调用 provider activate
  -> 返回统一 entitlement snapshot
  -> 客户端缓存授权并解锁 Pro
```

### 4.3 Direct 启动验证

```text
App 启动 / 前台恢复 / 打开 License 设置
  -> 读取本地 license key + instance id
  -> 调用 validate
  -> 后端同步 provider 状态
  -> 更新本机 Pro entitlement
```
