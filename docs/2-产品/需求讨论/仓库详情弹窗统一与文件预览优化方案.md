# 仓库详情弹窗统一与文件预览优化方案

> 状态：2026-11-15 实现与自动化验证已完成，本地提交待人工界面与全语言审核；未合回 `dev`，未 push。
> 创建日期：2026-11-15
> 主关联：GitHub [#209](https://github.com/starcat-app/Starcat/issues/209) / Multica `HOM-241`。
> 实施位置：`codex/repo-workspace-unification`，worktree `Starcat-repo-workspace-unification`，基线 `dev@b961902b`。
> 适用范围：仓库详情打开的 Issues、仓库 Skills 安装窗口、下载文件窗口，以及主窗口仓库管理列表的项目卡片笔记标识。
> 核对依据：dong4j 提供的三张弹窗截图、补充的 GitHub 手机版文件树截图与项目卡片截图，以及当日主工作区 `dev` 源码。截图用于识别布局问题，尺寸以源码中的逻辑点 pt 为准。

## 1. 推荐结论

建议把三个弹窗收敛为同一套仓库工作区外壳，统一尺寸和顶栏；下载文件窗口增加可收起的文件详情栏、阅读放大、默认 Markdown 预览，以及按文件名称和类型区分的图标。项目卡片底栏同时补充右对齐的笔记状态胶囊，后续统一实施。

| 需求 | 推荐方案 | 用户获得的变化 |
|---|---|---|
| 三个窗口大小一致 | 标准内容尺寸统一为 **1180 × 720 pt**，共用屏幕适配规则 | 在同一屏幕、同一宿主条件下切换三个入口，窗口外框和内容画布一致 |
| 左上角标题一致 | 共用 **仓库头像 + `owner/repo`**；可见性徽章、单行简介按下载窗口样式统一 | 仓库身份稳定，Issues 不再以绿色功能图标和 “Issues” 作为主标题 |
| 下载右栏可折叠 | 默认收起，预览工具栏保留“显示 / 隐藏文件信息”按钮 | 首次点开文件后，更多宽度留给正文 |
| 中间内容可放大 | 同窗“放大阅读 / 还原布局”，收起文件树、右栏和空闲底栏 | 一次点击扩大阅读区，Esc 可还原，不额外打开窗口 |
| `.md` 可读 | Markdown 文件默认“预览”，提供“源码”切换；`Raw` 继续表示浏览器打开原文件 | 可以阅读标题、列表和表格，同时保留查看、复制原文的能力 |
| 文件树有辨识度 | 优先复用现有 Devicon 彩色语言 / 工具图标，README、LICENSE、CHANGELOG 等使用独立语义图标 | 扫描文件树时能快速分辨代码、配置与项目文档，不再大面积重复灰色代码图标 |
| 卡片能看出是否有笔记 | Stars 所在底栏的最右侧显示仅图标的笔记胶囊；有笔记显示，无笔记隐藏 | 浏览项目列表时即可识别已记录笔记的仓库，胶囊规格与同行一致 |

窗口统一不要求内部列宽一致。Issues 的列表、Skills 的选择列表、下载页的文件树承担不同任务，继续使用各自合适的宽度。

1180 × 720 是推荐值，尚未确认。Issues 现有代码记载了 2026-11-01 “首版过大”的反馈；本方案选择现有 Skills 的标准尺寸，是为了兼顾三窗统一与文件阅读，意味着 Issues 的标准尺寸增加 140 × 60 pt。若仍优先考虑紧凑窗口，可把三个窗口一起改为 1100 × 680 pt，右栏折叠策略保持相同；不建议三者继续保留独立尺寸。

## 2. 当前实现与问题定位

### 2.1 三个窗口确实使用不同尺寸和承载方式

| 窗口 | 源码中的尺寸 | 承载方式 | 当前顶栏 |
|---|---|---|---|
| Issues | 上限 1040 × 660；按 `NSScreen.main.visibleFrame` 调整，内含 880 × 520 下限 | `RepoDetailScaffold` 中的 SwiftUI `.sheet`，内容自身固定 frame | 绿色 Issue 图标 + Issues + 较小的仓库名 |
| Skills | 上限 1180 × 720；宿主屏幕宽减 64、高减 80 | `RepoSkillWindowController` 创建固定 AppKit sheet，`sizingOptions = []` | 28 pt Owner 头像 + 仓库全名 |
| 下载文件 | 固定 1020 × 660 | `RepoListView` 中的 SwiftUI `.sheet`，内容自身固定 frame | 28 pt Owner 头像 + 仓库全名 + 可见性 + 简介 |

对应代码：

- [RepoIssuesWorkspaceView.swift](../../../Starcat/Features/RepoIssues/RepoIssuesWorkspaceView.swift)：`workspaceSize`、`topBar`。
- [RepoSkillWindowController.swift](../../../Starcat/Features/Home/RepoSkillWindowController.swift)：窗口创建、屏幕钳制与关闭。
- [RepoSkillSheet.swift](../../../Starcat/Features/Home/RepoSkillSheet.swift)：顶栏、阅读放大和安装浮层。
- [RepoFileBrowserSheet.swift](../../../Starcat/Features/Home/RepoFileBrowserSheet.swift)：固定 frame、三栏、预览和下载入口。
- [RepoDetailScaffold.swift](../../../Starcat/Shared/Components/RepoDetailScaffold.swift)、[RepoListView.swift](../../../Starcat/Features/Home/RepoListView.swift)：实际展示入口。

因此，仅替换三个 `.frame` 数字不足以完成尺寸统一。还要统一窗口尺寸所有权、实际父窗口、屏幕选择和关闭回调，遵守现有 [Sheet 尺寸与承载规范](../../5-规范/UI-Sheet-尺寸与承载规范.md)。

### 2.2 下载页阅读宽度主要被固定右栏占用

下载页当前在未选文件时只展示文件树；点开文件后，左侧树收为 240 pt，右侧文件信息固定 260 pt，中间使用剩余宽度。

按当前外边距和栏间距计算，中间面板约为：

`1020 − 32（左右边距）− 240（文件树）− 260（信息栏）− 24（栏间距）= 464 pt`

这里还未扣除正文内部留白。单纯把整个窗口放大，仍会保留大量非阅读区域；右栏折叠与阅读放大应一起设计。

### 2.3 Markdown 原文已经取得，缺的是预览分流

[RepoFileBrowserViewModel.loadPreview](../../../Starcat/Features/Home/RepoFileBrowserViewModel.swift) 已通过文件 blob SHA 获取内容；文本统一进入 `.text`，随后交给 [RepoFileSourcePreview](../../../Starcat/Features/Home/RepoFileSourcePreview.swift) 的只读 `NSTextView`。

所以截图中的 `AGENTS.md` 原文显示是当前设计结果，不是下载或解码失败。无需为 Markdown 再下载一次文件，也不需要新增服务端渲染接口。

现有 Skills 已有可参考路径：

- [RepoSkillReadingCache](../../../Starcat/Core/Skills/RepoSkillReadingCache.swift)：在 actor 中使用 `MarkdownContent(...).renderHTML()` 准备 HTML，并处理相对图片地址。
- [RepoSkillDetailPane](../../../Starcat/Features/Home/RepoSkillDetailPane.swift)：使用 `ReadmeWebView`，维护文档身份、骨架、渲染就绪和过渡。
- [ReadmeWebView](../../../Starcat/Shared/Components/ReadmeWebView.swift)：已有主题、字号、代码和表格样式、图片展示、工具栏及文档就绪回调。

这些是复用依据，不代表任意 Markdown 文件接入后即可直接宣称全部行为兼容。路径解析、快捷键和错误反馈仍有本专题需要补齐的接缝。

### 2.4 文件图标已有映射，但分类和渲染方式限制了辨识度

[RepoFileTypeIcon](../../../Starcat/Features/Home/RepoFileTree.swift) 当前先取最后一段扩展名，再匹配无扩展名文件：

- Swift、JavaScript、TypeScript、Python、Go、Rust、Kotlin、JSON、YAML 等都返回同一个 `.codeContext`。
- `.md`、`.markdown`、LICENSE、README、CHANGELOG 使用普通文件图标；`README.md` 会先命中 `.md`，没有专属文档身份。
- 文件树、预览标题与右侧信息栏已共用这一映射，适合在同一处升级。

项目并不缺少本地图标资源：[Devicons 资源目录](../../../Starcat/Resources/Assets.xcassets/Devicons/) 当日实际包含 **561 个 imageset**，已有 Swift、Kotlin、Java、Git、Gradle、Markdown、JSON、YAML、Docker 等资源；[LanguageIconView](../../../Starcat/Shared/Components/LanguageIcon.swift) 已在其他界面使用彩色语言图标。该数量是本地资产盘点，不是上游图标总量。

另一处限制来自 [BusinessIcon](../../../Starcat/Shared/Components/BusinessIcon.swift)：资产统一经过 `.renderingMode(.template)`，文件树调用处还设置 `.foregroundStyle(.secondary)`。因此，只把映射换成彩色资产名称，仍可能被画成单色；需要同时区分彩色内容图标和单色业务图标的绘制方式。

## 3. 统一窗口尺寸与宿主

### 3.1 尺寸契约

以内容区 **1180 × 720 pt** 为标准，三个入口共用一处尺寸策略。

| 项目 | 约定 |
|---|---|
| 标准尺寸 | 1180 × 720 pt |
| 屏幕来源 | 点击入口实际所属 `NSWindow.screen`；确实没有宿主时才用现有回退 |
| 屏幕适配 | 宽不超过可见区域减 64 pt，高不超过可见区域减 80 pt |
| 内容变化 | 文件切换、列表加载、错误、翻译、折叠和放大均不改变窗口外框 |
| 计算时机 | 打开前计算一次；普通内容更新不重新测量整个窗口 |
| 超小工作区 | 不用硬性下限把窗口撑出可见区域；进入紧凑布局，优先保留关闭、还原及核心操作 |
| 多屏 | 同一宿主条件下三窗同尺寸；不同屏幕可以按同一规则得到不同结果 |

这里只统一本次涉及的三个弹窗，不改主窗口、独立 README 窗口或独立 Skill 管理工作台的尺寸恢复规则。

### 3.2 统一为固定 AppKit sheet

Skills 已具备合适的承载方式，建议以其模式为基础，为 Issues 与下载文件补齐轻量窗口控制器：

1. 从实际入口取得父窗口，不继续依赖 `NSApp.mainWindow ?? NSApp.keyWindow` 猜测。
2. 由 `NSWindow` 设置内容尺寸、最小尺寸和最大尺寸；`NSHostingController.sizingOptions = []`。
3. SwiftUI 根内容填满宿主，不再各自持有另一套固定尺寸。
4. 通过 `.appHostEnvironment(...)` 注入实际使用的依赖、本地化、字号与主题环境。
5. 各窗口保留自己的业务会话和关闭动作；公共部分只处理尺寸与视觉，不接管下载、安装或 Issue 草稿。

现有 [WorkspaceSceneWindowReader](../../../Starcat/Shared/Utilities/AIWorkspaceSceneCoordinator.swift) 可用于取得实际窗口引用，读取时不设置主窗口最小尺寸。

重点回归关闭行为：Issues 保存草稿；下载页沿用 `stop()` 取消下载与预览；Skills 沿用会话的安装取消和清理。关闭按钮、Esc、宿主结束展示都必须走正确的生命周期，不能把原先依赖 `.onDisappear` 的清理遗落。

## 4. 统一仓库顶栏

### 4.1 身份区域

“logo”沿用当前下载页的含义：仓库 Owner 头像，不新增仓库专属 logo 探测。

| 元素 | 统一规则 |
|---|---|
| 头像 | 28 pt，优先已有头像 URL；缺失时复用现有 Owner 头像解析与占位 |
| 主标题 | `owner/repo`，`.title3.weight(.semibold)`；单行，中间截断，悬停显示完整值 |
| 可见性 | 复用 Public / Private 小徽章，跟随真实仓库元数据 |
| 简介 | 有数据时一行 `.secondary`；只读取已有模型，不为顶栏增加网络请求 |
| 高度 | 标准字号下统一 64 pt；大字号使用同一高度计算规则，不由各页独立增长 |
| 边界 | 统一左右 18 pt 内边距和底部分隔线 |

缺少简介时保留同一顶栏高度，避免打开不同仓库时正文起点变化。功能名称保留在窗口标题、辅助功能标签或所属内容区，不和仓库名称竞争主标题。

### 4.2 操作区域

| 窗口 | 保留的专属操作 |
|---|---|
| Issues | 刷新、新建 Issue、关闭 |
| Skills | 添加到 Skill 库、扫描诊断 / 进度、刷新、关闭 |
| 下载文件 | 分支、搜索文件、关闭 |

关闭入口统一 `SheetCloseButton`，刷新继续使用 `SyncIconButton`。分支和搜索框应有宽度上限，长名称或译文首先截断并提供 tooltip，关闭按钮不能被挤出窗口。

只抽取共用顶栏组件及身份数据，不把三个 ViewModel 合并。Issues 右侧复用的通知详情内容保留原结构，本轮不顺带重做评论区与内部标题。

## 5. 下载页右栏折叠

### 5.1 默认状态与入口

建议新打开窗口时文件信息栏默认收起。尚未选文件时继续使用现有整宽文件树；点开文件后进入“文件树 + 内容预览”。

在预览工具栏右侧常驻“显示 / 隐藏文件信息”图标按钮。按钮状态、tooltip 和辅助功能名称同步；还原入口始终位于正文外，不随正文滚动消失。

正常宽度下，展开右栏在窗口内部重新分配空间；右栏宽度先沿用 260 pt。中间面板不足 520 pt 时，使用覆盖式信息面板，避免继续压缩正文。阈值从列宽、间距和正文下限推导，按当前建议参数约为窗口宽 1076 pt。

只在当前打开会话中保留右栏偏好。切文件不自动展开，重新打开窗口恢复默认；首版不增加全局设置或跨启动持久化。

### 5.2 收起后操作仍然可达

右栏现在包含单文件下载，因此折叠不能只把现有 `inspector` 隐藏：

- 预览工具栏增加“下载当前文件”，调用现有 `startDownloadPreviewed()`。
- 复制原文 / 图片和 `Raw` 保留在预览工具栏。
- “复制 raw URL”“在 GitHub 查看”等放入紧凑的更多菜单，并保留复制成功反馈。
- 窗口底栏仍负责“下载已勾选文件”，与“下载当前文件”明确区分。
- 当前文件下载不自动勾选文件树；折叠不更改已勾选集合。

窄窗口下优先把次要操作收入更多菜单，不通过缩小字体或让工具栏溢出来容纳全部按钮。

### 5.3 预期阅读面积

沿用下载页左右各 16 pt 内容边距、240 pt 文件树、260 pt 信息栏和 12 pt 间距时：

| 状态 | 中间面板宽度，未扣内部留白 |
|---|---:|
| 当前 1020 pt 窗口、三栏 | 约 464 pt |
| 统一为 1180 pt、三栏 | 约 624 pt |
| 统一为 1180 pt、右栏收起 | 约 896 pt |
| 统一为 1180 pt、放大阅读 | 约 1148 pt |

右栏收起带来的收益比单纯扩大外框更明显，也保留了随时查看文件信息的能力。

## 6. 下载页阅读放大

### 6.1 行为定义

放大沿用 Skills 的语义：扩大本窗口内的内容区域，不是字体缩放，也不是进入系统全屏。

| 区域 | 普通状态 | 放大状态 |
|---|---|---|
| 仓库顶栏 | 显示 | 保留 |
| 左侧文件树 | 显示 | 隐藏 |
| 预览工具栏 | 显示 | 保留文件名、模式、复制、下载、还原 |
| 右侧信息栏 | 按会话偏好 | 暂时隐藏 |
| 空闲批量下载底栏 | 显示 | 隐藏 |
| 下载进行中 | 底栏显示进度与取消 | 保留紧凑进度与取消入口 |

Markdown、普通文本和图片都可放大。没有可展示内容时不提供有效的放大操作；加载与错误仍保留复制、源码回退或下载等当前可用操作。

### 6.2 状态恢复

- 进入放大仅改变布局，不改当前文件、分支、批量勾选或预览 / 源码模式。
- 退出后恢复放大前的右栏偏好，不一律展开。
- 折叠和放大不重新拉树、不重新下载、不重新解析当前正文。
- 保持阅读器实例与文档身份稳定；宽度变化可自然重排，阅读位置不能无故回到顶部，文本选择尽量保持。
- 切分支沿用现有清空预览规则，同时退出放大；不在空白页面留下放大状态。

状态只需表达“是否放大”和“是否希望显示信息栏”，实际可见性由当前文件、可用宽度和放大状态派生。无需为每种组合新建业务会话。

### 6.3 键盘与关闭顺序

Esc 按当前层级消费：先关闭菜单 / 查找等局部浮层，再关闭覆盖式信息面板，再退出阅读放大，最后才关闭整个窗口。一次按键不能同时还原并关闭窗口。

下载页目前明确把 `⌘F` 留给文件树搜索，而 `ReadmeWebView` 会登记正文查找动作。接入时必须消除冲突：本窗口继续让 `⌘F` 搜文件，Markdown 阅读器在此调用点不登记同一个命令；在放大状态进入文件搜索时先还原布局，让筛选结果可见。其他 README / Skills 调用方继续保留既有正文查找。

## 7. Markdown 预览

### 7.1 类型与显示模式

| 文件情况 | 默认显示 | 可用切换 |
|---|---|---|
| `.md` / `.markdown`，忽略大小写，且成功识别为文本 | Markdown 预览 | 预览 / 源码 |
| 其他文本、代码、配置文件 | 现有带行号源码 | 无 Markdown 模式 |
| 图片 | 现有图片预览 | 可放大 |
| 二进制、超限、不可预览的 LFS 对象 | 现有对应提示 | 下载 / 外部查看 |

不能只看扩展名就强行解码二进制，也不能把 MDX 当作可执行内容。空 Markdown 显示明确的空文件状态。

“源码”是窗口内查看原文；现有 `Raw` 继续打开浏览器中的原文件，二者不能复用同一个状态含义。复制全文和下载始终使用仓库原始内容，不复制渲染后的 HTML，也不修改源文件。

首版每次选中新文件默认回到该类型的默认模式；同一文件的右栏显隐、放大和还原保留用户已选模式。

### 7.2 渲染路径

建议采用已经存在于 Skills 的组合：

1. 继续使用 `RepoFileDownloader` 获取原始字节和文本。
2. 在独立于主线程 UI 的准备步骤中执行 `MarkdownContent(text).renderHTML()`。
3. 按当前仓库、树快照与文件目录解析资源地址。
4. 把 HTML 和明确的 `documentID` 交给现有 `ReadmeWebView`。
5. 收到当前文档的 `onDocumentReady` 后完成骨架与正文交接。

不引入新的 Markdown 依赖，不把文件伪装成 `RepoSkill`，也不直接复用包含安装领域数据的 Skill 会话。首版保留当前文件的原文和已准备 HTML 即可，不新增磁盘缓存或数据库表。

预览 / 源码两种展示复用同一份已读取文本。切换模式不触发网络请求；当前 Markdown 阅读器应保持稳定身份，重新回到预览时恢复该模式的阅读位置。两种排版分别保留滚动状态，不承诺源码行与 Markdown 段落逐行对齐。

### 7.3 相对链接与版本一致性

这是渲染接入的必要工作，而不是后续装饰：

- 文件位于 `docs/guide/setup.md` 时，`./image.png` 相对于 `docs/guide/` 解析，`../intro.md` 相对于父目录解析。
- 图片使用对应快照下的 raw 资源地址，文档链接使用对应快照下的 GitHub 内容地址；基址必须保留目录末尾 `/`。
- 相对路径不能无条件拼在仓库根目录，非默认分支不能改用 `HEAD`。
- `fetchTree` 已取得最新提交，但当前只作为局部值参与树缓存查询。实施时保留这次树获取实际使用的提交 SHA / ref，供预览身份与相对资源使用。
- 不把文件 `blobSHA`、Git tree SHA 或 `previewCommit` 中“该文件最近一次提交”误当作整棵树的提交。
- 文档身份包含账户作用域、仓库、树提交 / ref、文件路径和 blob SHA；同名文件跨分支或刷新后不能串内容。
- 若现有 API 未取得提交 SHA，沿用本次取树的 ref 并明确这一回退；不声称该情形已经获得不可变快照。

当前 [ReadmeAssetURLRewriter.rewrite](../../../Starcat/Core/Network/GitHubAPI/ReadmeAssetURLRewriter.swift) 的默认入口使用 `HEAD`，并从 GitHub HTML 的 `data-path` 推断目录；不能直接套到任意文件。建议补充显式提交和文件路径的调用入口，复用现有图片、`picture/srcset` 等处理；原 README 调用保持原行为，并跑现有回归。

普通文档链接先沿用浏览器打开，不在本专题新增文件浏览历史或跳转栈。若包含页内锚点，要单独验证当前渲染器的标题 ID 和点击处理；首版只承诺正确显示链接并按现有链接策略打开，不把页内目录导航写成已具备能力。

### 7.4 内容能力与失败边界

验收样例至少包含标题、段落、列表、任务列表、表格、引用、链接、图片和围栏代码。代码高亮、Mermaid、HTML 混排等扩展以现有本地渲染链路的实测结果为准；无法增强时应保留可读代码或源码入口，不承诺与 GitHub 页面逐像素一致。

沿用现有文本预览上限 **512 KiB**、图片上限 **8 MiB**；本轮不顺带提高大文件预览限制。Markdown 预览失败时保留已取得的原文，提供“查看源码”和重试，而不是一直停留在骨架。

`ReadmeWebView` 当前失败 delegate 主要记录日志。为本次骨架等待提供带文档身份的失败回调，才能在导航失败或 Web 内容进程终止时进入可恢复状态；其他调用方默认行为保持不变。

私有仓库正文继续走已有鉴权下载。嵌入图片是否可访问取决于现有图片链路，不能因为正文成功就宣称私有附件已全部支持；不可访问图片保留替代文字 / 失败反馈，正文和源码继续可读。本轮不新增私有附件下载代理，也不把 Token 放进 HTML 或资源 URL。

沿用 `ReadmeWebView` 现有页面脚本与导航限制，Markdown 文件中的命令、脚本和操作说明只作为内容展示。

### 8.3 绘制、主题与布局规则

- 下载窗口增加局部文件图标视图，明确区分“保留原色的资产”和“使用语义前景色的图标”。Devicon 使用原色绘制；现有 Lucide / SF Symbols 继续采用 `.primary` / `.secondary`，不把全局 `BusinessIcon` 改成原色。

- 原色资源不能被父级 `.secondary`、选中态或 disabled 样式意外洗成灰色。图标颜色只表达文件身份，选中与勾选继续由背景和复选框表达，不靠图标变色判断状态。

- 图标与文件名一起出现时不额外朗读资产名；图标变化不影响文件树整行点击、悬停、斑马纹、勾选、目录展开或阅读选择。

### 8.4 资源与维护边界

在 [RepoFileTypeIcon](../../../Starcat/Features/Home/RepoFileTree.swift) 保持一份匹配表，文件树、预览标题和信息栏共用；不要在三个 View 分别写后缀判断，也不要把文件图标分类接入下载、内容解码或权限判断。

本次只核对与使用实际选中的资源，不扩大为全 App 图标替换。复用前核对相应资产来源；新增 / 替换素材时记录来源路径、上游版本或 commit 与许可证，保留必要声明。目录名称本身不能替代素材来源记录。

现有 Devicon 和 Lucide 已在 [AboutDependency.all](../../../Starcat/Features/About/AboutView.swift) 登记；单纯复用不重复新增致谢。若取用新的图标库，即使只复制几个 SVG，也须按 [开源致谢同步规范](../../5-规范/开源致谢同步-规范.md) 登记，版权行取自对应上游许可证。Lucide 的许可证同时包含 Feather 派生图标声明，新增素材时保留涉及的完整声明。Devicon 的 [使用说明](https://github.com/devicons/devicon) 同时提示品牌 logo 应遵守各自品牌政策；不把开源许可理解成品牌背书。

首版不增加图标主题设置，不增加网络服务、字体图标包或整库导入；图标映射本身不产生新文案。若实施时需要新增辅助功能说明，仍按全部支持语言交付。

| 项目 | 推荐规则 |
|---|---|
| 位置 | 同行最右侧，与卡片内容右边界对齐；左侧统计胶囊与笔记胶囊之间保留弹性空白 |
| 显示条件 | 当前仓库存在已保存、去除首尾空白后非空的笔记正文时显示；无笔记时隐藏，不显示空胶囊或数字 0 |

| 交互 | 首版作为状态标识；点击该区域仍沿用卡片选择行为，不新增独立按钮或笔记弹窗 |

“有笔记”只取笔记正文：仅有已读状态、知识库状态、AI 摘要或尚未保存的 AI 笔记草稿均不算；已保存的手写笔记与 AI 笔记同样算作有笔记。

标识应放在底栏弹性空白之后，不追加进左侧 `metadataChipCluster`。若同时有语义搜索分数，笔记胶囊位于分数右侧，保持最右位置；窄栏沿用现有次要元数据降级，优先保留语言、Stars 和完整笔记胶囊，不换行、不裁掉半个胶囊，也不因此增加卡片高度。

### 9.2 现有依据与状态来源

- [UnifiedRepoRow](../../../Starcat/Shared/Components/UnifiedRepoRow.swift) 已有 Stars 所在底栏、宽窄两档元数据簇和右侧弹性空白，可在底栏尾部增加独立的笔记标识。
- [MetaBadge](../../../Starcat/Shared/Components/RepoRowComponents.swift) 已支持仅图标的胶囊及辅助功能标签，无需另造一套胶囊样式。
- [ManageRepoRowContent](../../../Starcat/Features/Home/RepoListView.swift) 已向卡片注入本地阅读、知识库与 AI 摘要状态；笔记状态沿用“管理列表提供、共享卡片展示”的分工，拟增加默认关闭的 `hasNote` 输入。
- [RepoNote](../../../Starcat/Core/Database/Models/RepoNote.swift) 同时保存正文、阅读状态与知识库状态，不能仅因 `repo_notes` 有记录就显示“有笔记”。
- [RepoNoteRepository](../../../Starcat/Core/Sync/RepoNoteRepository.swift) 已有 `fetchRepoIdsWithNonEmptyContent()`，正文保存后也会发布 `.repoNoteContentDidChange`；可复用其批量查询与变更通知。

列表层批量读取有笔记的仓库 ID 集合，统一正文存在性的判断口径，再将布尔值传给卡片。不要让每张卡片在 `body`、出现或滚动时分别查询数据库，也不增加网络请求、数据库字段或迁移。

现有批量查询使用 SQLite `TRIM(content)`，仅默认去除普通空格；笔记编辑界面的判定使用 `.whitespacesAndNewlines`。实施时对齐本次查询与通知更新的空白判定，并覆盖空格、换行、制表符，不能让两条路径对同一正文给出不同结果。

笔记保存成功后显示，清空或删除成功后隐藏；列表重新出现时重载以补齐离开期间的变更，账号数据库切换时清空旧集合。状态集合需要支持新增与移除，不能只做并集合并。初次尚未读取或读取失败时暂不显示标识，不阻断项目列表；笔记图标更新只影响当前卡片，不重置列表选中与滚动位置。

## 10. 动效、状态与无障碍

按 [列表与详情切换动效规范](../../5-规范/UI-列表与详情切换动效规范.md) 落实当前页面：

| 区域 | 要求 |
|---|---|
| Issues 列表 | 复用现有列表骨架，补齐适用的斑马纹、整行悬停、单选背景跨行反馈 |
| 下载文件树 | 当前阅读文件与批量勾选独立；按实际可见树行表达条纹，目录展开与复选框点击不互相吞事件 |
| 项目卡片笔记标识 | 保持原有卡片选中与悬停；正文保存或清空后仅更新对应标识，不让整张卡片重新入场 |
| Skills 左栏及正文 | 保留已经存在的跨行选中、过渡、骨架和翻译，不重复重建 |
| 文件正文切换 | 旧内容退场后再替换展示快照，当前内容就绪后入场；快速切换取消旧任务 |
| 首次加载 | 文件树、文本 / Markdown、图片分别使用合适占位；已有内容刷新继续显示结果 |
| 右栏显隐 | 内部分配宽度，短时过渡；窗口外框不变 |
| 减少动态效果 | 遵守 `starcatReduceMotion`，关闭位移、模糊和扫光，保留静态状态与必要短淡化 |

不能用固定延迟模拟渲染就绪，不能给整个 WebView 加文件 `.id` 来重播动画，也不能因为补骨架把懒加载列表改为全量创建。

隐藏面板、源码 / 预览的非当前层和离场内容不得继续接收点击或被辅助功能朗读。图标按钮提供本地化 tooltip 和 accessibility label，plain 按钮禁用 focus ring，复制操作继续使用 `CopyFeedbackButton`。正文与工具栏需要避让系统滚动条。

本方案与现有 [列表与详情动效优化专题](../../4-工程进度/列表与详情动效优化专题/列表与详情动效优化方案与Checklist.md) 的 C01、C02 有重叠：后续由同一实施批次交付并协调记录，不两套方案各重做一次。本轮不改变该专题的确认或完成状态。
