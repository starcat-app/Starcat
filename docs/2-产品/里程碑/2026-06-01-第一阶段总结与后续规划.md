# Starcat 第一阶段总结与后续规划

> 日期：2026-06-01
> 状态：第一阶段 (MVP) 基本收官，即将开启第二阶段 (AI 对接)

---

## 一、 阶段一：MVP 工程实现总结

第一阶段的目标是构建稳固的工程脚手架、打通 GitHub 核心同步流程并实现原生感的管理 UI。目前已完成约 95% 的 P0 级功能。

### 1.1 基础设施与数据层
- **本地存储**：基于 GRDB 7 (SQLite) 实现了 10+ 表结构，支持 FTS5 全文搜索。
- **凭证管理**：实现了统一的认证会话管理，支持 GitHub Device Flow 登录。
- **日志系统**：封装了 OSLog，提供分级业务日志。

### 1.2 网络与同步系统
- **核心同步**：支持全量同步与基于 `starred_at` 的增量同步，实测可稳定承载 2000+ Stars。
- **性能优化**：实现了 ETag 缓存（304 命中）与 Rate Limit 主动退避机制，大幅降低 API 消耗。
- **错误处理**：建立了集中式的 401/403 拦截与自动下线引导机制。

### 1.3 UI 与交互 (macOS 原生体验)
- **三栏布局**：采用 `NavigationSplitView` 实现了标准的 macOS 生产力布局。
- **README 渲染**：基于 WKWebView 实现了高度定制化的阅读器，支持 SWR 缓存、GFM 样式及亮/暗自适应。
- **整理工具**：完整的标签 CRUD、多选批量操作、私有笔记及阅读状态管理。
- **Trending**：打通了 GitHub Trending 发现页，支持周期筛选与初步的 AI 评分展示。

## 二、 遗留技术债与已知问题

在开启 AI 对接前，需记录并关注以下“工程债”，确保项目质量。

### 2.1 高危项：凭证安全 (D-16)
- **问题**：目前 GitHub Token 与 AI Key 存储于沙盒目录下的明文 `credentials.json` 中。
- **风险**：存在泄露风险。
- **对策**：发布前必须切回加密存储（Keychain 或应用层加密）。

### 2.2 数据联动与体验
- **状态联动**：详情页修改仓库状态（Status）后，左侧列表过滤不会即时刷新（需引入 Combine/NotificationCenter）。
- **计数差异**：Sidebar 分类计数目前未与列表内的 Archived/Fork 过滤口径完全对齐。
- **延迟功能**：JSON 导入/导出功能已延后至第五周实施。

## 三、 阶段二：全面 AI 对接与核心差异化 (当前重心)

本阶段旨在利用大模型能力，提升用户整理、理解和找回知识的效率。

### 3.1 AI 基础设施 (BYOK)
- **服务配置**：支持用户配置 OpenAI、Gemini、DeepSeek、Ollama 等 API。
- **AI 代理**：实现 Starcat 专用 AI 代理转发逻辑。

### 3.2 智能化核心功能
- **单仓 AI 摘要**：基于 README 生成结构化中文摘要。
- **AI 标签推荐**：智能提取仓库特征，提供标签建议并支持用户一键确认。
- **AI 语义搜索**：基于向量 Embedding 的自然语言查询（预研与落地）。

### 3.3 Release 订阅追踪 (P1 优先)
- **订阅机制**：实现仓库 Release 的订阅与本地推送。
- **时间线视图**：统一管理所有关注项目的发布动态。

## 四、 阶段三：上架准备与商业化收尾

本阶段关注产品的生态完备性、商业化变现及 App Store 审核准入。

### 4.1 多端同步与生态
- **CloudKit**：实现用户标签、笔记、状态等元数据的跨设备同步。
- **Apple 集成**：Spotlight 搜索支持、Widgets 小组件、MenuBar 快捷入口。

### 4.2 商业化落地
- **StoreKit 2**：接入应用内订阅/买断方案（Pro 版）。
- **配额管理**：实现 AI 调用配额与 Pro 权限的严格门控。

### 4.3 上架冲刺
- **UI/UX 优化**：全面适配 macOS 26 Liquid Glass 视觉规范。
- **合规性**：隐私政策页面、EULA、App Store 截图与描述撰写。
- **官网设计**：搭建高转化率的产品落地页。
