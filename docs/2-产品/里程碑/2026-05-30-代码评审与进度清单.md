### 2.5 Week 4 - 1：README WebView 渲染 + 抓取缓存（2026-05-30 下午追加）

Week 4 第一项功能落地，覆盖 P0 详情子模块的核心体验。

#### 2.5.1 设计决策

| 决策点 | 选择 | 拒绝项 | 原因 |
|---|---|---|---|
| 渲染方式 | GitHub 服务端 HTML（`Accept: application/vnd.github.html`） | 客户端 Markdown 解析器（cmark-gfm / Down / Ink） | 100% GFM 兼容（任务列表 / 表格 / mermaid / emoji / alerts）；零客户端解析负担；攻击面更小 |
| 视图框架 | `WKWebView` (`NSViewRepresentable` 包装) | `AttributedString` / 第三方 Markdown View | GitHub HTML 含完整样式类，AttributedString 无法 1:1 还原 |
| JavaScript | 禁用（`allowsContentJavaScript = false`） | 允许 | GitHub 返回的 HTML 是静态结构，关闭 JS 减少攻击面 |
| 链接策略 | 全部转 `NSWorkspace.shared.open` 跳系统浏览器 | WebView 内部导航 | 沙盒约束 + 避免页面变成"浏览器" |
| 缓存策略 | ETag + If-None-Match + Last-Modified（304 → 本地命中） | 仅 cached_at + TTL | GitHub README 端点支持 ETag；304 不计入 Rate Limit；体验最优 |
| 主题适配 | 内嵌 CSS + `prefers-color-scheme`（亮/暗自动切换） | JS 动态注入 / GitHub CDN CSS | 完全离线；零网络依赖；CSS 体积可控（约 5KB） |

#### 2.5.4 加载状态机

```text
.idle ──load(repo)──▶ .loading ──┬── 200 + html ──▶ .loaded(html, cachedAt)
                                  ├── 304 + 本地命中 ──▶ .loaded(本地 html, 旧 cachedAt)
                                  ├── 404 ──▶ .empty
                                  ├── Cancelled ──▶ (静默)
                                  └── 其他 NetworkError ──▶ .error(message) → 用户可点"重试"
```

#### 2.5.8 收尾时的两次回归及修复（追溯记录）

W4-1 初版于 17:40 落地后，dong4j 验证时连续暴露 2 个回归 bug。**记录如下，作为 SwiftUI on macOS 26 SDK 的踩坑沉淀**。

##### 回归 1：点击中栏仓库无选中 + 右侧无内容（17:50 ~ 18:00）

**症状**：列表能滚动，行无高亮，详情区一直显示 empty 占位。

**第一次尝试（17:52，没修好）**：

| 改动 | 文件 | 理由（看起来合理但不是根因） |
|---|---|---|
| `Repo` 加自定义 `static func ==` 只比 id | `Core/Database/Models/Repo.swift` | 与 `hash(into:)` 对齐，避免 Hashable/Equatable 违反契约 |
| `ReadmeViewModel` 从 `RepoDetailView` 上移到 `HomeView` 作 `@State` 持有 + `.environment(_:)` 注入 | `Features/Home/HomeView.swift` / `RepoDetailView.swift` | 修复 `RepoDetailView.task` 里 `@State` 异步赋值导致首次 `load` 调用被 nil 吞 |

两个改动**本身正确**，应该保留。但**症状没消失**——说明 `List(selection:)` 的写法本身有问题。

**第二次（18:00，真正修好）—— 核心改动**：

```swift
// HomeViewModel.swift（修改前）
var selectedRepo: Repo?

// HomeViewModel.swift（修改后）
var selectedRepoID: Int64?
var selectedRepo: Repo? {  // computed property，派生自 items
    guard let id = selectedRepoID else { return nil }
    return items.first { $0.id == id }
}
```

```swift
// RepoListView.swift（修改前）
List(selection: $vm.selectedRepo) {
    ForEach(viewModel.items) { repo in
        RepoRowView(...)
            .tag(Optional(repo))   // 用整 Repo 值作 tag
    }
}

// RepoListView.swift（修改后）
List(selection: $vm.selectedRepoID) {       // selection 类型 = Int64?
    ForEach(viewModel.items) { repo in
        RepoRowView(...)
        // 不写 .tag，由 Repo: Identifiable 自动用 repo.id 匹配
    }
}
```

**根因总结**：`List(selection: $selectedRepo)` + `.tag(Optional(repo))` 这种"用整 `Repo` 值作 selection"的写法依赖 SwiftUI 内部对 `Repo` 做 hash 索引 + `==` 配对，在 macOS 26 SDK 下点击事件无法稳定写回 binding。改为 **id-based selection** 后 SwiftUI 直接用 `ForEach.id == selection` 简单匹配，完全绕开 Hashable/Equatable 一致性问题。

**结论沉淀**（**写入团队规范**）：**SwiftUI `List(selection:)` 一律用 `ID` 而不是值类型**。即便整个类型已经 `Hashable`，也避免 selection 走值类型路径。

##### 回归 2：列表能选了，但 README 仍白屏（18:05 ~ 18:10）

**症状**：选中行高亮 ✓；metadata 卡片正常 ✓；日志显示 `GET-raw /repos/.../readme -> 200, bytes=50771` ✓；但 WebView 区域纯白。

**误导信号**：Console 一大堆 WebContent sandbox 错误（`pboard / launchservicesd / networkd / RunningBoard` 等），看起来像沙箱阻止了 WebView。**实际不是**——这些是 App Sandbox 下 WebContent 进程访问受限服务被拒的常规噪音，不致命。

**根因**：

```swift
// ReadmeWebView.swift Coordinator.decidePolicyFor 修改前
if navigationAction.navigationType == .other && url.absoluteString == "about:blank" {
    decisionHandler(.allow); return
}
if navigationAction.navigationType == .linkActivated {
    NSWorkspace.shared.open(url)
    decisionHandler(.cancel); return
}
if url.fragment != nil, navigationAction.navigationType == .other {
    decisionHandler(.allow); return
}
decisionHandler(.cancel)   // ← 兜底拒绝，把首次加载也拒了
```

我们调用 `webView.loadHTMLString(fullHTML, baseURL: repo.htmlUrl)`，WebKit 主框架导航的 `request.url` 是 baseURL（如 `https://github.com/Gitlawb/openclaude`），**不是 `about:blank`**：
- 不命中 `about:blank` 分支
- 不是 `.linkActivated`
- baseURL 没有 fragment

→ 落到默认 `.cancel` → 自己把自己的首次渲染 cancel 了。

**修复**：

```swift
// ReadmeWebView.swift Coordinator.decidePolicyFor 修改后
if navigationAction.navigationType == .linkActivated {
    NSWorkspace.shared.open(url)
    decisionHandler(.cancel); return
}
// 其他全部放行（loadHTMLString 触发的 .other / anchor 跳转 / form 提交）
decisionHandler(.allow)
```

白名单倒置：只拦用户点击的链接转外部浏览器，其余一律放行。

**附加增强**：补 `didFail / didFailProvisionalNavigation` 日志（`AppLog.ui.error`），未来沙箱 / HTML / 网络异常都能直接在 Console 看到，避免重蹈"沉默白屏"覆辙。

**结论沉淀**：
- 沙箱噪音不要被带偏，**先看自家代码的 navigationDelegate 兜底逻辑**。
- WKWebView 加载失败必须有日志，不要等下次 bug 时再补。

## 四、代码评审：可重构 / 待优化项

按"修改必要性"分四级：**P0 必改 / P1 建议 / P2 可选 / P3 测试覆盖**。

每项给出：**问题描述 / 当前位置 / 影响 / 建议改法 / 工作量**。

### 4.1 P0 - 必改（影响测试 / 类型安全 / 设计正确性）

#### P0-1：抽 `RepoRepository` 协议
- **问题**：当前 `RepoRepository` 是具体 struct，`HomeViewModel` / `SyncManager` 直接依赖类型
- **影响**：无法 mock，写 `HomeViewModelTests` / `SyncManagerTests` 必须真接 GRDB
- **建议**：
  ```swift
  protocol RepoRepositoryProtocol: Sendable {
      func fetchAllStarred() async throws -> [Repo]
      func fetchUntagged() async throws -> [Repo]
      func fetchByLanguage(_ lang: String?) async throws -> [Repo]
      func searchFTS(query: String) async throws -> [Repo]
      func languageStats() async throws -> [LanguageStat]
      func starredCount() async throws -> Int
      func upsertStarred(_ dtos: [StarredRepoDTO], userID: Int64, syncedAt: Date) async throws
      func markUnstarredExcept(remoteRepoIDs: Set<Int64>, userID: Int64) async throws
      func updateSyncState(userID: Int64, starredCount: Int, syncedCount: Int, status: String) async throws
  }
  ```
  现有 struct 改名为 `GRDBRepoRepository`，HomeViewModel / SyncManager 依赖 protocol
- **工作量**：S（约 30 分钟）

#### P0-2：抽 `GitHubAPIClientProtocol`
- **问题**：`SyncManager` / `AuthSession` 直接依赖 `GitHubAPIClient` actor 类型
- **影响**：无法 mock 网络层；写 SyncManager 测试要起 URLProtocol stub
- **建议**：
  ```swift
  protocol GitHubAPIClientProtocol: Sendable {
      func starredRepos(page: Int, perPage: Int) async throws -> APIResponse<[StarredRepoDTO]>
      func getCurrentUser() async throws -> GitHubUserDTO
      func unstar(owner: String, repo: String) async throws
      func star(owner: String, repo: String) async throws
  }
  ```
  + Mock 实现写在测试 target
- **工作量**：S

#### P0-3：`GitHubAPIClient.perform` 中的 `as! T` 强转
- **位置**：`GitHubAPIClient.swift:176`
  ```swift
  let empty = EmptyResponse() as! T
  ```
- **影响**：违反 generic 类型安全；万一 caller 传错 `T`（不是 `EmptyResponse`）会运行时崩溃
- **建议**：把 DELETE / PUT 路径独立成 `performNoBody()` 函数，不走 generic
- **工作量**：S

#### P0-4：`HomeViewModel` 过度暴露 mutable 属性
- **位置**：`HomeViewModel.swift` 共 9 个属性全部 `var public`
- **影响**：外部 View 可任意改 `items` / `isLoading` 等，状态一致性靠"自律"
- **建议**：除 `selection` / `searchQuery` / `selectedRepo`（需要 SwiftUI 双向绑定）外，其余改 `private(set)`
- **工作量**：XS

#### P0-5：`HomeViewModel.reloadItems` 没有 Task 取消机制
- **问题**：快速切换 sidebar 时，上一次查询的回调仍可能写入 `items`

## 五、接口设计评估

### 5.1 优点

- **DatabaseManaging 协议**：抽象到位，生产 / 内存测试无缝切换
- **GitHubTokenProviding 协议**：解耦 Keychain 依赖，便于测试
- **APIResponse 包装**：业务数据 + 分页 + 速率信息一次返回，调用方不用碰 raw 头
- **AuthState enum**：状态机清晰，三态全覆盖
- **SyncState enum**：含 `rateLimited` / `failed`，便于 UI 差异化展示
- **SidebarItem enum**：用 enum 把所有合法导航态封死，避免 stringly typed

### 5.2 待提升

- **RepoRepository / GitHubAPIClient / SyncManager / AuthSession 缺协议层**（见 P0-1 / P0-2）
- **AppDependencies 没有协议**：当前 .environment(AppDependencies.self) 注入，未来如需替换（如 PreviewProvider）只能整体替换
- **GitHubAPIClient 用 extension 加端点的模式**：StarsAPI / UserAPI 都是 extension；未来端点多了（Releases / Issues / Search...）会扩展爆炸。可考虑改为独立 Service：`StarsService(api: GitHubAPIClientProtocol)`
- **Migration 不可降级**：现在 v1 一次性建全；未来 v2/v3 出错时无法回滚（GRDB Migrator 不支持 down）。生产 OK，但 dev 期切换分支时可能踩坑
